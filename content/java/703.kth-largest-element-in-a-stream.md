## 题目描述

设计一个找到数据流中第 `k` 大元素的类（class）。注意是排序后的第 `k` 大元素，不是第 `k` 个不同的元素。

请实现 `KthLargest` 类：

- `KthLargest(int k, int[] nums)` 使用整数 `k` 和整数流 `nums` 初始化对象。
- `int add(int val)` 将 `val` 插入数据流 `nums` 后，返回当前数据流中第 `k` 大的元素。

**示例：**
```
输入：
["KthLargest", "add", "add", "add", "add", "add"]
[[3, [4, 5, 8, 2]], [3], [5], [10], [9], [4]]
输出：
[null, 4, 5, 5, 8, 8]

解释：
KthLargest kthLargest = new KthLargest(3, [4, 5, 8, 2]);
kthLargest.add(3);   // 返回 4，数据流为 [2, 3, 4, 5, 8]，第3大元素是4
kthLargest.add(5);   // 返回 5，数据流为 [2, 3, 4, 5, 5, 8]，第3大元素是5
kthLargest.add(10);  // 返回 5，数据流为 [2, 3, 4, 5, 5, 8, 10]，第3大元素是5
kthLargest.add(9);   // 返回 8，数据流为 [2, 3, 4, 5, 5, 8, 9, 10]，第3大元素是8
kthLargest.add(4);   // 返回 8，数据流为 [2, 3, 4, 4, 5, 5, 8, 9, 10]，第3大元素是8
```

**提示：**
- `1 <= k <= 10^4`
- `0 <= nums.length <= 10^4`
- `-10^4 <= nums[i] <= 10^4`
- `-10^4 <= val <= 10^4`
- 最多调用 `add` 方法 `10^4` 次
- 题目数据保证，在查找第 `k` 大元素时，数组中至少有 `k` 个元素

## 解题思路

这是一道经典的**数据流问题**，核心是维护动态变化的第 k 大元素。

**关键洞察：最小堆（Min Heap）**

维护一个大小为 `k` 的最小堆：
- 堆顶元素就是第 `k` 大的元素
- 堆中存储当前数据流中最大的 `k` 个元素
- 新元素插入时，若大于堆顶，则弹出堆顶并插入新元素

**为什么用最小堆？**
1. 我们需要快速访问第 k 大元素（堆顶）
2. 需要快速判断新元素是否在前 k 大（与堆顶比较）
3. 最小堆堆顶是最小值，刚好是第 k 大元素

**操作流程：**
1. 初始化：将 `nums` 中所有元素加入堆，保持堆大小为 `k`
2. 添加元素：
   - 如果堆大小 < k，直接加入
   - 如果新元素 > 堆顶，弹出堆顶，加入新元素
   - 返回堆顶元素

## Java 代码实现

### 方法一：最小堆实现（推荐）⭐

```java
import java.util.PriorityQueue;

class KthLargest {
    private int k;
    // Java 的 PriorityQueue 默认是最小堆
    private PriorityQueue<Integer> heap;
    
    public KthLargest(int k, int[] nums) {
        this.k = k;
        this.heap = new PriorityQueue<>(k);
        
        // 将所有元素加入堆，并保持堆大小为 k
        for (int num : nums) {
            add(num);
        }
    }
    
    public int add(int val) {
        // 如果堆未满 k 个元素，直接加入
        if (heap.size() < k) {
            heap.offer(val);
        } else if (val > heap.peek()) {
            // 如果新元素大于堆顶（第 k 大元素），更新堆
            heap.poll(); // 弹出堆顶
            heap.offer(val); // 插入新值
        }
        
        // 堆顶元素就是第 k 大元素
        return heap.peek();
    }
}
```

### 方法二：优化版（简化逻辑）

```java
import java.util.PriorityQueue;

class KthLargest {
    private int k;
    private PriorityQueue<Integer> heap;
    
    public KthLargest(int k, int[] nums) {
        this.k = k;
        this.heap = new PriorityQueue<>();
        
        // 逐个添加元素，利用 add 方法的逻辑
        for (int num : nums) {
            add(num);
        }
    }
    
    public int add(int val) {
        heap.offer(val);
        
        // 如果堆大小超过 k，弹出最小元素
        if (heap.size() > k) {
            heap.poll();
        }
        
        return heap.peek();
    }
}
```

## 复杂度分析

**初始化：**
- 时间复杂度：O(n log k)
  - 逐个添加 n 个元素，每次堆操作 O(log k)
- 空间复杂度：O(k)，堆的大小

**添加元素 add：**
- 时间复杂度：O(log k)
  - 堆的插入/删除操作：O(log k)
- 空间复杂度：O(1)

**总体效率：**
- 初始化：O(n log k)
- m 次 add 操作：O(m log k)
- 总时间：O((n+m) log k)

## 关键点总结

1. **数据结构选择**：最小堆维护前 k 大元素
2. **堆的性质**：堆顶是最小值，恰好是第 k 大元素
3. **堆大小控制**：始终保持堆大小为 k
4. **PriorityQueue**：Java 内置最小堆实现
5. **peek() vs poll()**：peek() 查看堆顶不删除，poll() 弹出堆顶

## 易错点

1. **堆的类型混淆**：Java `PriorityQueue` 默认是最小堆（不是最大堆）
2. **堆大小管理**：忘记限制堆大小为 k
3. **边界条件**：堆未满 k 个元素时的处理
4. **返回值错误**：应返回 `heap.peek()`（堆顶），不是堆尾
5. **初始化优化**：利用 add 方法统一处理初始化元素

## 图解示例

以 `k=3, nums=[4,5,8,2]` 为例：

```
初始化过程：
1. add(4) -> heap: [4]
2. add(5) -> heap: [4, 5]
3. add(8) -> heap: [4, 5, 8]
4. add(2) -> 2 < 4（堆顶），不操作 -> heap: [4, 5, 8]

add(3):
   3 < 4（堆顶），不操作 -> 返回 4

add(5):
   5 > 4，替换堆顶 -> heap: [5, 5, 8] -> 返回 5
   
add(10):
   10 > 5，替换堆顶 -> heap: [5, 8, 10] -> 返回 5
```
