## 题目描述

这是一个交互式问题。

你有一个升序整数数组，数组长度未知。你没有访问数组的权限，但是可以使用 `ArrayReader` 接口访问它。你可以调用 `ArrayReader.get(i)` ：

- 返回数组第 `i` 个索引（从 0 开始）处的值（即 `secret[i]`），或者
- 如果 `i` 超出了数组的边界，返回 `2^31 - 1`

你也会得到一个整数 `target`。

如果存在 `k` 满足 `secret[k] == target`，请返回索引 `k`；否则返回 `-1`。

你必须写一个时间复杂度为 `O(log n)` 的算法。

**示例 1：**
```
输入：secret = [-1,0,3,5,9,12], target = 9
输出：4
解释：9 出现在 secret 中，下标为 4
```

**示例 2：**
```
输入：secret = [-1,0,3,5,9,12], target = 2
输出：-1
解释：2 不在数组中所以返回 -1
```

**提示：**
- `1 <= secret.length <= 10^4`
- `-10^4 <= secret[i], target <= 10^4`
- `secret` 严格递增

## 解题思路

这道题的核心挑战是：**数组长度未知，但需要在 O(log n) 时间内完成查找**。

**关键策略：倍增法 + 二分查找**

**步骤一：确定搜索边界（倍增法）**
- 从索引 0 开始，每次将边界翻倍：1, 2, 4, 8, 16, ...
- 当 `reader.get(right) >= target` 或到达数组末尾时停止
- 这样可以在 O(log n) 时间内找到包含 target 的范围

**步骤二：在边界内二分查找**
- 在 `[left, right]` 范围内进行标准二分查找
- 遇到 `2^31 - 1` 说明超出数组，缩小右边界

**时间复杂度分析：**
- 倍增法：O(log n)，找到边界最多需要 log n 次翻倍
- 二分查找：O(log n)
- 总时间：O(log n)

## Java 代码实现

### 方法一：倍增 + 二分查找（推荐）⭐

```java
/**
 * // This is ArrayReader's API interface.
 * // You should not implement it, or speculate about its implementation
 * interface ArrayReader {
 *     public int get(int index) {}
 * }
 */

class Solution {
    public int search(ArrayReader reader, int target) {
        // 步骤一：使用倍增法找到搜索右边界
        int left = 0;
        int right = 1;
        
        // 不断翻倍扩大右边界，直到 right 位置的值 >= target 或到达数组末尾
        while (reader.get(right) < target) {
            left = right;
            right *= 2; // 指数增长
        }
        
        // 步骤二：在 [left, right] 范围内二分查找
        while (left <= right) {
            int mid = left + (right - left) / 2;
            int num = reader.get(mid);
            
            if (num == target) {
                return mid;
            } else if (num > target || num == Integer.MAX_VALUE) {
                // 值太大或超出数组边界，搜索左半部分
                right = mid - 1;
            } else {
                // 值太小，搜索右半部分
                left = mid + 1;
            }
        }
        
        return -1;
    }
}
```

### 方法二：优化的倍增（直接定位边界）

```java
class Solution {
    public int search(ArrayReader reader, int target) {
        // 快速找到包含 target 的范围
        if (reader.get(0) == target) {
            return 0;
        }
        
        // 倍增找右边界
        int left = 0;
        int right = 1;
        while (reader.get(right) < target) {
            left = right;
            right <<= 1; // 位运算，等同于 right *= 2
        }
        
        // 二分查找
        while (left <= right) {
            int mid = (left + right) >>> 1; // 无符号右移，避免溢出
            int val = reader.get(mid);
            
            if (val == target) {
                return mid;
            }
            if (val > target || val == Integer.MAX_VALUE) {
                right = mid - 1;
            } else {
                left = mid + 1;
            }
        }
        
        return -1;
    }
}
```

### 方法三：固定边界法（简化版）

```java
class Solution {
    public int search(ArrayReader reader, int target) {
        // 利用题目约束：最多 10^4 个元素，直接设置右边界为 10000
        int left = 0, right = 10000;
        
        while (left <= right) {
            int mid = left + (right - left) / 2;
            int num = reader.get(mid);
            
            if (num == target) {
                return mid;
            } else if (num > target || num == Integer.MAX_VALUE) {
                right = mid - 1;
            } else {
                left = mid + 1;
            }
        }
        
        return -1;
    }
}
```

## 复杂度分析

**方法一、二（倍增 + 二分）：**
- 时间复杂度：O(log n)
  - 倍增阶段：最多 log n 次翻倍
  - 二分查找：O(log n)
  - 总体：O(log n)
- 空间复杂度：O(1)

**方法三（固定边界）：**
- 时间复杂度：O(log 10000) = O(14)，常数时间
- 空间复杂度：O(1)
- 注意：虽然简单，但依赖题目给定的数组长度上限

## 关键点总结

1. **倍增法**：指数增长快速定位边界，时间复杂度 O(log n)
2. **边界标记**：`Integer.MAX_VALUE` 表示超出数组范围
3. **二分查找变体**：需要处理越界情况
4. **时间要求**：必须 O(log n)，不能线性扫描
5. **位运算优化**：`<<` 代替 `*2`，`>>>` 代替 `/2`（无符号右移避免溢出）

## 易错点

1. **初始边界设置**：`right` 应从 1 开始（不是 0）
2. **倍增条件**：判断 `reader.get(right) < target`，而不是 `<= target`
3. **越界处理**：遇到 `Integer.MAX_VALUE` 需要将其视为"大于 target"
4. **整数溢出**：使用 `left + (right - left) / 2` 避免溢出
5. **边界更新**：二分查找时 `left` 和 `right` 的更新逻辑要正确
