## 题目描述

给你一个整数数组 `arr` 和一个整数 `k`。现需要从数组中恰好删除 `k` 个元素，请返回删除后数组中**不同整数的最少数目**。

**示例 1：**

```
输入：arr = [5,5,4], k = 1
输出：1
解释：删除 1 个 4，剩余 [5,5]，有 1 种不同整数。
```

**示例 2：**

```
输入：arr = [4,3,1,1,3,3,2], k = 3
输出：2
解释：最优做法：删除 1 个 4（频率1），1 个 2（频率1），1 个 1（频率2中删1个）？
不对，让我重新分析：删除 4（1次），2（1次），1（全部2次），共删3个，消除了3种：4,2,1。
剩余 [3,3,3]，有 1 种不同整数。
实际：arr 中 4→1次，2→1次，1→2次，3→3次，删除频率最小的先消除：
删4(1次)，删2(1次)，还剩1次可删，从剩余中选：删1中的一个，1还剩1个。
剩余 1,3，2种不同整数。最优结果=2。
```

**提示：**
- `1 <= arr.length <= 10^5`
- `1 <= arr[i] <= 10^9`
- `0 <= k <= arr.length`

---

## 解题思路

**贪心思想：** 要用 k 次删除操作尽量减少不同整数的数量，应该优先删除**出现频率最低**的整数——因为删少量次数就能完全消灭一种整数。

**具体步骤：**
1. 统计每个整数出现的频率（使用 HashMap）。
2. 将频率从小到大排序。
3. 从频率最小的整数开始删除：
   - 若 k >= 当前整数的频率，完全删除该整数（k -= freq，unique_count -= 1）。
   - 若 k < 当前整数的频率，无法完全删除（停止）。
4. 返回剩余不同整数的数量。

## Java 代码实现

### 方法一：贪心 + 排序（推荐）

```java
import java.util.Arrays;
import java.util.HashMap;
import java.util.Map;

class Solution {
    public int findLeastNumOfUniqueInts(int[] arr, int k) {
        // 统计每个整数的出现频率
        Map<Integer, Integer> freq = new HashMap<>();
        for (int num : arr) {
            freq.put(num, freq.getOrDefault(num, 0) + 1);
        }

        // 按频率从小到大排序
        int[] freqs = freq.values().stream().mapToInt(Integer::intValue).toArray();
        Arrays.sort(freqs);

        // 从频率最小的开始删除
        int uniqueCount = freqs.length;
        for (int f : freqs) {
            if (k >= f) {
                k -= f;           // 删除该整数的所有出现
                uniqueCount--;    // 不同整数数量减 1
            } else {
                break;            // k 不足以完全消除这种整数，停止
            }
        }

        return uniqueCount;
    }
}
```

### 方法二：手动统计频率数组（不用 stream）

```java
import java.util.ArrayList;
import java.util.Collections;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

class Solution {
    public int findLeastNumOfUniqueInts(int[] arr, int k) {
        Map<Integer, Integer> freq = new HashMap<>();
        for (int num : arr) {
            freq.put(num, freq.getOrDefault(num, 0) + 1);
        }

        // 按频率从小到大排序
        List<Integer> freqs = new ArrayList<>(freq.values());
        Collections.sort(freqs);

        int remaining = freqs.size();  // 当前不同整数的数量

        for (int f : freqs) {
            if (k >= f) {
                k -= f;
                remaining--;
            } else {
                break;
            }
        }

        return remaining;
    }
}
```

### 方法三：不排序，用优先队列（最小堆）

```java
import java.util.HashMap;
import java.util.Map;
import java.util.PriorityQueue;

class Solution {
    public int findLeastNumOfUniqueInts(int[] arr, int k) {
        Map<Integer, Integer> freq = new HashMap<>();
        for (int num : arr) {
            freq.put(num, freq.getOrDefault(num, 0) + 1);
        }

        // 最小堆：每次弹出频率最小的整数
        PriorityQueue<Integer> heap = new PriorityQueue<>(freq.values());

        int uniqueCount = heap.size();

        while (!heap.isEmpty() && k >= heap.peek()) {
            k -= heap.poll();  // 完全删除频率最小的整数
            uniqueCount--;
        }

        return uniqueCount;
    }
}
```

## 复杂度分析

| 方法 | 时间复杂度 | 空间复杂度 |
|------|-----------|-----------|
| 贪心 + 排序 | O(n log n) | O(n) |
| 堆（优先队列） | O(n log n) | O(n) |

- n 为数组长度。
- HashMap 统计频率 O(n)，排序 O(m log m)（m 为不同整数数量，m <= n），总体 O(n log n)。

## 图解示例

以 `arr = [4,3,1,1,3,3,2], k = 3` 为例：

```
频率统计：{4:1, 3:3, 1:2, 2:1}
按频率排序：[1, 1, 2, 3]（对应整数：4或2, 2或4, 1, 3）

开始删除（k=3）：
  f=1（整数4）：k=3 >= 1，删除，k=2，unique=3
  f=1（整数2）：k=2 >= 1，删除，k=1，unique=2
  f=2（整数1）：k=1 < 2，无法完全删除，停止

最终 unique=2（剩余整数：1 和 3）
```

## 关键点总结

1. **贪心策略**：优先删除频率最低的整数，可以用最少的删除次数消灭最多种类的整数。
2. 按频率从小到大排序后，依次判断 k 是否足以完全删除当前整数。
3. 一旦 k 不足以完全删除某个整数，后面（频率更高的）也肯定不行，可以直接停止。
4. `HashMap` 是 Java 统计频率的标准工具，配合 `.values()` 和排序即可实现。

---

## 易错点

- **贪心方向**：要从**频率最小**的开始删，而不是频率最大的（删最大的消除数量少但会剩很多种类）。
- **整数不能部分删除**：题目允许只删除某整数的部分出现次数，但贪心策略下我们只在 k 足够时才完全删除一种整数。
- **k == 0 的情况**：如果 k=0，不能删除任何元素，返回不同整数的总数。

## 学习建议

1. 本题是贪心算法的典型应用：正确性依赖于"优先删频率低的整数更高效"这一贪心策略。
2. 贪心策略的正确性证明：假设最优解删了频率高的，不删频率低的，但交换为"删频率低的"后，消除的种类数不减少（因为频率低的更容易消除），所以贪心最优。
3. `HashMap` 是 Java 中非常实用的数据结构，本题及类似的频率统计题目中经常使用。
