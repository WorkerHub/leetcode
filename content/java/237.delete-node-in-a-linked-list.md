## 题目描述

有一个单链表的 `head`，我们想删除它其中的一个节点 `node`。

给你一个需要删除的节点 `node`。你将无法访问第一个节点 `head`。

链表的所有值都是唯一的，并且保证给定的节点 `node` 不是链表中的最后一个节点。

删除给定的节点。注意，删除节点并不是指从内存中删除它。这里的意思是：
- 给定节点的值不应该存在于链表中。
- 链表中的节点数应该减少 1。
- `node` 前面的所有值顺序相同。
- `node` 后面的所有值顺序相同。

**自定义测试：**
- 对于输入，你应该提供整个链表 `head` 和要给出的节点 `node`。`node` 不应该是链表的最后一个节点，而应该是链表中的一个实际节点。
- 我们将构建链表，并将节点传递给你的函数。
- 输出将是调用你函数后的整个链表。

**示例 1：**
```
输入：head = [4,5,1,9], node = 5
输出：[4,1,9]
解释：指定链表中值为 5 的第二个节点，那么在调用了你的函数之后，该链表应变为 4 -> 1 -> 9
```

**示例 2：**
```
输入：head = [4,5,1,9], node = 1
输出：[4,5,9]
解释：指定链表中值为 1 的第三个节点，那么在调用了你的函数之后，该链表应变为 4 -> 5 -> 9
```

**提示：**
- 链表中节点的数目范围是 `[2, 1000]`
- `-1000 <= Node.val <= 1000`
- 链表中每个节点的值都是唯一的
- 需要删除的节点 `node` 是链表中的一个有效节点，且不是末尾节点

## 解题思路

这道题非常特殊，也很有趣。

**问题的特殊性：**
- 通常删除链表节点需要知道前一个节点（`prev`）
- 但这道题只给了要删除的节点 `node`，没有给 `head`
- 无法访问 `node` 的前一个节点

**解决方案：障眼法**

既然无法删除当前节点，那就"假装"删除它：

1. **复制下一个节点的值到当前节点**
2. **删除下一个节点**

这样看起来就像删除了当前节点。

**关键观察：**
- `node` 不是最后一个节点，所以一定有 `node.next`
- 我们可以把 `node.next` 的值复制到 `node`
- 然后删除 `node.next`

**示例演示：**
```
原链表：4 -> 5 -> 1 -> 9
删除节点 node = 5（第二个节点）

步骤 1：复制下一个节点的值
4 -> 1 -> 1 -> 9
     ↑
    node

步骤 2：删除下一个节点
4 -> 1 -> 9
     ↑
    node（实际上是原来的第三个节点，但值变成了 1）
```

## Java 代码实现

### 方法一：复制值 + 删除下一个节点（唯一解法）⭐

```java
// Definition for singly-linked list.
// public class ListNode {
//     int val;
//     ListNode next;
//     ListNode(int x) { val = x; }
// }

class Solution {
    public void deleteNode(ListNode node) {
        // 将下一个节点的值复制到当前节点
        node.val = node.next.val;

        // 删除下一个节点（跳过它）
        node.next = node.next.next;
    }
}
```

### 方法二：更详细的注释版本

```java
class Solution {
    public void deleteNode(ListNode node) {
        // 通过复制下一个节点的值来"假删除"当前节点
        // 时间复杂度：O(1)
        // 空间复杂度：O(1)

        // 保存下一个节点
        ListNode nextNode = node.next;

        // 将下一个节点的值复制到当前节点
        node.val = nextNode.val;

        // 跳过下一个节点（删除它）
        node.next = nextNode.next;

        // Java 有垃圾回收机制，会自动处理 nextNode 的内存
    }
}
```

## 复杂度分析

- 时间复杂度：O(1)，只需要修改两个字段
- 空间复杂度：O(1)，只使用了常数额外空间

## 图解示例

```
示例 1：删除值为 5 的节点

初始状态：
4 -> 5 -> 1 -> 9
     ↑

步骤 1：node.val = node.next.val（复制值）
4 -> 1 -> 1 -> 9
     ↑    ↑

步骤 2：node.next = node.next.next（跳过下一节点）
4 -> 1 -----> 9

最终结果：[4, 1, 9]
```

## 关键点总结

1. **障眼法**：无法删除当前节点，就删除下一个节点
2. **值复制**：将下一个节点的值复制到当前节点
3. **指针调整**：跳过下一个节点
4. **题目保证**：node 不是最后一个节点，所以一定有 next
5. **O(1) 操作**：只需要常数时间和空间

## 易错点

1. **忘记复制值**：
   ```java
   // 错误：只修改指针，没有复制值
   node.next = node.next.next;
   
   // 正确：先复制值，再修改指针
   node.val = node.next.val;
   node.next = node.next.next;
   ```

2. **理解题目意思**：
   - 不是真正删除节点
   - 而是让链表"看起来"删除了节点
   - 实际上删除的是下一个节点

3. **空指针检查**：
   - 题目保证 node 不是最后一个节点
   - 所以不需要检查 `node.next` 是否为 null
   - 但在其他场景中需要检查

4. **理解限制**：
   - 这个方法只在给定条件下有效
   - 如果 node 是最后一个节点，这个方法无效
   - 如果链表中的值有特殊意义（比如节点地址很重要），这个方法不适用

## 扩展思考

**这个方法的局限性：**

1. **值的重要性**：如果链表节点的值有特殊含义（比如指向其他数据结构），复制值可能破坏语义

2. **最后一个节点**：无法删除最后一个节点，因为没有下一个节点可以复制

3. **内存管理**：Java 有垃圾回收机制，被删除节点会自动释放；但在 C++ 中需要手动 delete

4. **线程安全**：在多线程环境中，这种修改可能导致数据不一致

**常规删除方法对比：**

```java
// 常规删除（需要 head）
public ListNode deleteByVal(ListNode head, int val) {
    ListNode dummy = new ListNode(0);
    dummy.next = head;
    ListNode prev = dummy;

    while (prev.next != null) {
        if (prev.next.val == val) {
            prev.next = prev.next.next;
            break;
        }
        prev = prev.next;
    }

    return dummy.next;
}

// 本题方法（只需要 node）
public void deleteNode(ListNode node) {
    node.val = node.next.val;
    node.next = node.next.next;
}
```

理解这道题的关键是：在特定约束下，用创造性的方法解决问题。
