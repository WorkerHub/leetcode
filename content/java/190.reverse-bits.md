## 题目描述

颠倒给定的 32 位无符号整数的二进制位。

**提示：**
- 请注意，在某些语言（如 Java）中，没有无符号整数类型。在这种情况下，输入和输出都将被指定为有符号整数类型，并且不应影响您的实现，因为无论整数是有符号的还是无符号的，其内部的二进制表示形式都是相同的。
- 在 Java 中，编译器使用二进制补码记法来表示有符号整数。因此，在上面的示例 2 中，输入表示有符号整数 `-3`，输出表示有符号整数 `-1073741825`。

**示例 1：**
```
输入：n = 00000010100101000001111010011100
输出：964176192 (00111001011110000010100101000000)
解释：输入的二进制串 00000010100101000001111010011100 表示无符号整数 43261596，
     因此返回 964176192，其二进制表示形式为 00111001011110000010100101000000。
```

**示例 2：**
```
输入：n = 11111111111111111111111111111101
输出：3221225471 (10111111111111111111111111111111)
解释：输入的二进制串 11111111111111111111111111111101 表示无符号整数 4294967293，
     因此返回 3221225471 其二进制表示形式为 10111111111111111111111111111111 。
```

**提示：**
- 输入是一个长度为 `32` 的二进制字符串

**进阶：**
如果多次调用这个函数，你将如何优化你的算法？

## 解题思路

这道题要求反转 32 位整数的二进制位。核心是**位运算**。

### 方法一：逐位处理

最直观的方法：
1. 从右往左遍历每一位
2. 取出当前位的值（用 `n & 1`）
3. 将这一位放到结果的对应位置
4. 右移原数字，左移结果

### 方法二：分治法

将 32 位分成两部分，递归地交换：
- 将 32 位分为左 16 位和右 16 位，交换
- 每 16 位再分为 8 位，交换
- 每 8 位再分为 4 位，交换
- 依此类推...

### 方法三：查找表（进阶优化）

如果需要多次调用，可以预先计算 8 位（256 种）的反转结果，存入表中。
32 位可以分为 4 个 8 位，分别查表再组合。

### Java 特别说明

Java 中没有无符号整数，但位运算对有符号整数同样有效。
- 使用 `>>>` （无符号右移）而不是 `>>` （有符号右移），避免符号位扩展问题
- 结果用 `int` 表示，虽然返回值看起来是负数，但二进制位是正确的

## Java 代码实现

### 方法一：逐位反转（推荐新手）

```java
public class Solution {
    // treat n as an unsigned value
    public int reverseBits(int n) {
        int result = 0;

        // 处理 32 位
        for (int i = 0; i < 32; i++) {
            // 取出 n 的最低位
            int bit = n & 1;

            // result 先左移，然后或上当前位
            result = (result << 1) | bit;

            // n 无符号右移一位，处理下一位
            n >>>= 1;
        }

        return result;
    }
}
```

### 方法二：简洁写法

```java
public class Solution {
    public int reverseBits(int n) {
        int result = 0;
        for (int i = 0; i < 32; i++) {
            result = (result << 1) | (n & 1);
            n >>>= 1; // 无符号右移
        }
        return result;
    }
}
```

### 方法三：分治法（进阶）

```java
public class Solution {
    public int reverseBits(int n) {
        // 交换相邻的 1 位
        n = ((n & 0xaaaaaaaa) >>> 1) | ((n & 0x55555555) << 1);
        // 交换相邻的 2 位
        n = ((n & 0xcccccccc) >>> 2) | ((n & 0x33333333) << 2);
        // 交换相邻的 4 位
        n = ((n & 0xf0f0f0f0) >>> 4) | ((n & 0x0f0f0f0f) << 4);
        // 交换相邻的 8 位
        n = ((n & 0xff00ff00) >>> 8) | ((n & 0x00ff00ff) << 8);
        // 交换相邻的 16 位
        n = (n >>> 16) | (n << 16);

        return n;
    }
}
```

### 方法四：查找表优化（多次调用时使用）

```java
public class Solution {
    private int[] lookup;

    public Solution() {
        // 预计算 8 位的所有反转结果（0-255）
        lookup = new int[256];
        for (int i = 0; i < 256; i++) {
            int val = i;
            int rev = 0;
            for (int j = 0; j < 8; j++) {
                rev = (rev << 1) | (val & 1);
                val >>>= 1;
            }
            lookup[i] = rev;
        }
    }

    public int reverseBits(int n) {
        int result = 0;
        // 将 32 位分为 4 个 8 位处理
        for (int i = 0; i < 4; i++) {
            // 取出最低 8 位
            result = (result << 8) | lookup[n & 0xff];
            // 处理下一个 8 位
            n >>>= 8;
        }
        return result;
    }
}
```

## 复杂度分析

**方法一、二（逐位处理）：**
- **时间复杂度**：O(1)，固定循环 32 次
- **空间复杂度**：O(1)

**方法三（分治法）：**
- **时间复杂度**：O(1)，固定 5 次操作
- **空间复杂度**：O(1)

**方法四（查找表）：**
- **时间复杂度**：O(1)，每次查询 4 次表
- **空间复杂度**：O(1)，固定 256 个元素的表

## 关键点总结

1. **位运算基础**：
   - `n & 1`：取最低位
   - `n >>> 1`：无符号右移一位（Java 特有）
   - `result << 1`：左移一位
   - `|`：按位或（合并结果）

2. **Java 中使用 `>>>` 而非 `>>`**：
   - `>>`：有符号右移，高位补符号位（负数补 1）
   - `>>>`：无符号右移，高位始终补 0

3. **固定位数**：题目明确是 32 位，所以时间复杂度是 O(1)

4. **分治思想**：将大问题分解为小问题递归解决

5. **空间换时间**：查找表适合多次调用的场景

## 易错点

1. **使用 `>>` 代替 `>>>`**：
   ```java
   n >>= 1;   // 错误：有符号右移，负数会填充 1
   n >>>= 1;  // 正确：无符号右移，始终填充 0
   ```

2. **循环次数错误**：必须是 32 次，不能是 31 次
   ```java
   for (int i = 0; i < 32; i++) // 正确：32 位
   for (int i = 0; i < 31; i++) // 错误：少了一位
   ```

3. **位移顺序错误**：先左移结果，再或上新位
   ```java
   result = (result << 1) | bit;  // 正确
   result = result | (bit << 1);  // 错误
   ```

4. **分治法中使用 `>>` 代替 `>>>`**：
   ```java
   // 错误：可能因为符号位扩展导致结果错误
   n = ((n & 0xaaaaaaaa) >> 1) | ((n & 0x55555555) << 1);

   // 正确：使用无符号右移
   n = ((n & 0xaaaaaaaa) >>> 1) | ((n & 0x55555555) << 1);
   ```

5. **分治法的掩码错误**：掩码必须准确
   ```java
   0xaaaaaaaa  // 正确：10101010... (32 位)
   0xaaa       // 错误：只有 12 位
   ```
