## 题目描述

给你一个长度为 n 的整数数组，每次操作将会使 n - 1 个元素增加 1。返回使数组所有元素相等的最小操作次数。

**示例 1:**

```
输入: nums = [1,2,3]
输出: 3
解释:
只需要3次操作（注意每次操作会增加两个元素的值）：
[1,2,3]  =>  [2,3,3]  =>  [3,4,3]  =>  [4,4,4]
```

**示例 2:**

```
输入: nums = [1,1,1]
输出: 0
```

**提示:**

- n == nums.length
- 1 <= nums.length <= 10^5
- -10^9 <= nums[i] <= 10^9
- 答案保证符合 32-bit 整数

## 解题思路

这道题看起来很复杂，但通过**数学转换**可以大大简化。

**关键观察：**
- 每次操作让 n-1 个元素 +1
- 等价于让 1 个元素 -1（相对差值不变）

**数学推导：**

假设操作 m 次后所有元素相等，值为 x。
- 对于任意元素 nums[i]，它被增加了 `m - k[i]` 次（k[i] 是它没被增加的次数）
- 最终：`nums[i] + (m - k[i]) = x`
- 求和：`sum(nums) + m*n - sum(k) = n*x`
- 因为 `sum(k) = m`（每次操作有一个元素不增加）
- 所以：`sum(nums) + m*n - m = n*x`
- 即：`sum(nums) + m*(n-1) = n*x`

**进一步简化：**
- 让所有元素等于最小值 min_num
- 每个元素需要"相对减少" `nums[i] - min_num`
- 总操作数：`sum(nums[i] - min_num) = sum(nums) - n * min_num`

## Java 代码实现

### 方法一：数学公式法（推荐）

```java
class Solution {
    public int minMoves(int[] nums) {
        // 数学转换：让 n-1 个元素 +1 等价于让 1 个元素 -1
        // 目标：让所有元素等于最小值
        // 时间复杂度: O(n)
        // 空间复杂度: O(1)

        // 找最小值
        int minVal = nums[0];
        for (int num : nums) {
            minVal = Math.min(minVal, num);
        }

        // 计算总和（用 long 避免溢出）
        long sum = 0;
        for (int num : nums) {
            sum += num;
        }

        // 操作次数 = sum - n * minVal
        return (int) (sum - (long) nums.length * minVal);
    }
}
```

### 方法二：详细注释版

```java
class Solution {
    public int minMoves(int[] nums) {
        /*
         * 思路：
         * 1. 每次让 n-1 个元素 +1，相当于让剩下的 1 个元素 -1
         * 2. 最终所有元素相等，最优策略是都降到最小值
         * 3. 操作次数 = 每个元素到最小值的差值之和
         */
        if (nums == null || nums.length == 0) {
            return 0;
        }

        // 找到最小值
        int minVal = nums[0];
        for (int num : nums) {
            if (num < minVal) {
                minVal = num;
            }
        }

        // 计算每个元素需要"减少"的次数
        long moves = 0;
        for (int num : nums) {
            moves += num - minVal;
        }

        return (int) moves;
    }
}
```

### 方法三：一次遍历同时求 sum 和 min

```java
class Solution {
    public int minMoves(int[] nums) {
        // 一次遍历同时求 sum 和 min
        long sum = 0;
        int minVal = Integer.MAX_VALUE;
        for (int num : nums) {
            sum += num;
            minVal = Math.min(minVal, num);
        }
        return (int) (sum - (long) nums.length * minVal);
    }
}
```

## 复杂度分析

**时间复杂度：** O(n)
- 找最小值：O(n)
- 求和：O(n)

**空间复杂度：** O(1)
- 只使用常量额外空间

## 图解示例

以 nums = [1, 2, 3] 为例：

```
方法一：模拟操作（暴力，不推荐）
[1, 2, 3]  每次让 n-1 个元素 +1
[2, 3, 3]  让前两个元素 +1
[3, 4, 3]  让第一个和第三个 +1
[4, 4, 4]  让后两个元素 +1
操作次数: 3

方法二：数学转换（推荐）
等价于每次让 1 个元素 -1
目标：让所有元素降到最小值 1

元素 2: 需要 -1，即 1 次操作
元素 3: 需要 -2，即 2 次操作
元素 1: 已经是最小值，0 次操作

总操作数: 0 + 1 + 2 = 3

公式计算:
sum(nums) - n * min(nums)
= (1 + 2 + 3) - 3 * 1
= 6 - 3
= 3
```

**数学证明：**

```
设最小值为 m，目标值为 x
每个元素 nums[i] 需要增加 k[i] 次（k[i] 可以为负）

nums[i] + k[i] = x

求和：
Σnums[i] + Σk[i] = n*x

因为每次操作让 n-1 个元素 +1，总共操作 moves 次
Σk[i] = moves * (n-1)

所以：
Σnums[i] + moves*(n-1) = n*x

最优情况下，x = m（最小值）
Σnums[i] + moves*(n-1) = n*m
moves = (n*m - Σnums[i]) / (n-1)
     = (Σnums[i] - n*m) / (n-1) * (-1)
     = Σ(nums[i] - m)

但更简单的理解：
让 n-1 个 +1 ≈ 让 1 个 -1
所以 moves = Σ(nums[i] - m)
```

## 关键点总结

1. **数学转换**：n-1 个元素 +1 等价于 1 个元素 -1
2. **最优目标**：让所有元素降到最小值
3. **操作次数**：每个元素与最小值的差值之和
4. **公式简化**：`sum(nums) - n * min(nums)`
5. **时间优化**：O(n) 而不是模拟的 O(n * moves)

## 易错点

1. **误以为要模拟操作**：
   ```java
   // 错误：模拟每一步（超时）
   // while (!allEqual(nums)) { increaseNMinus1Elements(nums); }

   // 正确：数学公式直接计算
   return (int)(sum - (long) nums.length * minVal);
   ```

2. **整数溢出**：
   ```java
   // 错误：sum 可能超过 int 范围
   int sum = 0;
   for (int num : nums) sum += num;

   // 正确：使用 long
   long sum = 0;
   for (int num : nums) sum += num;
   ```

3. **目标值选择**：
   - 必须选择最小值作为目标
   - 不能选择其他值（会导致负数操作）

## 学习建议

1. **数学思维**：
   - 看到复杂操作，思考能否数学转换
   - n-1 个 +1 = 1 个 -1 是关键洞察

2. **相对思考**：
   - 绝对值不重要，相对差值才重要
   - 理解"相对变化"的概念

3. **最优性证明**：
   - 为什么目标是最小值？
   - 能否选择其他值？

4. **避免模拟**：
   - 模拟复杂度高
   - 优先寻找数学规律

5. **整数溢出注意**：
   - Java 中 int 范围约为 ±2×10^9
   - sum 涉及 n 个元素求和，容易超出 int 范围，务必使用 long
