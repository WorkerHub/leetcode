## 题目描述

已知一个长度为 `n` 的数组，预先按照升序排列，经由 `1` 到 `n` 次旋转后，得到输入数组。例如，原数组 `nums = [0,1,4,4,5,6,7]` 在变化后可能得到：

- 若旋转 `4` 次，则可以得到 `[4,5,6,7,0,1,4]`
- 若旋转 `7` 次，则可以得到 `[0,1,4,4,5,6,7]`

注意，数组 `[a[0], a[1], a[2], ..., a[n-1]]` 旋转一次的结果为数组 `[a[n-1], a[0], a[1], a[2], ..., a[n-2]]`。

给你一个可能存在重复元素值的数组 `nums`，它原来是一个升序排列的数组，并按上述情形进行了多次旋转。请你找出并返回数组中的最小元素。

你必须尽可能减少整个过程的操作步骤。

**示例 1：**

```
输入: nums = [1,3,5]
输出: 1
```

**示例 2：**

```
输入: nums = [2,2,2,0,1]
输出: 0
```

**提示：**

- `n == nums.length`
- `1 <= n <= 5000`
- `-5000 <= nums[i] <= 5000`
- `nums` 原来是一个升序排序的数组，并进行了 `1` 至 `n` 次旋转

**进阶：** 本题与第 153 题相同，但 `nums` 可能包含重复元素。这会影响到程序的时间复杂度吗？会如何影响，为什么？

## 解题思路

这道题是第 153 题的进阶版，区别在于数组可能包含重复元素。

**重复元素的影响：**

在第 153 题中，我们通过比较 `nums[mid]` 和 `nums[right]` 来判断最小值在哪一半：
- `nums[mid] > nums[right]`：最小值在右半部分
- `nums[mid] < nums[right]`：最小值在左半部分

但是，如果有重复元素，可能出现 `nums[mid] == nums[right]` 的情况。

**当 nums[mid] == nums[right] 时：**

无法判断最小值在哪一边，例如：
- `[1, 3, 3]`：mid=3, right=3，最小值在左边
- `[3, 3, 1]`：mid=3, right=1，最小值在右边
- `[3, 1, 3]`：mid=1, right=3，最小值是 mid

**解决方案：**

当 `nums[mid] == nums[right]` 时，无法判断，只能让 `right--`，缩小搜索范围。

为什么可以 `right--`？
- 因为 `nums[mid] == nums[right]`
- 即使 `nums[right]` 是最小值，`nums[mid]` 也是相同的值
- 所以可以安全地排除 `right`

## Java 代码实现

### 方法一：二分查找（处理重复元素，推荐）

```java
class Solution {
    public int findMin(int[] nums) {
        int left = 0, right = nums.length - 1;

        while (left < right) {
            int mid = left + (right - left) / 2;

            if (nums[mid] > nums[right]) {
                // 最小值在右半部分
                left = mid + 1;
            } else if (nums[mid] < nums[right]) {
                // 最小值在左半部分（包括mid）
                right = mid;
            } else {
                // nums[mid] == nums[right]，无法判断
                // 缩小右边界
                right--;
            }
        }

        return nums[left];
    }
}
```

### 方法二：带详细注释的版本

```java
class Solution {
    public int findMin(int[] nums) {
        /**
         * 在可能包含重复元素的旋转数组中找最小值
         *
         * 关键点：
         * 1. nums[mid] > nums[right]: 最小值在右边
         * 2. nums[mid] < nums[right]: 最小值在左边
         * 3. nums[mid] == nums[right]: 无法判断，缩小右边界
         */
        int left = 0, right = nums.length - 1;

        while (left < right) {
            int mid = left + (right - left) / 2;

            // 情况1: [3,4,5,1,2]
            // nums[mid]=5 > nums[right]=2 -> 最小值在右边
            if (nums[mid] > nums[right]) {
                left = mid + 1;
            }

            // 情况2: [5,1,2,3,4]
            // nums[mid]=2 < nums[right]=4 -> 最小值在左边
            else if (nums[mid] < nums[right]) {
                right = mid;
            }

            // 情况3: [3,3,1,3] 或 [3,1,3,3]
            // nums[mid]=1, nums[right]=3 或
            // nums[mid]=3, nums[right]=3
            // 无法确定，缩小右边界
            else {
                right--;
            }
        }

        return nums[left];
    }
}
```

### 方法三：去重后二分（优化思路）

```java
class Solution {
    public int findMin(int[] nums) {
        int left = 0, right = nums.length - 1;

        // 先去除右边的重复元素
        while (right > 0 && nums[right] == nums[0]) {
            right--;
        }

        // 如果全部相同，返回第一个
        if (right == 0) {
            return nums[0];
        }

        // 标准二分查找
        while (left < right) {
            int mid = left + (right - left) / 2;

            if (nums[mid] > nums[right]) {
                left = mid + 1;
            } else {
                right = mid;
            }
        }

        return nums[left];
    }
}
```

### 方法四：暴力法（仅供对比）

```java
class Solution {
    public int findMin(int[] nums) {
        int min = nums[0];
        for (int num : nums) {
            min = Math.min(min, num);
        }
        return min;
    }
}
// 时间复杂度: O(n)
```

## 复杂度分析

**方法一、二：二分查找**

- 时间复杂度：
  - 平均：O(log n)
  - 最坏：O(n) - 当数组元素全部相同时，每次只能 `right--`
  - 例如：`[1,1,1,1,1]`，需要遍历整个数组
- 空间复杂度：O(1)

**方法三：去重 + 二分**

- 时间复杂度：
  - 平均：O(log n)
  - 最坏：O(n) - 去重阶段
- 空间复杂度：O(1)

**方法四：暴力法**

- 时间复杂度：O(n)
- 空间复杂度：O(1)

## 关键点总结

1. **三种情况的处理**：
   - `nums[mid] > nums[right]`：`left = mid + 1`
   - `nums[mid] < nums[right]`：`right = mid`
   - `nums[mid] == nums[right]`：`right--`（新增）

2. **为什么可以 right--**：
   - 因为 `nums[mid] == nums[right]`
   - 即使 `right` 是最小值，`mid` 也有相同的值
   - 不会错过最小值

3. **时间复杂度退化**：
   - 最坏情况下退化到 O(n)
   - 发生在所有元素相同或大量重复时

4. **和第 153 题的区别**：
   - 153 题：元素互不相同，时间复杂度稳定 O(log n)
   - 本题：可能重复，最坏 O(n)

5. **无法完全避免 O(n)**：
   - 当元素全部相同时，必须遍历才能确定
   - 这是重复元素带来的必然代价

## 易错点

1. **相等情况的处理**：
   - 不能直接 `left = mid + 1` 或 `right = mid`
   - 必须谨慎地 `right--`

2. **为什么不能 left++**：
   - `left++` 可能跳过最小值
   - `right--` 不会，因为有 `mid` 作为备份

3. **循环条件**：
   - 仍然是 `while left < right`
   - 不要用 `left <= right`

4. **最坏情况的认知**：
   - 不要期望总是 O(log n)
   - 重复元素会导致性能退化

5. **边界情况**：
   - 所有元素相同：`[1,1,1,1]`
   - 只有两个不同值：`[1,1,1,2,1,1]`
