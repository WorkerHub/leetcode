## 题目描述

给定一组非负整数 `nums`，重新排列每个数的顺序（每个数不可拆分）使之组成一个最大的整数。

注意：输出结果可能非常大，所以你需要返回一个字符串而不是整数。

**示例 1：**

```
输入：nums = [10,2]
输出："210"
```

**示例 2：**

```
输入：nums = [3,30,34,5,9]
输出："9534330"
```

**提示：**

- `1 <= nums.length <= 100`
- `0 <= nums[i] <= 10^9`

## 解题思路

这道题的关键在于：**如何定义两个数字的大小关系**？

### 核心观察

对于两个数字 `a` 和 `b`，有两种拼接方式：
- 方式1：`ab`（a 在前，b 在后）
- 方式2：`ba`（b 在前，a 在后）

我们应该选择拼接结果更大的方式。例如：
- `3` 和 `30`：比较 `"330"` 和 `"303"`，显然 `"330" > "303"`，所以 `3` 应该排在 `30` 前面
- `10` 和 `2`：比较 `"102"` 和 `"210"`，显然 `"210" > "102"`，所以 `2` 应该排在 `10` 前面

### 解题步骤

1. 将所有数字转换为字符串
2. 自定义比较规则：对于字符串 `x` 和 `y`，如果 `x + y > y + x`，则 `x` 应该排在 `y` 前面
3. 按照自定义规则排序
4. 拼接排序后的字符串
5. 处理特殊情况：如果结果全是 0，返回 `"0"`

## Java 代码实现

### 方法一：自定义排序（推荐）

```java
import java.util.Arrays;

class Solution {
    public String largestNumber(int[] nums) {
        // 将数字转换为字符串数组
        String[] strs = new String[nums.length];
        for (int i = 0; i < nums.length; i++) {
            strs[i] = String.valueOf(nums[i]);
        }

        // 自定义比较：比较两种拼接方式，选择更大的
        Arrays.sort(strs, (x, y) -> (y + x).compareTo(x + y));

        // 处理全 0 的情况（例如 [0, 0]）
        if (strs[0].equals("0")) {
            return "0";
        }

        // 拼接结果
        StringBuilder sb = new StringBuilder();
        for (String s : strs) {
            sb.append(s);
        }

        return sb.toString();
    }
}
```

### 方法二：使用 Comparator 类

```java
import java.util.Arrays;
import java.util.Comparator;

class Solution {
    public String largestNumber(int[] nums) {
        // 将 int 数组转换为 String 数组
        String[] strs = Arrays.stream(nums)
                              .mapToObj(String::valueOf)
                              .toArray(String[]::new);

        // 自定义比较器
        Comparator<String> comp = (a, b) -> {
            String ab = a + b;
            String ba = b + a;
            return ba.compareTo(ab);  // 降序：ba > ab 时 b 排在前面
        };

        Arrays.sort(strs, comp);

        // 处理全 0 情况
        if (strs[0].equals("0")) {
            return "0";
        }

        return String.join("", strs);
    }
}
```

### 方法三：详细注释版本

```java
import java.util.Arrays;

class Solution {
    public String largestNumber(int[] nums) {
        int n = nums.length;

        // 步骤1：将所有整数转为字符串
        String[] strs = new String[n];
        for (int i = 0; i < n; i++) {
            strs[i] = Integer.toString(nums[i]);
        }

        // 步骤2：自定义排序
        // 对于字符串 x 和 y：
        // 如果 x + y > y + x，则 x 应排在前面（降序）
        Arrays.sort(strs, (x, y) -> {
            String xy = x + y;
            String yx = y + x;
            return yx.compareTo(xy);  // 降序排列
        });

        // 步骤3：处理边界情况——所有数字都是 0
        if (strs[0].equals("0")) {
            return "0";
        }

        // 步骤4：拼接所有字符串
        StringBuilder result = new StringBuilder();
        for (String s : strs) {
            result.append(s);
        }

        return result.toString();
    }
}
```

## 复杂度分析

**方法一、二、三（自定义排序）：**
- 时间复杂度：O(n log n × k)
  - `n` 是数组长度
  - `k` 是数字的平均位数（字符串比较的复杂度）
  - 排序的时间复杂度为 O(n log n)，每次比较需要 O(k)
- 空间复杂度：O(n × k)，存储字符串数组

## 关键点总结

1. **自定义比较规则**：核心是比较 `x + y` 和 `y + x` 的大小
2. **字符串比较**：Java 使用 `compareTo()` 比较字符串字典序
3. **Lambda 表达式**：Java 8+ 可用 Lambda 简洁表达 Comparator
4. **边界情况**：全 0 的数组（如 `[0, 0, 0]`）应返回 `"0"` 而不是 `"000"`
5. **贪心思想**：局部最优（每次选择拼接结果更大的顺序）能得到全局最优

## 易错点

1. **忘记处理全 0 情况**
   ```java
   // 错误：[0, 0] 会返回 "00"
   return String.join("", strs);
   
   // 正确：检查第一个字符串
   if (strs[0].equals("0")) return "0";
   ```

2. **比较规则错误**
   ```java
   // 错误：直接比较数字大小
   Arrays.sort(strs, Comparator.reverseOrder());
   // [3, 30, 34, 5, 9] -> [9, 5, 34, 30, 3] -> "9534330" (碰巧正确)
   // 但 [3, 30] -> [3, 30] -> "330" vs 正确应是 "330"（部分情况错误）
   
   // 正确：比较拼接后的字符串
   Arrays.sort(strs, (x, y) -> (y + x).compareTo(x + y));
   ```

3. **compareTo 方向错误**
   ```java
   // 错误：这会导致升序（最小数在前）
   (x + y).compareTo(y + x)
   
   // 正确：降序（最大拼接在前）
   (y + x).compareTo(x + y)
   ```

4. **字符串拼接溢出**
   ```java
   // 注意：两个字符串拼接后长度不超过 20 位，不需要担心整数溢出
   // 因为我们是字符串比较，不是整数比较
   String xy = x + y;  // 安全，字符串拼接
   ```

5. **忘记转换类型**
   ```java
   // 错误：int 数组不能直接排序字符串
   Arrays.sort(nums, ...);  // 编译错误
   
   // 正确：先转为 String 数组
   String[] strs = new String[nums.length];
   for (int i = 0; i < nums.length; i++) strs[i] = String.valueOf(nums[i]);
   ```

## 图解示例

以 `nums = [3, 30, 34, 5, 9]` 为例：

```
比较过程：
3 vs 30:  "330" > "303"  -> 3 排在前面
3 vs 34:  "334" < "343"  -> 34 排在前面
34 vs 5:  "345" < "534"  -> 5 排在前面
5 vs 9:   "59" < "95"    -> 9 排在前面

排序结果：[9, 5, 34, 3, 30]
拼接：     "9" + "5" + "34" + "3" + "30" = "9534330"
```

## 学习建议

1. **理解自定义排序**：
   - Java 的 `Arrays.sort()` 和 `Collections.sort()` 支持 `Comparator` 参数
   - Java 8+ 可以使用 Lambda 表达式简化 Comparator
   - `compareTo()` 方法：返回负数表示前者小，返回正数表示前者大

2. **掌握贪心思想**：
   - 本题是贪心算法的典型应用
   - 证明局部最优能得到全局最优（可以用反证法）

3. **实践练习**：
   - 手动模拟排序过程，理解为什么这样排序是最优的
   - 尝试不同的测试用例：`[0, 0]`, `[1]`, `[10, 2]`, `[3, 30, 34, 5, 9]`
   - 思考：如果要求最小数，如何修改代码？

4. **字符串比较**：
   - 理解字符串字典序比较的规则
   - 例如：`"9".compareTo("80") > 0`（因为 '9' > '8'）
   - 这也是为什么我们需要比较 `x + y` 和 `y + x`，而不是直接比较 `x` 和 `y`

5. **面试技巧**：
   - 能够清晰解释比较规则：为什么是 `(y + x).compareTo(x + y)`
   - 能够分析时间复杂度
   - 能够举例说明为什么直接按数字大小排序不行（如 `3` vs `30`）
   - 记得处理全 0 的边界情况

6. **Java 技巧**：
   - `String.valueOf(num)` 或 `Integer.toString(num)` 整数转字符串
   - `(y + x).compareTo(x + y)` 字符串比较
   - `String.join("", arr)` 拼接字符串数组
   - `StringBuilder` 高效拼接多个字符串
   - Java 8 Stream：`Arrays.stream(nums).mapToObj(String::valueOf).toArray(String[]::new)`
