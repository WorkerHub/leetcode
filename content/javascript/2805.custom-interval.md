## 题目描述

编写两个函数：`customInterval` 和 `customClearInterval`。

`customInterval(fn, delay, period)` 的行为：
- 在 `delay` 毫秒后执行 `fn`
- 之后每隔 `delay + period * 1`、`delay + period * 2`、... 毫秒执行 `fn`

即第 k 次（从 1 开始）执行是在 `delay + period * (k - 1)` 毫秒后。

`customClearInterval(id)` 用于取消由 `customInterval` 创建的定时器。

**示例 1：**
```
输入：delay = 50, period = 20, cancelTime = 225
输出：[50, 120, 210]
解释：
第1次在 50ms 执行
第2次在 50+20=70ms? 不对...
```

实际上，每次间隔递增：
- 第 1 次：50ms
- 第 2 次：50 + 20 = 70ms（累计 120ms）
- 第 3 次：70 + 20 = 90ms（累计 210ms）
- 第 4 次：90 + 20 = 110ms（累计 320ms > 225ms，不执行）

**提示：**
- `fn` 是有效函数
- `1 <= delay, period <= 250`
- `1 <= cancelTime <= 1000`

## 解题思路

本题是 JavaScript 异步编程题，核心是实现一个**间隔递增的定时器**。

关键观察：
- 第 k 次执行距离上一次执行的时间为 `delay + period * (k-1)`
- 可以用 `setTimeout` 递归地调度下一次执行
- 需要返回一个 ID 以便 `customClearInterval` 取消

策略：
1. 用对象存储定时器 ID（一个 `id` 对应一个 `timeout`）
2. 递归地用 `setTimeout` 安排下一次调用，每次增加 period

## Python 代码实现

### 方法一：Python 等效模拟（理解用）

```python
import threading
from typing import Callable

# 存储定时器
_timers = {}
_next_id = [0]

def customInterval(fn: Callable, delay: float, period: float) -> int:
    """自定义间隔递增定时器（Python 模拟版）"""
    _next_id[0] += 1
    timer_id = _next_id[0]
    call_count = [0]  # 记录调用次数

    def execute():
        if timer_id not in _timers:
            return
        fn()
        call_count[0] += 1
        # 下一次间隔 = delay + period * call_count
        next_delay = delay + period * call_count[0]
        t = threading.Timer(next_delay / 1000, execute)
        _timers[timer_id] = t
        t.start()

    # 第一次在 delay 毫秒后执行
    t = threading.Timer(delay / 1000, execute)
    _timers[timer_id] = t
    t.start()
    return timer_id

def customClearInterval(timer_id: int) -> None:
    """取消定时器"""
    if timer_id in _timers:
        _timers[timer_id].cancel()
        del _timers[timer_id]
```

### 方法二：JavaScript 实现（LeetCode 原题解）

```javascript
/**
 * 存储所有定时器的映射：id -> timeoutId
 */
const timers = new Map();
let idCounter = 0;

/**
 * @param {Function} fn - 要执行的函数
 * @param {number} delay - 第一次执行的延迟（毫秒）
 * @param {number} period - 每次递增的时间（毫秒）
 * @return {number} 定时器 ID
 */
function customInterval(fn, delay, period) {
    const id = idCounter++;
    let callCount = 0;  // 已调用次数

    function schedule() {
        // 当前间隔 = delay + period * callCount
        const interval = delay + period * callCount;
        const timeoutId = setTimeout(() => {
            if (!timers.has(id)) return;  // 已被取消
            fn();
            callCount++;
            schedule();  // 递归安排下一次
        }, interval);
        timers.set(id, timeoutId);
    }

    timers.set(id, null);  // 先注册 id
    schedule();
    return id;
}

/**
 * @param {number} id - 要取消的定时器 ID
 */
function customClearInterval(id) {
    if (timers.has(id)) {
        clearTimeout(timers.get(id));  // 取消当前等待的 timeout
        timers.delete(id);             // 从映射中删除
    }
}
```

## 复杂度分析

- 时间复杂度：O(k)，k 为实际执行次数
- 空间复杂度：O(n)，n 为同时活跃的定时器数量

## 关键点总结

1. 使用 `setTimeout` 递归调度，每次计算新的延迟时间
2. 使用 Map 存储 id 到 timeoutId 的映射，以便取消
3. 取消时先调用 `clearTimeout`，再删除 Map 记录
4. 每次执行后递增 `callCount`，用于计算下一次间隔

## 易错点

1. 间隔计算错误：第 k 次（0-indexed）间隔是 `delay + period * k`
2. 取消时必须调用 `clearTimeout`，不能只删除 Map 记录
3. 在执行前检查 timer 是否已被取消，避免竞态条件
