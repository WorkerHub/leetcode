## 题目描述

给你 `n` 个盒子，每个盒子的格式为 `[status, candies, keys, containedBoxes]`，其中：

- `status[i]`：整数，`1` 代表盒子是打开的，`0` 代表盒子是关闭的
- `candies[i]`：整数，表示盒子 `i` 中糖果的数目
- `keys[i]`：数组，包含盒子 `i` 中所有的钥匙（这些钥匙可以开启对应编号的盒子）
- `containedBoxes[i]`：数组，表示盒子 `i` 里面包含的盒子

给你一个 `initialBoxes` 数组，表示你一开始拥有的盒子列表。你可以获得盒子里的糖果，也可以使用盒子里的钥匙，还可以打开盒子里的盒子。

**规则**：只有当你拥有一个盒子且该盒子是打开状态（或你拥有它的钥匙），你才能打开这个盒子并获取里面的内容。

请你按照上述规则，返回你可以获得糖果的**最大数目**。

**示例 1：**

```
输入：status = [1,0,1,0], candies = [7,5,4,100],
     keys = [[],[],[1],[]], containedBoxes = [[1,2],[3],[],[]]
     initialBoxes = [0]
输出：16
解释：
- 一开始你有盒子 0，它是打开的，里面有 7 颗糖果。
  打开后得到盒子 1 和 2（来自 containedBoxes[0]）。
- 盒子 1 是关闭的，且没有钥匙，暂时无法打开。
- 盒子 2 是打开的（status[2]=1），里面有 4 颗糖果和钥匙 1。
  打开后得到钥匙 1，现在可以打开盒子 1。
- 盒子 1 打开后有 5 颗糖果和盒子 3。
- 盒子 3 是关闭的且没有钥匙，无法打开。
- 总糖果：7 + 4 + 5 = 16。
```

**示例 2：**

```
输入：status = [1,0], candies = [7,5], keys = [[1],[]], containedBoxes = [[1],[]]
     initialBoxes = [0]
输出：12
解释：
- 打开盒子 0（状态为 1），得到 7 颗糖果、钥匙 1、盒子 1。
- 用钥匙 1 打开盒子 1，得到 5 颗糖果。
- 总糖果：7 + 5 = 12。
```

**提示：**

- `1 <= status.length <= 1000`
- `status[i]` 为 `0` 或 `1`
- `1 <= candies[i] <= 1000`
- `0 <= keys[i].length <= status.length`
- `0 <= containedBoxes[i].length <= status.length`
- `containedBoxes[i]` 中的值各不相同
- `keys[i]` 中的值各不相同
- `keys[i]` 和 `containedBoxes[i]` 中的值都是有效的盒子编号
- 初始盒子中，每个盒子最多只有一把对应的钥匙
- `initialBoxes` 中的值各不相同
- `0 <= initialBoxes.length <= status.length`

## 解题思路

### 问题分析

这是一个典型的**状态传播**问题。盒子之间存在依赖关系：
- 一个盒子能被打开的条件：**拥有它** AND（**它本身是开着的** OR **拥有它的钥匙**）
- 打开一个盒子会触发新的状态：获得新盒子、获得新钥匙

这类"触发-传播"的问题非常适合用**广度优先搜索（BFS）**来模拟。

### BFS 思路

维护两个核心状态集合：
- `has_box`：当前拥有的盒子集合
- `has_key`：当前拥有的钥匙集合

BFS 队列中存放**可以立即打开的盒子**。

每次从队列取出一个盒子，处理后：
1. 累加糖果
2. 将获得的新钥匙加入 `has_key`，并检查是否可以打开已有的盒子
3. 将获得的新盒子加入 `has_box`，并检查是否可以立即打开

**能打开一个盒子的条件**：拥有这个盒子 AND（这个盒子原本是开着的 OR 拥有它的钥匙）

```
可以打开 <==> box in has_box AND (status[box] == 1 OR box in has_key)
```

### 关键细节

- 需要记录一个盒子是否**已经被处理过**（避免重复打开）
- 获得钥匙时，要检查对应盒子是否已经在 `has_box` 中（若在则可以入队）
- 获得盒子时，要检查是否已有钥匙或它本身是开着的（若满足则入队）

## Python 代码实现

### 方法一：BFS（推荐）

```python
from collections import deque
from typing import List

class Solution:
    def maxCandies(
        self,
        status: List[int],
        candies: List[int],
        keys: List[List[int]],
        containedBoxes: List[List[int]],
        initialBoxes: List[int],
    ) -> int:
        n = len(status)

        # 记录当前拥有的盒子和钥匙
        has_box = set()    # 拥有的盒子编号
        has_key = set()    # 拥有的钥匙（对应盒子编号）
        opened = set()     # 已经打开（处理）过的盒子，防止重复计算

        queue = deque()    # BFS 队列，存放可以立即打开的盒子

        def try_open(box: int):
            """尝试将盒子加入队列（若满足打开条件且未处理过）"""
            if box not in opened and box in has_box and (status[box] == 1 or box in has_key):
                opened.add(box)
                queue.append(box)

        # 初始化：将初始盒子加入 has_box，并尝试打开
        for box in initialBoxes:
            has_box.add(box)
            try_open(box)

        total_candies = 0

        # BFS 主循环
        while queue:
            box = queue.popleft()

            # 累加当前盒子的糖果
            total_candies += candies[box]

            # 处理盒子中包含的钥匙
            for key in keys[box]:
                if key not in has_key:
                    has_key.add(key)
                    # 如果已经拥有这把钥匙对应的盒子，尝试打开它
                    if key in has_box:
                        try_open(key)

            # 处理盒子中包含的盒子
            for inner_box in containedBoxes[box]:
                if inner_box not in has_box:
                    has_box.add(inner_box)
                    # 尝试打开新获得的盒子
                    try_open(inner_box)

        return total_candies
```

### 方法二：BFS（使用 visited 数组，替代 set）

当盒子编号连续时，用布尔数组代替集合，访问速度更快：

```python
from collections import deque
from typing import List

class Solution:
    def maxCandies(
        self,
        status: List[int],
        candies: List[int],
        keys: List[List[int]],
        containedBoxes: List[List[int]],
        initialBoxes: List[int],
    ) -> int:
        n = len(status)

        # 用布尔数组替代集合，访问更快
        has_box = [False] * n   # 是否拥有该盒子
        has_key = [False] * n   # 是否拥有该盒子的钥匙
        opened = [False] * n    # 是否已经打开过

        queue = deque()

        def try_open(box: int):
            if not opened[box] and has_box[box] and (status[box] == 1 or has_key[box]):
                opened[box] = True
                queue.append(box)

        # 初始化
        for box in initialBoxes:
            has_box[box] = True
            try_open(box)

        total_candies = 0

        while queue:
            box = queue.popleft()
            total_candies += candies[box]

            # 获得钥匙
            for key in keys[box]:
                if not has_key[key]:
                    has_key[key] = True
                    if has_box[key]:
                        try_open(key)

            # 获得盒子
            for inner_box in containedBoxes[box]:
                if not has_box[inner_box]:
                    has_box[inner_box] = True
                    try_open(inner_box)

        return total_candies
```

### 方法三：暴力模拟（理解用）

反复扫描所有盒子，直到没有新盒子可以打开：

```python
from typing import List

class Solution:
    def maxCandies(
        self,
        status: List[int],
        candies: List[int],
        keys: List[List[int]],
        containedBoxes: List[List[int]],
        initialBoxes: List[int],
    ) -> int:
        # 当前拥有的盒子和钥匙
        has_box = set(initialBoxes)
        has_key = set()
        opened = set()

        total_candies = 0
        changed = True  # 标记是否有新盒子被打开

        # 反复扫描，直到没有新盒子可以打开
        while changed:
            changed = False
            for box in list(has_box):
                if box in opened:
                    continue
                if status[box] == 1 or box in has_key:
                    # 打开盒子
                    opened.add(box)
                    changed = True
                    total_candies += candies[box]
                    # 获得钥匙
                    for key in keys[box]:
                        has_key.add(key)
                    # 获得盒子
                    for inner_box in containedBoxes[box]:
                        has_box.add(inner_box)

        return total_candies
```

**缺点**：时间复杂度 O(n^2)，每轮需要扫描所有盒子，效率低。

## 复杂度分析

### 方法一/二（BFS）

- **时间复杂度**：O(n + E)，其中 n 是盒子数量，E 是所有钥匙和内含盒子的总数量。每个盒子最多入队一次，每把钥匙和每个内含盒子最多处理一次。
- **空间复杂度**：O(n)，队列、`has_box`、`has_key`、`opened` 均为 O(n)

### 方法三（暴力）

- **时间复杂度**：O(n^2)，最坏情况下需要扫描 n 轮，每轮扫描 n 个盒子
- **空间复杂度**：O(n)

## 图解示例

以示例 1 为例，演示 BFS 流程：

```
初始状态：has_box={0}, has_key={}, status=[1,0,1,0]
  盒子 0 满足条件（status=1），入队

第 1 步：出队盒子 0
  糖果 += 7（总计 7）
  获得钥匙：无
  获得盒子：{1, 2} → has_box={0,1,2}
    盒子 1：status=0，无钥匙，不入队
    盒子 2：status=1，直接入队

第 2 步：出队盒子 2
  糖果 += 4（总计 11）
  获得钥匙：{1} → has_key={1}
    盒子 1 在 has_box 中，且现在有钥匙，入队
  获得盒子：无

第 3 步：出队盒子 1
  糖果 += 5（总计 16）
  获得钥匙：无
  获得盒子：{3} → has_box={0,1,2,3}
    盒子 3：status=0，无钥匙，不入队

队列为空，结束。总糖果 = 16
```

## 关键点总结

1. **BFS 的适用场景**：当处理一个节点会触发新节点可用时，优先考虑 BFS
2. **双条件解锁**：打开盒子需要同时满足"拥有"和"有钥匙或已开"，两个条件缺一不可
3. **触发时机**：获得钥匙时检查对应盒子，获得盒子时检查对应钥匙，两处都要触发尝试
4. **防止重复处理**：`opened` 集合/数组保证每个盒子只被处理一次
5. **`try_open` 辅助函数**：将入队逻辑封装，避免代码重复

## 易错点

1. **两处都要触发尝试**：获得钥匙后要检查盒子，获得盒子后要检查钥匙，漏掉一处会导致某些盒子永远无法打开
2. **初始 status 的利用**：初始化时，状态为 1 的盒子可以直接入队，不要忘记检查
3. **重复打开**：没有 `opened` 记录，同一个盒子可能被重复处理，导致糖果重复计算
4. **钥匙是针对其他盒子的**：`keys[i]` 中的钥匙打开的是编号对应的盒子，不是盒子 i 自己
