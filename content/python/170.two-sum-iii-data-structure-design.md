## 题目描述

设计一个接收整数流的数据结构，该数据结构支持检查是否存在两数之和等于特定值。

实现 `TwoSum` 类：

- `TwoSum()` 初始化 `TwoSum` 对象
- `void add(int number)` 向数据结构中添加一个数 `number`
- `boolean find(int value)` 寻找数据结构中是否存在一对整数，使得两数之和等于给定的值 `value`。如果存在，返回 `true`；否则，返回 `false`。

**示例 1：**
```
输入：
["TwoSum", "add", "add", "add", "find", "find"]
[[], [1], [3], [5], [4], [7]]
输出：
[null, null, null, null, true, false]

解释：
TwoSum twoSum = new TwoSum();
twoSum.add(1);   // [] --> [1]
twoSum.add(3);   // [1] --> [1,3]
twoSum.add(5);   // [1,3] --> [1,3,5]
twoSum.find(4);  // 1 + 3 = 4，返回 true
twoSum.find(7);  // 没有两个整数加和等于 7，返回 false
```

**提示：**
- -10^5 <= number <= 10^5
- -2^31 <= value <= 2^31 - 1
- 最多调用 10^4 次 `add` 和 `find`

## 解题思路

这是一个**数据结构设计**问题，需要在 `add` 和 `find` 操作之间做权衡。

**核心问题：** 优化 `add` 还是优化 `find`？

### 策略一：优化 add（哈希表计数）
- `add`：O(1)，直接存入哈希表
- `find`：O(n)，遍历哈希表查找配对

### 策略二：优化 find（预计算所有和）
- `add`：O(n)，更新所有可能的两数之和
- `find`：O(1)，直接查哈希表

**选择依据：**
- 如果 `add` 频繁，选策略一
- 如果 `find` 频繁，选策略二
- **通常选策略一**，因为实际场景中添加数据更频繁

## Python 代码实现

### 方法一：哈希表计数（推荐，优化 add）

```python
from collections import defaultdict

class TwoSum:
    def __init__(self):
        # 使用哈希表存储数字及其出现次数
        self.num_counts = defaultdict(int)

    def add(self, number: int) -> None:
        # O(1) 时间添加
        self.num_counts[number] += 1

    def find(self, value: int) -> bool:
        # O(n) 时间查找
        for num in self.num_counts:
            complement = value - num
            
            # 情况1：两个不同的数
            if complement != num:
                if complement in self.num_counts:
                    return True
            # 情况2：两个相同的数（需要至少出现2次）
            else:
                if self.num_counts[num] > 1:
                    return True
        
        return False
```

### 方法二：列表存储 + 哈希集合查找

```python
class TwoSum:
    def __init__(self):
        self.nums = []
        self.is_sorted = False

    def add(self, number: int) -> None:
        # 添加到列表
        self.nums.append(number)
        self.is_sorted = False

    def find(self, value: int) -> bool:
        # 使用集合加速查找
        num_set = set(self.nums)
        
        for num in self.nums:
            complement = value - num
            # 注意：需要确保不是同一个元素
            if complement != num:
                if complement in num_set:
                    return True
            else:
                # 相同数需要至少2个
                if self.nums.count(num) > 1:
                    return True
        
        return False
```

### 方法三：预计算所有和（优化 find，不推荐）

```python
class TwoSum:
    def __init__(self):
        self.nums = []
        self.sums = set()  # 存储所有可能的两数之和

    def add(self, number: int) -> None:
        # O(n) 时间，计算新数与已有数的所有和
        for num in self.nums:
            self.sums.add(num + number)
        self.nums.append(number)

    def find(self, value: int) -> bool:
        # O(1) 时间查找
        return value in self.sums
```

### 方法四：哈希表 + 双指针（排序后查找）

```python
class TwoSum:
    def __init__(self):
        self.nums = []

    def add(self, number: int) -> None:
        self.nums.append(number)

    def find(self, value: int) -> bool:
        # 排序后使用双指针
        self.nums.sort()
        left, right = 0, len(self.nums) - 1
        
        while left < right:
            current_sum = self.nums[left] + self.nums[right]
            if current_sum == value:
                return True
            elif current_sum < value:
                left += 1
            else:
                right -= 1
        
        return False
```

## 复杂度分析

| 方法 | add 时间 | find 时间 | 空间复杂度 |
|------|---------|----------|-----------|
| 方法一（哈希表计数） | O(1) | O(n) | O(n) |
| 方法二（列表+集合） | O(1) | O(n) | O(n) |
| 方法三（预计算） | O(n) | O(1) | O(n²) |
| 方法四（排序双指针） | O(1) | O(n log n) | O(1) |

**推荐方法一**，因为：
- `add` 操作更频繁，O(1) 添加很重要
- `find` 的 O(n) 复杂度可接受
- 空间复杂度 O(n) 合理

## 图解示例

**方法一示例：**
```
初始化：num_counts = {}

add(1): num_counts = {1: 1}
add(3): num_counts = {1: 1, 3: 1}
add(5): num_counts = {1: 1, 3: 1, 5: 1}

find(4):
  遍历 num_counts:

  遍历 num_counts:
```

## 关键点总结

1. **重复元素处理**：相同数字需要出现至少 2 次
2. **哈希表计数**：使用 `defaultdict(int)` 或普通字典
3. **权衡选择**：根据操作频率选择优化策略
4. **边界情况**：空数据结构、单个元素
5. **避免自身配对**：`complement != num` 或检查计数 > 1

## 易错点

1. **重复数字判断错误**
   - 错误：`if complement in num_counts`（相同数时会误判）
   - 正确：分情况讨论，相同数需要 `count > 1`

2. **使用列表的陷阱**
   ```python
   # 错误：同一个元素会自己和自己配对
   for num in nums:
       if (value - num) in nums:
           return True
   
   # 需要额外处理相同元素的情况
   ```

3. **预计算方法的空间问题**
   - n 个数有 O(n²) 个两数之和，空间消耗大

4. **排序方法的效率**
   - 每次 `find` 都排序会导致 O(n log n)，不如方法一

5. **初始化遗漏**
   - 必须在 `__init__` 中初始化数据结构
