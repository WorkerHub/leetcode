## 题目描述

与 3218 题相同，但数据规模更大：
- `1 <= m, n <= 10^5`
- `horizontalCut[i], verticalCut[j]` 可达 `10^9`

因此需要高效的贪心算法，而不能用 DP。

**示例 1：**
```
输入：m = 3, n = 2, horizontalCut = [1,3], verticalCut = [5]
输出：13
```

**提示：**
- `1 <= m, n <= 10^5`
- `horizontalCut.length == m - 1`
- `verticalCut.length == n - 1`
- `1 <= horizontalCut[i], verticalCut[j] <= 10^9`

## 解题思路

与 3218 相同的贪心策略，但数据量大，需要高效实现：

贪心：降序排序，用双指针合并两个有序数组，优先处理成本大的切割。

每次水平切割的成本 = 切割值 × 当前垂直段数（v_segs）
每次垂直切割的成本 = 切割值 × 当前水平段数（h_segs）

注意：答案可能超过 32 位整数，需要用 64 位整数（Python 自动处理）。

## Python 代码实现

### 方法一：贪心双指针（推荐）

```python
from typing import List

class Solution:
    def minimumCost(self, m: int, n: int, horizontalCut: List[int], verticalCut: List[int]) -> int:
        # 降序排序
        horizontalCut.sort(reverse=True)
        verticalCut.sort(reverse=True)
        
        h_segs = 1  # 当前水平段数（初始为1）
        v_segs = 1  # 当前垂直段数（初始为1）
        
        total = 0
        i, j = 0, 0
        hl, vl = len(horizontalCut), len(verticalCut)
        
        while i < hl or j < vl:
            h_val = horizontalCut[i] if i < hl else 0
            v_val = verticalCut[j] if j < vl else 0
            
            if h_val >= v_val:
                # 水平切割
                total += h_val * v_segs
                h_segs += 1
                i += 1
            else:
                # 垂直切割
                total += v_val * h_segs
                v_segs += 1
                j += 1
        
        return total
```

### 方法二：合并排序后遍历

```python
from typing import List

class Solution:
    def minimumCost(self, m: int, n: int, horizontalCut: List[int], verticalCut: List[int]) -> int:
        # 合并两个列表，标记类型，降序排序
        events = [(c, 'h') for c in horizontalCut] + [(c, 'v') for c in verticalCut]
        events.sort(reverse=True)
        
        h_segs = 1
        v_segs = 1
        total = 0
        
        for cost, typ in events:
            if typ == 'h':
                total += cost * v_segs
                h_segs += 1
            else:
                total += cost * h_segs
                v_segs += 1
        
        return total
```

## 复杂度分析

- 时间复杂度：O((m + n) log(m + n))，排序
- 空间复杂度：O(m + n)

## 关键点总结

1. 和 3218 完全相同的贪心思路，只是数据范围更大
2. Python 的整数不会溢出，不需要特别处理大数
3. 同等成本时，水平和垂直切割先后顺序不影响结果

## 易错点

1. 注意答案可能非常大（10^5 * 10^9 = 10^14），要用 long 类型（Python 自动处理）
2. 当成本相同时，两者都可以选，结果相同
