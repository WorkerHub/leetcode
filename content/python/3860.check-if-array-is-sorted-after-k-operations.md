## 题目描述

给你一个整数数组 `nums` 和一个正整数 `k`，每次操作可以选择数组中的任意一个元素加 1（但每个元素最多操作 `k` 次）。

判断是否能通过这些操作使数组变为非递减序列。

**示例 1：**

```
输入：nums = [1, 3, 2], k = 1
输出：true
解释：将 nums[2]=2 加 1 得 3，[1,3,3] 非递减。
```

**示例 2：**

```
输入：nums = [3, 1, 2], k = 1
输出：false
解释：nums[0]=3 不能减少，nums[1]=1 最多增加到 2 < 3，无法使 [1] >= [0]。
```

**提示：**
- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^9`
- `1 <= k <= 10^9`

## 解题思路

贪心检查：从左到右，维护当前最大值（即前一个元素加上最多 k 次操作后可以达到的最大值）。

对于每个位置 i，若 `nums[i] + k < prev`（即使加 k 次也比前一个小），则不可能满足条件。

否则，`prev = max(nums[i], prev)`（nums[i] 只需达到 prev 即可）。

## Python 代码实现

### 方法一：贪心遍历（推荐）

```python
from typing import List

class Solution:
    def isSortedAfterOperations(self, nums: List[int], k: int) -> bool:
        n = len(nums)
        # 维护前一个元素在操作后的最小值（即至少要达到的值）
        prev = nums[0]

        for i in range(1, n):
            v = nums[i]
            # 要使 v 加上若干次（<=k）操作后 >= prev
            if v + k < prev:
                return False  # 即使加 k 次也不够
            # 更新 prev：当前元素可以达到的最大值 = v + k
            # 但只需要达到 prev 即可（尽量少操作）
            # 下一个元素只需 >= max(v + 已操作次数, prev)
            # 保守估计：prev = max(v, prev)（因为 v 可以自由增加到 prev，但下一个元素看的是 v 的实际值）
            # 实际上，我们只要知道 nums[i] 最终变成什么
            # 若 v < prev：需要将 v 增加到 prev（操作 prev - v 次，需 <= k）
            # 若 v >= prev：不需要操作，prev = v
            if v < prev:
                # 需要增加 prev - v 次
                if prev - v > k:
                    return False
                # 增加后 v 变为 prev
                prev = prev
            else:
                prev = v

        return True
```

### 方法二：模拟操作

```python
from typing import List

class Solution:
    def isSortedAfterOperations(self, nums: List[int], k: int) -> bool:
        arr = nums[:]
        n = len(arr)

        for i in range(1, n):
            if arr[i] < arr[i - 1]:
                need = arr[i - 1] - arr[i]
                if need > k:
                    return False
                arr[i] = arr[i - 1]  # 增加到刚好等于前一个

        return True
```

## 复杂度分析

- 时间复杂度：O(n)
- 空间复杂度：O(1)（方法一）；O(n)（方法二，复制数组）

## 关键点总结

1. 只能增加元素，不能减少，所以前面大的元素是约束。
2. 贪心：每个元素只增加到恰好等于前一个元素（最少操作）。
3. 若某个元素需要增加 `need > k` 次，则不可能完成。

## 易错点

1. 只能增加（加 1），不能减少。
2. 每个元素操作次数不超过 k，检查 `need <= k`。
3. 操作后的值传递给下一个位置作为约束。
