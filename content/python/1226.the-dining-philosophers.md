## 题目描述

5 个沉默寡言的哲学家围坐在圆桌前，每人面前一盘意面。叉子放在每两个相邻的哲学家之间。

每个哲学家必须交替进行思考和进食。哲学家只有同时拿起左边和右边的叉子才能吃意面。每个叉子只能被一个哲学家使用，所以如果另一个哲学家正在使用叉子，则另一个哲学家必须等待，直到可以使用叉子。

哲学家吃完后，需要把两个叉子都放回原处，这样其他哲学家就可以使用了。哲学家可以在等待时思考。

每个哲学家从 0 到 4 按顺时针编号。请实现函数 `void wantsToEat(philosopher, pickLeftFork, pickRightFork, eat, putLeftFork, putRightFork)`：

- `philosopher` 是哲学家的编号（0 到 4）
- `pickLeftFork` 和 `pickRightFork` 是拿起左边或右边叉子的函数
- `eat` 是吃意面的函数
- `putLeftFork` 和 `putRightFork` 是放下左边或右边叉子的函数

哲学家编号从 0 到 4，按顺时针编号。假设所有哲学家同时开始思考和进食。函数可能会为同一个哲学家多次调用，甚至在上一次调用结束前就再次调用。

示例：
```
输入：n = 1
输出：[[4,2,1],[4,1,1],[0,1,1],[2,2,1],[2,1,1],[2,0,3],[2,1,2],[2,2,2],[4,0,3],[4,1,2],[0,2,1],[4,2,2],[3,2,1],[3,1,1],[0,0,3],[0,1,2],[0,2,2],[1,2,1],[1,1,1],[3,0,3],[3,1,2],[3,2,2],[1,0,3],[1,1,2],[1,2,2]]
解释：
n 表示每个哲学家需要进食的次数。
输出数组描述了叉子的控制和进食的调用，格式如下：
output[i] = [a, b, c] (其中三个整数)
- a 是哲学家编号。
- b 指定叉子：{1 : 左边, 2 : 右边}.
- c 指定行为：{1 : 拿起, 2 : 放下, 3 : 吃}。
```

## 解题思路

这是经典的哲学家就餐问题，核心挑战是避免死锁（所有哲学家都拿着左边的叉子等右边的）。

解决方案：

1. **打破循环等待**：让编号为偶数的哲学家先拿左叉子，奇数的先拿右叉子
2. **限制同时进餐人数**：最多允许 4 个哲学家同时尝试吃饭
3. **使用锁机制**：为每个叉子创建一个锁

我们采用方案1 + 锁机制，这样可以确保不会出现死锁：
- 哲学家 0, 2, 4（偶数）：先拿左叉子，再拿右叉子
- 哲学家 1, 3（奇数）：先拿右叉子，再拿左叉子

## Python 代码实现

### 方法一：打破循环等待（推荐）

```python
import threading
from typing import Callable

class DiningPhilosophers:
    def __init__(self):
        # 为每个叉子创建一个锁
        self.forks = [threading.Lock() for _ in range(5)]
    
    def wantsToEat(self,
                   philosopher: int,
                   pickLeftFork: Callable[[], None],
                   pickRightFork: Callable[[], None],
                   eat: Callable[[], None],
                   putLeftFork: Callable[[], None],
                   putRightFork: Callable[[], None]) -> None:
        
        # 计算左右叉子的编号
        left_fork = philosopher
        right_fork = (philosopher + 1) % 5
        
        # 偶数编号的哲学家先拿左叉子，奇数先拿右叉子
        # 这样打破了循环等待条件，避免死锁
        if philosopher % 2 == 0:
            # 偶数：左 -> 右
            with self.forks[left_fork]:
                with self.forks[right_fork]:
                    pickLeftFork()
                    pickRightFork()
                    eat()
                    putLeftFork()
                    putRightFork()
        else:
            # 奇数：右 -> 左
            with self.forks[right_fork]:
                with self.forks[left_fork]:
                    pickRightFork()
                    pickLeftFork()
                    eat()
                    putRightFork()
                    putLeftFork()
```

### 方法二：限制同时进餐人数

```python
import threading
from typing import Callable

class DiningPhilosophers:
    def __init__(self):
        # 为每个叉子创建锁
        self.forks = [threading.Lock() for _ in range(5)]
        # 使用信号量限制最多4个哲学家同时尝试进餐
        self.semaphore = threading.Semaphore(4)
    
    def wantsToEat(self,
                   philosopher: int,
                   pickLeftFork: Callable[[], None],
                   pickRightFork: Callable[[], None],
                   eat: Callable[[], None],
                   putLeftFork: Callable[[], None],
                   putRightFork: Callable[[], None]) -> None:
        
        left_fork = philosopher
        right_fork = (philosopher + 1) % 5
        
        # 限制最多4个哲学家同时尝试拿叉子
        with self.semaphore:
            # 按顺序获取叉子
            with self.forks[left_fork]:
                pickLeftFork()
                with self.forks[right_fork]:
                    pickRightFork()
                    eat()
                    putRightFork()
                putLeftFork()
```

### 方法三：使用全局锁

```python
import threading
from typing import Callable

class DiningPhilosophers:
    def __init__(self):
        self.forks = [threading.Lock() for _ in range(5)]
        # 使用一个全局锁保护整个进餐过程
        self.mutex = threading.Lock()
    
    def wantsToEat(self,
                   philosopher: int,
                   pickLeftFork: Callable[[], None],
                   pickRightFork: Callable[[], None],
                   eat: Callable[[], None],
                   putLeftFork: Callable[[], None],
                   putRightFork: Callable[[], None]) -> None:
        
        left_fork = philosopher
        right_fork = (philosopher + 1) % 5
        
        # 使用全局锁确保同一时间只有一个哲学家在拿叉子
        with self.mutex:
            pickLeftFork()
            pickRightFork()
        
        # 吃饭可以并发进行
        eat()
        
        # 放下叉子
        putLeftFork()
        putRightFork()
```

### 方法四：使用 RLock 和有序获取

```python
import threading
from typing import Callable

class DiningPhilosophers:
    def __init__(self):
        self.forks = [threading.Lock() for _ in range(5)]
    
    def wantsToEat(self,
                   philosopher: int,
                   pickLeftFork: Callable[[], None],
                   pickRightFork: Callable[[], None],
                   eat: Callable[[], None],
                   putLeftFork: Callable[[], None],
                   putRightFork: Callable[[], None]) -> None:
        
        left_fork = philosopher
        right_fork = (philosopher + 1) % 5
        
        # 总是按编号从小到大的顺序获取叉子，避免循环等待
        first_fork = min(left_fork, right_fork)
        second_fork = max(left_fork, right_fork)
        
        with self.forks[first_fork]:
            with self.forks[second_fork]:
                # 根据实际的左右关系调用函数
                if left_fork < right_fork:
                    pickLeftFork()
                    pickRightFork()
                else:
                    pickRightFork()
                    pickLeftFork()
                
                eat()
                
                if left_fork < right_fork:
                    putLeftFork()
                    putRightFork()
                else:
                    putRightFork()
                    putLeftFork()
```

## 复杂度分析

**所有方法：**
- 时间复杂度：O(1)，每次调用的操作都是常数时间
- 空间复杂度：O(1)，固定使用 5 个锁

## 关键点总结

1. 死锁的四个必要条件：互斥、持有并等待、非抢占、循环等待
2. 解决哲学家就餐问题的核心：打破循环等待条件
3. Python 中 `with` 语句自动管理锁的获取和释放
4. 信号量可以限制同时访问资源的线程数量
5. 不同的解决方案性能不同：
   - 方法一性能最好，允许最大并发
   - 方法二性能较好，限制并发度
   - 方法三最简单但并发度最低

## 易错点

1. 直接让所有哲学家都先拿左叉子会导致死锁
2. 忘记释放锁会导致死锁
3. 锁的获取顺序不一致可能导致死锁
4. 使用全局锁时，不应该把 eat 也放在锁内（降低并发性）
5. 注意右叉子的编号计算：`(philosopher + 1) % 5`
