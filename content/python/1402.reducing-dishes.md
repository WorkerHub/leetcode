## 题目描述

一个厨师收集了他 `n` 道菜的满意程度 `satisfaction`，这个厨师做出每道菜的时间都是 1 单位时间。

一道菜的**「like-time 系数」**定义为烹饪这道菜以及之前每道菜所花费的时间乘以这道菜的满意程度，也就是 `time[k] * satisfaction[k]`，其中 `time[k]` 是烹饪第 `k` 道菜的时间（`k` 从 1 开始计数）。

请你返回做完所有菜**「like-time 系数」**之和的**最大值**为多少。

你可以按**任意顺序**安排上菜顺序，也可以选择丢弃某些菜，不做所有菜都是允许的。

**示例 1：**

```
输入：satisfaction = [-1,-8,0,5,-9]
输出：14
解释：去掉第二道和最后一道菜，最大的 like-time 系数和为
(-1 * 1 + 0 * 2 + 5 * 3) = 14。每道菜都可以成为「like-time 系数」最大的那道菜。
```

**示例 2：**

```
输入：satisfaction = [4,3,2]
输出：20
解释：按照原来的顺序上菜 (3,2,1)。Total like-time coefficient will be equal to
(4 * 1 + 3 * 2 + 2 * 3) = 4 + 6 + 6 = 16 ... 嗯？
实际上排序后最优是 [2,3,4]：2*1 + 3*2 + 4*3 = 2 + 6 + 12 = 20。
```

**示例 3：**

```
输入：satisfaction = [-1,-4,-5]
输出：0
解释：大家都不喜欢这些菜，所以不做任何菜可以获得最大的 like-time 系数。
```

**提示：**

- `n == satisfaction.length`
- `1 <= n <= 500`
- `-10^3 <= satisfaction[i] <= 10^3`

## 解题思路

**贪心策略：** 排序后，从最大满意度的菜开始向左扩展，每次考虑是否将更小满意度的菜加入序列。

**关键观察：**

最优方案一定是取排序后满意度最大的某个后缀（连续末尾段）。

**为什么从大到小排序后取后缀最优？**

设当前已选菜的满意度之和为 `total`，当前结果为 `ans`。

若在现有序列前加一道新菜（满意度为 `s`），则：
- 现有序列中每道菜的时间系数都增加 1，贡献增加 `total`
- 新菜作为第 1 道贡献 `s * 1 = s`
- 总增加量 = `total + s`

因此，**只要 `total + s > 0`，就值得加入这道菜**。

从最大满意度开始，从右向左（从大到小排序后）依次尝试加入菜，每次检查是否能增加总值。

## Python 代码实现

### 方法一：贪心（从右往左扫）（推荐）

```python
from typing import List

class Solution:
    def maxSatisfaction(self, satisfaction: List[int]) -> int:
        # 排序，满意度从小到大
        satisfaction.sort()
        n = len(satisfaction)

        ans = 0        # 当前最大 like-time 系数之和
        total = 0      # 当前选取菜的满意度之和（前缀和）

        # 从满意度最大的菜开始（从右往左），逐步考虑加入满意度更小的菜
        for i in range(n - 1, -1, -1):
            total += satisfaction[i]
            if total <= 0:
                # 加入这道菜（以及更左边的菜）无法增加总值，停止
                break
            # 每加入一道菜，现有序列中每道菜的时间系数都增加 1，贡献增加 total
            ans += total

        return ans
```

### 方法二：动态规划

```python
from typing import List

class Solution:
    def maxSatisfaction(self, satisfaction: List[int]) -> int:
        satisfaction.sort()
        n = len(satisfaction)

        # dp[i] 表示从第 i 道菜开始做（到最后一道），所能获得的最大 like-time 系数之和
        # 递推关系：若从第 i 道菜开始，在原基础上，所有后面菜的时间系数都加1
        # 即 dp[i] = max(0, satisfaction[i] + dp[i+1] + sum(satisfaction[i+1:]))
        # 简化：prefix_sum = sum of chosen dishes, ans += prefix_sum each time we add a dish

        # 等价于方法一的贪心，但写成 DP 形式
        dp = 0          # 当前子问题的最优值
        suffix_sum = 0  # 当前已选菜满意度之和

        for s in reversed(satisfaction):
            # 考虑将满意度为 s 的菜加到序列最前面
            suffix_sum += s
            if suffix_sum > 0:
                dp += suffix_sum
            else:
                break  # 贡献为负，后面更小的菜也不用考虑了

        return dp
```

### 方法三：暴力枚举（帮助理解）

```python
from typing import List

class Solution:
    def maxSatisfaction(self, satisfaction: List[int]) -> int:
        satisfaction.sort()  # 最优顺序一定是排序后的顺序
        n = len(satisfaction)
        ans = 0

        # 枚举从哪个位置开始选（取后缀）
        for start in range(n):
            total = 0
            for k, s in enumerate(satisfaction[start:], 1):
                total += k * s
            ans = max(ans, total)

        return ans
```

## 复杂度分析

| 方法 | 时间复杂度 | 空间复杂度 |
|------|-----------|-----------|
| 方法一（贪心） | O(n log n) | O(1) |
| 方法二（DP） | O(n log n) | O(1) |
| 方法三（暴力） | O(n^2) | O(1) |

排序是 O(n log n)，贪心扫描是 O(n)，整体 O(n log n)。

## 图解示例

以 `satisfaction = [-1,-8,0,5,-9]` 为例，排序后：`[-9,-8,-1,0,5]`

从右往左扫描：

```
i=4, s=5:  total = 5 > 0, ans += 5,  ans = 5
i=3, s=0:  total = 5 > 0, ans += 5,  ans = 10
i=2, s=-1: total = 4 > 0, ans += 4,  ans = 14
i=1, s=-8: total = -4 <= 0, 停止

返回 14
```

验证：选 `[-1, 0, 5]`，like-time = -1*1 + 0*2 + 5*3 = -1 + 0 + 15 = 14，正确。

## 关键点总结

1. 最优顺序一定是排序后的顺序（满意度从小到大依次上菜）
2. 最优方案一定是排序后的某个**后缀**（不选满意度最小的若干道菜）
3. 贪心：当在序列前加一道菜时，增量 = `total + s`，只要为正就加入
4. `ans += total` 等价于对所有已选菜的时间系数加 1 并累计

## 易错点

- 不排序直接贪心是错误的，排序是保证结论成立的前提
- 停止条件：`total <= 0` 而不是 `s <= 0`，因为负数菜也可能有价值（如果之后的菜足够多）
- 方法三验证时注意时间系数从 1 开始，不是从 0
