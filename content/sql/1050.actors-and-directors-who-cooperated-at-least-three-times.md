## 题目描述

表：`ActorDirector`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| actor_id    | int     |
| director_id | int     |
| timestamp   | int     |
+-------------+---------+
timestamp 是这张表的主键（具有唯一值的列）。
```

编写一个解决方案，找出所有合作过至少三次的演员和导演的对 `(actor_id, director_id)`。

以任意顺序返回结果表。

**示例 1：**

输入：
ActorDirector 表：
```
+-------------+-------------+-------------+
| actor_id    | director_id | timestamp   |
+-------------+-------------+-------------+
| 1           | 1           | 0           |
| 1           | 1           | 1           |
| 1           | 1           | 2           |
| 1           | 2           | 3           |
| 1           | 2           | 4           |
| 2           | 1           | 5           |
| 2           | 1           | 6           |
+-------------+-------------+-------------+
```

输出：
```
+-------------+-------------+
| actor_id    | director_id |
+-------------+-------------+
| 1           | 1           |
+-------------+-------------+
```

解释：唯一的 `(actor_id, director_id)` 对是 `(1, 1)`，他们恰好合作了 3 次。

## 解题思路

这是一道典型的 SQL 分组聚合问题，核心思想是：

1. **分组统计**：按照演员和导演的组合（`actor_id`, `director_id`）进行分组
2. **计数筛选**：统计每个组合出现的次数，筛选出出现次数 ≥ 3 的记录
3. **返回结果**：只需返回符合条件的演员和导演对

**关键观察：**
- 每条记录代表一次合作（通过 timestamp 唯一标识）
- 需要找的是「同一演员和同一导演」的合作次数
- 使用 `GROUP BY` 和 `HAVING` 可以高效完成筛选

**算法流程：**
1. 使用 `GROUP BY actor_id, director_id` 对数据分组
2. 使用 `COUNT(*)` 统计每组的记录数（即合作次数）
3. 使用 `HAVING COUNT(*) >= 3` 筛选合作次数 ≥ 3 的组
4. 返回 `actor_id` 和 `director_id`

## SQL 代码实现

### 方法一：GROUP BY + HAVING（标准解法）⭐

这是最直接、最高效的解法，利用 SQL 的分组聚合功能：

```sql
SELECT actor_id, director_id
FROM ActorDirector
GROUP BY actor_id, director_id
HAVING COUNT(*) >= 3
```

**代码说明：**
- `GROUP BY actor_id, director_id`：按演员和导演的组合分组
- `COUNT(*)`：统计每组中的记录数
- `HAVING COUNT(*) >= 3`：过滤条件，只保留合作次数 ≥ 3 的组
- `HAVING` 与 `WHERE` 的区别：`HAVING` 用于分组后的筛选，`WHERE` 用于分组前的筛选

### 方法二：子查询方式

使用子查询先统计次数，再筛选：

```sql
SELECT actor_id, director_id
FROM (
    SELECT actor_id, director_id, COUNT(*) as cooperation_count
    FROM ActorDirector
    GROUP BY actor_id, director_id
) AS cooperation_stats
WHERE cooperation_count >= 3
```

**代码说明：**
- 内层查询：先分组统计每对演员-导演的合作次数
- 外层查询：使用 `WHERE` 筛选合作次数 ≥ 3 的记录
- 这种方法更直观，但性能与方法一相当

### 方法三：使用窗口函数（过度设计）

仅作学习参考，实际不推荐用于此题：

```sql
SELECT DISTINCT actor_id, director_id
FROM (
    SELECT 
        actor_id, 
        director_id,
        COUNT(*) OVER (PARTITION BY actor_id, director_id) as cooperation_count
    FROM ActorDirector
) AS window_stats
WHERE cooperation_count >= 3
```

**代码说明：**
- `COUNT(*) OVER (PARTITION BY ...)`：窗口函数统计分组内的记录数
- `DISTINCT`：去除重复行（因为窗口函数会为每条原始记录都计算一次）
- 不推荐原因：比方法一复杂，且需要去重，性能较差

## 复杂度分析

**SQL 方法一（推荐）：**
- **时间复杂度**：O(n)，其中 n 是表中的记录数。需要遍历所有记录进行分组和计数。
- **空间复杂度**：O(k)，其中 k 是不同的 (actor_id, director_id) 组合数量，用于存储分组结果。

**Python Pandas 方法：**
- **时间复杂度**：O(n)，groupby 操作需要遍历所有记录。
- **空间复杂度**：O(k)，存储分组后的结果。

**性能优化建议：**
- 在 `actor_id` 和 `director_id` 列上建立联合索引可以加速分组操作
- 对于大规模数据，SQL 的分组聚合通常比应用层处理更高效

## 关键点总结

1. **GROUP BY 多列**：可以按多个列的组合进行分组，这里是 `(actor_id, director_id)` 的组合
2. **HAVING vs WHERE**：`HAVING` 用于聚合函数的筛选，在分组后执行；`WHERE` 在分组前执行
3. **COUNT(*) 的含义**：统计每组中的行数，即合作次数
4. **简洁性优先**：方法一是最简洁、最高效的解法，无需子查询或窗口函数
5. **Pandas 替代方案**：对于小数据集，Pandas 的 `groupby` 提供了类似 SQL 的分组聚合能力

## 易错点

1. **忘记 HAVING 条件**
   ```sql
   -- 错误：没有筛选条件，返回所有组合
   SELECT actor_id, director_id
   FROM ActorDirector
   GROUP BY actor_id, director_id
   ```

2. **误用 WHERE 代替 HAVING**
   ```sql
   -- 错误：WHERE 不能直接使用聚合函数
   SELECT actor_id, director_id
   FROM ActorDirector
   WHERE COUNT(*) >= 3  -- 语法错误
   GROUP BY actor_id, director_id
   ```

3. **COUNT 函数使用不当**
   ```sql
   -- 可能出错：COUNT(timestamp) 会忽略 NULL 值
   -- 虽然 timestamp 是主键不会为 NULL，但 COUNT(*) 更清晰
   HAVING COUNT(timestamp) >= 3
   ```

4. **忘记分组列包含所有需要的维度**
   ```sql
   -- 错误：只按 actor_id 分组，无法区分不同的导演
   SELECT actor_id, director_id
   FROM ActorDirector
   GROUP BY actor_id
   HAVING COUNT(*) >= 3
   ```

5. **Pandas 中忘记 reset_index**
   ```python
   # 错误：groupby 后的结果索引是 (actor_id, director_id)，需要转回列
   result = actor_director.groupby(['actor_id', 'director_id']).size()
   # 正确：使用 reset_index() 转换
   result = actor_director.groupby(['actor_id', 'director_id']).size().reset_index()
   ```

## 学习建议

**对于 SQL 新手：**

1. **理解分组的本质**：
   - `GROUP BY` 将具有相同值的行合并成一组
   - 多列分组时，只有所有分组列的值都相同才会合并
   - 分组后，每组只返回一行结果

2. **掌握聚合函数**：
   - `COUNT(*)`：统计行数
   - `SUM()`、`AVG()`、`MAX()`、`MIN()`：其他常用聚合函数
   - 聚合函数在分组后对每组数据进行计算

3. **区分 WHERE 和 HAVING**：
   - `WHERE`：在分组前筛选行（不能使用聚合函数）
   - `HAVING`：在分组后筛选组（可以使用聚合函数）
   - 执行顺序：WHERE → GROUP BY → HAVING → SELECT

4. **练习建议**：
   - 先掌握单列分组，再学习多列分组
   - 尝试用 SQL 和 Pandas 两种方式实现，加深理解
   - 查看数据库执行计划，了解查询优化

5. **扩展学习**：
   - 学习索引对分组性能的影响
   - 了解 DISTINCT 与 GROUP BY 的区别
   - 探索更复杂的分组场景（如嵌套分组、ROLLUP、CUBE）

**推荐学习路径：**
1. 熟练掌握基础 SELECT 和 WHERE 语句
2. 学习 GROUP BY 和常用聚合函数
3. 理解 HAVING 子句的使用场景
4. 练习多表 JOIN 与分组的结合
5. 进阶学习窗口函数和 CTE（公共表表达式）
