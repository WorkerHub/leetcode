## 题目描述

**Customers 表：**

| 列名          | 类型    |
|---------------|---------|
| customer_id   | int     |
| customer_name | varchar |
| email         | varchar |

`customer_id` 是该表主键。

**Contacts 表：**

| 列名          | 类型    |
|---------------|---------|
| user_id       | int     |
| contact_name  | varchar |
| contact_email | varchar |

没有主键，每行记录某个顾客（user_id）的一个联系人信息。

**Invoices 表：**

| 列名        | 类型    |
|-------------|---------|
| invoice_id  | int     |
| price       | decimal |
| user_id     | int     |
| contact     | varchar |

`invoice_id` 是主键。`user_id` 是购买该发票的顾客编号。

对每张发票，统计：
- `invoice_id`：发票编号
- `customer_name`：顾客姓名
- `price`：发票价格
- `contacts_cnt`：该顾客的**总联系人数**
- `trusted_contacts_count`：该顾客的联系人中，同时也是平台注册顾客（在 Customers 表中有 email 记录）的数量

结果按 `invoice_id` 升序排列。

**示例（略，题目描述已足够清晰）**

## 解题思路

本题需要三表关联：

1. **Invoices** 表提供发票主数据（每行是一张发票）。
2. **Customers** 表提供顾客信息（通过 `user_id` 关联）。
3. **Contacts** 表提供联系人信息（通过 `user_id` 关联），需要：
   - 统计总联系人数（COUNT）
   - 统计其中 email 在 Customers 表中的数量（"受信任联系人"）

**关键步骤：**
1. 先对 Contacts 表按 user_id 分组，统计总联系人数和可信联系人数（email 在 Customers 中的）。
2. 将统计结果与 Invoices 表和 Customers 表关联，得到最终结果。

## SQL 解法

### 方法一：LEFT JOIN + 子查询（推荐）

```sql
SELECT
    i.invoice_id,
    c.customer_name,
    i.price,
    IFNULL(t.contacts_cnt, 0) AS contacts_cnt,
    IFNULL(t.trusted_contacts_count, 0) AS trusted_contacts_count
FROM Invoices i
JOIN Customers c ON i.user_id = c.customer_id
LEFT JOIN (
    -- 子查询：统计每个顾客的联系人总数和可信联系人数
    SELECT
        con.user_id,
        COUNT(con.contact_email) AS contacts_cnt,
        SUM(
            CASE WHEN cus.email IS NOT NULL THEN 1 ELSE 0 END
        ) AS trusted_contacts_count
    FROM Contacts con
    LEFT JOIN Customers cus ON con.contact_email = cus.email
    GROUP BY con.user_id
) t ON i.user_id = t.user_id
ORDER BY i.invoice_id;
```

### 方法二：CTE（公用表表达式）写法

```sql
WITH contact_stats AS (
    -- 统计每个顾客的联系人总数和可信联系人数
    SELECT
        con.user_id,
        COUNT(*) AS contacts_cnt,
        COUNT(cus.customer_id) AS trusted_contacts_count
    FROM Contacts con
    LEFT JOIN Customers cus
        ON con.contact_email = cus.email
    GROUP BY con.user_id
)
SELECT
    i.invoice_id,
    c.customer_name,
    i.price,
    COALESCE(cs.contacts_cnt, 0)          AS contacts_cnt,
    COALESCE(cs.trusted_contacts_count, 0) AS trusted_contacts_count
FROM Invoices i
JOIN Customers c ON i.user_id = c.customer_id
LEFT JOIN contact_stats cs ON i.user_id = cs.user_id
ORDER BY i.invoice_id;
```

**解释：**
- `contact_stats` CTE：
  - LEFT JOIN Customers：找出 contact_email 在 Customers.email 中的联系人（即"可信联系人"）。
  - `COUNT(*)` 统计所有联系人总数。
  - `COUNT(cus.customer_id)` 统计 JOIN 成功的（即可信）联系人数，NULL 值不被 COUNT 计入。
- 主查询：
  - `JOIN Customers`：获取顾客姓名（用 JOIN 而非 LEFT JOIN，因为 Invoices 中的 user_id 保证在 Customers 中存在）。
  - `LEFT JOIN contact_stats`：有些顾客可能没有任何联系人，用 LEFT JOIN 并 COALESCE 处理 NULL。

### 方法三：使用窗口函数（MySQL 8.0+）

```sql
SELECT
    i.invoice_id,
    c.customer_name,
    i.price,
    COUNT(con.contact_email) OVER (PARTITION BY i.user_id) AS contacts_cnt,
    COUNT(cus.email) OVER (PARTITION BY i.user_id) AS trusted_contacts_count
FROM Invoices i
JOIN Customers c ON i.user_id = c.customer_id
LEFT JOIN Contacts con ON i.user_id = con.user_id
LEFT JOIN Customers cus ON con.contact_email = cus.email
ORDER BY i.invoice_id;
```

**注意：** 这个写法可能产生重复行（因为 LEFT JOIN Contacts 可能扩展行数），需要先测试是否产生正确结果。在标准情况下，建议使用方法一或方法二。

### 方法四：使用 EXISTS 统计可信联系人

```sql
SELECT
    i.invoice_id,
    c.customer_name,
    i.price,
    (SELECT COUNT(*) FROM Contacts con WHERE con.user_id = i.user_id) AS contacts_cnt,
    (SELECT COUNT(*) FROM Contacts con
     WHERE con.user_id = i.user_id
     AND EXISTS (
         SELECT 1 FROM Customers c2 WHERE c2.email = con.contact_email
     )) AS trusted_contacts_count
FROM Invoices i
JOIN Customers c ON i.user_id = c.customer_id
ORDER BY i.invoice_id;
```

## 复杂度分析

- SQL 方法一/二：时间复杂度取决于数据库优化器，通常 O(N+M+K)，其中 N、M、K 分别是三个表的行数；使用索引后性能更优。
- Python 模拟：O(N+M+K)，线性遍历三个表。

## 关键点总结

1. "可信联系人"的定义：联系人的 email 在 Customers.email 中存在。
2. 两步处理：先在 Contacts 上分组统计（GROUP BY + 条件聚合），再与 Invoices 和 Customers 关联。
3. `COUNT(cus.customer_id)` 而非 `COUNT(*)`：当 LEFT JOIN 不匹配时，cus.customer_id 为 NULL，COUNT 不计入，自然得到可信联系人数。
4. `COALESCE(val, 0)` 处理没有联系人的顾客（此时 LEFT JOIN 结果为 NULL，需要转为 0）。
5. 最终按 `invoice_id` 升序排列。

## 易错点

- 混淆 `COUNT(*)` 和 `COUNT(列名)`：前者计所有行包括 NULL，后者不计 NULL 行，本题利用这个区别统计"可信"联系人。
- Invoices 与 Customers 的关联用 `JOIN`（内连接）而不是 `LEFT JOIN`，因为每张发票必然对应一个存在的顾客。
- Invoices 与 contact_stats 的关联用 `LEFT JOIN`，因为某顾客可能没有联系人（contact_stats 中无对应行）。
