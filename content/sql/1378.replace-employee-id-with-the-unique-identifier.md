## 题目描述

**Employees** 表：

| 列名 | 类型    |
|------|---------|
| id   | int     |
| name | varchar |

`id` 是该表的主键。

**EmployeeUNI** 表：

| 列名      | 类型 |
|-----------|------|
| id        | int  |
| unique_id | int  |

`(id, unique_id)` 是该表的主键。

**要求：** 对于每位员工，展示他们的 `unique_id`（来自 EmployeeUNI 表）和 `name`（来自 Employees 表）。如果某员工没有对应的 unique_id，则显示 `null`。

**结果可以按任意顺序返回。**

**示例：**

输入：

Employees 表：

| id | name      |
|----|-----------|
| 1  | Alice     |
| 7  | Bob       |
| 11 | Meir      |
| 90 | Winston   |
| 3  | Jonathan  |

EmployeeUNI 表：

| id | unique_id |
|----|-----------|
| 3  | 1         |
| 11 | 2         |
| 90 | 3         |

输出：

| unique_id | name      |
|-----------|-----------|
| null      | Alice     |
| null      | Bob       |
| 2         | Meir      |
| 3         | Winston   |
| 1         | Jonathan  |

解释：Alice 和 Bob 没有 unique_id，显示 null。

## 解题思路

### 核心思想

本题是最经典的 **LEFT JOIN** 应用场景：

- 以 `Employees` 表为主表，保留所有员工。
- 左连接 `EmployeeUNI` 表，若某员工没有 unique_id，对应字段显示 `NULL`。

**为什么用 LEFT JOIN 而不是 INNER JOIN？**
- INNER JOIN 只返回两表都有的记录，没有 unique_id 的员工会被丢失。
- LEFT JOIN 保留左表（Employees）的所有记录，右表没有匹配时填 NULL。

### 方法一：LEFT JOIN（推荐，标准解法）

### 方法二：使用子查询（不推荐，但有助理解）

## 代码实现

### 方法一：LEFT JOIN（推荐）

```sql
-- 以 Employees 为主表，左连接 EmployeeUNI
-- 没有 unique_id 的员工自动填充 NULL
SELECT
    eu.unique_id,
    e.name
FROM Employees e
LEFT JOIN EmployeeUNI eu
ON e.id = eu.id;
```

### 方法二：RIGHT JOIN（等价写法）

```sql
-- 如果从 EmployeeUNI 表的角度，改用 RIGHT JOIN
-- 效果与方法一等价，但语义不如 LEFT JOIN 直观
SELECT
    eu.unique_id,
    e.name
FROM EmployeeUNI eu
RIGHT JOIN Employees e
ON e.id = eu.id;
```

### 方法三：子查询（理解用）

```sql
-- 对每个员工，用子查询查找其 unique_id
SELECT
    (SELECT eu.unique_id
     FROM EmployeeUNI eu
     WHERE eu.id = e.id
     LIMIT 1) AS unique_id,
    e.name
FROM Employees e;
-- 注意：子查询效率低，不推荐生产使用
```

## 复杂度分析

### SQL 方法一（LEFT JOIN）
- **时间复杂度**：O(m + n)（m 为 Employees 行数，n 为 EmployeeUNI 行数），数据库引擎通常用哈希或索引优化
- **空间复杂度**：O(m)，结果集行数与 Employees 相同

### Python pandas
- **时间复杂度**：O(m + n)
- **空间复杂度**：O(m + n)

## 关键点总结

1. **LEFT JOIN 是本题核心**：以员工表为主表，确保每位员工都出现在结果中。
2. **NULL 的语义**：没有匹配记录时，`unique_id` 自动为 NULL，无需额外处理。
3. **连接条件**：`ON e.id = eu.id`，通过员工 ID 关联两表。
4. **列的选取顺序**：题目要求先输出 `unique_id` 再输出 `name`，注意 SELECT 的列顺序。
5. **不需要 GROUP BY**：每个员工最多有一个 unique_id（EmployeeUNI 以 (id, unique_id) 为主键），不会出现重复。

## 易错点

1. **使用 INNER JOIN 导致数据丢失**：INNER JOIN 会丢失没有 unique_id 的员工（Alice, Bob），必须用 LEFT JOIN。
2. **连接方向**：LEFT JOIN 中，左表是主表（完整保留），右表是补充（可以为NULL）。本题左表应为 Employees。
3. **列名冲突**：两表都有 `id` 列，在 SELECT 时若需要 `id` 要指定表名（本题不需要 id，只需 unique_id 和 name）。

## 学习建议

1. **JOIN 的四种类型**：
   - `INNER JOIN`：只返回两表都有的行
   - `LEFT JOIN`：保留左表所有行，右表无匹配则 NULL
   - `RIGHT JOIN`：保留右表所有行，左表无匹配则 NULL
   - `FULL OUTER JOIN`：保留两表所有行（MySQL 不直接支持，需用 UNION）
2. 本题是 **LEFT JOIN** 的入门练习，也是 SQL 中最常用的连接方式。
3. 记住规则：**需要保留哪张表的完整数据，那张表就放在 LEFT 侧**（或用 RIGHT JOIN 放在右侧）。
4. 对应的 pandas 操作是 `merge(how='left')`，是数据分析中非常常用的操作。
