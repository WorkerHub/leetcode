## 题目描述

表：`Events`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| business_id   | int     |
| event_type    | varchar |
| occurrences   | int     | 
+---------------+---------+
(business_id, event_type) 是这张表的主键（具有唯一值的列的组合）
表中的每一行记录了某种类型的事件在某些业务中多次发生的信息。
```

**活跃业务**是指在所有事件类型中，至少有两个事件的发生次数严格大于该事件的平均发生次数。

编写解决方案找出所有**活跃业务**的 `business_id`。

以**任意顺序**返回结果表。

查询结果格式如下所示。

**示例 1：**

**输入：**

Events 表：
```
+-------------+------------+-------------+
| business_id | event_type | occurrences |
+-------------+------------+-------------+
| 1           | reviews    | 7           |
| 3           | reviews    | 3           |
| 1           | ads        | 11          |
| 2           | ads        | 7           |
| 3           | ads        | 6           |
| 1           | page views | 3           |
| 2           | page views | 12          |
+-------------+------------+-------------+
```

**输出：**
```
+-------------+
| business_id |
+-------------+
| 1           |
+-------------+
```

**解释：**

每种事件的平均发生次数：
- 'reviews'：(7+3)/2 = 5
- 'ads'：(11+7+6)/3 = 8
- 'page views'：(3+12)/2 = 7.5

business_id = 1 有 2 个事件类型的发生次数高于平均值：
- reviews：7 > 5
- ads：11 > 8

business_id = 2 只有 1 个事件类型高于平均值：
- page views：12 > 7.5

business_id = 3 没有事件类型高于平均值。

因此只有 business_id = 1 是活跃业务。

## 解题思路

这道题需要分三步解决：

1. **计算每种事件类型的平均发生次数**
2. **找出每个业务中发生次数高于平均值的事件**
3. **筛选出至少有 2 个这样的事件的业务**

### 核心思想

使用**子查询**或**窗口函数**计算平均值，然后通过 `HAVING` 子句统计符合条件的事件数量。

## SQL 代码实现

### 方法一：使用子查询（推荐）

```sql
SELECT business_id
FROM Events e
WHERE occurrences > (
    SELECT AVG(occurrences)
    FROM Events
    WHERE event_type = e.event_type
)
GROUP BY business_id
HAVING COUNT(*) >= 2;
```

**解释：**
1. 对于每一条记录，使用相关子查询计算该事件类型的平均发生次数
2. 筛选出发生次数大于平均值的记录
3. 按 `business_id` 分组
4. 使用 `HAVING` 筛选出至少有 2 条这样记录的业务

### 方法二：使用 JOIN

```sql
SELECT e.business_id
FROM Events e
JOIN (
    SELECT event_type, AVG(occurrences) AS avg_occurrences
    FROM Events
    GROUP BY event_type
) avg_table
ON e.event_type = avg_table.event_type
WHERE e.occurrences > avg_table.avg_occurrences
GROUP BY e.business_id
HAVING COUNT(*) >= 2;
```

**解释：**
1. 先在子查询中计算每种事件类型的平均发生次数
2. 将原表与平均值表连接
3. 筛选出高于平均值的记录
4. 分组并统计，找出至少有 2 个事件高于平均值的业务

### 方法三：使用窗口函数

```sql
SELECT business_id
FROM (
    SELECT 
        business_id,
        event_type,
        occurrences,
        AVG(occurrences) OVER (PARTITION BY event_type) AS avg_occurrences
    FROM Events
) t
WHERE occurrences > avg_occurrences
GROUP BY business_id
HAVING COUNT(*) >= 2;
```

**解释：**
1. 使用窗口函数 `AVG() OVER (PARTITION BY event_type)` 为每条记录计算对应事件类型的平均值
2. 在外层查询中筛选高于平均值的记录
3. 分组统计，找出符合条件的业务

### 方法四：使用 CTE（通用表表达式）

```sql
WITH AvgEvents AS (
    SELECT event_type, AVG(occurrences) AS avg_occurrences
    FROM Events
    GROUP BY event_type
),
AboveAvg AS (
    SELECT e.business_id
    FROM Events e
    JOIN AvgEvents a
    ON e.event_type = a.event_type
    WHERE e.occurrences > a.avg_occurrences
)
SELECT business_id
FROM AboveAvg
GROUP BY business_id
HAVING COUNT(*) >= 2;
```

**解释：**
1. 第一个 CTE 计算每种事件类型的平均值
2. 第二个 CTE 找出所有高于平均值的记录
3. 最后分组统计，筛选出至少有 2 个事件的业务

## 复杂度分析

### SQL 方法一（子查询）

- **时间复杂度**：O(n²)，对于每条记录都需要执行一次子查询计算平均值
- **空间复杂度**：O(n)，用于存储中间结果

### SQL 方法二（JOIN）

- **时间复杂度**：O(n)，先计算平均值（O(n)），再连接（O(n)），最后分组（O(n)）
- **空间复杂度**：O(k)，k 是事件类型数量，用于存储平均值表

### SQL 方法三（窗口函数）

- **时间复杂度**：O(n log n)，窗口函数需要排序
- **空间复杂度**：O(n)

## 关键点总结

1. **理解题意**：活跃业务是指至少有 2 个事件类型的发生次数高于该事件类型的平均值
2. **相关子查询**：在 WHERE 子句中使用子查询，引用外层查询的列（`e.event_type`）
3. **分组聚合**：先用 `WHERE` 筛选，再用 `GROUP BY` 分组，最后用 `HAVING` 过滤分组结果
4. **窗口函数优势**：可以在一次扫描中计算每种事件类型的平均值，避免多次子查询
5. **性能考虑**：方法二（JOIN）和方法三（窗口函数）性能通常优于方法一（相关子查询）

## 易错点

1. **平均值计算范围**：平均值是按 `event_type` 计算的，不是所有记录的总平均值
2. **比较运算符**：题目要求"严格大于"平均值，应使用 `>` 而非 `>=`
3. **HAVING 条件**：需要至少 2 个事件，条件是 `>= 2` 而非 `> 2`
4. **GROUP BY 位置**：必须在 WHERE 之后，HAVING 之前
5. **NULL 值处理**：如果存在 NULL 值，AVG 函数会自动忽略
