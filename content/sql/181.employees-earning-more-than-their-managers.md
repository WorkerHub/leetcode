## 题目描述

表：`Employee`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| name        | varchar |
| salary      | int     |
| managerId   | int     |
+-------------+---------+
```

id 是这个表的主键。
表的每一行都表示雇员的 ID、姓名、工资和经理的 ID。

编写一个 SQL 查询来查找收入比他们的经理高的员工。

返回结果表可以按任意顺序排列。

查询结果格式如下所示。

**示例 1：**

```
输入：
Employee 表：
+----+-------+--------+-----------+
| id | name  | salary | managerId |
+----+-------+--------+-----------+
| 1  | Joe   | 70000  | 3         |
| 2  | Henry | 80000  | 4         |
| 3  | Sam   | 60000  | null      |
| 4  | Max   | 90000  | null      |
+----+-------+--------+-----------+

输出：
+----------+
| Employee |
+----------+
| Joe      |
+----------+

解释：Joe 是唯一挣得比他的经理多的员工。
```

## 解题思路

这是一道经典的自连接问题。关键点：

1. **理解数据关系**：`managerId` 指向经理的 `id`
2. **需要比较的数据**：员工的工资 vs 经理的工资
3. **数据在同一张表**：需要自连接

### 核心思路

- 表 Employee 既包含员工信息，也包含经理信息
- 需要将表与自身连接：一份作为员工表，一份作为经理表
- 连接条件：员工的 `managerId` = 经理的 `id`
- 筛选条件：员工的 `salary` > 经理的 `salary`

## SQL 代码实现

### 方法一：自连接（推荐）

```sql
SELECT 
    e.name AS Employee
FROM 
    Employee e
JOIN 
    Employee m ON e.managerId = m.id
WHERE 
    e.salary > m.salary;
```

**代码解释：**
1. `Employee e`：将表命名为 `e`，表示员工（Employee）
2. `Employee m`：将表命名为 `m`，表示经理（Manager）
3. `ON e.managerId = m.id`：连接条件，找到每个员工对应的经理
4. `WHERE e.salary > m.salary`：筛选工资比经理高的员工
5. `e.name AS Employee`：返回员工姓名

### 方法二：使用 INNER JOIN（等价于方法一）

```sql
SELECT 
    e.name AS Employee
FROM 
    Employee e
INNER JOIN 
    Employee m ON e.managerId = m.id AND e.salary > m.salary;
```

**代码解释：**
- 将筛选条件移到 `ON` 子句中
- 逻辑与方法一完全相同，只是写法不同

### 方法三：子查询

```sql
SELECT 
    name AS Employee
FROM 
    Employee e
WHERE 
    salary > (
        SELECT salary 
        FROM Employee m 
        WHERE m.id = e.managerId
    );
```

**代码解释：**
1. 外层查询：遍历每个员工
2. 子查询：根据 `managerId` 查找经理的工资
3. `WHERE e.salary > 子查询结果`：比较工资
4. 注意：如果员工没有经理（managerId 为 NULL），子查询返回 NULL，条件不成立

### 方法四：使用逗号连接（旧式写法）

```sql
SELECT 
    e.name AS Employee
FROM 
    Employee e, 
    Employee m
WHERE 
    e.managerId = m.id 
    AND e.salary > m.salary;
```

**代码解释：**
- 使用逗号 `,` 代替 `JOIN`（笛卡尔积）
- 在 `WHERE` 中指定连接条件和筛选条件
- 这是 SQL-89 标准的写法，不推荐使用

## 复杂度分析

**方法一、二、四（自连接）：**
- 时间复杂度：O(n²)，最坏情况下需要比较每对员工
- 空间复杂度：O(n)，连接结果集
- 优点：代码简洁，易于理解

**方法三（子查询）：**
- 时间复杂度：O(n²)，每个员工都执行一次子查询
- 空间复杂度：O(1)，不需要存储中间结果
- 缺点：可能比 JOIN 慢（无法利用索引优化）

**性能提示：**
- 在 `managerId` 和 `id` 上建立索引可以显著提升性能
- 现代数据库优化器通常会将子查询改写为 JOIN

## 关键点总结

1. **自连接技巧**：同一张表用不同别名连接，模拟两个不同的表
2. **别名清晰性**：使用 `e`（employee）和 `m`（manager）增强可读性
3. **NULL 处理**：没有经理的员工（managerId = NULL）会自动被过滤
4. **JOIN vs 子查询**：JOIN 通常性能更好，子查询更直观
5. **列名要求**：结果列必须命名为 `Employee`

## 易错点

1. **忘记给表起别名**
   ```sql
   -- 错误：无法区分哪个是员工，哪个是经理
   SELECT name 
   FROM Employee, Employee
   WHERE managerId = id  -- 哪个表的 managerId？哪个表的 id？
   
   -- 正确：使用别名
   FROM Employee e, Employee m
   WHERE e.managerId = m.id
   ```

2. **连接条件错误**
   ```sql
   -- 错误：条件反了
   ON m.managerId = e.id  -- 这是找员工的下属
   
   -- 正确：员工的经理 ID 对应经理的 ID
   ON e.managerId = m.id
   ```

3. **列名错误**
   ```sql
   -- 错误：列名必须是 Employee
   SELECT e.name AS name
   
   -- 正确：
   SELECT e.name AS Employee
   ```

4. **SELECT 不指定表**
   ```sql
   -- 错误：name 列存在于两个表中，不明确
   SELECT name AS Employee
   FROM Employee e JOIN Employee m ON e.managerId = m.id
   
   -- 正确：明确指定是哪个表的 name
   SELECT e.name AS Employee
   ```

5. **忘记处理 NULL**
   ```sql
   -- 实际上不需要特别处理，JOIN 会自动过滤 NULL
   -- 但如果用 LEFT JOIN，就需要注意
   LEFT JOIN Employee m ON e.managerId = m.id  -- 会保留没有经理的员工
   WHERE e.salary > m.salary  -- m.salary 可能是 NULL，比较结果为 NULL（不满足）
   ```

## 图解示例

以示例数据为例：

```
Employee 表（员工视角）：
id  name   salary  managerId
1   Joe    70000   3         -> 经理是 Sam (60000)
2   Henry  80000   4         -> 经理是 Max (90000)
3   Sam    60000   null      -> 没有经理（老板）
4   Max    90000   null      -> 没有经理（老板）

自连接后：
e.id  e.name  e.salary  e.managerId  m.id  m.name  m.salary
1     Joe     70000     3            3     Sam     60000     ✓ 70000 > 60000
2     Henry   80000     4            4     Max     90000     ✗ 80000 < 90000

结果：Joe
```

1. **理解自连接**：
   - 自连接是 SQL 中非常重要的技巧
   - 当需要比较同一张表中不同行的数据时使用
   - 别名是自连接的关键

2. **画图理解**：
   - 画出表的两份副本（员工表和经理表）
   - 画箭头连接 `managerId` 和 `id`
   - 标注哪些满足 `salary` 比较条件

3. **实践练习**：
   - 尝试不同的 JOIN 类型（INNER, LEFT, RIGHT）
   - 思考：如何找出工资比经理低的员工？
   - 扩展：找出比自己所有下属工资都高的经理？

4. **性能优化**：
   - 在 `managerId` 和 `id` 列上建立索引
   - 比较 JOIN 和子查询的执行计划（EXPLAIN）
   - 理解数据库如何优化自连接

5. **扩展思考**：
   - 如果需要找出比经理高多少，如何修改查询？
   - 如果有多层管理关系（员工 -> 经理 -> 总经理），如何查询？
   - 如何找出一个员工的所有上级？（递归查询）

6. **面试要点**：
   - 能够快速识别需要自连接的场景
   - 清楚解释连接条件和筛选条件
   - 能够画图说明数据关系
   - 记住别名的重要性（e 和 m）
