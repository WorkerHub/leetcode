## 题目描述

表：`Customer`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| customer_id | int     |
| product_key | int     |
+-------------+---------+
```

该表可能包含重复的行。`customer_id` 不为空。`product_key` 是 `Product` 表的外键。

表：`Product`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| product_key | int     |
+-------------+---------+
```

`product_key` 是这张表的主键。

编写一个 SQL 查询，从 `Customer` 表中查询购买了 `Product` 表中所有产品的客户的 id。

返回结果表无顺序要求。

查询结果格式如下所示。

**示例 1：**

输入：

Customer 表：

```
+-------------+-------------+
| customer_id | product_key |
+-------------+-------------+
| 1           | 5           |
| 2           | 6           |
| 3           | 5           |
| 3           | 6           |
| 1           | 6           |
+-------------+-------------+
```

Product 表：

```
+-------------+
| product_key |
+-------------+
| 5           |
| 6           |
+-------------+
```

输出：

```
+-------------+
| customer_id |
+-------------+
| 1           |
| 3           |
+-------------+
```

解释：

购买了所有产品（5 和 6）的客户的 id 是 1 和 3。

## 解题思路

这道题的核心是找出购买了"所有产品"的客户。关键思路如下：

1. **分组统计**：按照 `customer_id` 对 `Customer` 表进行分组，统计每个客户购买的不同产品数量
2. **全量对比**：计算 `Product` 表中的总产品数量
3. **筛选条件**：使用 `HAVING` 子句筛选出购买产品数量等于总产品数量的客户

**核心观察：**
- 如果一个客户购买了所有产品，那么他购买的不同产品的数量应该等于产品表中的总产品数量
- 需要使用 `DISTINCT` 去重，因为 `Customer` 表可能有重复记录
- 使用 `GROUP BY` 和 `HAVING` 子句可以高效地完成分组筛选

## SQL 代码实现

### 方法一：GROUP BY + HAVING + 子查询（推荐）

```sql
SELECT customer_id
FROM Customer
GROUP BY customer_id
HAVING COUNT(DISTINCT product_key) = (
    SELECT COUNT(*) 
    FROM Product
)
```

**代码说明：**
- `GROUP BY customer_id`：按客户 ID 分组
- `COUNT(DISTINCT product_key)`：统计每个客户购买的不同产品数量（去重）
- 子查询 `SELECT COUNT(*) FROM Product`：计算产品表中的总产品数
- `HAVING` 子句：筛选出购买产品数量等于总产品数的客户

### 方法二：使用变量存储产品总数

```sql
SELECT customer_id
FROM Customer
GROUP BY customer_id
HAVING COUNT(DISTINCT product_key) = (
    SELECT COUNT(DISTINCT product_key) 
    FROM Product
)
```

**代码说明：**
- 这个方法与方法一类似，但在子查询中也使用了 `DISTINCT`
- 虽然 `Product` 表的 `product_key` 是主键（已去重），但这样写更具通用性
- 如果 `Product` 表没有主键约束，这种写法更安全

### 方法三：使用 JOIN + GROUP BY

```sql
SELECT DISTINCT c.customer_id
FROM Customer c
WHERE NOT EXISTS (
    SELECT p.product_key
    FROM Product p
    WHERE NOT EXISTS (
        SELECT 1
        FROM Customer c2
        WHERE c2.customer_id = c.customer_id
        AND c2.product_key = p.product_key
    )
)
```

**代码说明：**
- 使用双重 `NOT EXISTS` 实现除法运算
- 外层 `NOT EXISTS`：不存在某个产品
- 内层 `NOT EXISTS`：该客户没有购买该产品
- 逻辑：找出"不存在任何一个产品是该客户没购买的"的客户

## 复杂度分析

### SQL 方法一（推荐）

**时间复杂度：** O(n + m)
- n 是 `Customer` 表的行数
- m 是 `Product` 表的行数
- 需要扫描 `Customer` 表进行分组：O(n)
- 需要扫描 `Product` 表计算总数：O(m)

**空间复杂度：** O(k)
- k 是不同客户的数量
- 需要存储分组结果

### SQL 方法三（NOT EXISTS）

**时间复杂度：** O(n × m × k)
- 最坏情况下需要多次嵌套扫描
- 效率较低，不推荐

### Python Pandas 方法

**时间复杂度：** O(n + m)
- 分组操作：O(n)
- 计算产品总数：O(m)

**空间复杂度：** O(k + m)
- 存储分组结果和产品集合

## 关键点总结

1. **使用 COUNT(DISTINCT) 去重**：`Customer` 表可能有重复记录，必须使用 `DISTINCT` 统计不同产品数量
2. **HAVING 子句筛选分组结果**：`WHERE` 子句在分组前过滤，`HAVING` 子句在分组后过滤
3. **子查询计算总数**：在 `HAVING` 子句中使用子查询获取产品总数，实现动态对比
4. **除法运算的 SQL 实现**：这是关系代数中"除法"运算的典型应用场景
5. **性能优化**：方法一的 `GROUP BY + HAVING` 方案是最优解，避免使用多重嵌套子查询

## 易错点

1. **忘记使用 DISTINCT**
   ```sql
   -- 错误：没有去重，可能因为重复购买记录导致结果错误
   SELECT customer_id
   FROM Customer
   GROUP BY customer_id
   HAVING COUNT(product_key) = (SELECT COUNT(*) FROM Product)
   ```
   
2. **WHERE 和 HAVING 混淆**
   ```sql
   -- 错误：WHERE 不能用于聚合函数
   SELECT customer_id
   FROM Customer
   WHERE COUNT(DISTINCT product_key) = (SELECT COUNT(*) FROM Product)
   GROUP BY customer_id
   ```

3. **子查询位置错误**
   ```sql
   -- 错误：子查询应该在 HAVING 子句中
   SELECT customer_id
   FROM Customer
   WHERE customer_id IN (
       SELECT customer_id
       FROM Customer
       GROUP BY customer_id
   )
   ```

4. **忽略空值处理**
   - 题目说明 `customer_id` 不为空，但在实际应用中需要注意空值的影响
   - `COUNT(*)` 会计算包括 NULL 的所有行，`COUNT(column)` 不计算 NULL

## 学习建议

**面向新手的学习路径：**

1. **掌握基础概念**
   - 理解 `GROUP BY` 的作用：将数据按某个字段分组
   - 理解聚合函数：`COUNT()`, `SUM()`, `AVG()`, `MAX()`, `MIN()`
   - 区分 `WHERE` 和 `HAVING`：前者在分组前过滤，后者在分组后过滤

2. **理解 DISTINCT 的重要性**
   - `COUNT(*)` vs `COUNT(column)` vs `COUNT(DISTINCT column)`
   - 在有重复数据的场景中，`DISTINCT` 是必需的

3. **子查询的应用**
   - 标量子查询（返回单个值）可以用在 `SELECT`、`WHERE`、`HAVING` 中
   - 本题中子查询用于动态获取产品总数

4. **关系代数的除法运算**
   - 本题是典型的"除法"场景：找出满足"所有条件"的记录
   - SQL 中没有直接的除法运算符，需要通过 `GROUP BY + HAVING` 或 `NOT EXISTS` 实现

5. **实践建议**
   - 先在纸上画出表格，手动模拟查询过程
   - 使用 SQL 在线工具（如 SQLFiddle、DB Fiddle）测试代码
   - 尝试修改数据，观察不同场景下的查询结果
   - 对比 SQL 和 Pandas 两种实现方式，理解数据处理的共通性

6. **进阶方向**
   - 学习窗口函数（Window Functions）处理更复杂的分组统计
   - 研究查询性能优化：索引、执行计划分析
   - 探索不同数据库（MySQL、PostgreSQL、SQL Server）的语法差异
