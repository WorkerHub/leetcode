## 题目描述

表：`Activity`

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| player_id    | int     |
| device_id    | int     |
| event_date   | date    |
| games_played | int     |
+--------------+---------+
```

`(player_id, event_date)` 是此表的主键。

这张表显示了某些游戏玩家的活动情况。每一行是一个玩家的记录，他在某一天使用某个设备登录并玩了若干游戏（可能为 0）。

编写一个 SQL 查询，报告每个安装日期、当日安装游戏的玩家数量、以及第一日留存率（Day 1 Retention）。

定义：
- 玩家的安装日期（install date）：该玩家第一次登录的日期
- 第一日留存率（Day 1 Retention）：安装日期为 X 的玩家中，在 X+1 日也登录的玩家数量 / 安装日期为 X 的玩家总数，结果保留两位小数

返回结果表无顺序要求。

查询结果格式如下例所示。

**示例 1：**

输入：

Activity 表：
```
+-----------+-----------+------------+--------------+
| player_id | device_id | event_date | games_played |
+-----------+-----------+------------+--------------+
| 1         | 2         | 2016-03-01 | 5            |
| 1         | 2         | 2016-03-02 | 6            |
| 2         | 3         | 2017-06-25 | 1            |
| 3         | 1         | 2016-03-01 | 0            |
| 3         | 4         | 2016-07-03 | 5            |
+-----------+-----------+------------+--------------+
```

输出：
```
+------------+----------+----------------+
| install_dt | installs | Day1_retention |
+------------+----------+----------------+
| 2016-03-01 | 2        | 0.50           |
| 2017-06-25 | 1        | 0.00           |
+------------+----------+----------------+
```

解释：
- 玩家 1 和 3 在 2016-03-01 安装了游戏，但只有玩家 1 在 2016-03-02 回来登录了，所以第一日留存率是 1/2 = 0.50
- 玩家 2 在 2017-06-25 安装了游戏，但在 2017-06-26 没有回来，所以留存率是 0/1 = 0.00

## 解题思路

这道题的核心是计算"第一日留存率"，需要分三步处理：

1. **找出每个玩家的安装日期（首次登录日期）**
   - 使用 `MIN(event_date)` 按玩家分组

2. **判断玩家是否在次日回归**
   - 将原表与安装日期表进行 JOIN
   - 检查是否存在 `event_date = install_date + 1` 的记录

3. **按安装日期聚合统计**
   - 统计每个安装日期的总安装人数
   - 统计次日回归的人数
   - 计算留存率并保留两位小数

**关键观察：**
- 需要自连接或使用子查询来获取首次登录日期
- 使用 `DATE_ADD` 或 `DATEDIFF` 来判断是否是次日
- 使用 `SUM(CASE WHEN...)` 或 `COUNT(DISTINCT CASE WHEN...)` 来计算回归人数
- 使用 `ROUND(..., 2)` 保留两位小数

## SQL 代码实现

### 方法一：使用子查询 + LEFT JOIN（推荐）

```sql
SELECT 
    a.install_dt,
    COUNT(DISTINCT a.player_id) AS installs,
    ROUND(
        COUNT(DISTINCT b.player_id) / COUNT(DISTINCT a.player_id),
        2
    ) AS Day1_retention
FROM (
    -- 获取每个玩家的安装日期
    SELECT 
        player_id,
        MIN(event_date) AS install_dt
    FROM Activity
    GROUP BY player_id
) a
LEFT JOIN Activity b
    ON a.player_id = b.player_id
    AND DATEDIFF(b.event_date, a.install_dt) = 1  -- 次日登录
GROUP BY a.install_dt;
```

### 方法二：使用窗口函数（简化版）

```sql
WITH FirstLogin AS (
    SELECT 
        player_id,
        MIN(event_date) AS install_dt
    FROM Activity
    GROUP BY player_id
),
NextDayLogin AS (
    SELECT DISTINCT
        f.install_dt,
        f.player_id
    FROM FirstLogin f
    INNER JOIN Activity a
        ON f.player_id = a.player_id
        AND DATE_ADD(f.install_dt, INTERVAL 1 DAY) = a.event_date
)
SELECT 
    f.install_dt,
    COUNT(DISTINCT f.player_id) AS installs,
    ROUND(
        IFNULL(COUNT(DISTINCT n.player_id) / COUNT(DISTINCT f.player_id), 0),
        2
    ) AS Day1_retention
FROM FirstLogin f
LEFT JOIN NextDayLogin n
    ON f.install_dt = n.install_dt
GROUP BY f.install_dt;
```

### 方法三：使用 SUM + CASE WHEN

```sql
SELECT 
    install_dt,
    COUNT(player_id) AS installs,
    ROUND(
        SUM(CASE WHEN next_day_login = 1 THEN 1 ELSE 0 END) / COUNT(player_id),
        2
    ) AS Day1_retention
FROM (
    SELECT 
        a.player_id,
        MIN(a.event_date) AS install_dt,
        MAX(CASE 
            WHEN DATEDIFF(a.event_date, first_login.install_dt) = 1 
            THEN 1 
            ELSE 0 
        END) AS next_day_login
    FROM Activity a
    INNER JOIN (
        SELECT player_id, MIN(event_date) AS install_dt
        FROM Activity
        GROUP BY player_id
    ) first_login
        ON a.player_id = first_login.player_id
    GROUP BY a.player_id
) player_retention
GROUP BY install_dt;
```

## 复杂度分析

### SQL 方案

**时间复杂度：** O(n log n)
- 子查询找出首次登录：O(n log n)（分组操作）
- JOIN 操作：O(n)
- 最终分组聚合：O(n)
- 总体：O(n log n)

**空间复杂度：** O(n)
- 需要存储中间结果表（首次登录表）

### Python Pandas 方案

**时间复杂度：** O(n log n)
- groupby 操作：O(n log n)
- merge 操作：O(n)
- 日期计算：O(n)

**空间复杂度：** O(n)
- 需要创建多个中间 DataFrame

其中 n 为 Activity 表的记录数。

## 关键点总结

1. **理解"首次登录日期"概念**：每个玩家可能有多条记录，需要用 MIN(event_date) 找到最早的
2. **次日判断方法**：使用 DATEDIFF = 1 或 DATE_ADD(..., INTERVAL 1 DAY)
3. **留存率计算**：分子是次日回归人数，分母是安装人数
4. **避免除零错误**：虽然本题保证有数据，但实际应用中可以使用 IFNULL 或 COALESCE
5. **保留小数位数**：使用 ROUND(..., 2)

## 易错点

1. **混淆"首次登录"和"所有登录"**
   - 错误：直接使用 event_date 而不先找出 install_dt
   - 正确：必须先通过 MIN(event_date) 找出每个玩家的安装日期

2. **次日判断逻辑错误**
   - 错误：使用 `event_date > install_dt`（这会包含所有后续日期）
   - 正确：必须精确判断 `DATEDIFF(event_date, install_dt) = 1`

3. **重复计数问题**
   - 错误：如果玩家在次日登录多次，可能被重复计数
   - 正确：使用 COUNT(DISTINCT player_id) 或先去重

4. **除法精度问题**
   - 错误：整数除法可能得到 0
   - 正确：确保至少一个操作数是浮点数，或使用 CAST

5. **Pandas 中日期类型处理**
   - 确保 event_date 列是 datetime 类型
   - 使用 pd.Timedelta 进行日期加减
