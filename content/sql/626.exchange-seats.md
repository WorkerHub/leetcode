## 题目描述

编写一个 SQL 查询来交换每两个连续的学生的座位号。如果学生人数是奇数，则最后一个学生的座位号不变。

表：`Seat`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| student     | varchar |
+-------------+---------+
id 是该表的主键列。
该表的每一行表示学生的姓名和座位号。
id 是一个连续递增的数字。
```

**示例 1：**

```
输入：
Seat 表：
+----+---------+
| id | student |
+----+---------+
| 1  | Abbot   |
| 2  | Doris   |
| 3  | Emerson |
| 4  | Green   |
| 5  | Jeames  |
+----+---------+

输出：
+----+---------+
| id | student |
+----+---------+
| 1  | Doris   |
| 2  | Abbot   |
| 3  | Green   |
| 4  | Emerson |
| 5  | Jeames  |
+----+---------+

解释：
请注意，如果学生人数为奇数，则不需要改变最后一个学生的座位。
- id=1 和 id=2 的学生互换
- id=3 和 id=4 的学生互换
- id=5 保持不变（奇数位）
```

## 解题思路

这道题的核心是交换相邻的座位号，规则如下：
- 奇数 id 的学生应该和 id+1 的学生交换（如果存在）
- 偶数 id 的学生应该和 id-1 的学生交换
- 如果是最后一个学生且 id 为奇数，保持不变

**解题策略：**

1. **使用 CASE WHEN**：根据 id 的奇偶性和是否是最后一个来决定新的 id
2. **判断奇偶**：使用 `MOD(id, 2)` 或 `id % 2`
3. **处理边界**：需要知道总人数，判断最后一个奇数位置

**核心逻辑：**
- 奇数 id 且不是最后一个：id + 1
- 偶数 id：id - 1
- 奇数 id 且是最后一个：id 不变

## SQL 解法实现

### 方法一：使用 CASE WHEN（推荐）

```sql
SELECT
    CASE
        -- 奇数 id 且不是最后一个：加 1
        WHEN MOD(id, 2) = 1 AND id != (SELECT COUNT(*) FROM Seat) 
            THEN id + 1
        -- 偶数 id：减 1
        WHEN MOD(id, 2) = 0 
            THEN id - 1
        -- 其他情况（最后一个奇数）：保持不变
        ELSE id
    END AS id,
    student
FROM Seat
ORDER BY id;
```

**解释：**
1. 第一个 WHEN：处理奇数位置且不是最后一个的情况，id 加 1
2. 第二个 WHEN：处理偶数位置，id 减 1
3. ELSE：处理最后一个奇数位置，id 不变
4. ORDER BY：确保结果按 id 排序

### 方法二：使用位运算优化

```sql
SELECT
    CASE
        WHEN MOD(id, 2) = 1 AND id = (SELECT COUNT(*) FROM Seat) 
            THEN id
        WHEN MOD(id, 2) = 1 
            THEN id + 1
        ELSE id - 1
    END AS id,
    student
FROM Seat
ORDER BY id;
```

### 方法三：使用 XOR 位运算（MySQL）

```sql
SELECT
    IF(id < (SELECT COUNT(*) FROM Seat),
       IF(MOD(id, 2) = 1, id + 1, id - 1),
       IF(MOD(id, 2) = 1, id, id - 1)
    ) AS id,
    student
FROM Seat
ORDER BY id;
```

### 方法四：使用子查询避免重复计算

```sql
SELECT
    CASE
        WHEN MOD(id, 2) = 1 AND id != cnt THEN id + 1
        WHEN MOD(id, 2) = 0 THEN id - 1
        ELSE id
    END AS id,
    student
FROM Seat, (SELECT COUNT(*) AS cnt FROM Seat) AS total
ORDER BY id;
```

**优势：** 避免在每一行都计算总数，使用笛卡尔积获取总数

### 方法五：使用 COALESCE 和自连接

```sql
SELECT
    s1.id,
    COALESCE(s2.student, s1.student) AS student
FROM Seat s1
LEFT JOIN Seat s2 ON 
    (MOD(s1.id, 2) = 1 AND s2.id = s1.id + 1) OR
    (MOD(s1.id, 2) = 0 AND s2.id = s1.id - 1)
ORDER BY s1.id;
```

**解释：**
- 自连接找到应该交换的学生
- COALESCE 处理最后一个奇数位置（找不到配对）

## 复杂度分析

**SQL 方法一至四：**
- 时间复杂度：O(n log n)，主要是排序的复杂度
- 空间复杂度：O(n)，结果集的大小

**SQL 方法五（自连接）：**
- 时间复杂度：O(n)，连接操作
- 空间复杂度：O(n)

**Python 实现：**
- 时间复杂度：O(n log n)，排序主导
- 空间复杂度：O(n)

## 关键点总结

1. **CASE WHEN 顺序重要**：先判断特殊情况（最后一个奇数），再判断一般情况
2. **MOD 函数**：判断奇偶性，`MOD(id, 2) = 1` 表示奇数
3. **获取总数**：使用子查询 `(SELECT COUNT(*) FROM Seat)` 获取总人数
4. **ORDER BY 必需**：交换后需要重新排序
5. **优化子查询**：使用笛卡尔积避免重复计算总数

## 易错点

1. **忘记处理最后一个奇数**：最后一个学生如果是奇数位置，不应该交换
2. **排序问题**：交换后必须按 id 排序，否则结果错误
3. **重复计算总数**：每行都计算总数会影响性能，应该用子查询或变量
4. **逻辑顺序**：CASE WHEN 的顺序很重要，应该先处理特殊情况
5. **边界情况**：只有一个学生时，不应该做任何交换
