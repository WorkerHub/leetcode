## 题目描述

表：`Tweets`

```
+----------------+---------+
| Column Name    | Type    |
+----------------+---------+
| tweet_id       | int     |
| content        | varchar |
+----------------+---------+
tweet_id 是这个表的主键。
这个表包含某社交媒体 App 中所有的推文。
```

写一个 SQL 查询，找出 `content` 字符数**严格大于 15** 的推文的 `tweet_id`。

以**任意顺序**返回结果。

**示例：**
```
输入：
Tweets 表：
+----------+----------------------------------+
| tweet_id | content                          |
+----------+----------------------------------+
| 1        | Vote for Biden                   |
| 2        | Let us make America great again! |
+----------+----------------------------------+

输出：
+----------+
| tweet_id |
+----------+
| 2        |
+----------+
解释：tweet_id 为 1 的 content 长度为 14，tweet_id 为 2 的 content 长度为 33
```

## 解题思路

使用 `LENGTH()` 或 `CHAR_LENGTH()` 函数计算字符串长度，筛选长度大于 15 的记录。

注意：
- `LENGTH()` 在 MySQL 中返回字节数（对于多字节字符如中文，结果可能不同）
- `CHAR_LENGTH()` 返回字符数，更加准确，推荐使用

## 代码实现

### 方法一：使用 CHAR_LENGTH（推荐）

```sql
SELECT tweet_id
FROM Tweets
WHERE CHAR_LENGTH(content) > 15;
```

### 方法二：使用 LENGTH

```sql
-- 对于纯 ASCII 字符，LENGTH 和 CHAR_LENGTH 等价
SELECT tweet_id
FROM Tweets
WHERE LENGTH(content) > 15;
```

## 复杂度分析

- **时间复杂度**：O(n)，需要扫描所有记录并计算每条记录的内容长度
- **空间复杂度**：O(1)，只需要常量额外空间

## 关键点总结

1. `CHAR_LENGTH()` 计算字符个数，`LENGTH()` 计算字节数
2. 对于纯英文内容，两者结果相同；涉及多字节字符时应使用 `CHAR_LENGTH()`
3. 条件是"严格大于 15"，使用 `> 15` 而非 `>= 15`

## 易错点

1. 混淆 `LENGTH()` 和 `CHAR_LENGTH()`：对于多字节字符（如中文、emoji），`LENGTH()` 会返回字节数而非字符数
2. 条件边界：题目要求严格大于 15，不包含等于 15 的情况
