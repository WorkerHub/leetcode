## 题目描述

表：`Employee`

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| id           | int     |
| name         | varchar |
| salary       | int     |
| departmentId | int     |
+--------------+---------+
```

id 是这个表的主键。
departmentId 是 Department 表中 ID 的外键。
该表的每一行都表示员工的 ID、姓名、工资和所属部门的 ID。

表：`Department`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| name        | varchar |
+-------------+---------+
```

id 是这个表的主键。
该表的每一行都表示一个部门的 ID 及其名称。

编写一个 SQL 查询，找出每个部门工资最高的员工。

按任意顺序返回结果表。

查询结果格式如下例所示。

**示例 1：**

```
输入：
Employee 表：
+----+-------+--------+--------------+
| id | name  | salary | departmentId |
+----+-------+--------+--------------+
| 1  | Joe   | 70000  | 1            |
| 2  | Jim   | 90000  | 1            |
| 3  | Henry | 80000  | 2            |
| 4  | Sam   | 60000  | 2            |
| 5  | Max   | 90000  | 1            |
+----+-------+--------+--------------+

Department 表：
+----+-------+
| id | name  |
+----+-------+
| 1  | IT    |
| 2  | Sales |
+----+-------+

输出：
+------------+----------+--------+
| Department | Employee | Salary |
+------------+----------+--------+
| IT         | Jim      | 90000  |
| IT         | Max      | 90000  |
| Sales      | Henry    | 80000  |
+------------+----------+--------+

解释：
Max 和 Jim 在 IT 部门的工资都是最高的，Henry 在 Sales 部门的工资最高。
```

## 解题思路

这道题的关键是 **分组求最大值**，有两个难点：

1. **找出每个部门的最高工资**：使用 GROUP BY + MAX
2. **找出拿最高工资的员工**：不能直接在分组中获取员工姓名
3. **处理并列情况**：一个部门可能有多个员工工资最高

### 核心思路

**方法选择：**
- **子查询**：先找出每个部门最高工资，再找对应员工
- **窗口函数**：使用 RANK/DENSE_RANK 标记最高工资
- **自连接**：将最高工资表与员工表连接

## SQL 代码实现

### 方法一：子查询 + JOIN（推荐）

```sql
SELECT 
    d.name AS Department,
    e.name AS Employee,
    e.salary AS Salary
FROM 
    Employee e
JOIN 
    Department d ON e.departmentId = d.id
WHERE 
    (e.departmentId, e.salary) IN (
        SELECT departmentId, MAX(salary)
        FROM Employee
        GROUP BY departmentId
    );
```

**代码解释：**
1. 子查询：找出每个部门的最高工资
2. `(departmentId, salary) IN (...)`：多列匹配，找出部门和工资都匹配的员工
3. `JOIN Department`：获取部门名称
4. 自动处理并列情况（多个员工同时拿最高工资）

### 方法二：窗口函数 DENSE_RANK

```sql
SELECT 
    Department,
    Employee,
    Salary
FROM (
    SELECT 
        d.name AS Department,
        e.name AS Employee,
        e.salary AS Salary,
        DENSE_RANK() OVER (PARTITION BY e.departmentId ORDER BY e.salary DESC) AS rk
    FROM 
        Employee e
    JOIN 
        Department d ON e.departmentId = d.id
) AS ranked
WHERE rk = 1;
```

**代码解释：**
1. `DENSE_RANK() OVER (PARTITION BY departmentId ORDER BY salary DESC)`：
   - 按部门分组，按工资降序排名
   - 相同工资排名相同
2. `WHERE rk = 1`：筛选排名第一的员工
3. 自动处理并列（相同工资排名都是 1）

### 方法三：多次子查询

```sql
SELECT 
    d.name AS Department,
    e.name AS Employee,
    e.salary AS Salary
FROM 
    Employee e
JOIN 
    Department d ON e.departmentId = d.id
WHERE 
    e.salary = (
        SELECT MAX(salary)
        FROM Employee
        WHERE departmentId = e.departmentId
    );
```

**代码解释：**
1. 对于每个员工，子查询找出其部门的最高工资
2. 比较该员工的工资是否等于最高工资
3. 相关子查询（依赖外层查询的 `e.departmentId`）

### 方法四：自连接最高工资表

```sql
SELECT 
    d.name AS Department,
    e.name AS Employee,
    e.salary AS Salary
FROM 
    Employee e
JOIN 
    (SELECT departmentId, MAX(salary) AS max_salary
     FROM Employee
     GROUP BY departmentId) AS max_sal
    ON e.departmentId = max_sal.departmentId 
    AND e.salary = max_sal.max_salary
JOIN 
    Department d ON e.departmentId = d.id;
```

**代码解释：**
1. 子查询：创建每个部门最高工资的临时表
2. 将员工表与这个临时表连接
3. 连接条件：部门相同且工资等于最高工资
4. 再连接部门表获取部门名称

## 复杂度分析

**方法一（子查询 + IN）：**
- 时间复杂度：O(n)，一次分组 + 一次筛选
- 空间复杂度：O(d)，d 是部门数
- 优点：简洁高效

**方法二（窗口函数）：**
- 时间复杂度：O(n log n)，分区排序
- 空间复杂度：O(n)，存储排名
- 优点：逻辑清晰，易于扩展

**方法三（相关子查询）：**
- 时间复杂度：O(n²)，每个员工都执行一次子查询
- 空间复杂度：O(1)
- 缺点：性能较差（但有索引时会优化）

**方法四（自连接）：**
- 时间复杂度：O(n)
- 空间复杂度：O(d)
- 优点：逻辑直观

## 关键点总结

1. **多列 IN**：`(col1, col2) IN (SELECT col1, col2 ...)`
2. **窗口函数分区**：`PARTITION BY` 实现分组排名
3. **处理并列**：所有方法都能自动处理并列情况
4. **列名顺序**：输出列顺序必须是 Department, Employee, Salary
5. **JOIN 顺序**：先连接员工和部门，便于后续筛选

## 易错点

1. **GROUP BY 后直接 SELECT 员工姓名**
   ```sql
   -- 错误：GROUP BY 后不能直接获取非分组列的具体值
   SELECT 
       departmentId, 
       name,  -- 错误！name 不在 GROUP BY 中
       MAX(salary)
   FROM Employee
   GROUP BY departmentId;
   
   -- MySQL 5.7+ 默认会报错：ONLY_FULL_GROUP_BY
   ```

2. **单列 IN 匹配**
   ```sql
   -- 错误：只匹配工资，不匹配部门（可能匹配到其他部门的员工）
   WHERE salary IN (
       SELECT MAX(salary)
       FROM Employee
       GROUP BY departmentId
   )
   
   -- 正确：同时匹配部门和工资
   WHERE (departmentId, salary) IN (
       SELECT departmentId, MAX(salary)
       FROM Employee
       GROUP BY departmentId
   )
   ```

3. **RANK vs DENSE_RANK**
   ```sql
   -- 错误：使用 RANK 会产生间隙
   -- 例如工资：90000, 90000, 80000
   -- RANK 排名：1, 1, 3（跳过 2）
   RANK() OVER (...)
   
   -- 正确：DENSE_RANK 无间隙
   -- 例如工资：90000, 90000, 80000
   -- DENSE_RANK 排名：1, 1, 2
   DENSE_RANK() OVER (...)
   
   -- 本题两者都可以（因为只取 rk = 1）
   ```

4. **忘记连接 Department 表**
   ```sql
   -- 错误：只有 departmentId，没有部门名称
   SELECT 
       e.departmentId,  -- 错误！需要部门名称
       e.name,
       e.salary
   FROM Employee e ...
   
   -- 正确：JOIN Department 表
   JOIN Department d ON e.departmentId = d.id
   SELECT d.name AS Department ...
   ```

5. **列名或顺序错误**
   ```sql
   -- 错误：列名或顺序不对
   SELECT name, salary, department ...
   
   -- 正确：
   SELECT Department, Employee, Salary
   ```

## 图解示例

以示例数据为例：

```
Employee 表按部门分组：
部门 1 (IT):
  id=1  Joe    70000
  id=2  Jim    90000  <- 最高
  id=5  Max    90000  <- 最高（并列）

部门 2 (Sales):
  id=3  Henry  80000  <- 最高
  id=4  Sam    60000

方法一子查询结果：
departmentId  MAX(salary)
1             90000
2             80000

匹配逻辑：
(1, 70000) IN ((1, 90000), (2, 80000))  -> FALSE
(1, 90000) IN ((1, 90000), (2, 80000))  -> TRUE  ✓ Jim
(2, 80000) IN ((1, 90000), (2, 80000))  -> TRUE  ✓ Henry
(2, 60000) IN ((1, 90000), (2, 80000))  -> FALSE
(1, 90000) IN ((1, 90000), (2, 80000))  -> TRUE  ✓ Max

最终结果：
Department  Employee  Salary
IT          Jim       90000
IT          Max       90000
Sales       Henry     80000
```

   - 不能直接获取非分组列的具体值
   - 理解为什么需要子查询或窗口函数

2. **掌握多列匹配**：
   - `(col1, col2) IN (SELECT col1, col2 ...)`
   - 这是解决"分组后找明细"问题的关键技巧
   - 练习不同场景的应用

3. **窗口函数的威力**：
   - `PARTITION BY` = 分组
   - `ORDER BY` = 排序
   - RANK/DENSE_RANK/ROW_NUMBER 的区别
   - 窗口函数可以保留原始行，不像 GROUP BY 会聚合

4. **实践练习**：
