## 题目描述

表：`Delivery`

```
+-----------------------------+---------+
| Column Name                 | Type    |
+-----------------------------+---------+
| delivery_id                 | int     |
| customer_id                 | int     |
| order_date                  | date    |
| customer_pref_delivery_date | date    |
+-----------------------------+---------+
delivery_id 是该表的主键（具有唯一值的列）。
该表保存顾客的食品配送信息，其中顾客在某日下了订单，并指定了一个期望的配送日期（和下单日期相同或者在那之后）。
```

如果顾客期望的配送日期和下单日期相同，则该订单称为「即时订单」，否则称为「计划订单」。

「首次订单」是顾客最早创建的订单。我们保证一个顾客只会有一个「首次订单」。

编写解决方案以获得即时订单在所有顾客的首次订单中的比例，保留两位小数。

**示例 1：**

输入：
Delivery 表：
```
+-------------+-------------+------------+-----------------------------+
| delivery_id | customer_id | order_date | customer_pref_delivery_date |
+-------------+-------------+------------+-----------------------------+
| 1           | 1           | 2019-08-01 | 2019-08-02                  |
| 2           | 2           | 2019-08-02 | 2019-08-02                  |
| 3           | 1           | 2019-08-11 | 2019-08-12                  |
| 4           | 3           | 2019-08-24 | 2019-08-24                  |
| 5           | 3           | 2019-08-21 | 2019-08-22                  |
| 6           | 2           | 2019-08-11 | 2019-08-13                  |
| 7           | 4           | 2019-08-09 | 2019-08-09                  |
+-------------+-------------+------------+-----------------------------+
```

输出：
```
+----------------------+
| immediate_percentage |
+----------------------+
| 50.00                |
+----------------------+
```

解释：
- 顾客 1 的首次订单是订单 1（2019-08-01），不是即时订单
- 顾客 2 的首次订单是订单 2（2019-08-02），是即时订单
- 顾客 3 的首次订单是订单 5（2019-08-21），不是即时订单
- 顾客 4 的首次订单是订单 7（2019-08-09），是即时订单
- 因此，在 4 个顾客中，有 2 个顾客的首次订单是即时订单，比例为 2/4 = 50.00%

## 解题思路

这道题相比 1173 题增加了难度，需要先找到每个顾客的首次订单，再计算即时订单的比例。

核心步骤：

1. **找出每个顾客的首次订单日期**
   - 使用 `MIN(order_date)` 按 customer_id 分组
   - 或使用窗口函数 `RANK()` / `ROW_NUMBER()`

2. **筛选出首次订单的记录**
   - 将原表与首次订单日期进行关联
   - 或使用窗口函数标记首次订单

3. **计算即时订单比例**
   - 判断 `order_date = customer_pref_delivery_date`
   - 计算比例并保留两位小数

关键观察：
- 题目保证每个顾客只有一个首次订单（order_date 最小的订单唯一）
- 需要过滤掉非首次订单，只统计首次订单的即时率
- 可以使用子查询、JOIN 或窗口函数多种方法实现

## SQL 代码实现

### 方法一：使用子查询 + JOIN（推荐）

```sql
SELECT 
    ROUND(
        SUM(CASE WHEN d.order_date = d.customer_pref_delivery_date THEN 1 ELSE 0 END) * 100.0 / COUNT(*),
        2
    ) AS immediate_percentage
FROM Delivery d
INNER JOIN (
    SELECT customer_id, MIN(order_date) AS first_order_date
    FROM Delivery
    GROUP BY customer_id
) first_orders
ON d.customer_id = first_orders.customer_id 
   AND d.order_date = first_orders.first_order_date;
```

**代码说明：**
- 子查询找出每个顾客的首次订单日期（最早的 order_date）
- JOIN 条件确保只保留首次订单的记录
- 外层计算即时订单比例

### 方法二：使用窗口函数 RANK()

```sql
SELECT 
    ROUND(
        SUM(CASE WHEN order_date = customer_pref_delivery_date THEN 1 ELSE 0 END) * 100.0 / COUNT(*),
        2
    ) AS immediate_percentage
FROM (
    SELECT 
        *,
        RANK() OVER (PARTITION BY customer_id ORDER BY order_date) AS order_rank
    FROM Delivery
) ranked
WHERE order_rank = 1;
```

**代码说明：**
- `RANK() OVER (PARTITION BY customer_id ORDER BY order_date)`：为每个顾客的订单按日期排序
- `WHERE order_rank = 1`：只保留首次订单（排名第一的订单）
- 外层计算即时订单比例

### 方法三：使用 IN 子查询

```sql
SELECT 
    ROUND(
        SUM(CASE WHEN order_date = customer_pref_delivery_date THEN 1 ELSE 0 END) * 100.0 / COUNT(*),
        2
    ) AS immediate_percentage
FROM Delivery
WHERE (customer_id, order_date) IN (
    SELECT customer_id, MIN(order_date)
    FROM Delivery
    GROUP BY customer_id
);
```

**代码说明：**
- 使用元组比较 `(customer_id, order_date) IN (...)`
- 子查询返回每个顾客的首次订单日期
- 简洁但在某些数据库中性能可能较差

### 方法四：使用 AVG 简化计算

```sql
SELECT 
    ROUND(
        AVG(CASE WHEN order_date = customer_pref_delivery_date THEN 1 ELSE 0 END) * 100,
        2
    ) AS immediate_percentage
FROM Delivery
WHERE (customer_id, order_date) IN (
    SELECT customer_id, MIN(order_date)
    FROM Delivery
    GROUP BY customer_id
);
```

**代码说明：**
- 使用 AVG 替代 SUM / COUNT，代码更简洁
- 筛选逻辑与方法三相同

## 复杂度分析

### SQL 方案

**方法一（子查询 + JOIN）：**
- 时间复杂度：O(n log n)
  - GROUP BY 需要排序或哈希，复杂度 O(n log n)
  - JOIN 操作复杂度 O(n)
  - 总体 O(n log n)
- 空间复杂度：O(n)
  - 需要存储子查询结果（每个顾客一条记录）

**方法二（窗口函数）：**
- 时间复杂度：O(n log n)
  - RANK() 窗口函数需要分区内排序
- 空间复杂度：O(n)
  - 需要存储排名列

### Python Pandas 方案

**所有方法：**
- 时间复杂度：O(n log n)
  - groupby、sort_values 都需要排序
  - n 为订单总数
- 空间复杂度：O(m)
  - m 为顾客数量（首次订单记录数）
  - 通常 m << n

## 关键点总结

1. **理解题意**：只统计每个顾客的首次订单，不是所有订单
2. **找首次订单**：使用 MIN(order_date) 或窗口函数
3. **数据过滤**：确保只保留首次订单的记录
4. **比例计算**：首次订单中即时订单的占比
5. **多种方法**：子查询、JOIN、窗口函数各有优劣，根据数据库选择

## 易错点

1. **理解错题意**
   - 错误：计算所有订单的即时率（这是 1173 题）
   - 正确：只计算首次订单的即时率

2. **首次订单定义**
   - 必须是 order_date 最小的订单
   - 题目保证每个顾客只有一个首次订单（日期唯一）

3. **JOIN 条件不完整**
   - 错误：只用 `customer_id` 关联
   - 正确：需要同时匹配 `customer_id` 和 `order_date`

4. **窗口函数选择**
   - RANK() 和 ROW_NUMBER() 在本题中效果相同（因为题目保证唯一）
   - DENSE_RANK() 也可以使用
   - 但理解它们的区别很重要

5. **Pandas 中的索引问题**
   - 使用 idxmin() 后，需要用 loc[] 而不是 iloc[] 获取数据
   - merge 后可能产生重复列，需要注意列名

6. **性能陷阱**
   - IN 子查询在大数据集上可能很慢
   - JOIN 通常比 IN 更高效
   - 窗口函数在支持的数据库中性能较好

## 图解示例

假设有如下数据：

```
顾客1: 订单A(8-01) → 订单B(8-11)  首次=8-01
顾客2: 订单C(8-02) → 订单D(8-11)  首次=8-02
顾客3: 订单E(8-21) → 订单F(8-24)  首次=8-21
顾客4: 订单G(8-09)               首次=8-09
```

处理步骤：
1. 找出首次订单：A, C, E, G
2. 判断即时性：
   - A: 8-01 ≠ 8-02 → 非即时
   - C: 8-02 = 8-02 → 即时 ✓
   - E: 8-21 ≠ 8-22 → 非即时
   - G: 8-09 = 8-09 → 即时 ✓
3. 计算比例：2/4 = 50%
