## 题目描述

表：`Tree`

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| id          | int  |
| p_id        | int  |
+-------------+------+
```

`id` 是该表的主键列。
表的每一行包含树中节点的 id 及其父节点的 id 信息。
给定的结构总是一个有效的树。

树中每个节点属于以下三种类型之一：

- **"Leaf"**：如果该节点是叶子节点。
- **"Root"**：如果该节点是树的根节点。
- **"Inner"**：如果该节点既不是叶子节点也不是根节点。

编写一个 SQL 查询，报告树中每个节点的类型。

返回结果表**按 id 升序排列**。

查询结果格式如下例所示。

**示例 1：**

![](https://assets.leetcode.com/uploads/2021/10/22/tree1.jpg)

```
输入：
Tree 表：
+----+------+
| id | p_id |
+----+------+
| 1  | null |
| 2  | 1    |
| 3  | 1    |
| 4  | 2    |
| 5  | 2    |
+----+------+

输出：
+----+-------+
| id | type  |
+----+-------+
| 1  | Root  |
| 2  | Inner |
| 3  | Leaf  |
| 4  | Leaf  |
| 5  | Leaf  |
+----+-------+

解释：
节点 1 是根节点，因为它的父节点为 null，并且它有孩子节点 2 和 3。
节点 2 是内部节点，因为它有父节点 1 和孩子节点 4 和 5。
节点 3、4 和 5 是叶子节点，因为它们有父节点但没有孩子节点。
```

**示例 2：**

![](https://assets.leetcode.com/uploads/2021/10/22/tree2.jpg)

```
输入：
Tree 表：
+----+------+
| id | p_id |
+----+------+
| 1  | null |
+----+------+

输出：
+----+-------+
| id | type  |
+----+-------+
| 1  | Root  |
+----+-------+

解释：如果树中只有一个节点，那么该节点被视为根节点。
```

## 解题思路

这道题需要根据节点的特征判断其类型：

**节点类型判断规则：**

1. **Root（根节点）**：`p_id IS NULL`（没有父节点）
2. **Leaf（叶子节点）**：`p_id IS NOT NULL` 且不在任何节点的 `p_id` 中（有父节点但没有子节点）
3. **Inner（内部节点）**：`p_id IS NOT NULL` 且在某些节点的 `p_id` 中（既有父节点又有子节点）

**核心思路：**

使用 `CASE WHEN` 条件判断，关键是判断节点是否有子节点。

**方法对比：**

- **方法一**：使用子查询判断是否有子节点
- **方法二**：LEFT JOIN 自身，检查是否有子节点
- **方法三**：使用 IN 判断

## SQL 代码实现

### 方法一：CASE WHEN + 子查询（推荐）⭐

```sql
SELECT id,
    CASE
        WHEN p_id IS NULL THEN 'Root'
        WHEN id IN (SELECT p_id FROM Tree WHERE p_id IS NOT NULL) THEN 'Inner'
        ELSE 'Leaf'
    END AS type
FROM Tree
ORDER BY id;
```

### 方法二：CASE WHEN + EXISTS（更高效）⭐⭐

```sql
SELECT id,
    CASE
        WHEN p_id IS NULL THEN 'Root'
        WHEN EXISTS (SELECT 1 FROM Tree t2 WHERE t2.p_id = t1.id) THEN 'Inner'
        ELSE 'Leaf'
    END AS type
FROM Tree t1
ORDER BY id;
```

### 方法三：LEFT JOIN（经典方法）

```sql
SELECT DISTINCT t1.id,
    CASE
        WHEN t1.p_id IS NULL THEN 'Root'
        WHEN t2.id IS NOT NULL THEN 'Inner'
        ELSE 'Leaf'
    END AS type
FROM Tree t1
LEFT JOIN Tree t2 ON t1.id = t2.p_id
ORDER BY t1.id;
```

### 方法四：三个 UNION（最清晰）

```sql
-- 根节点
SELECT id, 'Root' AS type
FROM Tree
WHERE p_id IS NULL

UNION

-- 内部节点
SELECT DISTINCT t1.id, 'Inner' AS type
FROM Tree t1
JOIN Tree t2 ON t1.id = t2.p_id

UNION

-- 叶子节点
SELECT id, 'Leaf' AS type
FROM Tree
WHERE p_id IS NOT NULL
  AND id NOT IN (SELECT p_id FROM Tree WHERE p_id IS NOT NULL)

ORDER BY id;
```

### 方法五：使用 IF（MySQL 特有）

```sql
SELECT id,
    IF(p_id IS NULL, 'Root',
       IF(id IN (SELECT p_id FROM Tree), 'Inner', 'Leaf')
    ) AS type
FROM Tree
ORDER BY id;
```

## 复杂度分析

### 方法一（IN 子查询）
- **时间复杂度**：O(n²)，对每个节点检查是否在子查询结果中
- **空间复杂度**：O(n)，子查询结果

### 方法二（EXISTS）
- **时间复杂度**：O(n²)，但 EXISTS 遇到匹配即停止
- **空间复杂度**：O(1)
- **性能最佳**

### 方法三（LEFT JOIN）
- **时间复杂度**：O(n²)，自连接
- **空间复杂度**：O(n)

## 关键点总结

1. **根节点判断**：`p_id IS NULL`，最简单
2. **叶子节点判断**：有父节点但不是任何节点的父节点
3. **内部节点判断**：既有父节点又是其他节点的父节点
4. **CASE WHEN 顺序**：先判断 Root，再判断 Inner，最后是 Leaf
5. **EXISTS vs IN**：EXISTS 性能更好，尤其在大数据集上

## 易错点

1. **CASE WHEN 顺序错误**：
   ```sql
   -- ❌ 错误：先判断 Leaf，会把 Root 也识别为 Leaf
   CASE
       WHEN id NOT IN (...) THEN 'Leaf'
       WHEN p_id IS NULL THEN 'Root'
       ...
   END
   ```
   应该先判断 Root

2. **忘记处理 NULL**：
   ```sql
   -- ❌ 错误：IN 不能匹配 NULL
   WHERE id IN (SELECT p_id FROM Tree)
   -- 应该加 WHERE p_id IS NOT NULL
   ```

3. **LEFT JOIN 没有 DISTINCT**：
   ```sql
   -- ❌ 可能产生重复：一个节点有多个子节点时会重复
   SELECT t1.id, ...
   FROM Tree t1
   LEFT JOIN Tree t2 ON t1.id = t2.p_id
   -- 应该加 DISTINCT
   ```

4. **逻辑重叠**：
   ```sql
   -- ❌ 错误：Root 也会被判断为 Inner
   WHEN id IN (SELECT p_id FROM Tree) THEN 'Inner'
   -- 应该先排除 Root
   ```

## 学习建议

**新手学习路径：**

1. **理解树的基本概念**：
   - **根节点**：树的起点，没有父节点
   - **叶子节点**：树的末端，没有子节点
   - **内部节点**：中间节点，既有父又有子

2. **判断逻辑梳理**：
   ```
   判断流程：
   ├─ p_id IS NULL? 
   │  └─ YES → Root
   │  └─ NO → 继续判断
   │     ├─ 是否有子节点?
   │     │  └─ YES → Inner
   │     │  └─ NO → Leaf
   ```

3. **循序渐进**：
   - 第一步：找出所有根节点（p_id IS NULL）
   - 第二步：找出所有内部节点（有子节点）
   - 第三步：剩余的就是叶子节点

4. **推荐方法**：
   - 初学者：方法四（UNION），逻辑最清晰
   - 进阶：方法二（EXISTS），性能最好
   - 实际应用：方法一，代码简洁

5. **手动验证示例**：
   ```sql
   -- 示例1验证
   id=1: p_id=NULL → Root ✅
   id=2: p_id=1 (有父), 被{4,5}引用(有子) → Inner ✅
   id=3: p_id=1 (有父), 没被引用(无子) → Leaf ✅
   id=4: p_id=2 (有父), 没被引用(无子) → Leaf ✅
   id=5: p_id=2 (有父), 没被引用(无子) → Leaf ✅
   ```

**实战技巧：**

1. **CASE WHEN 的顺序很重要**：
   - 按照"排除法"：先判断特殊情况（Root），再判断中间情况（Inner），最后是默认情况（Leaf）

2. **判断"是否有子节点"的方法**：
   ```sql
   -- 方法A：IN
   id IN (SELECT p_id FROM Tree WHERE p_id IS NOT NULL)
   
   -- 方法B：EXISTS（推荐）
   EXISTS (SELECT 1 FROM Tree t2 WHERE t2.p_id = t1.id)
   
   -- 方法C：LEFT JOIN
   LEFT JOIN Tree t2 ON t1.id = t2.p_id
   WHERE t2.id IS NOT NULL
   ```

3. **优化技巧**：
   - 使用 `EXISTS` 代替 `IN`，性能更好
   - 子查询中使用 `SELECT 1` 而非 `SELECT *`
   - 在 `id` 和 `p_id` 上建立索引

- 如何查询每个节点的子孙数量？
- 如何找出某个节点到根节点的路径？
