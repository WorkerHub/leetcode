## 题目描述

表：`Person`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| email       | varchar |
+-------------+---------+
```

id 是这个表的主键。
表的每一行包含一个电子邮件。电子邮件不包含大写字母。

编写一个 SQL 查询来报告所有重复的电子邮件。注意可以以任意顺序返回结果表。

查询结果格式如下所示。

**示例 1：**

```
输入：
Person 表：
+----+---------+
| id | email   |
+----+---------+
| 1  | a@b.com |
| 2  | c@d.com |
| 3  | a@b.com |
+----+---------+

输出：
+---------+
| Email   |
+---------+
| a@b.com |
+---------+

解释：a@b.com 出现了两次。
```

## 解题思路

这是一道简单的分组统计问题，核心思路：

1. 按 `email` 分组
2. 统计每组的数量
3. 筛选出现次数 > 1 的邮箱

### 知识点

- `GROUP BY`：按指定列分组
- `HAVING`：对分组后的结果进行筛选（类似 WHERE，但用于聚合函数）
- `COUNT(*)`：统计每组的行数

## SQL 代码实现

### 方法一：GROUP BY + HAVING（推荐）

```sql
SELECT 
    email AS Email
FROM 
    Person
GROUP BY 
    email
HAVING 
    COUNT(*) > 1;
```

**代码解释：**
1. `GROUP BY email`：按邮箱分组
2. `COUNT(*) > 1`：统计每组的行数，大于 1 表示重复
3. `HAVING`：在分组后筛选（不能用 WHERE，因为 WHERE 在分组前执行）
4. `email AS Email`：返回重复的邮箱，注意列名首字母大写

### 方法二：自连接

```sql
SELECT DISTINCT 
    p1.email AS Email
FROM 
    Person p1
JOIN 
    Person p2 ON p1.email = p2.email AND p1.id != p2.id;
```

**代码解释：**
1. 将表与自身连接
2. `ON p1.email = p2.email`：找到相同邮箱
3. `AND p1.id != p2.id`：排除自己与自己比较（确保是不同的记录）
4. `DISTINCT`：去重（因为每个重复邮箱会匹配多次）

### 方法三：子查询

```sql
SELECT 
    email AS Email
FROM 
    Person
WHERE 
    email IN (
        SELECT email
        FROM Person
        GROUP BY email
        HAVING COUNT(*) > 1
    );
```

**代码解释：**
1. 子查询：找出所有重复的邮箱
2. 外层查询：从原表中筛选这些邮箱
3. 注意：这种方法会返回所有重复记录，需要外层加 `DISTINCT`

**改进版（避免重复）：**
```sql
SELECT DISTINCT
    email AS Email
FROM 
    Person
WHERE 
    email IN (
        SELECT email
        FROM Person
        GROUP BY email
        HAVING COUNT(*) > 1
    );
```

### 方法四：窗口函数

```sql
SELECT DISTINCT 
    email AS Email
FROM (
    SELECT 
        email,
        COUNT(*) OVER (PARTITION BY email) AS cnt
    FROM Person
) AS temp
WHERE cnt > 1;
```

**代码解释：**
1. `COUNT(*) OVER (PARTITION BY email)`：为每行计算该邮箱的总出现次数
2. `WHERE cnt > 1`：筛选出现次数大于 1 的
3. `DISTINCT`：去重

## 复杂度分析

**方法一（GROUP BY + HAVING）：**
- 时间复杂度：O(n)，单次扫描 + 分组
- 空间复杂度：O(n)，存储分组结果
- 优点：最简洁高效，最推荐

**方法二（自连接）：**
- 时间复杂度：O(n²)，笛卡尔积
- 空间复杂度：O(n²)，连接结果集
- 缺点：性能差，不推荐

**方法三（子查询）：**
- 时间复杂度：O(n)，两次扫描
- 空间复杂度：O(n)
- 缺点：代码冗余，性能略低于方法一

**方法四（窗口函数）：**
- 时间复杂度：O(n)
- 空间复杂度：O(n)
- 缺点：对于这种简单问题，过于复杂

## 关键点总结

1. **HAVING vs WHERE**：
   - `WHERE` 在分组前筛选（不能用聚合函数）
   - `HAVING` 在分组后筛选（可以用聚合函数）
2. **COUNT(*) vs COUNT(email)**：
   - `COUNT(*)`：统计所有行，包括 NULL
   - `COUNT(email)`：统计 email 非 NULL 的行
   - 本题两者等价（因为 email 不为 NULL）
3. **DISTINCT 的使用**：方法一不需要 DISTINCT，其他方法需要
4. **列名大小写**：注意输出列名是 `Email` 而不是 `email`
5. **性能最优**：方法一（GROUP BY + HAVING）

## 易错点

1. **使用 WHERE 代替 HAVING**
   ```sql
   -- 错误：WHERE 不能用于聚合函数
   SELECT email
   FROM Person
   GROUP BY email
   WHERE COUNT(*) > 1;  -- 语法错误
   
   -- 正确：使用 HAVING
   HAVING COUNT(*) > 1;
   ```

2. **忘记 GROUP BY**
   ```sql
   -- 错误：没有分组就使用 COUNT(*)
   SELECT email, COUNT(*)
   FROM Person
   HAVING COUNT(*) > 1;  -- 错误：email 必须在 GROUP BY 中
   
   -- 正确：
   SELECT email, COUNT(*)
   FROM Person
   GROUP BY email
   HAVING COUNT(*) > 1;
   ```

3. **列名大小写错误**
   ```sql
   -- 错误：题目要求列名是 Email（首字母大写）
   SELECT email
   FROM Person
   GROUP BY email
   HAVING COUNT(*) > 1;
   
   -- 正确：
   SELECT email AS Email
   ```

4. **自连接忘记去重**
   ```sql
   -- 错误：没有 DISTINCT，会返回多条相同记录
   SELECT p1.email AS Email
   FROM Person p1 JOIN Person p2 
   ON p1.email = p2.email AND p1.id != p2.id;
   
   -- 正确：加 DISTINCT
   SELECT DISTINCT p1.email AS Email ...
   ```

5. **自连接条件遗漏**
   ```sql
   -- 错误：没有 p1.id != p2.id，会匹配自己
   ON p1.email = p2.email
   
   -- 正确：排除自己
   ON p1.email = p2.email AND p1.id != p2.id
   ```

## 学习建议

1. **掌握 GROUP BY 基础**：
   - 理解分组的概念：相同值的行被归为一组
   - 分组后只能 SELECT 分组列和聚合函数
   - 熟悉常用聚合函数：COUNT, SUM, AVG, MAX, MIN

2. **理解 HAVING vs WHERE**：
   - WHERE：在分组前过滤行
   - HAVING：在分组后过滤组
   - 记忆口诀：WHERE 筛行，HAVING 筛组

3. **实践练习**：
   - 修改条件：找出出现次数 >= 3 的邮箱
   - 扩展：同时返回邮箱和出现次数
   - 思考：如何删除重复的邮箱，只保留 ID 最小的那个？（见题 196）

4. **SQL 执行顺序**：
   ```
   FROM -> WHERE -> GROUP BY -> HAVING -> SELECT -> ORDER BY
   ```
   理解这个顺序有助于避免错误

5. **性能对比**：
   - 在大数据集上比较不同方法的性能
   - 使用 EXPLAIN 查看执行计划
   - 理解为什么 GROUP BY 比自连接快

6. **面试技巧**：
   - 能够快速写出方法一（最优解）
   - 能够解释 HAVING 和 WHERE 的区别
   - 知道何时使用 GROUP BY（需要分组统计时）
   - 记住常见聚合函数的用法

7. **扩展知识**：
   - 学习 GROUP BY 多列（例如：按部门和职位分组）
   - 学习 ROLLUP 和 CUBE（多维汇总）
   - 学习 GROUPING SETS（自定义分组）
