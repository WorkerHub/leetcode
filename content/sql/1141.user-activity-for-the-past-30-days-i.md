## 题目描述

表：`Activity`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| user_id       | int     |
| session_id    | int     |
| activity_date | date    |
| activity_type | enum    |
+---------------+---------+
该表没有主键，可能包含重复行。
activity_type 列是 ENUM 类型，可能的值为 ('open_session', 'end_session', 'scroll_down', 'send_message')。
该表显示了社交媒体网站的用户活动。
请注意，每个会话只属于一个用户。
```

编写一个 SQL 查询，以查找截至 2019-07-27（包括此日期）的 30 天内每天的活跃用户数（活跃用户是指在某一天进行了至少一次活动的用户）。

查询结果格式如下例所示。

**示例 1：**

输入：
```
Activity 表：
+---------+------------+---------------+---------------+
| user_id | session_id | activity_date | activity_type |
+---------+------------+---------------+---------------+
| 1       | 1          | 2019-07-20    | open_session  |
| 1       | 1          | 2019-07-20    | scroll_down   |
| 1       | 1          | 2019-07-20    | end_session   |
| 2       | 4          | 2019-07-20    | open_session  |
| 2       | 4          | 2019-07-21    | send_message  |
| 2       | 4          | 2019-07-21    | end_session   |
| 3       | 2          | 2019-07-21    | open_session  |
| 3       | 2          | 2019-07-21    | send_message  |
| 3       | 2          | 2019-07-21    | end_session   |
| 4       | 3          | 2019-06-25    | open_session  |
| 4       | 3          | 2019-06-25    | end_session   |
+---------+------------+---------------+---------------+
```

输出：
```
+------------+--------------+ 
| day        | active_users |
+------------+--------------+ 
| 2019-07-20 | 2            |
| 2019-07-21 | 2            |
+------------+--------------+ 
```

解释：
注意，我们不关心活动的计数，只关心用户的计数。

## 解题思路

这道题要求统计指定日期范围内每天的活跃用户数。

**核心要点：**

1. **时间范围筛选**：
   - 截至 2019-07-27（包括）的 30 天内
   - 即日期在 `['2019-06-28', '2019-07-27']` 区间内
   - 使用 `DATEDIFF` 或 `BETWEEN` 筛选

2. **去重统计**：
   - 同一用户在同一天可能有多条活动记录
   - 需要使用 `COUNT(DISTINCT user_id)` 去重

3. **按日期分组**：
   - 使用 `GROUP BY activity_date`
   - 统计每天的不同用户数

4. **日期计算方法**：
   - 方法一：`DATEDIFF('2019-07-27', activity_date) < 30`
   - 方法二：`activity_date BETWEEN '2019-06-28' AND '2019-07-27'`
   - 方法三：`activity_date > DATE_SUB('2019-07-27', INTERVAL 30 DAY)`

## SQL 代码实现

### 方法一：使用 DATEDIFF ⭐

```sql
-- 使用 DATEDIFF 计算日期差
SELECT 
    activity_date AS day,
    COUNT(DISTINCT user_id) AS active_users
FROM 
    Activity
WHERE 
    DATEDIFF('2019-07-27', activity_date) < 30
    AND DATEDIFF('2019-07-27', activity_date) >= 0
GROUP BY 
    activity_date;
```

### 方法二：使用 BETWEEN ⭐ 推荐

```sql
-- 使用 BETWEEN 指定日期范围
SELECT 
    activity_date AS day,
    COUNT(DISTINCT user_id) AS active_users
FROM 
    Activity
WHERE 
    activity_date BETWEEN '2019-06-28' AND '2019-07-27'
GROUP BY 
    activity_date;
```

### 方法三：使用 DATE_SUB

```sql
-- 使用 DATE_SUB 函数
SELECT 
    activity_date AS day,
    COUNT(DISTINCT user_id) AS active_users
FROM 
    Activity
WHERE 
    activity_date > DATE_SUB('2019-07-27', INTERVAL 30 DAY)
    AND activity_date <= '2019-07-27'
GROUP BY 
    activity_date;
```

### 方法四：使用 DATE_ADD（另一种写法）

```sql
-- 使用 DATE_ADD
SELECT 
    activity_date AS day,
    COUNT(DISTINCT user_id) AS active_users
FROM 
    Activity
WHERE 
    activity_date BETWEEN DATE_ADD('2019-07-27', INTERVAL -29 DAY) 
                      AND '2019-07-27'
GROUP BY 
    activity_date;
```

### 方法五：通用模板（使用变量）

```sql
-- 使用变量，更灵活
SET @end_date = '2019-07-27';
SET @days = 30;

SELECT 
    activity_date AS day,
    COUNT(DISTINCT user_id) AS active_users
FROM 
    Activity
WHERE 
    activity_date BETWEEN DATE_SUB(@end_date, INTERVAL @days - 1 DAY) 
                      AND @end_date
GROUP BY 
    activity_date
ORDER BY 
    day;
```

## 复杂度分析

**时间复杂度**：O(n)
- 需要扫描整个 Activity 表
- WHERE 条件可以利用索引优化

**空间复杂度**：O(k)
- k 为结果集大小，最多 30 行

## 关键点总结

1. **日期范围理解**：过去 30 天包括截止日期，不包括第 30 天之前的日期
2. **去重关键**：使用 `COUNT(DISTINCT user_id)` 而不是 `COUNT(*)`
3. **日期函数选择**：DATEDIFF、BETWEEN、DATE_SUB 都可以
4. **边界条件**：注意等号，是 `<= 30` 还是 `< 30`
5. **性能优化**：在 activity_date 列上建立索引

## 易错点

1. **重复计数**：忘记使用 DISTINCT 导致同一用户被多次计数
2. **日期范围错误**：
   - 过去 30 天是 29 天前到今天，共 30 天
   - `DATEDIFF < 30` 且 `>= 0` 才是正确的 30 天
3. **未分组**：忘记 GROUP BY 导致只有一行结果
4. **列名错误**：输出列名应为 day 和 active_users
5. **NULL 值处理**：虽然本题没有，但实际中需要注意 NULL 日期

## SQL 技巧总结

1. **日期范围的多种写法**：
   ```sql
   -- 写法1
   WHERE DATEDIFF('2019-07-27', activity_date) BETWEEN 0 AND 29
   
   -- 写法2
   WHERE activity_date >= '2019-06-28' AND activity_date <= '2019-07-27'
   
   -- 写法3
   WHERE activity_date BETWEEN DATE_SUB('2019-07-27', INTERVAL 29 DAY) 
                           AND '2019-07-27'
   ```

2. **COUNT DISTINCT 去重**：
   ```sql
   -- 去重计数
   COUNT(DISTINCT user_id)
   
   -- 错误写法（不去重）
   COUNT(user_id)
   ```

3. **索引优化建议**：
   ```sql
   -- 在日期列创建索引
   CREATE INDEX idx_activity_date ON Activity(activity_date);
   
   -- 复合索引（如果经常按用户查询）
   CREATE INDEX idx_date_user ON Activity(activity_date, user_id);
   ```

## 学习建议

1. **掌握日期函数**：
   - DATEDIFF：计算两个日期的天数差
   - DATE_SUB/DATE_ADD：日期加减
   - BETWEEN：范围查询

2. **理解去重**：
   - COUNT(*) vs COUNT(column) vs COUNT(DISTINCT column)
   - 什么时候需要去重

3. **GROUP BY 用法**：
   - 聚合函数配合分组
   - SELECT 中非聚合列必须在 GROUP BY 中

4. **日期边界**：
   - 包含边界 vs 不包含边界
   - 过去 N 天的准确含义

5. **性能优化**：
   - 在日期列上建索引
   - 避免在 WHERE 中对列进行函数操作
