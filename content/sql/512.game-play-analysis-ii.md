## 题目描述

表：`Activity`

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| player_id    | int     |
| device_id    | int     |
| event_date   | date    |
| games_played | int     |
+--------------+---------+
(player_id, event_date) 是此表的主键（具有唯一值的列的组合）。
这张表显示了某些游戏的玩家活动情况。
每一行是一个玩家的记录，他在某一天使用某个设备注销之前登录并玩了若干游戏（可能为 0）。
```

编写解决方案，报告每位玩家**首次登录**时使用的**设备 ID**。

返回结果格式如下所示：

**示例 1：**

输入：
```
Activity 表：
+-----------+-----------+------------+--------------+
| player_id | device_id | event_date | games_played |
+-----------+-----------+------------+--------------+
| 1         | 2         | 2016-03-01 | 5            |
| 1         | 2         | 2016-05-02 | 6            |
| 2         | 3         | 2017-06-25 | 1            |
| 3         | 1         | 2016-03-02 | 0            |
| 3         | 4         | 2018-07-03 | 5            |
+-----------+-----------+------------+--------------+
```

输出：
```
+-----------+-----------+
| player_id | device_id |
+-----------+-----------+
| 1         | 2         |
| 2         | 3         |
| 3         | 1         |
+-----------+-----------+
```

## 解题思路

这道题是 [511. Game Play Analysis I](https://leetcode.com/problems/game-play-analysis-i/) 的延续，需要找到每个玩家**首次登录日期对应的设备 ID**。

### 核心思想：
1. 先找到每个玩家的首次登录日期（511 题）
2. 再根据日期找到对应的设备 ID

### 解法对比：
- **方法一**：子查询（将 511 题结果作为子查询）
- **方法二**：窗口函数（RANK/ROW_NUMBER）
- **方法三**：自连接（JOIN 511 题的结果）

## SQL 解决方案

### 方法一：子查询（推荐）⭐

```sql
-- MySQL / PostgreSQL / SQLite
SELECT 
    player_id,
    device_id
FROM 
    Activity
WHERE 
    (player_id, event_date) IN (
        SELECT 
            player_id,
            MIN(event_date) AS first_login
        FROM 
            Activity
        GROUP BY 
            player_id
    );
```

**解释：**
1. 子查询找到每个玩家的首次登录日期
2. 外层查询根据 (player_id, event_date) 匹配对应的记录
3. 返回对应的 device_id

### 方法二：窗口函数（ROW_NUMBER）

```sql
-- MySQL 8.0+, PostgreSQL, SQL Server
SELECT 
    player_id,
    device_id
FROM (
    SELECT 
        player_id,
        device_id,
        ROW_NUMBER() OVER (PARTITION BY player_id ORDER BY event_date) AS rn
    FROM 
        Activity
) t
WHERE rn = 1;
```

**解释：**
1. `ROW_NUMBER()` 为每个玩家的记录按日期编号
2. `rn = 1` 筛选出首次登录的记录

### 方法三：自连接

```sql
SELECT 
    a.player_id,
    a.device_id
FROM 
    Activity a
JOIN (
    SELECT 
        player_id,
        MIN(event_date) AS first_login
    FROM 
        Activity
    GROUP BY 
        player_id
) b ON a.player_id = b.player_id AND a.event_date = b.first_login;
```

**解释：**
1. 子查询 b 得到每个玩家的首次登录日期
2. 与原表 JOIN，匹配日期
3. 返回对应的 device_id

### 方法四：使用 RANK（处理同日多次登录）

```sql
-- MySQL 8.0+, PostgreSQL
SELECT 
    player_id,
    device_id
FROM (
    SELECT 
        player_id,
        device_id,
        RANK() OVER (PARTITION BY player_id ORDER BY event_date) AS rk
    FROM 
        Activity
) t
WHERE rk = 1;
```

**说明：** 如果同一天有多次登录，RANK 可能返回多条记录，但题目保证 (player_id, event_date) 是主键，所以不会发生。

## 复杂度分析

### 方法一（子查询）：
- **时间复杂度**：O(n log n)
  - 子查询分组排序：O(n log n)
  - IN 查询：O(n)
- **空间复杂度**：O(n)

### 方法二（窗口函数）：
- **时间复杂度**：O(n log n)
  - 窗口函数需要排序
- **空间复杂度**：O(n)

### 方法三（自连接）：
- **时间复杂度**：O(n log n)
  - JOIN 操作
- **空间复杂度**：O(n)

**结论：** 三种方法效率相近，方法一最直观，方法二最简洁。

## 关键点总结

1. **复合条件匹配**：(player_id, event_date) IN (...)
2. **窗口函数应用**：PARTITION BY 分组，ORDER BY 排序
3. **ROW_NUMBER vs RANK**：本题两者结果相同
4. **主键约束**：(player_id, event_date) 唯一，避免重复
5. **可读性**：方法一最易理解，方法二最简洁

## 易错点

1. **只用 MIN(device_id)**：错误！首次登录日期对应的设备，不是最小设备号
2. **忘记匹配 player_id**：子查询要同时匹配 player_id 和 event_date
3. **窗口函数语法**：PARTITION BY 和 ORDER BY 不能省略
4. **NULL 处理**：虽然本题没有，但实际中要注意 NULL
5. **数据库兼容性**：窗口函数需要较新版本数据库

## 常见错误示例

### ❌ 错误写法 1：只按 device_id 最小值
```sql
-- 错误！这是找最小设备 ID，不是首次登录设备
SELECT 
    player_id,
    MIN(device_id) AS device_id
FROM Activity
GROUP BY player_id;
```

### ❌ 错误写法 2：忘记匹配 player_id
```sql
-- 错误！子查询没有按 player_id 分组
SELECT player_id, device_id
FROM Activity
WHERE event_date = (SELECT MIN(event_date) FROM Activity);
```

### ✅ 正确写法：
使用上述三种方法之一。
