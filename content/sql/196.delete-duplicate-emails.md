## 题目描述

编写一个 SQL 删除语句来删除 `Person` 表中所有重复的电子邮箱，重复的邮箱里只保留 **Id 最小** 的那个。

**表：Person**

```
+----+------------------+
| Id | Email            |
+----+------------------+
| 1  | john@example.com |
| 2  | bob@example.com  |
| 3  | john@example.com |
+----+------------------+
```

**说明：**
- `Id` 是这个表的主键
- 每个 Email 包含一个唯一的电子邮箱

例如，在运行你的查询语句之后，上面的 `Person` 表应返回以下几行:

```
+----+------------------+
| Id | Email            |
+----+------------------+
| 1  | john@example.com |
| 2  | bob@example.com  |
+----+------------------+
```

**提示：**
- 执行 SQL 之后，输出是整个 `Person` 表
- 使用 `DELETE` 语句

## 解题思路

这道题要求删除重复的邮箱记录，只保留 Id 最小的记录。

**核心思想：**
1. 找出所有重复的 Email
2. 对于每个重复的 Email，找出 Id 最小的记录
3. 删除其他 Id 较大的重复记录

**关键点：**
- 不能在同一个表上同时进行 SELECT 和 DELETE 操作
- 需要使用自连接或子查询
- 删除条件：相同 Email 但 Id 较大的记录

**算法步骤：**
1. 使用自连接找出重复记录
2. 比较同一 Email 的不同 Id
3. 删除 Id 较大的记录

## SQL 代码实现

### 方法一：自连接 DELETE（推荐）⭐

```sql
-- Write your MySQL query statement below
DELETE p1 
FROM Person p1
INNER JOIN Person p2 
ON p1.Email = p2.Email
WHERE p1.Id > p2.Id;
```

**代码说明：**
- `DELETE p1`：指定删除 p1 表的记录
- `INNER JOIN`：自连接，找出相同 Email 的记录对
- `WHERE p1.Id > p2.Id`：只删除 Id 较大的记录
- 逻辑：如果存在相同 Email 且 Id 更小的记录，则删除当前记录

### 方法二：使用子查询（不推荐）

```sql
-- Write your MySQL query statement below
DELETE FROM Person
WHERE Id NOT IN (
    SELECT Id FROM (
        SELECT MIN(Id) AS Id
        FROM Person
        GROUP BY Email
    ) AS temp
);
```

**代码说明：**
- `MIN(Id)`：每个 Email 的最小 Id
- `GROUP BY Email`：按 Email 分组
- `NOT IN`：删除不在最小 Id 列表中的记录
- 需要嵌套子查询是因为 MySQL 不允许在同一表上同时 SELECT 和 DELETE

**注意：** 这种方法在某些数据库版本中可能有性能问题。

### 方法三：使用窗口函数（MySQL 8.0+）

```sql
-- Write your MySQL query statement below
DELETE FROM Person
WHERE Id IN (
    SELECT Id FROM (
        SELECT Id,
               ROW_NUMBER() OVER (PARTITION BY Email ORDER BY Id) AS rn
        FROM Person
    ) AS temp
    WHERE rn > 1
);
```

**代码说明：**
- `ROW_NUMBER()`：为每个分组内的记录编号
- `PARTITION BY Email`：按 Email 分组
- `ORDER BY Id`：按 Id 升序排列
- `rn > 1`：保留第一条记录（rn=1），删除其他记录

## 复杂度分析

### 方法一（自连接）：
**时间复杂度：** O(n²)
- 最坏情况下，所有记录 Email 相同，需要比较所有记录对
- 实际上，有索引时性能更好

**空间复杂度：** O(1)
- 不需要额外存储空间

### 方法二（子查询）：
**时间复杂度：** O(n)
- GROUP BY 操作 O(n)
- DELETE 操作 O(n)

**空间复杂度：** O(n)
- 需要存储临时结果集

## 关键点总结

1. **DELETE 自连接语法**：`DELETE t1 FROM table t1 JOIN table t2 ...`
2. **保留最小 Id**：使用 `p1.Id > p2.Id` 条件
3. **避免同表查询限制**：MySQL 不允许在 DELETE 的同一表上直接 SELECT，需要子查询嵌套
4. **性能优化**：自连接方法通常比子查询更高效
5. **Email 索引**：在 Email 列上建立索引可以显著提升性能

## 易错点

1. **DELETE 语法错误**：
   - 错误：`DELETE FROM p1 JOIN ...`
   - 正确：`DELETE p1 FROM Person p1 JOIN ...`

2. **条件写反**：
   - 错误：`WHERE p1.Id < p2.Id` 会删除 Id 最小的记录
   - 正确：`WHERE p1.Id > p2.Id` 删除 Id 较大的记录

3. **忘记嵌套子查询**：
   ```sql
   -- 错误：MySQL 报错
   DELETE FROM Person
   WHERE Id NOT IN (
       SELECT MIN(Id) FROM Person GROUP BY Email
   );
   
   -- 正确：需要再包装一层
   DELETE FROM Person
   WHERE Id NOT IN (
       SELECT Id FROM (
           SELECT MIN(Id) AS Id FROM Person GROUP BY Email
       ) AS temp
   );
   ```

4. **使用 LEFT JOIN 而非 INNER JOIN**：
   - LEFT JOIN 会保留所有记录，逻辑可能出错
   - INNER JOIN 只匹配相同 Email 的记录对

5. **不理解自连接逻辑**：
   - 自连接会产生笛卡尔积
   - `ON p1.Email = p2.Email` 限制只匹配相同 Email
   - `WHERE p1.Id > p2.Id` 进一步过滤

## 图解示例

**原始数据：**
```
Id | Email
1  | john@example.com
2  | bob@example.com
3  | john@example.com
```

**自连接过程：**
```
p1.Id | p1.Email         | p2.Id | p2.Email         | 删除?
1     | john@example.com | 1     | john@example.com | No (Id 相等)
1     | john@example.com | 3     | john@example.com | No (1 < 3)
2     | bob@example.com  | 2     | bob@example.com  | No (唯一)
3     | john@example.com | 1     | john@example.com | Yes (3 > 1) ✓
3     | john@example.com | 3     | john@example.com | No (Id 相等)
```

**结果：**
```
Id | Email
1  | john@example.com
2  | bob@example.com
```
