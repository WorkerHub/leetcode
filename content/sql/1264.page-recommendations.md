## 题目描述

表：`Friendship`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| user1_id      | int     |
| user2_id      | int     |
+---------------+---------+
(user1_id, user2_id) 是这张表的主键（具有唯一值的列的组合）
这张表的每一行代表着 user1_id 和 user2_id 之间存在着朋友关系
```

表：`Likes`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| user_id     | int     |
| page_id     | int     |
+-------------+---------+
(user_id, page_id) 是这张表的主键
这张表的每一行代表着 user_id 喜欢 page_id
```

你需要为用户 `user_id = 1` 推荐页面。推荐的页面应该是该用户的朋友们喜欢的页面，但该用户自己还没有喜欢过的页面。

返回的结果表可以按**任意顺序**排列，且**不包含重复**的页面。

**示例：**

```
输入：
Friendship table:
+----------+----------+
| user1_id | user2_id |
+----------+----------+
| 1        | 2        |
| 1        | 3        |
| 1        | 4        |
| 2        | 3        |
| 2        | 4        |
| 2        | 5        |
| 6        | 1        |
+----------+----------+

Likes table:
+---------+---------+
| user_id | page_id |
+---------+---------+
| 1       | 88      |
| 2       | 23      |
| 3       | 24      |
| 4       | 56      |
| 5       | 11      |
| 6       | 33      |
| 2       | 77      |
| 3       | 77      |
| 6       | 88      |
+---------+---------+

输出：
+------------------+
| recommended_page |
+------------------+
| 23               |
| 24               |
| 56               |
| 33               |
| 77               |
+------------------+

解释：
用户 1 的朋友有 2, 3, 4, 6
- 朋友 2 喜欢页面 23 和 77
- 朋友 3 喜欢页面 24 和 77
- 朋友 4 喜欢页面 56
- 朋友 6 喜欢页面 33 和 88
页面 88 不推荐，因为用户 1 已经喜欢了它
所以推荐的页面是：23, 24, 56, 33, 77
```

## 解题思路

这道题的核心是**找到用户 1 的朋友**，然后**推荐朋友喜欢的页面**，但要**排除用户 1 已经喜欢的页面**。

**关键步骤：**

1. **找到用户 1 的所有朋友**：
   - 在 `Friendship` 表中，朋友关系是双向的
   - 用户 1 的朋友可能在 `user1_id = 1` 或 `user2_id = 1` 的记录中

2. **找到朋友喜欢的页面**：
   - 将朋友列表与 `Likes` 表连接
   - 获取所有朋友喜欢的 `page_id`

3. **排除用户 1 已经喜欢的页面**：
   - 使用 `NOT IN` 或 `LEFT JOIN` 排除用户 1 已喜欢的页面

4. **去重**：
   - 使用 `DISTINCT` 或 `GROUP BY` 去重

## SQL 代码实现

### 方法一：UNION + NOT IN（推荐）⭐

```sql
SELECT DISTINCT page_id AS recommended_page
FROM Likes
WHERE user_id IN (
    -- 找到用户 1 的所有朋友
    SELECT user2_id FROM Friendship WHERE user1_id = 1
    UNION
    SELECT user1_id FROM Friendship WHERE user2_id = 1
)
AND page_id NOT IN (
    -- 排除用户 1 已经喜欢的页面
    SELECT page_id FROM Likes WHERE user_id = 1
);
```

### 方法二：UNION ALL + NOT EXISTS

```sql
SELECT DISTINCT page_id AS recommended_page
FROM Likes
WHERE user_id IN (
    SELECT user2_id FROM Friendship WHERE user1_id = 1
    UNION ALL
    SELECT user1_id FROM Friendship WHERE user2_id = 1
)
AND NOT EXISTS (
    SELECT 1 FROM Likes AS L2
    WHERE L2.user_id = 1 AND L2.page_id = Likes.page_id
);
```

### 方法三：CTE（公共表表达式）

```sql
WITH Friends AS (
    -- 找到用户 1 的所有朋友
    SELECT user2_id AS friend_id FROM Friendship WHERE user1_id = 1
    UNION
    SELECT user1_id AS friend_id FROM Friendship WHERE user2_id = 1
),
UserLikes AS (
    -- 用户 1 已经喜欢的页面
    SELECT page_id FROM Likes WHERE user_id = 1
)

SELECT DISTINCT L.page_id AS recommended_page
FROM Likes L
INNER JOIN Friends F ON L.user_id = F.friend_id
WHERE L.page_id NOT IN (SELECT page_id FROM UserLikes);
```

### 方法四：LEFT JOIN 排除

```sql
WITH Friends AS (
    SELECT user2_id AS friend_id FROM Friendship WHERE user1_id = 1
    UNION
    SELECT user1_id AS friend_id FROM Friendship WHERE user2_id = 1
)

SELECT DISTINCT L.page_id AS recommended_page
FROM Likes L
INNER JOIN Friends F ON L.user_id = F.friend_id
LEFT JOIN Likes L2 ON L.page_id = L2.page_id AND L2.user_id = 1
WHERE L2.page_id IS NULL;  -- 排除用户 1 已喜欢的页面
```

### 方法五：简化版（单查询）

```sql
SELECT DISTINCT page_id AS recommended_page
FROM Likes
WHERE user_id IN (
    SELECT 
        CASE 
            WHEN user1_id = 1 THEN user2_id
            ELSE user1_id
        END AS friend_id
    FROM Friendship
    WHERE user1_id = 1 OR user2_id = 1
)
AND page_id NOT IN (
    SELECT page_id FROM Likes WHERE user_id = 1
);
```

## 复杂度分析

### 方法一（UNION + NOT IN）

- **时间复杂度**：
  - UNION 去重：O(F log F)，F 为朋友数
  - 主查询扫描 Likes 表：O(L)，L 为 Likes 表行数
  - NOT IN 子查询：O(P)，P 为用户 1 喜欢的页面数
  - 总计：O(L + F log F + P)

- **空间复杂度**：O(F + P)，存储朋友列表和已喜欢页面

### 方法三（CTE）

- **时间复杂度**：与方法一类似，O(L + F log F + P)
- **空间复杂度**：O(F + P)，CTE 会被物化

## 关键点总结

1. **朋友关系是双向的**：需要 UNION 两个方向的朋友
2. **UNION vs UNION ALL**：UNION 自动去重，UNION ALL 保留重复（后续 DISTINCT 会去重）
3. **NOT IN vs NOT EXISTS**：NOT IN 简洁，NOT EXISTS 性能可能更好
4. **去重**：使用 DISTINCT 或 GROUP BY
5. **CTE 提高可读性**：将复杂查询拆分成多个步骤

## 易错点

1. **遗漏朋友关系的双向性**：只查 `user1_id = 1` 会遗漏 `user2_id = 1` 的情况
2. **未排除已喜欢的页面**：必须使用 NOT IN 或 LEFT JOIN 排除
3. **未去重**：朋友可能喜欢相同的页面，需要 DISTINCT
4. **NULL 值处理**：NOT IN 遇到 NULL 时可能产生意外结果，建议检查数据
5. **列名错误**：输出列名必须是 `recommended_page`
