## 题目描述

表：`Stadium`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| id            | int     |
| visit_date    | date    |
| people        | int     |
+---------------+---------+
```

`visit_date` 是该表的主键。
每日人流量信息被记录在这张表中。
每一行都包含 id、访问日期以及访问人数。

写一个 SQL 查询以找出每行的人数大于或等于 100 且 id 连续的三行或更多行记录。

返回按 `visit_date` **升序排列** 的结果表。

查询结果格式如下例所示。

**示例 1：**

```
输入：
Stadium 表：
+------+------------+-----------+
| id   | visit_date | people    |
+------+------------+-----------+
| 1    | 2017-01-01 | 10        |
| 2    | 2017-01-02 | 109       |
| 3    | 2017-01-03 | 150       |
| 4    | 2017-01-04 | 99        |
| 5    | 2017-01-05 | 145       |
| 6    | 2017-01-06 | 1455      |
| 7    | 2017-01-07 | 199       |
| 8    | 2017-01-09 | 188       |
+------+------------+-----------+

输出：
+------+------------+-----------+
| id   | visit_date | people    |
+------+------------+-----------+
| 5    | 2017-01-05 | 145       |
| 6    | 2017-01-06 | 1455      |
| 7    | 2017-01-07 | 199       |
| 8    | 2017-01-09 | 188       |
+------+------------+-----------+

解释：
id 为 5、6、7、8 的四行 id 连续，并且每行都有 >= 100 的人数记录。
请注意，即使第 7 行和第 8 行的 visit_date 不连续，输出也应当包含第 8 行，因为我们只需要考虑 id 连续。
不输出 id 为 2 和 3 的行，因为至少需要三条 id 连续的记录。
```

## 解题思路

这道题的核心是找出**至少连续3个 id**，且这些 id 对应的 `people` 都 >= 100 的记录。

**关键点：**
1. **连续性判断**：基于 `id` 连续，而非 `visit_date`
2. **窗口函数**：使用窗口函数判断前后行的 people 值
3. **分组技巧**：需要找到连续的满足条件的区间

**核心思路：**

**方法一：使用窗口函数（推荐）**
- 使用 `LAG()` 和 `LEAD()` 获取前后两行的 people 值
- 判断每个位置是否可以作为连续3个的起点、中间或终点
- 合并所有满足条件的记录

**方法二：自连接**
- 三次自连接，判断连续3个 id
- 扩展到更长的连续序列

**方法三：使用变量（MySQL 特有）**
- 使用用户变量记录连续计数
- 标记连续的满足条件的组

## SQL 代码实现

### 方法一：窗口函数 + CASE WHEN（推荐）⭐

```sql
SELECT DISTINCT s1.id, s1.visit_date, s1.people
FROM (
    SELECT id, visit_date, people,
           LAG(people, 1) OVER (ORDER BY id) AS prev1_people,
           LAG(people, 2) OVER (ORDER BY id) AS prev2_people,
           LEAD(people, 1) OVER (ORDER BY id) AS next1_people,
           LEAD(people, 2) OVER (ORDER BY id) AS next2_people,
           LAG(id, 1) OVER (ORDER BY id) AS prev1_id,
           LAG(id, 2) OVER (ORDER BY id) AS prev2_id,
           LEAD(id, 1) OVER (ORDER BY id) AS next1_id,
           LEAD(id, 2) OVER (ORDER BY id) AS next2_id
    FROM Stadium
) s1
WHERE s1.people >= 100
  AND (
      -- 当前行是起点：当前、后1、后2都满足且id连续
      (s1.next1_people >= 100 AND s1.next2_people >= 100 
       AND s1.next1_id = s1.id + 1 AND s1.next2_id = s1.id + 2)
      OR
      -- 当前行是中间：前1、当前、后1都满足且id连续
      (s1.prev1_people >= 100 AND s1.next1_people >= 100
       AND s1.prev1_id = s1.id - 1 AND s1.next1_id = s1.id + 1)
      OR
      -- 当前行是终点：前2、前1、当前都满足且id连续
      (s1.prev1_people >= 100 AND s1.prev2_people >= 100
       AND s1.prev1_id = s1.id - 1 AND s1.prev2_id = s1.id - 2)
  )
ORDER BY s1.visit_date;
```

### 方法二：自连接（经典方法）

```sql
SELECT DISTINCT s1.*
FROM Stadium s1, Stadium s2, Stadium s3
WHERE s1.people >= 100 AND s2.people >= 100 AND s3.people >= 100
  AND (
      -- s1是起点：s1, s2, s3连续
      (s1.id + 1 = s2.id AND s2.id + 1 = s3.id)
      OR
      -- s2是起点：s2, s1, s3连续（s1在中间）
      (s2.id + 1 = s1.id AND s1.id + 1 = s3.id)
      OR
      -- s3是起点：s3, s2, s1连续（s1在末尾）
      (s3.id + 1 = s2.id AND s2.id + 1 = s1.id)
  )
ORDER BY s1.visit_date;
```

### 方法三：使用变量标记连续组（MySQL 8.0之前）

```sql
SELECT id, visit_date, people
FROM (
    SELECT id, visit_date, people,
           @rank := IF(@prev >= 100 AND id = @prev_id + 1, @rank, @rank + 1) AS rank,
           @count := IF(@prev >= 100 AND id = @prev_id + 1, @count + 1, 1) AS cnt,
           @prev := people,
           @prev_id := id
    FROM Stadium, (SELECT @rank := 0, @prev := 0, @prev_id := 0, @count := 0) init
    WHERE people >= 100
    ORDER BY id
) t
WHERE t.rank IN (
    SELECT rank 
    FROM (
        SELECT id, visit_date, people,
               @r := IF(@p >= 100 AND id = @p_id + 1, @r, @r + 1) AS rank,
               @c := IF(@p >= 100 AND id = @p_id + 1, @c + 1, 1) AS cnt,
               @p := people,
               @p_id := id
        FROM Stadium, (SELECT @r := 0, @p := 0, @p_id := 0, @c := 0) init2
        WHERE people >= 100
        ORDER BY id
    ) temp
    GROUP BY rank
    HAVING MAX(cnt) >= 3
)
ORDER BY visit_date;
```

### 方法四：使用 ROW_NUMBER 分组技巧（最优雅）⭐⭐

```sql
WITH filtered AS (
    SELECT id, visit_date, people,
           id - ROW_NUMBER() OVER (ORDER BY id) AS grp
    FROM Stadium
    WHERE people >= 100
),
grouped AS (
    SELECT grp, COUNT(*) AS cnt
    FROM filtered
    GROUP BY grp
    HAVING COUNT(*) >= 3
)
SELECT f.id, f.visit_date, f.people
FROM filtered f
JOIN grouped g ON f.grp = g.grp
ORDER BY f.visit_date;
```

## 复杂度分析

### 方法一（窗口函数）
- **时间复杂度**：O(n)，扫描一次表
- **空间复杂度**：O(n)，窗口函数的中间结果

### 方法二（自连接）
- **时间复杂度**：O(n³)，三表笛卡尔积
- **空间复杂度**：O(n²)，连接结果

### 方法四（ROW_NUMBER 分组）
- **时间复杂度**：O(n)，最优
- **空间复杂度**：O(n)

## 关键点总结

1. **连续性判断基于 id**：题目要求 id 连续，而非 visit_date 连续
2. **至少三条记录**：需要找到连续的至少3个满足条件的 id
3. **窗口函数的应用**：`LAG()` 和 `LEAD()` 可以获取相邻行数据
4. **分组技巧**：`id - ROW_NUMBER()` 可以将连续的记录分到同一组
5. **DISTINCT 去重**：某些方法会产生重复结果，需要去重

## 易错点

1. **忘记判断 id 连续**：仅检查 people >= 100 不够，还要确保 id 连续
2. **只考虑恰好3条**：题目要求"三行或更多行"，不是恰好3行
3. **排序错误**：结果要按 `visit_date` 排序，而非 `id`
4. **重复记录**：自连接方法容易产生重复，需要 DISTINCT
5. **边界情况**：表中少于3条记录时应返回空结果
