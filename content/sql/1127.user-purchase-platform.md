## 题目描述

表：`Spending`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| user_id     | int     |
| spend_date  | date    |
| platform    | enum    | 
| amount      | int     |
+-------------+---------+
这张表的主键是 (user_id, spend_date, platform)。
platform 列是一种 ENUM 类型，其值包含 ('mobile', 'desktop', 'both')。
这张表记录了用户在某个平台上某一天的花费金额。
```

编写 SQL 查询，查找每个日期、每个平台的总花费金额和总用户数。注意，一个用户在某一天可能在多个平台上消费。如果某用户在某一天同时在桌面端和移动端消费，我们认为该用户属于 `'both'` 平台。

需要显示所有日期的所有平台（包括没有用户的情况），对于没有用户的日期和平台，用户数和总花费都应该是 0。

返回结果表按 `spend_date` 和 `platform` 排序。

查询结果格式如下所示。

**示例 1：**

**输入：**

Spending 表：
```
+---------+------------+----------+--------+
| user_id | spend_date | platform | amount |
+---------+------------+----------+--------+
| 1       | 2019-07-01 | mobile   | 100    |
| 1       | 2019-07-01 | desktop  | 100    |
| 2       | 2019-07-01 | mobile   | 100    |
| 2       | 2019-07-02 | mobile   | 100    |
| 3       | 2019-07-01 | desktop  | 100    |
| 3       | 2019-07-02 | desktop  | 100    |
+---------+------------+----------+--------+
```

**输出：**
```
+------------+----------+--------------+-------------+
| spend_date | platform | total_amount | total_users |
+------------+----------+--------------+-------------+
| 2019-07-01 | desktop  | 100          | 1           |
| 2019-07-01 | mobile   | 100          | 1           |
| 2019-07-01 | both     | 200          | 1           |
| 2019-07-02 | desktop  | 100          | 1           |
| 2019-07-02 | mobile   | 100          | 1           |
| 2019-07-02 | both     | 0            | 0           |
+------------+----------+--------------+-------------+
```

**解释：**

2019-07-01：
- user_id = 1 在 desktop 和 mobile 都有消费，属于 'both' 平台，总消费 200
- user_id = 2 只在 mobile 消费 100
- user_id = 3 只在 desktop 消费 100

2019-07-02：
- user_id = 2 只在 mobile 消费 100
- user_id = 3 只在 desktop 消费 100
- 没有用户在 both 平台消费

## 解题思路

这道题的难点在于：

1. **识别 'both' 平台用户**：某用户在同一天同时在 mobile 和 desktop 消费
2. **生成完整的日期-平台组合**：确保所有日期都有 3 个平台（mobile、desktop、both）
3. **处理缺失数据**：没有用户的平台显示 0

### 解题步骤

1. 识别每个用户每天的实际平台（单平台或 both）
2. 计算每个用户每天的总消费
3. 生成所有日期和平台的笛卡尔积
4. 左连接用户数据，填充缺失值为 0

## SQL 代码实现

### 方法一：使用 UNION 和 CROSS JOIN（推荐）

```sql
WITH UserDailyPlatform AS (
    -- 识别每个用户每天的实际平台
    SELECT 
        user_id,
        spend_date,
        CASE 
            WHEN COUNT(DISTINCT platform) = 2 THEN 'both'
            ELSE MAX(platform)  -- 只有一个平台时取该平台
        END AS platform,
        SUM(amount) AS total_amount
    FROM Spending
    GROUP BY user_id, spend_date
),
AllDatesAndPlatforms AS (
    -- 生成所有日期和平台的组合
    SELECT DISTINCT spend_date FROM Spending
    CROSS JOIN 
    (SELECT 'desktop' AS platform 
     UNION SELECT 'mobile' 
     UNION SELECT 'both') AS Platforms
)
SELECT 
    a.spend_date,
    a.platform,
    COALESCE(SUM(u.total_amount), 0) AS total_amount,
    COUNT(DISTINCT u.user_id) AS total_users
FROM AllDatesAndPlatforms a
LEFT JOIN UserDailyPlatform u
    ON a.spend_date = u.spend_date 
    AND a.platform = u.platform
GROUP BY a.spend_date, a.platform
ORDER BY a.spend_date, a.platform;
```

### 方法二：不使用 UNION（简化版）

```sql
WITH UserDailyPlatform AS (
    SELECT 
        user_id,
        spend_date,
        IF(COUNT(DISTINCT platform) = 2, 'both', MAX(platform)) AS platform,
        SUM(amount) AS total_amount
    FROM Spending
    GROUP BY user_id, spend_date
),
DateList AS (
    SELECT DISTINCT spend_date FROM Spending
)
SELECT 
    d.spend_date,
    p.platform,
    IFNULL(SUM(u.total_amount), 0) AS total_amount,
    COUNT(DISTINCT u.user_id) AS total_users
FROM DateList d
CROSS JOIN (
    SELECT 'desktop' AS platform 
    UNION ALL SELECT 'mobile' 
    UNION ALL SELECT 'both'
) p
LEFT JOIN UserDailyPlatform u
    ON d.spend_date = u.spend_date 
    AND p.platform = u.platform
GROUP BY d.spend_date, p.platform
ORDER BY d.spend_date, p.platform;
```

### 方法三：使用临时表

```sql
-- 步骤1：识别用户的实际平台
WITH UserActualPlatform AS (
    SELECT 
        user_id,
        spend_date,
        CASE 
            WHEN COUNT(DISTINCT platform) = 1 THEN MIN(platform)
            ELSE 'both'
        END AS actual_platform,
        SUM(amount) AS daily_amount
    FROM Spending
    GROUP BY user_id, spend_date
),
-- 步骤2：获取所有日期
AllDates AS (
    SELECT DISTINCT spend_date FROM Spending
),
-- 步骤3：生成日期和平台的笛卡尔积
AllCombinations AS (
    SELECT 
        d.spend_date,
        p.platform
    FROM AllDates d
    CROSS JOIN (
        SELECT 'mobile' AS platform
        UNION SELECT 'desktop'
        UNION SELECT 'both'
    ) p
)
-- 步骤4：聚合统计
SELECT 
    ac.spend_date,
    ac.platform,
    COALESCE(SUM(uap.daily_amount), 0) AS total_amount,
    COUNT(uap.user_id) AS total_users
FROM AllCombinations ac
LEFT JOIN UserActualPlatform uap
    ON ac.spend_date = uap.spend_date
    AND ac.platform = uap.actual_platform
GROUP BY ac.spend_date, ac.platform
ORDER BY ac.spend_date, ac.platform;
```

## 复杂度分析

- **时间复杂度**：O(n + d × p)，其中 n 是原始记录数，d 是日期数，p 是平台数（固定为 3）
- **空间复杂度**：O(d × p)，用于存储所有日期和平台的组合

## 关键点总结

1. **CASE 表达式**：根据用户在同一天的平台数量判断实际平台
   - `COUNT(DISTINCT platform) = 2` → 'both'
   - `COUNT(DISTINCT platform) = 1` → 该平台
2. **CROSS JOIN**：生成日期和平台的笛卡尔积，确保所有组合都存在
3. **LEFT JOIN**：保留所有日期-平台组合，即使没有对应的用户数据
4. **COALESCE/IFNULL**：将 NULL 值替换为 0
5. **COUNT(DISTINCT user_id)**：统计不同用户数，而非记录数

## 易错点

1. **平台识别错误**：必须先按用户和日期分组，统计每个用户每天的平台数量
2. **遗漏 'both' 平台**：需要显式创建包含 'both' 的平台列表
3. **缺失组合**：必须使用 CROSS JOIN 生成所有日期和平台的组合
4. **聚合函数选择**：
   - 用户数应该用 `COUNT(DISTINCT user_id)`，而非 `COUNT(user_id)`
   - 金额用 `SUM(amount)`
5. **NULL 值处理**：没有数据的组合应显示 0，而非 NULL
6. **分组顺序**：必须先识别用户的实际平台，再进行最终的聚合
