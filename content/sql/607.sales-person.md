## 题目描述

表：`SalesPerson`

```
+-----------------+---------+
| Column Name     | Type    |
+-----------------+---------+
| sales_id        | int     |
| name            | varchar |
| salary          | int     |
| commission_rate | int     |
| hire_date       | date    |
+-----------------+---------+
```

`sales_id` 是该表的主键列。
该表的每一行都显示了销售人员的姓名和 ID，以及他们的工资、佣金率和雇佣日期。

表：`Company`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| com_id      | int     |
| name        | varchar |
| city        | varchar |
+-------------+---------+
```

`com_id` 是该表的主键列。
该表的每一行都表示公司的名称和 ID，以及所在城市。

表：`Orders`

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| order_id    | int  |
| order_date  | date |
| com_id      | int  |
| sales_id    | int  |
| amount      | int  |
+-------------+------+
```

`order_id` 是该表的主键列。
`com_id` 是 Company 表的外键。
`sales_id` 是 SalesPerson 表的外键。
该表的每一行都包含一个订单的信息。包括订单 ID、订单日期、公司 ID、销售人员 ID 和订单金额。

编写一个 SQL 查询，报告没有任何与名为 **"RED"** 公司相关订单的所有销售人员的姓名。

返回结果表**无顺序要求**。

查询结果格式如下所示。

**示例 1：**

```
输入：
SalesPerson 表：
+----------+------+--------+-----------------+------------+
| sales_id | name | salary | commission_rate | hire_date  |
+----------+------+--------+-----------------+------------+
| 1        | John | 100000 | 6               | 4/1/2006   |
| 2        | Amy  | 12000  | 5               | 5/1/2010   |
| 3        | Mark | 65000  | 12              | 12/25/2008 |
| 4        | Pam  | 25000  | 25              | 1/1/2005   |
| 5        | Alex | 5000   | 10              | 2/3/2007   |
+----------+------+--------+-----------------+------------+

Company 表：
+--------+--------+----------+
| com_id | name   | city     |
+--------+--------+----------+
| 1      | RED    | Boston   |
| 2      | ORANGE | New York |
| 3      | YELLOW | Boston   |
| 4      | GREEN  | Austin   |
+--------+--------+----------+

Orders 表：
+----------+------------+--------+----------+--------+
| order_id | order_date | com_id | sales_id | amount |
+----------+------------+--------+----------+--------+
| 1        | 1/1/2014   | 3      | 4        | 10000  |
| 2        | 2/1/2014   | 4      | 5        | 5000   |
| 3        | 3/1/2014   | 1      | 1        | 50000  |
| 4        | 4/1/2014   | 1      | 4        | 25000  |
+----------+------------+--------+----------+--------+

输出：
+------+
| name |
+------+
| Amy  |
| Mark |
| Alex |
+------+

解释：
根据表 orders 中的订单 '3' 和 '4'，容易看出只有 'John' 和 'Pam' 两个销售员曾经向公司 'RED' 销售过。
所以我们需要输出表 salesperson 中所有其他人的名字。
```

## 解题思路

这道题要求找出**没有向 RED 公司销售过产品的销售员**。

**核心思路：**

1. **找出 RED 公司的 ID**
2. **找出向 RED 公司销售过的销售员**
3. **排除这些销售员，剩下的就是答案**

**三种实现方法：**

**方法一：NOT IN 子查询（推荐）**
- 子查询找出向 RED 销售过的销售员 ID
- 主查询排除这些 ID

**方法二：LEFT JOIN + WHERE NULL**
- 左连接订单表和公司表
- 筛选出没有 RED 订单的销售员

**方法三：NOT EXISTS**
- 使用相关子查询检查是否存在 RED 订单

## SQL 代码实现

### 方法一：NOT IN 子查询（最简洁）⭐

```sql
SELECT name
FROM SalesPerson
WHERE sales_id NOT IN (
    SELECT o.sales_id
    FROM Orders o
    JOIN Company c ON o.com_id = c.com_id
    WHERE c.name = 'RED'
);
```

**简化版（不使用 JOIN）：**

```sql
SELECT name
FROM SalesPerson
WHERE sales_id NOT IN (
    SELECT sales_id
    FROM Orders
    WHERE com_id = (
        SELECT com_id
        FROM Company
        WHERE name = 'RED'
    )
);
```

### 方法二：LEFT JOIN + IS NULL

```sql
SELECT DISTINCT s.name
FROM SalesPerson s
LEFT JOIN Orders o ON s.sales_id = o.sales_id
LEFT JOIN Company c ON o.com_id = c.com_id AND c.name = 'RED'
WHERE c.com_id IS NULL;
```

**优化版（先筛选 RED 公司）：**

```sql
SELECT s.name
FROM SalesPerson s
LEFT JOIN (
    SELECT o.sales_id
    FROM Orders o
    JOIN Company c ON o.com_id = c.com_id
    WHERE c.name = 'RED'
) AS red_sales ON s.sales_id = red_sales.sales_id
WHERE red_sales.sales_id IS NULL;
```

### 方法三：NOT EXISTS（最优雅）⭐

```sql
SELECT name
FROM SalesPerson s
WHERE NOT EXISTS (
    SELECT 1
    FROM Orders o
    JOIN Company c ON o.com_id = c.com_id
    WHERE o.sales_id = s.sales_id
      AND c.name = 'RED'
);
```

### 方法四：使用 EXCEPT（部分数据库支持）

```sql
-- PostgreSQL, SQL Server 支持
SELECT name
FROM SalesPerson
WHERE sales_id IN (
    SELECT sales_id FROM SalesPerson
    EXCEPT
    SELECT sales_id FROM Orders o
    JOIN Company c ON o.com_id = c.com_id
    WHERE c.name = 'RED'
);
```

## 复杂度分析

### 方法一（NOT IN）
- **时间复杂度**：O(n × m)，n 为销售员数，m 为订单数
- **空间复杂度**：O(m)，子查询结果
- **注意**：如果子查询结果包含 NULL，NOT IN 会返回空结果

### 方法二（LEFT JOIN）
- **时间复杂度**：O(n × m)
- **空间复杂度**：O(n × m)，连接结果

### 方法三（NOT EXISTS）
- **时间复杂度**：O(n × m)
- **空间复杂度**：O(1)，不需要额外空间
- **性能最佳**：遇到第一个匹配就停止

## 关键点总结

1. **反向思维**：不是直接找"没有"，而是先找"有"再排除
2. **NOT IN vs NOT EXISTS**：
   - `NOT IN` 简洁但要注意 NULL 问题
   - `NOT EXISTS` 性能更好，推荐使用
3. **LEFT JOIN + IS NULL**：经典的"找不存在"模式
4. **子查询优化**：先筛选 RED 公司，减少数据量
5. **DISTINCT 的使用**：LEFT JOIN 方法可能产生重复，需要去重

## 易错点

1. **NOT IN 遇到 NULL**：
   ```sql
   -- ⚠️ 警告：如果子查询结果包含 NULL
   WHERE sales_id NOT IN (NULL, 1, 2)
   -- 结果为空！因为 sales_id NOT IN (NULL) 总是 UNKNOWN
   ```
   解决方法：
   ```sql
   WHERE sales_id NOT IN (
       SELECT sales_id 
       FROM Orders 
       WHERE sales_id IS NOT NULL  -- 过滤 NULL
   )
   ```

2. **LEFT JOIN 条件位置**：
   ```sql
   -- ❌ 错误：WHERE 中过滤会变成 INNER JOIN
   FROM SalesPerson s
   LEFT JOIN Company c ON s.sales_id = c.com_id
   WHERE c.name = 'RED'
   
   -- ✅ 正确：在 ON 中过滤
   LEFT JOIN Company c ON s.sales_id = c.com_id AND c.name = 'RED'
   ```

3. **忘记 DISTINCT**：
   ```sql
   -- ❌ 可能产生重复：一个销售员可能有多个非RED订单
   SELECT s.name
   FROM SalesPerson s
   LEFT JOIN Orders o ON s.sales_id = o.sales_id
   -- 应该加 DISTINCT
   ```

4. **逻辑错误**：
   ```sql
   -- ❌ 错误：找的是"有 RED 订单"而非"没有"
   WHERE sales_id IN (...)
   -- 应该是 NOT IN
   ```

## 学习建议

**新手学习路径：**

1. **理解"不存在"的查询方式**：
   - 方法一：`NOT IN` - 最直观
   - 方法二：`LEFT JOIN + IS NULL` - 最常用
   - 方法三：`NOT EXISTS` - 性能最好

2. **NOT IN vs NOT EXISTS 对比**：
   ```sql
   -- NOT IN：子查询只执行一次，结果缓存
   WHERE id NOT IN (SELECT id FROM table)
   
   -- NOT EXISTS：对每行执行，但遇到匹配即停止
   WHERE NOT EXISTS (SELECT 1 FROM table WHERE ...)
   ```

3. **循序渐进**：
   - 第一步：找出 RED 公司的订单
   - 第二步：找出参与这些订单的销售员
   - 第三步：排除这些销售员

4. **推荐方法**：
   - 初学者：方法一（NOT IN），最容易理解
   - 进阶：方法三（NOT EXISTS），性能更好
   - 实际生产：根据数据特点选择

5. **手动验证**：
   ```
   销售员：1-John, 2-Amy, 3-Mark, 4-Pam, 5-Alex
   RED公司订单：order 3(sales_id=1), order 4(sales_id=4)
   向RED销售过的：John(1), Pam(4)
   答案：Amy(2), Mark(3), Alex(5)
   ```

**实战技巧：**
- `NOT EXISTS` 通常比 `NOT IN` 性能更好
- 使用 `NOT IN` 时一定要确保子查询结果不含 NULL
- `LEFT JOIN + IS NULL` 是面试中最常见的方法
- 复杂查询优先使用 CTE 提高可读性

**性能优化：**
- 在 `com_id` 和 `sales_id` 上建立索引
- 子查询中避免 `SELECT *`，只选择需要的列
- 考虑使用 `EXISTS` 代替 `IN`（数据量大时）
