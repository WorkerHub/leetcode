## 题目描述

表：`Employee`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| employee_id   | int     |
| team_id       | int     |
+---------------+---------+
employee_id 是这个表的主键
表中的每一行都包含每个员工的 ID 和他们所属的团队
```

编写一个 SQL 查询，以求得每个员工所在团队的总人数。

查询结果格式如下所示：

```
Employee Table:
+-------------+------------+
| employee_id | team_id    |
+-------------+------------+
|     1       |     8      |
|     2       |     8      |
|     3       |     8      |
|     4       |     7      |
|     5       |     9      |
|     6       |     9      |
+-------------+------------+

Result table:
+-------------+------------+
| employee_id | team_size  |
+-------------+------------+
|     1       |     3      |
|     2       |     3      |
|     3       |     3      |
|     4       |     1      |
|     5       |     2      |
|     6       |     2      |
+-------------+------------+

员工 1、2、3 是团队 8 的成员
员工 4 是团队 7 的成员
员工 5、6 是团队 9 的成员
```

## 解题思路

这道题要求为每个员工计算其所在团队的总人数。有多种 SQL 实现方式：

### 思路一：窗口函数（推荐）
使用 `COUNT() OVER (PARTITION BY team_id)` 窗口函数，按团队分组计数，为每个员工返回其团队的总人数。

### 思路二：子查询
先用子查询计算每个团队的人数，再与原表连接。

### 思路三：自连接 + GROUP BY
通过自连接和分组聚合来计算每个团队的人数。

## SQL 代码实现

### 方法一：窗口函数（推荐）⭐

```sql
-- 使用窗口函数是最简洁高效的方法
SELECT 
    employee_id,
    COUNT(*) OVER (PARTITION BY team_id) AS team_size
FROM Employee
ORDER BY employee_id;
```

### 方法二：子查询

```sql
-- 先计算每个团队的人数，再连接回原表
SELECT 
    e.employee_id,
    t.team_size
FROM Employee e
JOIN (
    SELECT 
        team_id,
        COUNT(*) AS team_size
    FROM Employee
    GROUP BY team_id
) t ON e.team_id = t.team_id
ORDER BY e.employee_id;
```

### 方法三：自连接 + GROUP BY

```sql
-- 自连接后分组计数
SELECT 
    e1.employee_id,
    COUNT(e2.employee_id) AS team_size
FROM Employee e1
JOIN Employee e2 ON e1.team_id = e2.team_id
GROUP BY e1.employee_id
ORDER BY e1.employee_id;
```

### 方法四：相关子查询

```sql
-- 对每个员工，用相关子查询计算其团队人数
SELECT 
    employee_id,
    (SELECT COUNT(*) 
     FROM Employee e2 
     WHERE e2.team_id = e1.team_id) AS team_size
FROM Employee e1
ORDER BY employee_id;
```

## 复杂度分析

### 方法一：窗口函数
- 时间复杂度：O(n log n)，需要按 team_id 分区和排序
- 空间复杂度：O(n)，窗口函数的中间结果
- 性能：最优，现代数据库对窗口函数优化很好

### 方法二：子查询
- 时间复杂度：O(n)，一次全表扫描 + 一次连接
- 空间复杂度：O(t)，其中 t 是不同团队的数量
- 性能：较好，适合团队数量远小于员工数量的场景

### 方法三：自连接
- 时间复杂度：O(n²)，最坏情况下（所有人同一团队）
- 空间复杂度：O(n²)，连接结果
- 性能：较差，不推荐用于大数据集

### 方法四：相关子查询
- 时间复杂度：O(n²)，每行都执行一次子查询
- 空间复杂度：O(1)
- 性能：最差，不推荐

## 关键点总结

1. 窗口函数是解决这类问题的最佳选择，代码简洁且性能好
2. `COUNT(*) OVER (PARTITION BY team_id)` 表示按 team_id 分组计数
3. 子查询方法也很实用，逻辑清晰易懂
4. 避免使用自连接和相关子查询，性能较差

## 易错点

1. 忘记使用 `PARTITION BY` 子句，导致计算的是全部员工数而非团队人数
2. 使用自连接时，GROUP BY 的列不正确
3. 窗口函数中使用了 `DISTINCT`，导致重复计数
4. 忘记对结果排序（虽然题目可能不要求）

## MySQL vs PostgreSQL vs SQL Server

不同数据库对窗口函数的支持：

```sql
-- MySQL 8.0+ 支持窗口函数
-- PostgreSQL 支持窗口函数
-- SQL Server 支持窗口函数

-- 如果是 MySQL 5.7 或更早版本，不支持窗口函数，使用方法二：
SELECT 
    e.employee_id,
    t.team_size
FROM Employee e
INNER JOIN (
    SELECT team_id, COUNT(*) AS team_size
    FROM Employee
    GROUP BY team_id
) t ON e.team_id = t.team_id;
```
