## 题目描述

表：`Activity`

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| player_id    | int     |
| device_id    | int     |
| event_date   | date    |
| games_played | int     |
+--------------+---------+
(player_id, event_date) 是该表的主键（具有唯一值的列组合）
该表显示某些游戏玩家的活动情况
每行是一个玩家的记录，他在某一天使用某个设备登录并玩了若干游戏（可能为 0）
```

编写解决方案，报告每个玩家和日期，玩家到该日期为止总共玩了多少游戏。也就是说，玩家直到该日期为止所玩的游戏总数。详见示例。

以任意顺序返回结果表。

结果格式如下所示。

**示例 1：**

输入：
```
Activity table:
+-----------+-----------+------------+--------------+
| player_id | device_id | event_date | games_played |
+-----------+-----------+------------+--------------+
| 1         | 2         | 2016-03-01 | 5            |
| 1         | 2         | 2016-05-02 | 6            |
| 1         | 3         | 2017-06-25 | 1            |
| 3         | 1         | 2016-03-02 | 0            |
| 3         | 4         | 2018-07-03 | 5            |
+-----------+-----------+------------+--------------+
```

输出：
```
+-----------+------------+---------------------+
| player_id | event_date | games_played_so_far |
+-----------+------------+---------------------+
| 1         | 2016-03-01 | 5                   |
| 1         | 2016-05-02 | 11                  |
| 1         | 2017-06-25 | 12                  |
| 3         | 2016-03-02 | 0                   |
| 3         | 2018-07-03 | 5                   |
+-----------+------------+---------------------+
```

解释：
```
对于 ID 为 1 的玩家，到 2016-05-02 为止，玩了 5 + 6 = 11 场游戏，
到 2017-06-25 为止，玩了 5 + 6 + 1 = 12 场游戏。
对于 ID 为 3 的玩家，到 2018-07-03 为止，玩了 0 + 5 = 5 场游戏。
注意，对于每个玩家，我们只关心玩家登录的日期。
```

## 解题思路

这道题需要计算累积和（Running Total），是 SQL 窗口函数的经典应用。

**核心思想：**

使用窗口函数 `SUM() OVER()` 对每个玩家按日期排序，计算累积游戏数。

**窗口函数语法：**

```sql
SUM(column) OVER (
    PARTITION BY group_column
    ORDER BY sort_column
)
```

- `PARTITION BY`：分组，相当于 `GROUP BY`，但不聚合行
- `ORDER BY`：在每个分组内排序
- `SUM()`：计算累积和

## SQL 代码实现

### 方法一：窗口函数（推荐）

```sql
-- MySQL / PostgreSQL / SQL Server
SELECT
    player_id,
    event_date,
    SUM(games_played) OVER (
        PARTITION BY player_id
        ORDER BY event_date
    ) AS games_played_so_far
FROM Activity;
```

**解释：**

1. `PARTITION BY player_id`：按玩家分组
2. `ORDER BY event_date`：在每个玩家组内按日期排序
3. `SUM(games_played) OVER (...)`：计算从第一行到当前行的累积和

### 方法二：子查询（不推荐）

```sql
-- 效率较低，但不需要窗口函数
SELECT
    a1.player_id,
    a1.event_date,
    (
        SELECT SUM(a2.games_played)
        FROM Activity a2
        WHERE a2.player_id = a1.player_id
          AND a2.event_date <= a1.event_date
    ) AS games_played_so_far
FROM Activity a1
ORDER BY a1.player_id, a1.event_date;
```

### 方法三：自连接（不推荐）

```sql
-- 效率最低
SELECT
    a1.player_id,
    a1.event_date,
    SUM(a2.games_played) AS games_played_so_far
FROM Activity a1
JOIN Activity a2
    ON a1.player_id = a2.player_id
    AND a2.event_date <= a1.event_date
GROUP BY a1.player_id, a1.event_date
ORDER BY a1.player_id, a1.event_date;
```

## 复杂度分析

### 方法一：窗口函数
- **时间复杂度**：O(n log n)，主要是排序
- **空间复杂度**：O(1)，不需要额外空间

### 方法二：子查询
- **时间复杂度**：O(n²)，每行都要执行子查询
- **空间复杂度**：O(1)

### 方法三：自连接
- **时间复杂度**：O(n² log n)，连接 + 排序 + 分组
- **空间复杂度**：O(n)，连接产生的中间结果

**强烈推荐使用方法一**，性能最优且代码简洁。

## 关键点总结

1. **窗口函数不聚合行**：与 `GROUP BY` 不同，保留所有原始行
2. **累积和模式**：`SUM() OVER (PARTITION BY ... ORDER BY ...)`
3. **分组和排序的重要性**：
   - `PARTITION BY` 确保每个玩家独立计算
   - `ORDER BY` 确保按时间累积
4. **窗口函数的优势**：简洁、高效、可读性强

## 易错点

1. **忘记 PARTITION BY**
   ```sql
   -- 错误：所有玩家混在一起累加
   SUM(games_played) OVER (ORDER BY event_date)
   
   -- 正确：每个玩家独立累加
   SUM(games_played) OVER (
       PARTITION BY player_id
       ORDER BY event_date
   )
   ```

2. **忘记 ORDER BY**
   ```sql
   -- 错误：没有排序，结果是总和
   SUM(games_played) OVER (PARTITION BY player_id)
   
   -- 正确：按日期排序，累积计算
   SUM(games_played) OVER (
       PARTITION BY player_id
       ORDER BY event_date
   )
   ```

3. **使用 GROUP BY 代替窗口函数**
   ```sql
   -- 错误：GROUP BY 会聚合行
   SELECT player_id, event_date, SUM(games_played)
   FROM Activity
   GROUP BY player_id, event_date
   
   -- 这只会得到每天的游戏数，不是累积数
   ```

## 窗口函数详解

### 常用窗口函数

```sql
-- 累积和
SUM(column) OVER (PARTITION BY ... ORDER BY ...)

-- 累积平均
AVG(column) OVER (PARTITION BY ... ORDER BY ...)

-- 累积计数
COUNT(*) OVER (PARTITION BY ... ORDER BY ...)

-- 排名
ROW_NUMBER() OVER (PARTITION BY ... ORDER BY ...)
RANK() OVER (PARTITION BY ... ORDER BY ...)
DENSE_RANK() OVER (PARTITION BY ... ORDER BY ...)

-- 前一行的值
LAG(column, 1) OVER (PARTITION BY ... ORDER BY ...)

-- 后一行的值
LEAD(column, 1) OVER (PARTITION BY ... ORDER BY ...)
```

### 窗口函数示例

```sql
-- 示例：计算每个玩家每天的游戏数占总游戏数的比例
SELECT
    player_id,
    event_date,
    games_played,
    SUM(games_played) OVER (
        PARTITION BY player_id
        ORDER BY event_date
    ) AS games_so_far,
    SUM(games_played) OVER (
        PARTITION BY player_id
    ) AS total_games,
    ROUND(
        100.0 * games_played / SUM(games_played) OVER (PARTITION BY player_id),
        2
    ) AS percentage
FROM Activity;
```

## 学习建议

1. **掌握窗口函数基本概念**：
   - 理解 `PARTITION BY` 和 `ORDER BY` 的作用
   - 区分窗口函数和聚合函数的差异
   - 窗口函数保留所有行，聚合函数减少行数

2. **练习累积计算**：
   - 累积和：`SUM() OVER ()`
   - 移动平均：`AVG() OVER (ROWS BETWEEN ... AND ...)`
   - 累积计数：`COUNT() OVER ()`

3. **理解窗口框架（Frame）**：
   ```sql
   -- 默认框架：从第一行到当前行
   SUM(column) OVER (ORDER BY date)
   
   -- 指定框架：当前行及前一行
   SUM(column) OVER (
       ORDER BY date
       ROWS BETWEEN 1 PRECEDING AND CURRENT ROW
   )
   
   -- 指定框架：所有行
   SUM(column) OVER (
       ORDER BY date
       ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
   )
   ```

4. **调试技巧**：
   ```sql
   -- 添加辅助列帮助理解
   SELECT
       player_id,
       event_date,
       games_played,
       ROW_NUMBER() OVER (
           PARTITION BY player_id
           ORDER BY event_date
       ) AS row_num,
       SUM(games_played) OVER (
           PARTITION BY player_id
           ORDER BY event_date
       ) AS cumulative_sum
   FROM Activity;
   ```

5. **从简单到复杂的学习路径**：
   - 第一步：理解简单聚合函数（SUM, AVG, COUNT）
   - 第二步：学习 GROUP BY
   - 第三步：理解窗口函数的概念
   - 第四步：练习 PARTITION BY 和 ORDER BY
   - 第五步：学习窗口框架（ROWS/RANGE）
   - 第六步：掌握高级窗口函数（LAG, LEAD, RANK 等）
