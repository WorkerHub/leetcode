## 题目描述

表：`Delivery`

```
+-----------------------------+---------+
| Column Name                 | Type    |
+-----------------------------+---------+
| delivery_id                 | int     |
| customer_id                 | int     |
| order_date                  | date    |
| customer_pref_delivery_date | date    |
+-----------------------------+---------+
delivery_id 是该表的主键（具有唯一值的列）。
该表保存顾客的食品配送信息，其中顾客在某日下了订单，并指定了一个期望的配送日期（和下单日期相同或者在那之后）。
```

如果顾客期望的配送日期和下单日期相同，则该订单称为「即时订单」，否则称为「计划订单」。

编写解决方案以获得即时订单在所有订单中的比例，保留两位小数。

**示例 1：**

输入：
Delivery 表：
```
+-------------+-------------+------------+-----------------------------+
| delivery_id | customer_id | order_date | customer_pref_delivery_date |
+-------------+-------------+------------+-----------------------------+
| 1           | 1           | 2019-08-01 | 2019-08-02                  |
| 2           | 5           | 2019-08-02 | 2019-08-02                  |
| 3           | 1           | 2019-08-11 | 2019-08-11                  |
| 4           | 3           | 2019-08-24 | 2019-08-26                  |
| 5           | 4           | 2019-08-21 | 2019-08-22                  |
| 6           | 2           | 2019-08-11 | 2019-08-13                  |
+-------------+-------------+------------+-----------------------------+
```

输出：
```
+----------------------+
| immediate_percentage |
+----------------------+
| 33.33                |
+----------------------+
```

解释：2 号订单和 3 号订单是即时订单，其他的都是计划订单。即时订单比例为 2/6 = 33.33%。

## 解题思路

这是一道简单的 SQL 统计题，核心思路是：

1. **识别即时订单**：即时订单的条件是 `order_date = customer_pref_delivery_date`
2. **计算比例**：即时订单数量 / 总订单数量
3. **格式化结果**：保留两位小数

关键点：
- 使用条件聚合（如 `SUM(CASE WHEN ... THEN 1 ELSE 0 END)`）来统计即时订单数量
- 使用 `COUNT(*)` 统计总订单数
- 使用 `ROUND()` 函数保留两位小数
- 乘以 100 将小数转换为百分比

## SQL 代码实现

### 方法一：使用 CASE WHEN 条件聚合（推荐）

```sql
SELECT 
    ROUND(
        SUM(CASE WHEN order_date = customer_pref_delivery_date THEN 1 ELSE 0 END) * 100.0 / COUNT(*),
        2
    ) AS immediate_percentage
FROM Delivery;
```

**代码说明：**
- `SUM(CASE WHEN ... THEN 1 ELSE 0 END)`：统计满足条件的订单数（即时订单）
- `COUNT(*)`：统计总订单数
- `* 100.0`：转换为百分比（注意使用 100.0 而不是 100，确保浮点数运算）
- `ROUND(..., 2)`：保留两位小数

### 方法二：使用 AVG 函数简化

```sql
SELECT 
    ROUND(
        AVG(CASE WHEN order_date = customer_pref_delivery_date THEN 1 ELSE 0 END) * 100,
        2
    ) AS immediate_percentage
FROM Delivery;
```

**代码说明：**
- `AVG(CASE WHEN ... THEN 1 ELSE 0 END)`：将即时订单标记为 1，非即时订单标记为 0，求平均值就是比例
- 这种方法更简洁，因为 AVG 自动完成了求和除以总数的操作

### 方法三：使用子查询

```sql
SELECT 
    ROUND(
        (SELECT COUNT(*) FROM Delivery WHERE order_date = customer_pref_delivery_date) * 100.0 / COUNT(*),
        2
    ) AS immediate_percentage
FROM Delivery;
```

**代码说明：**
- 子查询单独计算即时订单数量
- 外层查询计算总数并求比例
- 这种方法逻辑更清晰，但可能需要扫描表两次

## 复杂度分析

### SQL 方案

**时间复杂度：** O(n)
- 需要扫描整个表一次（方法三可能扫描两次）
- n 为 Delivery 表的行数

**空间复杂度：** O(1)
- 只需要常数空间存储计算结果

### Python Pandas 方案

**时间复杂度：** O(n)
- 需要遍历 DataFrame 的所有行进行比较
- n 为 DataFrame 的行数

**空间复杂度：** O(n)
- 布尔索引会创建一个与原 DataFrame 等长的布尔数组

## 关键点总结

1. **即时订单定义**：订单日期等于期望配送日期
2. **百分比计算**：要乘以 100 转换为百分比形式
3. **精度控制**：使用 ROUND 函数保留两位小数
4. **类型注意**：SQL 中使用 100.0 而非 100，确保浮点数运算
5. **Pandas 优化**：使用向量化操作（如 mean）比循环更高效

## 易错点

1. **整数除法问题**
   - 错误：`SUM(...) * 100 / COUNT(*)`（可能因整数除法导致精度丢失）
   - 正确：`SUM(...) * 100.0 / COUNT(*)`（使用浮点数）

2. **忘记乘以 100**
   - 题目要求的是百分比，需要将小数乘以 100

3. **精度问题**
   - 必须使用 ROUND 函数保留两位小数

4. **空表处理**
   - 如果表为空，COUNT(*) 返回 0，会导致除以 0 错误
   - 实际 LeetCode 测试用例不会有空表，但实际应用中需要考虑

5. **Pandas 中的数据类型**
   - 日期列需要是 datetime 类型才能正确比较
   - 如果是字符串类型，需要先转换
