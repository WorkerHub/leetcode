## 题目描述

写一个 SQL 查询，找出每个用户的加入日期和在 2019 年作为买家的订单总数。

表：`Users`

```
+----------------+---------+
| Column Name    | Type    |
+----------------+---------+
| user_id        | int     |
| join_date      | date    |
| favorite_brand | varchar |
+----------------+---------+
```

`user_id` 是这个表的主键。表中包含了一个在线购物网站的用户信息，用户可以在该网站卖出或买入商品。

表：`Orders`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| order_id      | int     |
| order_date    | date    |
| item_id       | int     |
| buyer_id      | int     |
| seller_id     | int     |
+---------------+---------+
```

`order_id` 是这个表的主键。`item_id` 是 `Items` 表的外键。`buyer_id` 和 `seller_id` 是 `Users` 表的外键。

表：`Items`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| item_id       | int     |
| item_brand    | varchar |
+---------------+---------+
```

`item_id` 是这个表的主键。

编写一个 SQL 查询，找出每个用户的注册日期和在 2019 年作为买家的订单总数。

查询结果格式如下所示：

```
Users 表：
+---------+------------+----------------+
| user_id | join_date  | favorite_brand |
+---------+------------+----------------+
| 1       | 2018-01-01 | Lenovo         |
| 2       | 2018-02-09 | Samsung        |
| 3       | 2018-01-19 | LG             |
| 4       | 2018-05-21 | HP             |
+---------+------------+----------------+

Orders 表：
+----------+------------+---------+----------+-----------+
| order_id | order_date | item_id | buyer_id | seller_id |
+----------+------------+---------+----------+-----------+
| 1        | 2019-08-01 | 4       | 1        | 2         |
| 2        | 2018-08-02 | 2       | 1        | 3         |
| 3        | 2019-08-03 | 3       | 2        | 3         |
| 4        | 2018-08-04 | 1       | 4        | 2         |
| 5        | 2018-08-04 | 1       | 3        | 4         |
| 6        | 2019-08-05 | 2       | 2        | 4         |
+----------+------------+---------+----------+-----------+

Items 表：
+---------+------------+
| item_id | item_brand |
+---------+------------+
| 1       | Samsung    |
| 2       | Lenovo     |
| 3       | LG         |

+---------+------------+

Result 表：
+-----------+------------+----------------+
| buyer_id  | join_date  | orders_in_2019 |
+-----------+------------+----------------+

| 2         | 2018-02-09 | 2              |

| 4         | 2018-05-21 | 0              |
+-----------+------------+----------------+
```

## 解题思路

这道题的核心考点是 SQL 的 JOIN 和日期过滤。

**关键观察：**

1. 需要返回所有用户，即使某些用户在 2019 年没有订单（此时订单数为 0）
2. 因此必须使用 LEFT JOIN，不能用 INNER JOIN
3. 需要筛选 2019 年的订单，可以用 YEAR 函数或日期范围判断
4. 使用 COUNT 统计订单数，注意 COUNT 对 NULL 值的处理

**解题步骤：**

1. 以 Users 表为主表，LEFT JOIN Orders 表（ON buyer_id = user_id）
2. 在 JOIN 条件或 WHERE 子句中添加 2019 年的过滤条件
3. 按 user_id 分组，统计订单数
4. 注意：LEFT JOIN 时，对于没有匹配的用户，Orders 表的字段为 NULL

## SQL 代码实现

### 方法一：LEFT JOIN + YEAR 函数（推荐）

```sql
SELECT 
    u.user_id AS buyer_id,
    u.join_date,
    COUNT(o.order_id) AS orders_in_2019
FROM 
    Users u
LEFT JOIN 
    Orders o ON u.user_id = o.buyer_id 
    AND YEAR(o.order_date) = 2019
GROUP BY 
    u.user_id, u.join_date
ORDER BY 
    u.user_id;
```

**说明：**
- 使用 LEFT JOIN 确保所有用户都出现在结果中
- 在 JOIN 条件中过滤 2019 年，这样未匹配的用户 COUNT 结果为 0
- COUNT(o.order_id) 会忽略 NULL 值，所以没有订单的用户结果为 0
- GROUP BY 需要包含 SELECT 中的非聚合字段

### 方法二：LEFT JOIN + 日期范围

```sql
SELECT 
    u.user_id AS buyer_id,
    u.join_date,
    COUNT(o.order_id) AS orders_in_2019
FROM 
    Users u
LEFT JOIN 
    Orders o ON u.user_id = o.buyer_id 
    AND o.order_date BETWEEN '2019-01-01' AND '2019-12-31'
GROUP BY 
    u.user_id, u.join_date
ORDER BY 
    u.user_id;
```

**说明：**
- 使用 BETWEEN 进行日期范围过滤
- 更明确，不依赖 YEAR 函数
- 性能上可能略有差异，取决于索引情况

### 方法三：子查询方式

```sql
SELECT 
    u.user_id AS buyer_id,
    u.join_date,
    IFNULL(t.orders_in_2019, 0) AS orders_in_2019
FROM 
    Users u
LEFT JOIN 
    (
        SELECT 
            buyer_id,
            COUNT(*) AS orders_in_2019
        FROM 
            Orders
        WHERE 
            YEAR(order_date) = 2019
        GROUP BY 
            buyer_id
    ) t ON u.user_id = t.buyer_id
ORDER BY 
    u.user_id;
```

**说明：**
- 先在子查询中统计每个用户在 2019 年的订单数
- 然后 LEFT JOIN 到 Users 表
- 使用 IFNULL 处理没有订单的用户（将 NULL 转为 0）
- 代码更模块化，逻辑清晰

### 方法四：COALESCE 处理 NULL

```sql
SELECT 
    u.user_id AS buyer_id,
    u.join_date,
    COALESCE(COUNT(o.order_id), 0) AS orders_in_2019
FROM 
    Users u
LEFT JOIN 
    Orders o ON u.user_id = o.buyer_id 
    AND o.order_date >= '2019-01-01' 
    AND o.order_date < '2020-01-01'
GROUP BY 
    u.user_id, u.join_date
ORDER BY 
    u.user_id;
```

**说明：**
- 使用 >= 和 < 进行日期范围判断，避免边界问题
- COALESCE 是标准 SQL 函数，兼容性更好

## 复杂度分析

**时间复杂度：**
- 主要取决于 JOIN 和 GROUP BY 操作
- 如果 buyer_id 和 order_date 有索引：`O(n + m)`，其中 n 是用户数，m 是订单数
- 无索引情况下：`O(n * m)`

**空间复杂度：**
- `O(n)`，用于存储分组结果

## 关键点总结

1. **LEFT JOIN vs INNER JOIN**：必须使用 LEFT JOIN 才能包含没有订单的用户

2. **过滤条件位置**：将年份过滤放在 JOIN 条件中，而不是 WHERE 子句中，这样才能保留所有用户

3. **COUNT 的特性**：COUNT(column) 不计算 NULL 值，COUNT(*) 计算所有行

4. **日期过滤方式**：YEAR() 函数、BETWEEN、比较运算符都可以，根据实际场景选择

5. **GROUP BY 规则**：在 MySQL 中，GROUP BY 需要包含 SELECT 中的所有非聚合字段

## 易错点

1. **错用 INNER JOIN**：会漏掉没有订单的用户

2. **WHERE 过滤位置错误**：
   ```sql
   -- 错误写法
   LEFT JOIN Orders o ON u.user_id = o.buyer_id
   WHERE YEAR(o.order_date) = 2019  -- 这会把没有订单的用户过滤掉
   ```

3. **忘记 GROUP BY**：如果不分组，COUNT 会统计所有行，得到错误结果

4. **COUNT(*) vs COUNT(column)**：
   - COUNT(*) 计算所有行，包括 NULL
   - COUNT(o.order_id) 只计算非 NULL 值

5. **日期格式问题**：确保日期格式与数据库一致
