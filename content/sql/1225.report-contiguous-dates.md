## 题目描述

表：`Failed`

```
+-------------------+---------+
| Column Name       | Type    |
+-------------------+---------+
| fail_date         | date    |
+-------------------+---------+
fail_date 是该表的主键。
该表包含失败任务的日期。
```

表：`Succeeded`

```
+-------------------+---------+
| Column Name       | Type    |
+-------------------+---------+
| success_date      | date    |
+-------------------+---------+
success_date 是该表的主键。
该表包含成功任务的日期。
```

系统每天运行一个任务。每个任务都独立于前一个任务。任务的状态可以是失败或是成功。

编写一个 SQL 查询，以生成一个报告，其中包含 2019-01-01 到 2019-12-31 期间每个连续的日期区间的 period_state 和持续时间。

如果任务失败了，period_state 为 'failed'；如果任务成功了，period_state 为 'succeeded'。

返回的结果表按 start_date 升序排序。

示例 1：
```
输入：
Failed 表：
+--------------+
| fail_date    |
+--------------+
| 2018-12-28   |
| 2018-12-29   |
| 2019-01-04   |
| 2019-01-05   |
+--------------+

Succeeded 表：
+--------------+
| success_date |
+--------------+
| 2018-12-30   |
| 2018-12-31   |
| 2019-01-01   |
| 2019-01-02   |
| 2019-01-03   |
| 2019-01-06   |
+--------------+

输出：
+--------------+--------------+--------------+
| period_state | start_date   | end_date     |
+--------------+--------------+--------------+
| succeeded    | 2019-01-01   | 2019-01-03   |
| failed       | 2019-01-04   | 2019-01-05   |
| succeeded    | 2019-01-06   | 2019-01-06   |
+--------------+--------------+--------------+

解释：
结果忽略了 2019 年以外的所有日期。
注意，2018-12-28 至 2018-12-29 是失败期，但不在所需的时间段内。
```

## 解题思路

这道题的核心是识别连续日期区间。解题思路如下：

1. 合并两个表，给每条记录标记状态（failed 或 succeeded）
2. 过滤出 2019 年的数据
3. 使用行号技巧识别连续区间：日期 - 行号 = 常数（对于连续日期）
4. 按状态和分组标识进行分组，找出每组的最小和最大日期

关键技巧：
- 连续日期的特征：如果按日期排序，日期值减去行号的结果相同
- 例如：2019-01-01 (row 1) -> 差值 0，2019-01-02 (row 2) -> 差值 0，说明连续

## SQL 代码实现

### 方法一：使用 ROW_NUMBER 窗口函数（推荐）

```sql
-- MySQL 8.0+ / PostgreSQL / SQL Server

WITH CombinedDates AS (
    -- 合并失败和成功的日期，并标记状态
    SELECT fail_date AS date, 'failed' AS period_state
    FROM Failed
    WHERE fail_date BETWEEN '2019-01-01' AND '2019-12-31'
    
    UNION ALL
    
    SELECT success_date AS date, 'succeeded' AS period_state
    FROM Succeeded
    WHERE success_date BETWEEN '2019-01-01' AND '2019-12-31'
),
GroupedDates AS (
    -- 使用日期减去行号来识别连续区间
    SELECT 
        period_state,
        date,
        DATE_SUB(date, INTERVAL ROW_NUMBER() OVER (PARTITION BY period_state ORDER BY date) DAY) AS group_id
    FROM CombinedDates
)
-- 按状态和分组ID分组，获取每个连续区间的开始和结束日期
SELECT 
    period_state,
    MIN(date) AS start_date,
    MAX(date) AS end_date
FROM GroupedDates
GROUP BY period_state, group_id
ORDER BY start_date;
```

### 方法二：使用 RANK 函数

```sql
-- 适用于 MySQL 8.0+

SELECT 
    period_state,
    MIN(date) AS start_date,
    MAX(date) AS end_date
FROM (
    SELECT 
        period_state,
        date,
        SUBDATE(date, RANK() OVER (PARTITION BY period_state ORDER BY date)) AS grp
    FROM (
        SELECT fail_date AS date, 'failed' AS period_state
        FROM Failed
        WHERE fail_date BETWEEN '2019-01-01' AND '2019-12-31'
        
        UNION ALL
        
        SELECT success_date AS date, 'succeeded' AS period_state
        FROM Succeeded
        WHERE success_date BETWEEN '2019-01-01' AND '2019-12-31'
    ) AS t
) AS grouped
GROUP BY period_state, grp
ORDER BY start_date;
```

### 方法三：PostgreSQL 版本

```sql
-- PostgreSQL 特定语法

WITH combined AS (
    SELECT fail_date AS dt, 'failed' AS state
    FROM Failed
    WHERE fail_date BETWEEN '2019-01-01' AND '2019-12-31'
    
    UNION ALL
    
    SELECT success_date AS dt, 'succeeded' AS state
    FROM Succeeded
    WHERE success_date BETWEEN '2019-01-01' AND '2019-12-31'
),
ranked AS (
    SELECT 
        state,
        dt,
        dt - (ROW_NUMBER() OVER (PARTITION BY state ORDER BY dt))::INTEGER * INTERVAL '1 day' AS grp
    FROM combined
)
SELECT 
    state AS period_state,
    MIN(dt) AS start_date,
    MAX(dt) AS end_date
FROM ranked
GROUP BY state, grp
ORDER BY start_date;
```

## 复杂度分析

- 时间复杂度：O(n log n)，其中 n 是记录总数，主要开销在排序和窗口函数
- 空间复杂度：O(n)，需要存储中间结果

## 关键点总结

1. 识别连续区间的核心技巧：日期 - 行号 = 分组标识
2. 使用 UNION ALL 合并两个表的数据
3. PARTITION BY 按状态分区，确保不同状态的日期分开编号
4. 使用 MIN 和 MAX 聚合函数获取区间的起止日期
5. 注意过滤 2019 年的数据

## 易错点

1. 忘记过滤 2019 年的数据范围
2. 使用 UNION 而不是 UNION ALL（UNION 会去重，可能影响结果）
3. 忘记在窗口函数中按状态分区
4. 日期计算时单位不正确（DAY、DAYS、INTERVAL 的使用）
5. 最后忘记按 start_date 排序
