## 题目描述

表：`Purchases`

```
+-------------+----------+
| Column Name | Type     |
+-------------+----------+
| user_id     | int      |
| time_stamp  | datetime |
| amount      | int      |
+-------------+----------+
(user_id, time_stamp) 是该表的主键。
```

编写一个 SQL 查询，找出满足以下条件的用户：在 `[startDate, endDate]` 之间（包含端点），进行了至少一次金额**严格小于** `minAmount` 的购买。

返回这些用户的 `user_id`，按升序排列。

函数定义：
```sql
CREATE PROCEDURE getUserIDs(startDate DATE, endDate DATE, minAmount INT)
BEGIN
  -- 返回满足条件的用户
END
```

**注意：** 本题（2230）与 2205 类似但以存储过程的形式实现，或作为普通查询题。

## 解题思路

筛选条件：
1. `time_stamp` 在 `[startDate, endDate]` 之间。
2. `amount < minAmount`（严格小于）。
3. 对 `user_id` 去重，按升序排列。

## 代码实现

### 方法一：存储过程（如果题目要求）

```sql
CREATE PROCEDURE getUserIDs(startDate DATE, endDate DATE, minAmount INT)
BEGIN
    SELECT DISTINCT user_id
    FROM Purchases
    WHERE DATE(time_stamp) BETWEEN startDate AND endDate
      AND amount < minAmount
    ORDER BY user_id;
END
```

### 方法二：普通 SELECT 查询

```sql
-- 直接查询满足条件的用户
SELECT DISTINCT user_id
FROM Purchases
WHERE DATE(time_stamp) BETWEEN '2022-03-08' AND '2022-03-20'
  AND amount < 1000
ORDER BY user_id;
```

### 方法三：使用子查询

```sql
SELECT user_id
FROM (
    SELECT DISTINCT user_id
    FROM Purchases
    WHERE DATE(time_stamp) BETWEEN startDate AND endDate
      AND amount < minAmount
) t
ORDER BY user_id;
```

## 复杂度分析

- 时间复杂度：O(n log n)，排序操作。
- 空间复杂度：O(k)，k 为满足条件的用户数。

## 关键点总结

1. `amount < minAmount` 严格小于，不包含等于。
2. `DATE(time_stamp)` 将 DATETIME 转为 DATE 后与边界比较。
3. `DISTINCT` 去重，同一用户多次购买只算一次。
4. `ORDER BY user_id` 升序排列。

## 易错点

- `time_stamp` 是 DATETIME，直接用 `BETWEEN date1 AND date2` 时，`date2 00:00:00` 可能遗漏当天后续时间，需用 `DATE()` 函数转换。
- 严格小于不要写成 `<=`。
