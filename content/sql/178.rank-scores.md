## 题目描述

表：`Scores`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| score       | decimal |
+-------------+---------+
```

id 是这个表的主键。
表的每一行都包含了一场比赛的分数。Score 是一个有两位小数点的浮点值。

编写 SQL 查询对分数进行排序。排名按以下规则计算:

- 分数应按从高到低排列。
- 如果两个分数相等，那么两个分数的排名应该相同。
- 在排名相同的分数后，排名数应该是下一个连续的整数。换句话说，排名之间不应该有空缺的数字。

按 `score` 降序返回结果表。

查询结果格式如下所示。

**示例 1：**

```
输入：
Scores 表：
+----+-------+
| id | score |
+----+-------+
| 1  | 3.50  |
| 2  | 3.65  |
| 3  | 4.00  |
| 4  | 3.85  |
| 5  | 4.00  |
| 6  | 3.65  |
+----+-------+

输出：
+-------+------+
| score | rank |
+-------+------+
| 4.00  | 1    |
| 4.00  | 1    |
| 3.85  | 2    |
| 3.65  | 3    |
| 3.65  | 3    |
| 3.50  | 4    |
+-------+------+
```

## 解题思路

这是一道经典的排名问题，关键要求：
1. 相同分数排名相同
2. 排名连续无间隙（例如：1, 1, 2, 3，而不是 1, 1, 3, 4）

这种排名规则对应 SQL 的 **DENSE_RANK()** 函数。

**排名函数对比：**
- `ROW_NUMBER()`：1, 2, 3, 4, 5, 6（每行唯一，不考虑相同值）
- `RANK()`：1, 1, 3, 4, 4, 6（有间隙）
- `DENSE_RANK()`：1, 1, 2, 3, 3, 4（无间隙，符合题意）

## SQL 代码实现

### 方法一：DENSE_RANK 窗口函数（推荐）

```sql
SELECT 
    score,
    DENSE_RANK() OVER (ORDER BY score DESC) AS 'rank'
FROM 
    Scores
ORDER BY 
    score DESC;
```

**代码解释：**
1. `DENSE_RANK() OVER (ORDER BY score DESC)`：按分数降序计算密集排名
2. `AS 'rank'`：列名为 rank（需要用引号，因为 rank 是 SQL 关键字）
3. `ORDER BY score DESC`：最终结果按分数降序排列

### 方法二：自连接计数（无窗口函数）

```sql
SELECT 
    s1.score,
    (SELECT COUNT(DISTINCT s2.score) 
     FROM Scores s2 
     WHERE s2.score >= s1.score) AS 'rank'
FROM 
    Scores s1
ORDER BY 
    s1.score DESC;
```

**代码解释：**
1. 对于每个分数 `s1.score`，统计大于等于它的不同分数个数
2. 这个个数就是该分数的排名
3. 例如：分数 3.65，有 4.00、3.85、3.65 三个不同分数 >= 它，排名为 3

### 方法三：变量模拟排名

```sql
SELECT 
    score,
    CASE 
        WHEN @prev_score = score THEN @rank
        WHEN @prev_score := score THEN @rank := @rank + 1
    END AS 'rank'
FROM 
    Scores,
    (SELECT @rank := 0, @prev_score := NULL) AS init
ORDER BY 
    score DESC;
```

**代码解释：**
1. `@rank` 存储当前排名，`@prev_score` 存储上一个分数
2. 如果当前分数等于上一个分数，排名不变
3. 如果当前分数不同，排名加 1
4. 注意：需要先按 score 降序排列

### 方法四：子查询 + COUNT DISTINCT

```sql
SELECT 
    s1.score,
    COUNT(DISTINCT s2.score) AS 'rank'
FROM 
    Scores s1
JOIN 
    Scores s2 ON s1.score <= s2.score
GROUP BY 
    s1.id, s1.score
ORDER BY 
    s1.score DESC;
```

**代码解释：**
1. 通过 JOIN 连接所有分数大于等于当前分数的记录
2. `COUNT(DISTINCT s2.score)` 统计有多少个不同的更高分数
3. `GROUP BY s1.id, s1.score` 对每条记录分组统计

## 复杂度分析

**方法一（DENSE_RANK）：**
- 时间复杂度：O(n log n)，排序开销
- 空间复杂度：O(n)，存储排名结果
- 优点：代码简洁，性能最优，最推荐

**方法二（自连接计数）：**
- 时间复杂度：O(n²)，每行都需要全表扫描
- 空间复杂度：O(1)
- 缺点：性能差，数据量大时不推荐

**方法三（变量）：**
- 时间复杂度：O(n log n)
- 空间复杂度：O(1)
- 注意：在新版 MySQL 中，变量赋值顺序可能不确定

**方法四（JOIN + COUNT）：**
- 时间复杂度：O(n²)
- 空间复杂度：O(n²)，JOIN 产生大量中间结果
- 缺点：性能最差

## 关键点总结

1. **DENSE_RANK 是最佳选择**：专门为连续排名设计，代码简洁性能好
2. **理解三种排名函数**：
   - ROW_NUMBER：唯一行号
   - RANK：有间隙排名
   - DENSE_RANK：无间隙排名
3. **rank 是关键字**：列名必须用引号 `'rank'` 或反引号 `` `rank` ``
4. **排序两次**：窗口函数内排序计算排名，外层排序展示结果
5. **性能考虑**：优先使用窗口函数，避免子查询和自连接

## 易错点

1. **使用 RANK 而不是 DENSE_RANK**
   ```sql
   -- 错误：会产生间隙
   RANK() OVER (ORDER BY score DESC)
   -- 结果：1, 1, 3, 4, 4, 6（不符合题意）
   
   -- 正确：无间隙
   DENSE_RANK() OVER (ORDER BY score DESC)
   -- 结果：1, 1, 2, 3, 3, 4
   ```

2. **列名未加引号**
   ```sql
   -- 错误：rank 是 SQL 关键字，直接使用可能报错
   AS rank
   
   -- 正确：加引号或反引号
   AS 'rank'  或  AS `rank`
   ```

3. **自连接条件错误**
   ```sql
   -- 错误：应该是 >=，不是 >
   WHERE s2.score > s1.score
   
   -- 正确：需要包含自己
   WHERE s2.score >= s1.score
   ```

4. **忘记 DISTINCT**
   ```sql
   -- 错误：没有去重，相同分数会被重复计数
   SELECT COUNT(s2.score) ...
   
   -- 正确：必须去重
   SELECT COUNT(DISTINCT s2.score) ...
   ```

5. **变量初始化位置**
   ```sql
   -- 错误：变量未初始化
   SELECT score, @rank ...
   
   -- 正确：在 FROM 子句中初始化
   FROM Scores, (SELECT @rank := 0, @prev_score := NULL) AS init
   ```
