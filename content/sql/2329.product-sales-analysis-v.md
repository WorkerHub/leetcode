## 题目描述

表 `Sales` 结构如下：

| Column Name | Type |
|-------------|------|
| sale_id     | int  |
| product_id  | int  |
| user_id     | int  |
| quantity    | int  |

`sale_id` 是该表的主键。

表 `Product` 结构如下：

| Column Name | Type |
|-------------|------|
| product_id  | int  |
| price       | int  |

`product_id` 是该表的主键。

查询每个用户的**总花费**（所有购买的总金额），返回 `user_id` 和 `spending`，按 `spending` 降序排列，若 `spending` 相同则按 `user_id` 升序排列。

花费 = `quantity * price`。

## 解题思路

JOIN Sales 与 Product，计算每笔销售的花费，按用户分组求总花费。

## 代码实现

### 方法一：JOIN + GROUP BY（推荐）

```sql
SELECT 
    s.user_id,
    SUM(s.quantity * p.price) AS spending
FROM Sales s
JOIN Product p ON s.product_id = p.product_id
GROUP BY s.user_id
ORDER BY spending DESC, user_id ASC
```

### 方法二：子查询方式

```sql
SELECT 
    user_id,
    SUM(spend) AS spending
FROM (
    SELECT 
        s.user_id,
        s.quantity * p.price AS spend
    FROM Sales s
    INNER JOIN Product p USING (product_id)
) t
GROUP BY user_id
ORDER BY spending DESC, user_id ASC
```

## 复杂度分析

| 方法 | 时间复杂度 | 空间复杂度 |
|------|-----------|-----------|
| JOIN + GROUP BY | O(n log n) | O(n) |

## 关键点总结

1. 连接两表后按 `user_id` 分组，用 `SUM` 累计每个用户的总花费。
2. 排序：先按花费降序，再按 user_id 升序。
3. `USING (product_id)` 是 `ON s.product_id = p.product_id` 的简写（两表有同名列时可用）。

## 易错点

- 同一用户可能多次购买，需要 GROUP BY 而不是直接查询。
- 排序条件是双重的：花费降序 + user_id 升序。
