## 题目描述

**表：Steps**

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| user_id     | int     |
| steps_count | int     |
| steps_date  | date    |
+-------------+---------+
(user_id, steps_date) 是主键。
```

计算每个用户**每三天的滚动平均步数**（当天及前两天的平均）。

只返回满足连续三天有记录的行（即至少有前两天的记录）。

按 user_id 升序，steps_date 升序排列。保留两位小数。

**示例：**
```
输入：
Steps 表（部分）：
+---------+-------------+------------+
| user_id | steps_count | steps_date |
+---------+-------------+------------+
| 1       | 687         | 2021-09-02 |
| 1       | 395         | 2021-09-04 |
| 1       | 562         | 2021-09-05 |
| 1       | 153         | 2021-09-06 |
...
输出：
+---------+------------+-----------+
| user_id | steps_date | rolling_average |
+---------+------------+-----------+
| 1       | 2021-09-06 | 370.00    |
...
```

## 解题思路

使用**窗口函数**（WINDOW FUNCTION）：
- `AVG(steps_count) OVER (PARTITION BY user_id ORDER BY steps_date ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)`

但需要保证三天是**连续的日期**（不是任意三行），需要额外判断。

判断是否为连续三天：当前行的日期 - 两行前的日期 = 2 天。

## 代码实现

### SQL 解法（窗口函数）

```sql
WITH rolling AS (
    SELECT 
        user_id,
        steps_date,
        steps_count,
        AVG(steps_count) OVER (
            PARTITION BY user_id 
            ORDER BY steps_date 
            ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
        ) AS rolling_avg,
        -- 检查是否有足够的连续行
        ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY steps_date) AS rn,
        LAG(steps_date, 2) OVER (PARTITION BY user_id ORDER BY steps_date) AS two_days_ago
    FROM Steps
)
SELECT 
    user_id,
    steps_date,
    ROUND(rolling_avg, 2) AS rolling_average
FROM rolling
WHERE rn >= 3 
  AND DATEDIFF(steps_date, two_days_ago) = 2  -- 确保三天连续
ORDER BY user_id, steps_date;
```

## 复杂度分析

- 时间复杂度：O(n log n)，排序操作
- 空间复杂度：O(n)

## 关键点总结

1. 滚动平均：使用窗口函数 `ROWS BETWEEN 2 PRECEDING AND CURRENT ROW`
2. 需额外判断三天连续：用 `LAG` 获取两行前的日期，检查 `DATEDIFF = 2`
3. 按 user_id 分区，按日期排序

## 易错点

1. 窗口函数的 3 行滑动不等于连续三天（日期可能有间隔）
2. `DATEDIFF(later, earlier) = 2` 表示相差 2 天（三天连续）
3. 结果精确到两位小数：`ROUND(avg, 2)`
