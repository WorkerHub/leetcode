## 题目描述

表：`Actions`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| user_id       | int     |
| post_id       | int     |
| action_date   | date    |
| action        | enum    |
| extra         | varchar |
+---------------+---------+
该表可能包含重复的行。
action 列是一个枚举类型，包含：('view', 'like', 'reaction', 'comment', 'report', 'share')
extra 列是可选信息，例如报告的原因或反应类型。
```

编写一个 SQL 查询，报告每种报告原因（report reason）在昨天的报告数量。假设今天是 `2019-07-05`。

返回结果表无顺序要求。

查询结果格式如下所示。

**示例：**

输入：
```
Actions 表：
+---------+---------+-------------+--------+--------+
| user_id | post_id | action_date | action | extra  |
+---------+---------+-------------+--------+--------+
| 1       | 1       | 2019-07-04  | view   | null   |
| 1       | 1       | 2019-07-04  | like   | null   |
| 2       | 2       | 2019-07-04  | report | spam   |
| 3       | 4       | 2019-07-04  | view   | null   |
| 3       | 4       | 2019-07-04  | report | spam   |
| 4       | 3       | 2019-07-04  | view   | null   |
| 5       | 2       | 2019-07-04  | report | racism |
| 5       | 5       | 2019-07-04  | view   | null   |
| 6       | 4       | 2019-07-04  | report | spam   |
+---------+---------+-------------+--------+--------+
```

输出：
```
+---------------+--------------+
| report_reason | report_count |
+---------------+--------------+
| spam          | 2            |
| racism        | 1            |
+---------------+--------------+
```

解释：
- 注意：我们只关心报告数量，而不是报告的帖子数量
- 虽然帖子 2 被报告了两次（用户 2 和用户 5），但它们的原因不同
- 帖子 4 被报告了两次 spam，所以 spam 的计数是 2（需要去重处理取决于具体需求）

## 解题思路

这道题的关键点：
1. 筛选出昨天（2019-07-04）的数据
2. 只关注 `action = 'report'` 的记录
3. 按报告原因（extra 字段）分组统计

**注意事项：**
- 题目说"报告数量"而不是"报告的帖子数量"，意味着可能需要去重
- 但根据示例，spam 计数为 2（帖子 4 被报告 2 次），说明不需要去重帖子

## SQL 代码实现

### 方法一：直接分组统计（标准解法）

```sql
SELECT 
    extra AS report_reason,
    COUNT(DISTINCT post_id) AS report_count
FROM 
    Actions
WHERE 
    action = 'report'
    AND action_date = '2019-07-04'
GROUP BY 
    extra;
```

### 方法二：不去重版本

```sql
-- 如果题目要求统计报告次数而非报告的帖子数
SELECT 
    extra AS report_reason,
    COUNT(*) AS report_count
FROM 
    Actions
WHERE 
    action = 'report'
    AND action_date = '2019-07-04'
GROUP BY 
    extra;
```

### 方法三：使用 DATE_SUB 计算昨天

```sql
-- 动态计算昨天的日期
SELECT 
    extra AS report_reason,
    COUNT(DISTINCT post_id) AS report_count
FROM 
    Actions
WHERE 
    action = 'report'
    AND action_date = DATE_SUB('2019-07-05', INTERVAL 1 DAY)
GROUP BY 
    extra;
```

### 方法四：使用 DATEDIFF

```sql
-- 使用日期差来筛选昨天
SELECT 
    extra AS report_reason,
    COUNT(DISTINCT post_id) AS report_count
FROM 
    Actions
WHERE 
    action = 'report'
    AND DATEDIFF('2019-07-05', action_date) = 1
GROUP BY 
    extra;
```

## 复杂度分析

- 时间复杂度：O(n log n)，其中 n 是表中的记录数。主要开销在于分组和排序（如果有的话）。
- 空间复杂度：O(k)，其中 k 是不同报告原因的数量。

## 关键点总结

1. **日期筛选**：确保只统计指定日期（昨天）的数据
2. **动作类型过滤**：只关注 `action = 'report'` 的记录
3. **分组字段**：按 `extra` 字段分组，它存储了报告原因
4. **去重考虑**：
   - `COUNT(DISTINCT post_id)`：统计不同帖子数
   - `COUNT(*)`：统计报告总次数
   - 根据题目要求选择合适的方式
5. **NULL 处理**：如果 extra 可能为 NULL，需要考虑是否过滤

## 易错点

1. **忘记过滤日期**：必须添加 `action_date = '2019-07-04'` 条件

2. **忘记过滤动作类型**：必须添加 `action = 'report'` 条件

3. **去重问题**：
   - 需要根据题目要求判断是否去重
   - 示例中 spam 为 2，说明可能不需要去重
   - 但通常统计"报告数"意味着去重帖子

4. **字段命名**：
   - 输出列名必须是 `report_reason` 和 `report_count`
   - 需要使用 `AS` 重命名

5. **空值处理**：
   - extra 字段可能为 NULL
   - 根据实际需求决定是否过滤 NULL

## 学习建议

1. **掌握日期函数**：
   - `DATE_SUB(date, INTERVAL n DAY)`：日期减法
   - `DATE_ADD(date, INTERVAL n DAY)`：日期加法
   - `DATEDIFF(date1, date2)`：计算日期差
   - `CURDATE()`：获取当前日期

2. **理解 COUNT 的变体**：
   - `COUNT(*)`：统计所有行
   - `COUNT(column)`：统计非 NULL 值
   - `COUNT(DISTINCT column)`：统计不同的值

3. **分组聚合模式**：
   ```sql
   SELECT 
       分组字段,
       聚合函数(列)
   FROM 表
   WHERE 过滤条件
   GROUP BY 分组字段;
   ```

4. **NULL 值处理**：
   - 使用 `IS NULL` 或 `IS NOT NULL` 判断
   - 使用 `COALESCE(column, default)` 提供默认值
   - 使用 `IFNULL(column, default)` （MySQL）

5. **实践建议**：
   - 先写出基本查询，再添加条件
   - 分步骤测试：先过滤，再分组，最后聚合
   - 使用小数据集验证逻辑

6. **性能优化**：
   - 在 `action_date` 和 `action` 列上建立索引
   - 先过滤再分组，减少数据量
   - 避免不必要的 DISTINCT 操作
