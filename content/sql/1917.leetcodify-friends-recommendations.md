## 题目描述

表 `Listens`：
```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| user_id     | int     |
| song_id     | int     |
| day         | date    |
+-------------+---------+
该表可能有重复行。
```

表 `Friendship`：
```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| user1_id      | int     |
| user2_id      | int     |
+---------------+---------+
(user1_id, user2_id) 是主键，user1_id < user2_id。
```

为用户推荐朋友：如果用户 `x` 和用户 `y` **不是朋友**，但在**同一天**听了**至少 3 首相同的歌曲**，则推荐 `y` 成为 `x` 的朋友（反之亦然）。

结果表中每对 `(user_id, friend_id)` 只出现一次，且 `user_id < friend_id`。

返回结果按 `(user_id, friend_id)` 升序排列。

---

## 解题思路

### 核心思想：自连接找共同听歌日 + 过滤已有朋友

1. 对 `Listens` 表按 `(user_id, song_id, day)` 去重（避免重复听同一首歌被重复计数）
2. 自连接：找同一天听了同一首歌的不同用户对
3. 按 `(user1, user2, day)` 分组，统计共同歌曲数 >= 3
4. 排除已经是朋友的用户对（NOT IN Friendship）

---

## 代码实现

### 方法一：子查询 + NOT IN（推荐）

```sql
-- 第一步：去重后的听歌记录
WITH distinct_listens AS (
    SELECT DISTINCT user_id, song_id, day
    FROM Listens
),
-- 第二步：找同一天听了相同歌曲的用户对
same_day_songs AS (
    SELECT
        l1.user_id AS user1,
        l2.user_id AS user2,
        l1.day,
        COUNT(*) AS common_songs
    FROM distinct_listens l1
    JOIN distinct_listens l2
        ON l1.song_id = l2.song_id
        AND l1.day = l2.day
        AND l1.user_id < l2.user_id  -- 避免重复对，保证 user1 < user2
    GROUP BY l1.user_id, l2.user_id, l1.day
    HAVING COUNT(*) >= 3
),
-- 第三步：从中选出至少有一天共听 3 首的不重复用户对
candidates AS (
    SELECT DISTINCT user1, user2
    FROM same_day_songs
)
-- 第四步：排除已经是朋友的对
SELECT user1 AS user_id, user2 AS friend_id
FROM candidates
WHERE (user1, user2) NOT IN (
    SELECT user1_id, user2_id FROM Friendship
)
ORDER BY user_id, friend_id;
```

### 方法二：LEFT JOIN 排除朋友（替代 NOT IN）

```sql
WITH distinct_listens AS (
    SELECT DISTINCT user_id, song_id, day FROM Listens
),
same_day AS (
    SELECT
        l1.user_id AS u1,
        l2.user_id AS u2,
        l1.day,
        COUNT(*) AS cnt
    FROM distinct_listens l1
    JOIN distinct_listens l2
        ON l1.song_id = l2.song_id
        AND l1.day = l2.day
        AND l1.user_id < l2.user_id
    GROUP BY l1.user_id, l2.user_id, l1.day
    HAVING COUNT(*) >= 3
),
candidates AS (
    SELECT DISTINCT u1, u2 FROM same_day
)
SELECT c.u1 AS user_id, c.u2 AS friend_id
FROM candidates c
LEFT JOIN Friendship f
    ON c.u1 = f.user1_id AND c.u2 = f.user2_id
WHERE f.user1_id IS NULL  -- 不是朋友
ORDER BY user_id, friend_id;
```

## 复杂度分析

| 操作 | 说明 |
|------|------|
| distinct_listens | 对 Listens 表去重 |
| 自连接 | 同一天同一首歌的用户对，O(n²) 最坏 |
| 过滤友谊 | 与 Friendship 表对比 |

---

## 关键点总结

1. 先对 Listens 去重（同用户同天同歌只算一次）
2. 自连接时用 `l1.user_id < l2.user_id` 保证 user1 < user2 且不重复
3. 最终排除已有朋友关系的用户对

---

## 易错点

- 不去重会导致同天听同首歌多次被重复计数，结果偏大
- `NOT IN` 遇到 NULL 会产生问题，建议用 LEFT JOIN 方法
