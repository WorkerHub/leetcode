## 题目描述

表：`Views`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| article_id    | int     |
| author_id     | int     |
| viewer_id     | int     |
| view_date     | date    |
+---------------+---------+
此表无主键,可能会有重复行。
此表的每一行都表示某人在某天浏览了某位作者的某篇文章。
```

编写一个 SQL 查询来找出在同一天浏览了多于一篇文章的所有用户,结果按照 `viewer_id` 升序排序。

查询结果格式如下例所示:

**示例 1:**

```
输入:
Views 表:
+------------+-----------+-----------+------------+
| article_id | author_id | viewer_id | view_date  |
+------------+-----------+-----------+------------+
| 1          | 3         | 5         | 2019-08-01 |
| 3          | 4         | 5         | 2019-08-01 |
| 1          | 3         | 6         | 2019-08-02 |
| 2          | 7         | 7         | 2019-08-01 |
| 2          | 7         | 6         | 2019-08-02 |
| 4          | 7         | 1         | 2019-07-22 |
| 3          | 4         | 4         | 2019-07-21 |
| 3          | 4         | 4         | 2019-07-21 |
+------------+-----------+-----------+------------+

输出:
+-------------+
| id          |
+-------------+
| 5           |
+-------------+
解释:
用户 5 在 2019-08-01 浏览了文章 1 和 3,共 2 篇文章。
```

## 解题思路

这道题的核心思想是:
1. 按照 `viewer_id` 和 `view_date` 分组
2. 统计每个分组内不同 `article_id` 的数量
3. 筛选出数量大于 1 的记录
4. 返回对应的 `viewer_id`

关键观察:
- 需要去重,因为同一用户在同一天可能多次浏览同一篇文章
- 使用 `COUNT(DISTINCT article_id)` 统计不同文章数
- `HAVING` 子句用于过滤分组后的结果

## SQL 代码实现

### 方法一: GROUP BY + HAVING(推荐)

```sql
SELECT DISTINCT viewer_id AS id
FROM Views
GROUP BY viewer_id, view_date
HAVING COUNT(DISTINCT article_id) > 1
ORDER BY viewer_id;
```

### 方法二: 子查询方式

```sql
SELECT DISTINCT viewer_id AS id
FROM (
    SELECT viewer_id, view_date, COUNT(DISTINCT article_id) AS article_count
    FROM Views
    GROUP BY viewer_id, view_date
) AS t
WHERE article_count > 1
ORDER BY viewer_id;
```

## 复杂度分析

**时间复杂度**: O(n log n)
- n 为表中的记录数
- GROUP BY 操作需要 O(n) 时间
- ORDER BY 排序需要 O(k log k) 时间,k 为结果集大小

**空间复杂度**: O(n)
- 需要存储分组结果和去重后的数据

## 关键点总结

1. 使用 `COUNT(DISTINCT article_id)` 统计不重复的文章数
2. `GROUP BY` 同时按照用户和日期分组
3. `HAVING` 子句用于筛选分组后满足条件的记录
4. 最外层使用 `DISTINCT` 确保用户 ID 不重复
5. 记得按照 `viewer_id` 升序排序

## 易错点

1. 忘记使用 `DISTINCT` 统计文章数,导致同一文章被重复计数
2. 忘记在最外层使用 `DISTINCT`,导致同一用户出现多次
3. 分组条件错误,只按 `viewer_id` 分组而忘记按日期分组
4. 使用 `WHERE` 而不是 `HAVING` 来过滤分组结果
5. 忘记排序或排序字段错误
