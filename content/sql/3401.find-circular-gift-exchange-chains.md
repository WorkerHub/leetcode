## 题目描述

表 `SecretSanta`：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| giver_id    | int     |
| receiver_id | int     |
+-------------+---------+
```

`giver_id` 是主键。每行表示 `giver_id` 将礼物送给 `receiver_id`。

找出所有循环礼物交换链，返回链的长度以及链中涉及的用户数量。循环链是指从某个用户出发，沿着送礼关系最终回到该用户本身。

结果按链长度升序排列。

**示例：**

输入：
```
+-----------+-------------+
| giver_id  | receiver_id |
+-----------+-------------+
| 1         | 2           |
| 2         | 3           |
| 3         | 1           |
| 4         | 5           |
| 5         | 4           |
+-----------+-------------+
```

输出：
```
+-------------+---------------+
| chain_length| num_of_users  |
+-------------+---------------+
| 2           | 2             |
| 3           | 3             |
+-------------+---------------+
```

**提示：**
- 每个 giver 只送一份礼物
- 每个 receiver 只收一份礼物
- 数据保证所有节点都在某个循环中

## 解题思路

利用递归公共表表达式（Recursive CTE）从每个节点出发追踪路径，直到形成回路。为避免重复计数，规定每条链只从链中最小 ID 的节点开始统计。

核心步骤：
1. 使用递归 CTE 从每个 giver 出发，沿 receiver 方向遍历
2. 记录起始节点和当前节点，当当前节点等于起始节点时即形成一个环
3. 限制只从最小节点 ID 出发，防止同一环被多次计数
4. 按链长分组统计

## SQL 代码实现

### 方法一：递归 CTE（推荐）

```sql
WITH RECURSIVE chain AS (
    -- 初始化：每个人作为链的起点
    SELECT
        giver_id AS start_id,
        receiver_id AS current_id,
        1 AS chain_length
    FROM SecretSanta

    UNION ALL

    -- 递归：沿着送礼关系继续追踪
    SELECT
        c.start_id,
        s.receiver_id AS current_id,
        c.chain_length + 1
    FROM chain c
    JOIN SecretSanta s ON c.current_id = s.giver_id
    -- 当回到起点时停止，或防止无限递归
    WHERE c.current_id != c.start_id
),
-- 找出完整的环：当前节点回到起点
cycles AS (
    SELECT
        start_id,
        chain_length
    FROM chain
    WHERE current_id = start_id
),
-- 找出每个环中最小的 start_id，避免重复计数
unique_cycles AS (
    SELECT chain_length, COUNT(*) AS num_of_users
    FROM (
        SELECT chain_length, start_id
        FROM cycles c1
        WHERE start_id = (
            -- 只保留链中最小 ID 的起点
            SELECT MIN(c2.start_id)
            FROM cycles c2
            WHERE c2.chain_length = c1.chain_length
              AND c2.start_id <= c1.start_id
            -- 这里需要确认是同一个环
        )
    ) t
    GROUP BY chain_length
)
SELECT chain_length, num_of_users
FROM unique_cycles
ORDER BY chain_length;
```

### 方法二：使用连通分量思想

```sql
WITH RECURSIVE chain AS (
    SELECT
        giver_id AS start_id,
        receiver_id AS current_id,
        1 AS depth,
        CAST(giver_id AS CHAR(1000)) AS path
    FROM SecretSanta

    UNION ALL

    SELECT
        c.start_id,
        s.receiver_id,
        c.depth + 1,
        CONCAT(c.path, ',', s.receiver_id)
    FROM chain c
    JOIN SecretSanta s ON c.current_id = s.giver_id
    WHERE c.current_id != c.start_id
      AND c.depth < 1000
),
complete_chains AS (
    SELECT start_id, depth AS chain_length
    FROM chain
    WHERE current_id = start_id
),
-- 每个环只由最小 start_id 代表
representative AS (
    SELECT chain_length, MIN(start_id) AS rep_id
    FROM complete_chains
    GROUP BY chain_length
)
SELECT
    cc.chain_length,
    COUNT(*) AS num_of_users
FROM complete_chains cc
JOIN representative r
    ON cc.chain_length = r.chain_length
   AND cc.start_id >= r.rep_id
GROUP BY cc.chain_length
ORDER BY cc.chain_length;
```

## 复杂度分析

- 时间复杂度：O(N * L)，N 为用户数，L 为最长环的长度
- 空间复杂度：O(N * L)，递归 CTE 中间状态

## 关键点总结

1. 递归 CTE 是处理图中路径/环问题的标准 SQL 工具
2. 必须防止重复计数——同一个环可以从任意节点出发，需要选定唯一代表
3. 终止条件是当前节点回到起点（current_id = start_id）
4. 设置递归深度上限防止死循环

## 易错点

1. 递归 CTE 的终止条件必须完整，否则会无限递归
2. 同一个环被多个起点发现，需要去重（取最小 start_id）
3. MySQL 中需要 `WITH RECURSIVE` 关键字
