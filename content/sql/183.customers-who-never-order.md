## 题目描述

表：`Customers`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| name        | varchar |
+-------------+---------+
```

id 是该表主键。
该表的每一行都表示客户的 ID 和名称。

表：`Orders`

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| id          | int  |
| customerId  | int  |
+-------------+------+
```

id 是该表主键。
customerId 是来自 Customers 表的 ID。
该表的每一行都表示订单的 ID 和订购该订单的客户的 ID。

编写一个 SQL 查询，找出所有从不订购任何东西的客户。

以任意顺序返回结果表。

查询结果格式如下所示。

**示例 1：**

```
输入：
Customers 表：
+----+-------+
| id | name  |
+----+-------+
| 1  | Joe   |
| 2  | Henry |
| 3  | Sam   |
| 4  | Max   |
+----+-------+

Orders 表：
+----+------------+
| id | customerId |
+----+------------+
| 1  | 3          |
| 2  | 1          |
+----+------------+

输出：
+-----------+
| Customers |
+-----------+
| Henry     |
| Max       |
+-----------+
```

## 解题思路

这道题的核心是找出 **不存在于** Orders 表中的客户。有多种方法：

1. **NOT IN 子查询**：找出 ID 不在订单客户 ID 列表中的客户
2. **NOT EXISTS 子查询**：找出不存在订单记录的客户
3. **LEFT JOIN + NULL**：左连接后，订单为 NULL 的客户即为从未订购的客户

### 方法对比

- `NOT IN`：简洁直观，但有 NULL 陷阱
- `NOT EXISTS`：性能通常最好，推荐使用
- `LEFT JOIN`：直观易懂，适合初学者

## SQL 代码实现

### 方法一：NOT IN 子查询

```sql
SELECT 
    name AS Customers
FROM 
    Customers
WHERE 
    id NOT IN (
        SELECT customerId 
        FROM Orders
    );
```

**代码解释：**
1. 子查询：获取所有有订单的客户 ID
2. `NOT IN`：找出 ID 不在这个列表中的客户
3. 返回这些客户的姓名

**注意陷阱：** 如果 Orders 表中的 customerId 存在 NULL，`NOT IN` 会返回空结果！

**安全版本：**
```sql
SELECT 
    name AS Customers
FROM 
    Customers
WHERE 
    id NOT IN (
        SELECT customerId 
        FROM Orders
        WHERE customerId IS NOT NULL  -- 过滤 NULL
    );
```

### 方法二：NOT EXISTS 子查询（推荐）

```sql
SELECT 
    name AS Customers
FROM 
    Customers c
WHERE 
    NOT EXISTS (
        SELECT 1 
        FROM Orders o 
        WHERE o.customerId = c.id
    );
```

**代码解释：**
1. 对于每个客户 `c`，检查是否存在订单
2. `NOT EXISTS`：如果子查询返回空结果，条件为真
3. `SELECT 1`：只需要判断存在性，不需要返回具体数据（也可以用 `SELECT *`）

**优点：**
- 性能通常最好（可以提前终止）
- 不受 NULL 影响
- 逻辑清晰

### 方法三：LEFT JOIN + IS NULL

```sql
SELECT 
    c.name AS Customers
FROM 
    Customers c
LEFT JOIN 
    Orders o ON c.id = o.customerId
WHERE 
    o.customerId IS NULL;
```

**代码解释：**
1. `LEFT JOIN`：保留所有客户，即使没有匹配的订单
2. 没有订单的客户，`o.customerId` 为 `NULL`
3. `WHERE o.customerId IS NULL`：筛选出没有订单的客户

**也可以用 `o.id IS NULL`：**
```sql
WHERE o.id IS NULL;
```

### 方法四：使用 EXCEPT（某些数据库支持）

```sql
SELECT name AS Customers
FROM Customers
WHERE id IN (
    SELECT id FROM Customers
    EXCEPT
    SELECT customerId FROM Orders
);
```

**代码解释：**
1. `EXCEPT`：集合差运算，返回在第一个集合但不在第二个集合中的元素
2. 注意：MySQL 不支持 `EXCEPT`，PostgreSQL 和 SQL Server 支持

## 复杂度分析

**方法一（NOT IN）：**
- 时间复杂度：O(n × m)，n 是客户数，m 是订单数
- 空间复杂度：O(m)，存储子查询结果
- 缺点：有 NULL 陷阱，性能可能较差

**方法二（NOT EXISTS）：**
- 时间复杂度：O(n × m)，但可以提前终止（实际更快）
- 空间复杂度：O(1)，相关子查询
- 优点：性能最好，无 NULL 问题

**方法三（LEFT JOIN）：**
- 时间复杂度：O(n + m)，连接 + 筛选
- 空间复杂度：O(n + m)，连接结果
- 优点：直观易懂

**性能建议：**
- 小数据集：方法差异不大
- 大数据集：NOT EXISTS 通常最快
- 有索引：LEFT JOIN 和 NOT EXISTS 性能接近

## 关键点总结

1. **NOT IN 的 NULL 陷阱**：如果子查询结果包含 NULL，整个查询返回空
2. **NOT EXISTS 最安全**：不受 NULL 影响，性能通常最好
3. **LEFT JOIN 最直观**：容易理解，适合初学者
4. **列名要求**：输出列名必须是 `Customers`（首字母大写）
5. **索引优化**：在 `customerId` 和 `id` 上建立索引可提升性能

## 易错点

1. **NOT IN 的 NULL 陷阱**
   ```sql
   -- 如果 Orders 表中有 customerId = NULL 的记录
   -- 这个查询会返回空结果！
   WHERE id NOT IN (SELECT customerId FROM Orders);
   
   -- 原因：id NOT IN (1, 3, NULL) 等价于
   -- id != 1 AND id != 3 AND id != NULL
   -- 任何值与 NULL 比较都返回 NULL（不是 FALSE）
   -- NULL AND ... 结果还是 NULL（不是 TRUE）
   
   -- 安全写法：
   WHERE id NOT IN (SELECT customerId FROM Orders WHERE customerId IS NOT NULL);
   ```

2. **LEFT JOIN 后的 NULL 判断列选择**
   ```sql
   -- 错误：判断主表的列（c.id 永远不为 NULL）
   WHERE c.id IS NULL  -- 错误！
   
   -- 正确：判断从表的列
   WHERE o.customerId IS NULL  或  WHERE o.id IS NULL
   ```

3. **列名大小写**
   ```sql
   -- 错误：列名必须是 Customers
   SELECT name
   
   -- 正确：
   SELECT name AS Customers
   ```

4. **子查询忘记关联**
   ```sql
   -- 错误：子查询没有与外层关联（NOT EXISTS 失效）
   WHERE NOT EXISTS (
       SELECT 1 FROM Orders
   )  -- 这会判断 Orders 表是否为空，而不是判断特定客户
   
   -- 正确：必须关联
   WHERE NOT EXISTS (
       SELECT 1 FROM Orders o WHERE o.customerId = c.id
   )
   ```

5. **JOIN 类型错误**
   ```sql
   -- 错误：使用 INNER JOIN 会丢失没有订单的客户
   FROM Customers c
   INNER JOIN Orders o ON c.id = o.customerId
   WHERE o.id IS NULL  -- 永远为空，因为 INNER JOIN 已经排除了不匹配的行
   
   -- 正确：使用 LEFT JOIN
   LEFT JOIN Orders o ON c.id = o.customerId
   ```

## 图解示例

以示例数据为例：

```
Customers 表：
id  name
1   Joe    -> 有订单（订单 2）
2   Henry  -> 无订单 ✓
3   Sam    -> 有订单（订单 1）
4   Max    -> 无订单 ✓

Orders 表：
id  customerId
1   3          (Sam 的订单)
2   1          (Joe 的订单)

LEFT JOIN 结果：
c.id  c.name  o.id  o.customerId
1     Joe     2     1            -> o.customerId 不为 NULL，有订单
2     Henry   NULL  NULL         -> o.customerId 为 NULL，无订单 ✓
3     Sam     1     3            -> o.customerId 不为 NULL，有订单
4     Max     NULL  NULL         -> o.customerId 为 NULL，无订单 ✓

最终结果：
Customers
Henry
Max
```

## 学习建议

1. **理解三种查找"不存在"的方法**：
   - NOT IN：简单但有陷阱
   - NOT EXISTS：推荐，性能好
   - LEFT JOIN + NULL：直观

2. **掌握 NULL 的特性**：
   - 任何值与 NULL 比较都返回 NULL（不是 TRUE 也不是 FALSE）
   - `NULL AND TRUE = NULL`
   - `NULL OR TRUE = TRUE`
   - 使用 `IS NULL` / `IS NOT NULL` 判断

3. **实践练习**：
   - 构造包含 NULL 的测试数据，观察 NOT IN 的行为
   - 使用 EXPLAIN 比较不同方法的执行计划
   - 测试大数据集上的性能差异

4. **LEFT JOIN 理解**：
   - 画维恩图理解 LEFT JOIN
   - 理解为什么未匹配的行从表列为 NULL
   - 练习其他 JOIN 类型（RIGHT, FULL OUTER）

5. **性能优化**：
   - 在关联列上建立索引
   - 理解数据库如何执行子查询（物化 vs 相关）
   - 学习使用 EXPLAIN 分析查询

6. **面试技巧**：
   - 优先写 NOT EXISTS（展示对性能的关注）
   - 能够解释 NOT IN 的 NULL 陷阱
   - 能够用 LEFT JOIN 实现（展示对 JOIN 的理解）
   - 记得列名是 `Customers`

7. **扩展思考**：
   - 如何找出订购次数最多的客户？
   - 如何找出只订购过一次的客户？
   - 如何找出既没有订单也没有地址的客户？（多表关联）
