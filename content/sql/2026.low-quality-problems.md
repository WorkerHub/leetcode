## 题目描述

给你一张 `Problems` 表：

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| problem_id  | int  |
| likes       | int  |
| dislikes    | int  |
+-------------+------+
problem_id 是该表的主键
```

**低质量问题**定义为：点赞率（`likes / (likes + dislikes)`）**严格小于 60%** 的问题。

返回所有低质量问题的 `problem_id`，结果按 `problem_id` **升序**排列。

**示例：**
```
输入：
Problems 表：
+------------+-------+----------+
| problem_id | likes | dislikes |
+------------+-------+----------+
| 6          | 1290  | 425      |
| 11         | 2677  | 8659     |
| 1          | 4446  | 2760     |
| 7          | 8569  | 765      |
| 13         | 2050  | 571      |
| 10         | 9002  | 7894     |
+------------+-------+----------+

输出：
+------------+
| problem_id |
+------------+
| 10         |
| 11         |
+------------+
```

## 解题思路

计算每道题的点赞率，筛选点赞率 < 60% 的题目。用 `likes * 1.0 / (likes + dislikes)` 计算比例，或等价地用 `likes * 5 < likes + dislikes * 3`（整数运算，避免浮点数误差）。

## 代码实现

### 方法一：浮点数比较

```sql
SELECT problem_id
FROM Problems
WHERE likes / (likes + dislikes) < 0.6
ORDER BY problem_id
```

### 方法二：整数运算避免精度问题（推荐）

```sql
-- 等价变换：likes / (likes + dislikes) < 0.6
-- => likes < 0.6 * (likes + dislikes)
-- => likes * 10 < 6 * (likes + dislikes)
-- => 10 * likes < 6 * likes + 6 * dislikes
-- => 4 * likes < 6 * dislikes
-- => 2 * likes < 3 * dislikes
SELECT problem_id
FROM Problems
WHERE likes * 10 < (likes + dislikes) * 6
ORDER BY problem_id
```

### 方法三：HAVING 子句（配合聚合）

```sql
-- 直接用 WHERE 更简洁，HAVING 用于聚合后筛选
SELECT problem_id
FROM Problems
WHERE ROUND(likes * 100.0 / (likes + dislikes), 2) < 60.0
ORDER BY problem_id
```

## 复杂度分析

- 时间复杂度：O(n log n)，排序主导
- 空间复杂度：O(1)

## 关键点总结

1. 点赞率 = `likes / (likes + dislikes)`，严格小于 0.6（不含 60%）
2. 整数运算更安全，避免浮点精度问题
3. 结果按 `problem_id` 升序排列

## 易错点

- **严格小于** 60%（不包含等于 60% 的情况）
- 注意除零问题：若 `likes + dislikes = 0`，但题目保证合法数据，通常不需要处理
- 整数乘法避免 `/ (likes + dislikes)` 时的隐式整数除法（MySQL 中 `1/3 = 0`）
