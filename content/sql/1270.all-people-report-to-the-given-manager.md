## 题目描述

**表结构：Employees**

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| employee_id   | int     |
| employee_name | varchar |
| manager_id    | int     |
+---------------+---------+
employee_id 是主键。
manager_id 是 employee_id 的外键（自引用），表示该员工的直属上级。
```

**说明：**
- CEO 的 `employee_id = 1`，`manager_id = 1`（自引用）
- 一个员工直接或间接向 CEO（`manager_id = 1`）汇报

**任务：** 找出所有直接或间接向 `employee_id = 1` 的 CEO 汇报的员工（**不超过 3 层**），不包括 CEO 自身（`employee_id = 1`）。

**示例：**
```
输入：
Employees 表：
+-------------+---------------+------------+
| employee_id | employee_name | manager_id |
+-------------+---------------+------------+
| 1           | Boss          | 1          |  <- CEO
| 2           | Alice         | 1          |  <- 直接向 CEO 汇报（第1层）
| 3           | Bob           | 3          |  <- CEO（不对，看题，3直接向2汇报）
| 4           | Daniel        | 2          |  <- 通过 Alice 向 CEO 汇报（第2层）
| 7           | Luis          | 4          |  <- 第3层
| 8           | Jhon          | 3          |  <- 通过 Bob 向 Alice 汇报（第3层）
| 9           | Angela        | 11         |  <- manager_id=11 不存在，不能追溯到 CEO
| 11          | Ethan         | 7          |  <- 第4层，超出范围
+-------------+---------------+------------+

输出：
+-------------+
| employee_id |
+-------------+
| 2           |
| 77          |
| 4           |
| ...         |
+-------------+
```

**实际示例输出（以下是完整示例）：**

```
Employees 表：
+-------------+---------------+------------+
| employee_id | employee_name | manager_id |
+-------------+---------------+------------+
| 1           | Boss          | 1          |
| 2           | Alice         | 1          |
| 3           | Bob           | 2          |
| 4           | Daniel        | 2          |
| 7           | Luis          | 4          |
| 8           | John          | 3          |
| 9           | Angela        | 11         |
| 77          | Robert        | 1          |
+-------------+---------------+------------+

输出：
+-------------+
| employee_id |
+-------------+
| 2           |
| 77          |
| 3           |
| 4           |
| 7           |
| 8           |
+-------------+

解释：
  employee 9 的 manager_id = 11，11 没有汇报给 CEO 的路径，排除。
  employee 1 是 CEO 本身，排除。
  其余员工都在 3 层以内汇报给 CEO，包含在结果中。
```

---

## 解题思路

题目要求找出在 **3 层以内** 向 CEO（`employee_id = 1`）汇报的员工。

**层级定义：**
- 第 1 层：直接向 CEO 汇报（`manager_id = 1`）
- 第 2 层：向第 1 层员工汇报
- 第 3 层：向第 2 层员工汇报

**SQL 思路：自连接展开 3 层**

通过三次 JOIN 将 Employees 表与自身连接，逐层找出 manager：
- e1：员工本身
- e2：e1 的直属上级（e1.manager_id = e2.employee_id）
- e3：e2 的直属上级
- e4：e3 的直属上级（应为 CEO，即 employee_id = 1）

---

## SQL 解法

### 方法一：三次自连接（推荐）

```sql
SELECT DISTINCT e1.employee_id
FROM Employees e1
JOIN Employees e2 ON e1.manager_id = e2.employee_id   -- e1 的直属上级是 e2
JOIN Employees e3 ON e2.manager_id = e3.employee_id   -- e2 的直属上级是 e3
JOIN Employees e4 ON e3.manager_id = e4.employee_id   -- e3 的直属上级是 e4
WHERE e4.employee_id = 1        -- e4 就是 CEO
  AND e1.employee_id != 1       -- 排除 CEO 本身
```

**逻辑解析：**
```
e1 -> e2 -> e3 -> e4(=CEO)

对于 employee 2（Alice）：
  e1 = Alice(manager_id=1), e2 = Boss(1), e3 = Boss(1), e4 = Boss(1)
  e4.employee_id = 1 ✓

对于 employee 3（Bob）：
  e1 = Bob(manager_id=2), e2 = Alice(manager_id=1), e3 = Boss(1), e4 = Boss(1)
  e4.employee_id = 1 ✓

对于 employee 7（Luis）：
  e1 = Luis(manager_id=4), e2 = Daniel(manager_id=2), e3 = Alice(manager_id=1), e4 = Boss(1)
  e4.employee_id = 1 ✓

对于 employee 9（Angela，manager_id=11，11 不存在）：
  JOIN 失败，不出现在结果中 ✓
```

**为什么 CEO(employee_id=1) 自身会被排除：**
- CEO 的 manager_id = 1（自引用）
- e1=CEO, e2=CEO, e3=CEO, e4=CEO → e4.employee_id=1 会满足，但被 `e1.employee_id != 1` 过滤掉。

---

### 方法二：使用 WHERE IN 子查询（逐层展开）

```sql
-- 第1层：直接向 CEO 汇报
-- 第2层：向第1层汇报
-- 第3层：向第2层汇报
SELECT employee_id
FROM Employees
WHERE manager_id = 1 AND employee_id != 1  -- 第1层

UNION

SELECT employee_id
FROM Employees
WHERE manager_id IN (
    -- 第1层员工的 employee_id
    SELECT employee_id FROM Employees
    WHERE manager_id = 1 AND employee_id != 1
)

UNION

SELECT employee_id
FROM Employees
WHERE manager_id IN (
    -- 第2层员工的 employee_id
    SELECT employee_id FROM Employees
    WHERE manager_id IN (
        SELECT employee_id FROM Employees
        WHERE manager_id = 1 AND employee_id != 1
    )
)
```

**优点：** 逻辑清晰，按层级展开，易于理解。
**缺点：** 嵌套子查询较深，可读性稍差。

---

### 方法三：WITH RECURSIVE（通用递归 CTE，适用于不限层数的场景）

```sql
-- MySQL 8.0+ / PostgreSQL 支持递归 CTE
WITH RECURSIVE subordinates AS (
    -- 基础情况：CEO 本身
    SELECT employee_id, 0 AS level
    FROM Employees
    WHERE employee_id = 1

    UNION ALL

    -- 递归：找每一层的下属
    SELECT e.employee_id, s.level + 1
    FROM Employees e
    JOIN subordinates s ON e.manager_id = s.employee_id
    WHERE s.level < 3    -- 只展开到第3层
      AND e.employee_id != 1  -- 避免 CEO 自引用死循环
)
SELECT employee_id
FROM subordinates
WHERE employee_id != 1   -- 排除 CEO 本身
  AND level > 0          -- 排除 CEO（level=0）
```

**注意：** 递归 CTE 需要数据库支持（MySQL 8.0+、PostgreSQL、SQL Server 2005+），不适用于 MySQL 5.x。

## 复杂度分析

| 方法 | 时间复杂度 | 空间复杂度 | 备注 |
|------|-----------|-----------|------|
| 方法一（自连接） | O(n^3) | O(n) | n 为员工数，三次 JOIN |
| 方法二（子查询） | O(n^3) | O(n) | 逻辑等价，优化器可能相同 |
| 方法三（递归 CTE） | O(n × d) | O(n) | d 为展开层数，通用性最强 |

## 关键点总结

1. **题目限制为 3 层**：只需固定展开 3 次连接，不需要通用递归（方法一最简洁）。
2. **自连接的含义**：`e1.manager_id = e2.employee_id` 表示 e1 的上级是 e2，从员工向上追溯管理链。
3. **CEO 的自引用**：CEO 的 `manager_id = 1`（指向自身），需要在结果中用 `e1.employee_id != 1` 排除。
4. **INNER JOIN vs LEFT JOIN**：方法一使用 INNER JOIN，自然过滤掉中间某层找不到上级的员工（如 employee 9）。
5. **DISTINCT 的使用**：方法一中加 `DISTINCT` 避免重复（CEO 自引用可能导致同一员工被匹配多次）。

---

## 易错点

1. **忘记排除 CEO 本身**：CEO（employee_id=1）满足 e4.employee_id=1 的条件，但被 `e1.employee_id != 1` 过滤。如果忘记这个条件，CEO 会出现在结果中。
2. **理解 manager_id 的方向**：`manager_id` 是"上级的 employee_id"，连接方向是从员工指向上级，不要搞反。
3. **JOIN 的类型**：使用 INNER JOIN（默认），当某员工的上级不存在时，该员工不会出现在结果中——这正是我们需要的行为。
4. **方法二的重复问题**：UNION 默认去重，如果不需要去重可以用 UNION ALL（此题需要去重，用 UNION 正确）。
5. **递归 CTE 的终止条件**：方法三中 `WHERE s.level < 3` 限制展开层数，同时 `e.employee_id != 1` 防止 CEO 自引用导致死循环。

## 学习建议

1. **自连接（Self Join）**：本题是自连接的典型应用场景——表内部的层级关系（树形结构）。掌握自连接是处理"组织架构"、"层级分类"等问题的基础。
2. **递归 CTE 的适用性**：当层级不固定时，方法三（递归 CTE）更通用。学会 WITH RECURSIVE 是处理树形结构 SQL 查询的进阶技能。
3. **执行计划分析**：对于大数据量，方法一的三次 JOIN 可能较慢，可以在 employee_id 和 manager_id 上建立索引，或使用 EXPLAIN 分析执行计划。
4. **理解外键约束**：本题 manager_id 是 employee_id 的自引用外键，这种设计在表示"员工-上级"等层级关系时非常常见，是数据库设计的基础知识。
