## 题目描述

表 `Patients`：
```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| patient_id   | int     |
| patient_name | varchar |
| conditions   | varchar |
+--------------+---------+
```
`patient_id` 是主键。`conditions` 包含 0 个或以上的疾病代码，由空格分隔。

编写 SQL 查询，报告患有 I 类糖尿病（疾病代码以 `DIAB1` 开头）的病人的所有信息。

**示例：**
```
输入：
patient_id | patient_name | conditions
1          | Daniel       | YFEV COUGH
2          | Alice        |
3          | Bob          | DIAB100 MYOP
4          | George       | ACNE DIAB100
5          | Alain        | DIAB201
输出：
patient_id | patient_name | conditions
3          | Bob          | DIAB100 MYOP
4          | George       | ACNE DIAB100
```

## 解题思路

### LIKE 模式匹配

`conditions` 字段中的疾病代码以空格分隔，以 `DIAB1` 开头的代码可能出现在：
1. 字符串开头（第一个疾病）：`'DIAB1%'`
2. 字符串中间（中间某个疾病）：`'% DIAB1%'`（前面有空格）

使用 `LIKE 'DIAB1%' OR LIKE '% DIAB1%'` 两个条件覆盖这两种情况。

## 代码实现

### 方法一：LIKE 匹配（推荐）

```sql
-- 匹配以 DIAB1 开头（第一个疾病）或前面有空格（中间的疾病）
SELECT patient_id, patient_name, conditions
FROM Patients
WHERE conditions LIKE 'DIAB1%'
   OR conditions LIKE '% DIAB1%';
```

### 方法二：REGEXP 正则（更灵活）

```sql
-- 使用正则：DIAB1 在开头或前面是空格
SELECT patient_id, patient_name, conditions
FROM Patients
WHERE conditions REGEXP '(^| )DIAB1';
```

### 方法三：结合两种写法确保兼容性

```sql
SELECT patient_id, patient_name, conditions
FROM Patients
WHERE conditions REGEXP '\\bDIAB1'
-- 注意：MySQL 不支持 \b 单词边界，建议用方法一或方法二
```

## 复杂度分析

- **时间复杂度**：O(N * L)，N 为行数，L 为 conditions 字段平均长度
- **空间复杂度**：O(1)

## 关键点总结

1. 疾病代码以空格分隔，`DIAB1` 开头的代码要么在字符串开头，要么前面有空格
2. 两个 LIKE 条件用 OR 连接即可覆盖所有情况
3. `LIKE '% DIAB1%'` 中 `%` 前面有一个空格，不能漏掉

## 易错点

- 只写 `LIKE '%DIAB1%'` 会匹配到 `XDIAB1` 这样不合法的前缀
- `LIKE '% DIAB1%'` 中间的空格不能省略
