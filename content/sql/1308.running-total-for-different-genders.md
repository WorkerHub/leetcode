## 题目描述

表 `Scores` 的结构如下：

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| player_name   | varchar |
| gender        | varchar |
| day           | date    |
| score_points  | int     |
+---------------+---------+
```

- `(gender, day)` 是该表的主键
- `gender` 的值为 `'F'`（女）或 `'M'`（男）
- `score_points` 为该玩家当天获得的分数

请编写 SQL 查询，计算每种性别每天的**累计得分**（Running Total），即从第一天到当天该性别的累计总分。

结果按 `gender` 和 `day` 升序排列。

**示例：**

输入：
```
Scores 表：
+-------------+--------+------------+--------------+
| player_name | gender | day        | score_points |
+-------------+--------+------------+--------------+
| Aron        | F      | 2020-01-01 | 17           |
| Alice       | F      | 2020-01-07 | 23           |
| Bajrang     | M      | 2020-01-07 | 7            |
| Khali       | M      | 2020-01-03 | 5            |
| Slaman      | M      | 2020-01-01 | 3            |
| Joe         | M      | 2020-01-02 | 8            |
| Jose        | M      | 2020-01-06 | 14           |
| Priya       | F      | 2020-01-06 | 9            |
| Priyanka    | F      | 2020-01-05 | 23           |
+-------------+--------+------------+--------------+
```

输出：
```
+--------+------------+-------+
| gender | day        | total |
+--------+------------+-------+
| F      | 2020-01-01 | 17    |
| F      | 2020-01-05 | 40    |
| F      | 2020-01-06 | 49    |
| F      | 2020-01-07 | 72    |
| M      | 2020-01-01 | 3     |
| M      | 2020-01-02 | 11    |
| M      | 2020-01-03 | 16    |
| M      | 2020-01-06 | 30    |
| M      | 2020-01-07 | 37    |
+--------+------------+-------+
```

## 解题思路

本题的核心是**分组累计求和**（Running Total / Cumulative Sum）：

- 按 `gender` 分组，在每组内按 `day` 升序累加 `score_points`
- 这正是 SQL 窗口函数 `SUM() OVER (PARTITION BY ... ORDER BY ...)` 的经典应用

**关键概念：**

窗口函数 `SUM() OVER` 与普通 `GROUP BY + SUM()` 的区别：
- `GROUP BY + SUM()`：将多行聚合为一行，返回总和
- `SUM() OVER`：保留原始行，并在每行附加累计值（不折叠行数）

累计求和的"窗口"定义：
```
PARTITION BY gender    -- 按性别分组，不同性别互不影响
ORDER BY day           -- 按日期排序
-- 默认窗口范围：ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
-- 即从分组第一行到当前行
```

## SQL 代码实现

### 方法一：窗口函数 SUM OVER（推荐）

```sql
-- 使用窗口函数计算分性别的累计得分
SELECT
    gender,
    day,
    SUM(score_points) OVER (
        PARTITION BY gender    -- 按性别分区，F 和 M 各自独立计算
        ORDER BY day           -- 在分区内按日期升序累加
    ) AS total
FROM Scores
ORDER BY gender, day;
```

**执行过程分析：**

对于 F 性别：
```
day        | score_points | 累计(total)
-----------|--------------|------------
2020-01-01 |      17      | 17
2020-01-05 |      23      | 40  (17+23)
2020-01-06 |       9      | 49  (40+9)
2020-01-07 |      23      | 72  (49+23)
```

### 方法二：自连接（不使用窗口函数）

```sql
-- 自连接：对每一行，找同性别且日期 <= 当前日期的所有行求和
SELECT
    s1.gender,
    s1.day,
    SUM(s2.score_points) AS total
FROM Scores s1
JOIN Scores s2
    ON s1.gender = s2.gender      -- 同性别
    AND s2.day <= s1.day          -- s2 的日期不晚于 s1 的当前日期
GROUP BY s1.gender, s1.day
ORDER BY s1.gender, s1.day;
```

**思路说明：**
- 对每个 `(gender, day)` 组合，通过自连接找到同性别中所有日期 ≤ 当前日期的记录
- 将这些记录的 `score_points` 求和，即为累计值

### 方法三：相关子查询

```sql
-- 相关子查询：对每行单独计算截止当天的累计值
SELECT
    gender,
    day,
    (
        SELECT SUM(s2.score_points)
        FROM Scores s2
        WHERE s2.gender = s1.gender   -- 同性别
          AND s2.day <= s1.day        -- 截止当天
    ) AS total
FROM Scores s1
ORDER BY gender, day;
```

### 方法四：Python pandas 模拟

```python
import pandas as pd

def running_total(scores: pd.DataFrame) -> pd.DataFrame:
    # 按 gender 分组后，在组内按 day 排序并累加 score_points
    scores = scores.sort_values(['gender', 'day'])
    
    # groupby + cumsum 实现分组累计求和
    scores['total'] = scores.groupby('gender')['score_points'].cumsum()
    
    # 返回所需列
    return scores[['gender', 'day', 'total']]
```

## 各方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 优点 | 缺点 |
|------|-----------|-----------|------|------|
| 窗口函数 | O(n log n) | O(n) | 简洁高效，现代SQL标准 | 需要数据库支持窗口函数 |
| 自连接 | O(n²) | O(n) | 兼容性好 | 数据量大时性能差 |
| 相关子查询 | O(n²) | O(1) | 逻辑直观 | 性能最差 |

## 复杂度分析

- **时间复杂度**：O(n log n)（窗口函数方法，排序开销）
- **空间复杂度**：O(n)（存储结果集）

## 关键点总结

1. **窗口函数** `SUM() OVER (PARTITION BY ... ORDER BY ...)` 是处理累计求和的标准做法
2. `PARTITION BY gender` 将数据按性别分成独立的计算窗口
3. `ORDER BY day` 决定累加顺序——必须按时间顺序累加
4. 窗口函数默认的帧范围是"从分区开头到当前行"，正好满足累计求和的需求
5. 输出结果需按 `gender`、`day` 升序排列

## 易错点

1. **忘记 ORDER BY**：窗口函数中 `ORDER BY day` 不可省略，省略后默认是对整个分区求总和，不是累计值
2. **混淆两种 ORDER BY**：`OVER()` 内的 `ORDER BY` 控制窗口顺序，最终查询的 `ORDER BY` 控制输出顺序，两者都要写
3. **自连接的 ≤ 号**：自连接方法中条件是 `s2.day <= s1.day`（包含当天），不是严格小于
4. **NULL 处理**：若某天某性别没有数据，窗口函数会自然跳过（不会补0）

## 学习建议

SQL 窗口函数是面试高频考点，建议掌握以下几个核心函数：
- `SUM() OVER` — 累计求和
- `ROW_NUMBER() OVER` — 行号
- `RANK() / DENSE_RANK() OVER` — 排名
- `LAG() / LEAD() OVER` — 取上/下一行的值

窗口函数模板：
```sql
函数名() OVER (
    PARTITION BY 分组列   -- 可选
    ORDER BY 排序列       -- 可选
    ROWS/RANGE BETWEEN ... AND ...  -- 可选，指定帧范围
)
```
