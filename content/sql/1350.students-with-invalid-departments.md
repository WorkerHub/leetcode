## 题目描述

**Departments 表：**

| 列名 | 类型    |
|------|---------|
| id   | int     |
| name | varchar |

`id` 是该表的主键。

**Students 表：**

| 列名          | 类型    |
|---------------|---------|
| id            | int     |
| name          | varchar |
| department_id | int     |

`id` 是该表的主键。

找出所有 `department_id` 不在 `Departments` 表中的学生的 `id` 和 `name`。

**示例：**

Departments 表：
```
+------+--------------------------+
| id   | name                     |
+------+--------------------------+
| 1    | Electrical Engineering   |
| 7    | Computer Engineering     |
| 13   | Bussiness Administration |
+------+--------------------------+
```

Students 表：
```
+------+----------+---------------+
| id   | name     | department_id |
+------+----------+---------------+
| 23   | Alice    | 1             |
| 1    | Bob      | 7             |
| 5    | Jennifer | 13            |
| 2    | John     | 14            |
| 4    | Jasmine  | 77            |
+------+----------+---------------+
```

结果表：
```
+------+---------+
| id   | name    |
+------+---------+
| 2    | John    |
| 4    | Jasmine |
+------+---------+
```

John 的 department_id=14，Jasmine 的 department_id=77，均不在 Departments 表中。

## 解题思路

本题要求找出"部门不存在"的学生，即 Students 表中 `department_id` 在 Departments 表的 `id` 列中找不到的记录。

有两种常见写法：

1. **NOT IN 子查询**：先查出所有合法的部门 id，再筛选 department_id 不在其中的学生。
2. **LEFT JOIN**：将 Students 表左连接 Departments 表，如果某个学生的 department_id 匹配不到任何部门，则 Departments 表的列为 NULL，过滤这些行即可。

## SQL 解法

### 方法一：NOT IN 子查询（直观）

```sql
SELECT id, name
FROM Students
WHERE department_id NOT IN (
    SELECT id
    FROM Departments
);
```

**解释：**
- 内层查询 `SELECT id FROM Departments` 得到所有合法的部门编号集合。
- 外层查询用 `NOT IN` 过滤掉 department_id 在该集合中的学生。
- 只剩下 department_id 无效的学生。

### 方法二：LEFT JOIN（推荐，性能更好）

```sql
SELECT s.id, s.name
FROM Students s
LEFT JOIN Departments d
    ON s.department_id = d.id
WHERE d.id IS NULL;
```

**解释：**
- `LEFT JOIN` 保留 Students 表的所有行，匹配不到的 Departments 列为 NULL。
- `WHERE d.id IS NULL` 筛选出没有匹配到任何部门的学生。

### 方法三：NOT EXISTS 子查询

```sql
SELECT id, name
FROM Students s
WHERE NOT EXISTS (
    SELECT 1
    FROM Departments d
    WHERE d.id = s.department_id
);
```

**解释：**
- `NOT EXISTS` 对每行检查是否存在满足条件的部门记录。
- 在某些数据库中，`NOT EXISTS` 的性能优于 `NOT IN`（特别是当子查询结果含 NULL 时）。

## 复杂度分析

**SQL 方法一（NOT IN）：**
- 时间复杂度：O(|Students| * |Departments|)，最坏情况下每个学生都要和所有部门比对。
- 实际上，数据库会对子查询结果建立哈希表，接近 O(|Students| + |Departments|)。

**SQL 方法二（LEFT JOIN）：**
- 时间复杂度：取决于数据库优化器，通常使用哈希连接，O(|Students| + |Departments|)。
- LEFT JOIN 通常是性能最优的写法。

## 关键点总结

1. `NOT IN` 与 `NOT EXISTS` 在子查询不含 NULL 时等价，含 NULL 时 `NOT IN` 会返回空结果集，需特别注意。
2. `LEFT JOIN ... WHERE 右表主键 IS NULL` 是查找"不存在关联记录"的标准模式。
3. 本题中 Departments.id 是主键，不含 NULL，三种写法结果相同。
4. 在大型数据集上，LEFT JOIN 通常比 NOT IN 子查询性能更好。

## 易错点

- 使用 `NOT IN` 时，如果子查询结果包含 NULL，整个 `NOT IN` 表达式会返回 UNKNOWN（而非 TRUE），导致过滤结果为空。本题 Departments.id 是主键不会有 NULL，但在其他场景需加 `WHERE id IS NOT NULL`。
- 注意 LEFT JOIN 的连接条件必须写在 ON 子句中，过滤条件（IS NULL）写在 WHERE 子句中，不能混淆。
