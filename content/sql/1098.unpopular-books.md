## 题目描述

表：`Books`

```
+----------------+---------+
| Column Name    | Type    |
+----------------+---------+
| book_id        | int     |
| name           | varchar |
| available_from | date    |
+----------------+---------+
```

`book_id` 是此表的主键（具有唯一值的列）。

表：`Orders`

```
+----------------+---------+
| Column Name    | Type    |
+----------------+---------+
| order_id       | int     |
| book_id        | int     |
| quantity       | int     |
| dispatch_date  | date    |
+----------------+---------+
```

`order_id` 是此表的主键。
`book_id` 是 Books 表的外键。

编写一个 SQL 查询，筛选出过去一年中销售量少于 10 本的书籍，不考虑上架（available）不到一个月的书籍。假设今天是 2019-06-23。

返回结果表无顺序要求。

查询结果格式如下例所示。

**示例 1：**

输入：

Books 表：
```
+---------+--------------------+----------------+
| book_id | name               | available_from |
+---------+--------------------+----------------+
| 1       | "Kalila And Demna" | 2010-01-01     |
| 2       | "28 Letters"       | 2012-05-12     |
| 3       | "The Hobbit"       | 2019-06-10     |
| 4       | "13 Reasons Why"   | 2019-06-01     |
| 5       | "The Hunger Games" | 2008-09-21     |
+---------+--------------------+----------------+
```

Orders 表：
```
+----------+---------+----------+---------------+
| order_id | book_id | quantity | dispatch_date |
+----------+---------+----------+---------------+
| 1        | 1       | 2        | 2018-07-26    |
| 2        | 1       | 1        | 2018-11-05    |
| 3        | 3       | 8        | 2019-06-11    |
| 4        | 4       | 6        | 2019-06-05    |
| 5        | 4       | 5        | 2019-06-20    |
| 6        | 5       | 9        | 2009-02-02    |
| 7        | 5       | 8        | 2010-04-13    |
+----------+---------+----------+---------------+
```

输出：
```
+-----------+--------------------+
| book_id   | name               |
+-----------+--------------------+
| 1         | "Kalila And Demna" |
| 2         | "28 Letters"       |
| 5         | "The Hunger Games" |
+-----------+--------------------+
```

解释：
- 书籍 1（"Kalila And Demna"）：过去一年（2018-06-23 到 2019-06-23）销售了 3 本（2+1），少于 10 本
- 书籍 2（"28 Letters"）：过去一年没有销售记录，0 本少于 10 本
- 书籍 3（"The Hobbit"）：2019-06-10 上架，不到一个月，排除
- 书籍 4（"13 Reasons Why"）：过去一年销售了 11 本（6+5），不符合条件
- 书籍 5（"The Hunger Games"）：过去一年销售了 0 本，少于 10 本

## 解题思路

这道题需要综合考虑多个条件：

1. **时间限制条件**：
   - 上架时间：必须在 2019-05-23 之前上架（距今超过 1 个月）
   - 销售统计：只统计 2018-06-23 到 2019-06-23 这一年的销售量

2. **销售量条件**：
   - 过去一年销售量 < 10 本
   - 注意：没有销售记录的书也算销售量为 0

3. **处理步骤**：
   - 筛选出上架超过 1 个月的书籍
   - LEFT JOIN Orders 表（保留没有销售记录的书）
   - 筛选过去一年的订单
   - 按书籍分组，计算销售总量
   - 筛选销售量 < 10 的书籍

**关键观察：**
- 使用 LEFT JOIN 而非 INNER JOIN，因为有些书可能没有销售记录
- 日期计算：`2019-06-23` 减去 1 个月 = `2019-05-23`，减去 1 年 = `2018-06-23`
- 使用 IFNULL 或 COALESCE 处理空值（没有订单的情况）

## SQL 代码实现

### 方法一：LEFT JOIN + HAVING（推荐）

```sql
SELECT 
    b.book_id,
    b.name
FROM Books b
LEFT JOIN Orders o
    ON b.book_id = o.book_id
    AND o.dispatch_date BETWEEN '2018-06-23' AND '2019-06-23'  -- 过去一年
WHERE b.available_from < '2019-05-23'  -- 上架超过一个月
GROUP BY b.book_id, b.name
HAVING IFNULL(SUM(o.quantity), 0) < 10;  -- 销售量少于10本
```

### 方法二：使用 DATE_SUB（更灵活）

```sql
SELECT 
    b.book_id,
    b.name
FROM Books b
LEFT JOIN Orders o
    ON b.book_id = o.book_id
    AND o.dispatch_date >= DATE_SUB('2019-06-23', INTERVAL 1 YEAR)
    AND o.dispatch_date <= '2019-06-23'
WHERE b.available_from < DATE_SUB('2019-06-23', INTERVAL 1 MONTH)
GROUP BY b.book_id, b.name
HAVING COALESCE(SUM(o.quantity), 0) < 10;
```

### 方法三：使用子查询（清晰版）

```sql
SELECT 
    b.book_id,
    b.name
FROM Books b
WHERE b.available_from < '2019-05-23'  -- 上架超过一个月
    AND b.book_id NOT IN (
        -- 找出过去一年销售量 >= 10 的书籍
        SELECT book_id
        FROM Orders
        WHERE dispatch_date BETWEEN '2018-06-23' AND '2019-06-23'
        GROUP BY book_id
        HAVING SUM(quantity) >= 10
    );
```

### 方法四：使用 CTE（可读性最佳）

```sql
WITH RecentBooks AS (
    -- 筛选上架超过一个月的书籍
    SELECT book_id, name
    FROM Books
    WHERE available_from < DATE_SUB('2019-06-23', INTERVAL 1 MONTH)
),
SalesLastYear AS (
    -- 统计过去一年每本书的销售量
    SELECT 
        book_id,
        SUM(quantity) AS total_sales
    FROM Orders
    WHERE dispatch_date BETWEEN DATE_SUB('2019-06-23', INTERVAL 1 YEAR) AND '2019-06-23'
    GROUP BY book_id
)
SELECT 
    r.book_id,
    r.name
FROM RecentBooks r
LEFT JOIN SalesLastYear s
    ON r.book_id = s.book_id
WHERE COALESCE(s.total_sales, 0) < 10;
```

## 复杂度分析

### SQL 方案

**时间复杂度：** O(n + m)
- 扫描 Books 表：O(n)
- 扫描 Orders 表：O(m)
- JOIN 操作：O(n + m)
- GROUP BY 聚合：O(n)
- 总体：O(n + m)

**空间复杂度：** O(n)
- 需要存储中间结果

### Python Pandas 方案

**时间复杂度：** O(n + m)
- 筛选操作：O(n) + O(m)
- groupby 聚合：O(m log m)
- merge 操作：O(n + m)
- 总体：O(n + m log m)

**空间复杂度：** O(n + m)
- 需要创建多个中间 DataFrame

其中 n 为 Books 表的记录数，m 为 Orders 表的记录数。

## 关键点总结

1. **使用 LEFT JOIN**：确保包含没有销售记录的书籍，这些书销售量为 0，也属于冷门书
2. **日期范围计算**：过去一年 = `[today - 1 year, today]`，上架超过 1 月 = `available_from < today - 1 month`
3. **空值处理**：使用 IFNULL/COALESCE（SQL）或 fillna（Pandas）处理没有订单的情况
4. **ON 条件中加日期筛选**：在 JOIN 的 ON 子句中加入日期条件可以提前过滤，提高性能
5. **HAVING vs WHERE**：聚合后的条件（如 SUM）要用 HAVING，而非 WHERE

## 易错点

1. **遗漏没有销售记录的书**
   - 错误：使用 INNER JOIN
   - 正确：使用 LEFT JOIN，并用 IFNULL 处理空值

2. **日期范围理解错误**
   - 错误：认为"过去一年"是从 2018-01-01 开始
   - 正确：是从 2019-06-23 往前推一年，即 2018-06-23 到 2019-06-23

3. **上架时间计算错误**
   - 错误：`available_from <= '2019-05-23'`（包含了恰好一个月的书）
   - 正确：`available_from < '2019-05-23'`（严格小于）

4. **聚合函数位置错误**
   - 错误：在 WHERE 子句中使用 SUM(quantity)
   - 正确：在 HAVING 子句中使用聚合函数

5. **Pandas 日期类型问题**
   - 错误：未将日期列转换为 datetime 类型就进行比较
   - 正确：使用 `pd.to_datetime()` 确保日期列是正确类型

6. **边界条件处理**
   - 注意日期范围是否包含边界（BETWEEN 包含两端）
   - 确保 `dispatch_date <= '2019-06-23'` 包含当天订单

4. **思路分解**
