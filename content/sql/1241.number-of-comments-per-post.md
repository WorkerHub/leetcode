## 题目描述

给定一个 `Submissions` 表，包含提交的帖子和评论信息。

表结构：

```
Submissions 表：
+---------------+----------+
| 列名           | 类型     |
+---------------+----------+
| sub_id        | int      |
| parent_id     | int      |
+---------------+----------+
sub_id 是这个表的主键。
每行可以是一个帖子或对该帖子的评论。
如果是帖子的话，parent_id 为 null。
对于评论来说，parent_id 就是表中对应帖子的 sub_id。
```

编写一个 SQL 查询，统计每个帖子的评论数。

结果表应包含帖子的 `post_id` 和对应的评论数 `number_of_comments`，并且按 `post_id` 升序排列。

注意：
- `Submissions` 表可能包含重复的评论，应该统计不重复的评论数。
- `Submissions` 表可能包含重复的帖子，应该将重复的帖子视为一个帖子。
- 即使帖子没有评论，结果表也应该包含该帖子（评论数为 0）。

示例 1：

输入：

```
Submissions 表：
+---------+------------+
| sub_id  | parent_id  |
+---------+------------+
| 1       | Null       |
| 2       | Null       |
| 1       | Null       |
| 12      | Null       |
| 3       | 1          |
| 5       | 2          |
| 3       | 1          |
| 4       | 1          |
| 9       | 1          |
| 10      | 2          |
| 6       | 7          |
+---------+------------+
```

输出：

```
+---------+--------------------+
| post_id | number_of_comments |
+---------+--------------------+
| 1       | 3                  |
| 2       | 2                  |
| 12      | 0                  |
+---------+--------------------+
```

解释：
- 帖子 1 有三条评论（sub_id 为 3、4、9），评论 3 重复但只计数一次。
- 帖子 2 有两条评论（sub_id 为 5、10）。
- 帖子 12 没有评论。
- sub_id 为 6 的评论对应的帖子 7 已被删除（不在表中），因此被忽略。

## 解题思路

这道题的核心在于理解帖子和评论的关系：
1. 帖子的 `parent_id` 为 `NULL`
2. 评论的 `parent_id` 是对应帖子的 `sub_id`

解题步骤：
1. 首先找出所有的帖子（`parent_id IS NULL`）
2. 对于每个帖子，统计有多少条评论（`parent_id` 等于该帖子的 `sub_id`）
3. 使用 `LEFT JOIN` 确保没有评论的帖子也能显示
4. 使用 `DISTINCT` 去除重复的评论
5. 使用 `COUNT` 统计评论数

关键点：
- 需要先去重帖子（因为表中可能有重复的帖子记录）
- 需要去重评论（因为表中可能有重复的评论记录）
- 使用 `LEFT JOIN` 而不是 `INNER JOIN`，以包含没有评论的帖子
- `COUNT(DISTINCT column)` 统计不重复的值

## SQL 代码实现

### 方法一：使用 LEFT JOIN（推荐）

```sql
SELECT 
    DISTINCT s1.sub_id AS post_id,
    COUNT(DISTINCT s2.sub_id) AS number_of_comments
FROM 
    Submissions s1
LEFT JOIN 
    Submissions s2 
ON 
    s1.sub_id = s2.parent_id
WHERE 
    s1.parent_id IS NULL
GROUP BY 
    s1.sub_id
ORDER BY 
    post_id;
```

### 方法二：使用子查询

```sql
SELECT 
    p.sub_id AS post_id,
    IFNULL(
        (SELECT COUNT(DISTINCT sub_id) 
         FROM Submissions 
         WHERE parent_id = p.sub_id),
        0
    ) AS number_of_comments
FROM 
    (SELECT DISTINCT sub_id FROM Submissions WHERE parent_id IS NULL) p
ORDER BY 
    post_id;
```

### 方法三：使用 COALESCE

```sql
SELECT 
    DISTINCT s1.sub_id AS post_id,
    COALESCE(COUNT(DISTINCT s2.sub_id), 0) AS number_of_comments
FROM 
    Submissions s1
LEFT JOIN 
    Submissions s2 
ON 
    s1.sub_id = s2.parent_id
WHERE 
    s1.parent_id IS NULL
GROUP BY 
    s1.sub_id
ORDER BY 
    post_id;
```

## 复杂度分析

### SQL 方案

时间复杂度：
- 方法一（LEFT JOIN）：O(n log n)，其中 n 是表的行数。主要开销在排序和连接操作。
- 方法二（子查询）：O(n²)，对每个帖子都执行一次子查询。
- 方法三（COALESCE）：O(n log n)，与方法一类似。

空间复杂度：O(n)，用于存储中间结果和最终结果。

### Python Pandas 方案

时间复杂度：
- 方法一：O(n log n)，主要开销在排序和 merge 操作。
- 方法二：O(n log n)，groupby 和排序的开销。
- 方法三：O(n log n)，value_counts 和排序的开销。

空间复杂度：O(n)，用于存储中间 DataFrame 和结果。

## 关键点总结

1. 理解数据结构：帖子的 `parent_id` 为 NULL，评论的 `parent_id` 是帖子的 `sub_id`
2. 去重处理：需要对帖子和评论都进行去重
3. 使用 LEFT JOIN：确保没有评论的帖子也能显示在结果中
4. COUNT DISTINCT：统计不重复的评论数
5. 处理 NULL 值：使用 IFNULL 或 COALESCE 将 NULL 转换为 0

## 易错点

1. 忘记去重：题目明确说明可能有重复的帖子和评论，必须去重
2. 使用 INNER JOIN：会遗漏没有评论的帖子
3. 忘记过滤帖子：WHERE 条件要确保 `parent_id IS NULL`
4. 统计时未使用 DISTINCT：可能重复计数相同的评论
5. 在 Pandas 中忘记处理 NaN：合并后没有评论的帖子会有 NaN，需要填充为 0
