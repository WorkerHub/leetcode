## 题目描述

表：`Visits`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| user_id       | int     |
| visit_date    | date    |
+---------------+---------+
(user_id, visit_date) 是该表的主键。
该表包含用户访问某特定零售商的数据。
```

表：`Transactions`

```
+------------------+---------+
| Column Name      | Type    |
+------------------+---------+
| user_id          | int     |
| transaction_date | date    |
| amount           | int     |
+------------------+---------+
该表没有主键，可能有重复行。
每行包含一次交易的信息，transactions.transaction_date 总是在 visits.visit_date 范围内。
```

银行希望了解用户访问的频率。统计每次访问时进行的交易数目。

返回下表：`transactions_count`：用户在一次访问时进行的交易数目；`visits_count`：进行了 `transactions_count` 次交易的一次访问数量。

`transactions_count` 的值从 `0` 到 `max(transactions_count)`，其中 `max(transactions_count)` 是用户在一次访问中进行最多交易的次数。

按 `transactions_count` 升序排列。

**示例：**
```
Visits 表：
+---------+------------+
| user_id | visit_date |
+---------+------------+
| 1       | 2020-01-01 |
| 2       | 2020-01-02 |
| 12      | 2020-01-01 |
| 19      | 2020-01-03 |
| 1       | 2020-01-02 |
| 2       | 2020-01-03 |
| 1       | 2020-01-04 |
| 7       | 2020-01-11 |
| 9       | 2020-01-25 |
| 8       | 2020-01-28 |
+---------+------------+

Transactions 表：
+---------+------------------+--------+
| user_id | transaction_date | amount |
+---------+------------------+--------+
| 1       | 2020-01-02       | 120    |
| 2       | 2020-01-03       | 22     |
| 7       | 2020-01-11       | 232    |
| 1       | 2020-01-04       | 7      |
| 9       | 2020-01-25       | 33     |
| 9       | 2020-01-25       | 66     |
| 8       | 2020-01-28       | 1      |
| 2       | 2020-01-03       | 199    |
+---------+------------------+--------+

输出：
+--------------------+--------------+
| transactions_count | visits_count |
+--------------------+--------------+
| 0                  | 4            |
| 1                  | 4            |
| 2                  | 2            |
+--------------------+--------------+
```

## 解题思路

**步骤分析：**

1. 对每次访问，统计该 `(user_id, visit_date)` 对应的交易次数（无交易为 0）
2. 统计每种交易次数对应的访问次数
3. 生成从 0 到最大交易次数的完整序列，没有访问的次数填 0

**关键难点：** 需要生成从 0 到 max 的连续序列，使用递归 CTE 生成数字序列。

## SQL 解法

### 方法一：递归 CTE 生成序列（MySQL 8.0+）

```sql
-- 第一步：每次访问的交易次数（左连接，无交易则为 0）
WITH visit_trans AS (
    SELECT
        v.user_id,
        v.visit_date,
        COUNT(t.transaction_date) AS trans_count
    FROM Visits v
    LEFT JOIN Transactions t
        ON v.user_id = t.user_id
        AND v.visit_date = t.transaction_date
    GROUP BY v.user_id, v.visit_date
),
-- 第二步：每种交易次数对应的访问次数
count_dist AS (
    SELECT
        trans_count,
        COUNT(*) AS visits_count
    FROM visit_trans
    GROUP BY trans_count
),
-- 第三步：生成 0 到 max(trans_count) 的连续数列
max_count AS (
    SELECT MAX(trans_count) AS max_val FROM visit_trans
),
-- 递归 CTE 生成数字序列
nums AS (
    SELECT 0 AS n
    UNION ALL
    SELECT n + 1
    FROM nums, max_count
    WHERE n + 1 <= max_val
)
-- 第四步：左连接，缺失的填 0
SELECT
    nums.n AS transactions_count,
    COALESCE(count_dist.visits_count, 0) AS visits_count
FROM nums
LEFT JOIN count_dist
    ON nums.n = count_dist.trans_count
ORDER BY transactions_count;
```

### 方法二：使用变量生成序列（MySQL 5.7 兼容）

```sql
-- 先计算基础数据
WITH visit_trans AS (
    SELECT
        v.user_id,
        v.visit_date,
        COUNT(t.transaction_date) AS trans_count
    FROM Visits v
    LEFT JOIN Transactions t
        ON v.user_id = t.user_id
        AND v.visit_date = t.transaction_date
    GROUP BY v.user_id, v.visit_date
),
count_dist AS (
    SELECT trans_count, COUNT(*) AS visits_count
    FROM visit_trans
    GROUP BY trans_count
),
-- 利用自连接生成足够大的数字表
-- 假设最大交易次数不超过 1000
nums AS (
    SELECT a.N + b.N * 10 + c.N * 100 AS n
    FROM (SELECT 0 AS N UNION SELECT 1 UNION SELECT 2 UNION SELECT 3 UNION
          SELECT 4 UNION SELECT 5 UNION SELECT 6 UNION SELECT 7 UNION
          SELECT 8 UNION SELECT 9) a
    CROSS JOIN (SELECT 0 AS N UNION SELECT 1 UNION SELECT 2 UNION SELECT 3 UNION
                SELECT 4 UNION SELECT 5 UNION SELECT 6 UNION SELECT 7 UNION
                SELECT 8 UNION SELECT 9) b
    CROSS JOIN (SELECT 0 AS N UNION SELECT 1 UNION SELECT 2 UNION SELECT 3 UNION
                SELECT 4 UNION SELECT 5 UNION SELECT 6 UNION SELECT 7 UNION
                SELECT 8 UNION SELECT 9) c
)
SELECT
    nums.n AS transactions_count,
    COALESCE(count_dist.visits_count, 0) AS visits_count
FROM nums
LEFT JOIN count_dist ON nums.n = count_dist.trans_count
WHERE nums.n <= (SELECT MAX(trans_count) FROM visit_trans)
ORDER BY transactions_count;
```

### 方法三：清晰分步版（带详细注释）

```sql
-- 步骤 1：统计每次访问的交易数
-- 左连接保证没有交易的访问也被包含，COUNT 不统计 NULL
WITH step1 AS (
    SELECT
        v.user_id,
        v.visit_date,
        COUNT(t.transaction_date) AS trans_count  -- NULL 不计入
    FROM Visits v
    LEFT JOIN Transactions t
        ON v.user_id = t.user_id
        AND v.visit_date = t.transaction_date
    GROUP BY v.user_id, v.visit_date
),

-- 步骤 2：统计每种交易次数有多少次访问
step2 AS (
    SELECT trans_count, COUNT(*) AS visits_count
    FROM step1
    GROUP BY trans_count
),

-- 步骤 3：生成 [0, max_trans_count] 的完整数列
max_t AS (
    SELECT MAX(trans_count) AS max_val FROM step1
),
numbers AS (
    SELECT 0 AS n
    UNION ALL
    SELECT n + 1 FROM numbers
    JOIN max_t ON n < max_val
)

-- 步骤 4：补齐缺失的交易次数（填 0）
SELECT
    numbers.n AS transactions_count,
    COALESCE(step2.visits_count, 0) AS visits_count
FROM numbers
LEFT JOIN step2 ON numbers.n = step2.trans_count
ORDER BY transactions_count;
```

## 复杂度分析

- **时间复杂度**：O(V log V + T log T)，V 为访问记录数，T 为交易记录数
- **空间复杂度**：O(V + T)

## 关键点总结

1. 使用 `LEFT JOIN` 确保没有交易的访问也被统计（交易次数为 0）
2. `COUNT(t.transaction_date)` 对 NULL 不计数，所以可以正确计算 0 次交易
3. 需要生成从 0 到最大值的连续数列，递归 CTE 是优雅的做法
4. `COALESCE(visits_count, 0)` 将 NULL 替换为 0，填补缺失的交易次数

## 易错点

1. 忘记没有交易的访问（应使用 LEFT JOIN 而非 INNER JOIN）
2. 结果需要从 0 开始的**连续**序列，不能只返回有访问的交易次数
3. `COUNT(*)` 和 `COUNT(column)` 的区别：后者不计入 NULL
4. 递归 CTE 需要有终止条件，避免无限递归
