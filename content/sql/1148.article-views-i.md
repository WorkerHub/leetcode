## 题目描述

表：`Views`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| article_id    | int     |
| author_id     | int     |
| viewer_id     | int     |
| view_date     | date    |
+---------------+---------+
此表无主键，可能会存在重复行。
此表的每一行都表示某人在某天浏览了某位作者的某篇文章。
请注意，同一人的 author_id 和 viewer_id 是相同的。
```

请编写一条 SQL 查询以找出所有浏览过自己文章的作者，结果按照 id 升序排列。

查询结果的格式如下所示：

**示例 1：**

输入：
```
Views 表：
+------------+-----------+-----------+------------+
| article_id | author_id | viewer_id | view_date  |
+------------+-----------+-----------+------------+
| 1          | 3         | 5         | 2019-08-01 |
| 1          | 3         | 6         | 2019-08-02 |
| 2          | 7         | 7         | 2019-08-01 |
| 2          | 7         | 6         | 2019-08-02 |
| 4          | 7         | 1         | 2019-07-22 |
| 3          | 4         | 4         | 2019-07-21 |
| 3          | 4         | 4         | 2019-07-21 |
+------------+-----------+-----------+------------+
```

输出：
```
+------+
| id   |
+------+
| 4    |
| 7    |
+------+
```

## 解题思路

这道题要求找出浏览过自己文章的作者。

**核心要点：**

1. **自浏览判断**：
   - author_id = viewer_id 时表示作者浏览了自己的文章

2. **去重**：
   - 使用 DISTINCT 去除重复的作者ID
   - 因为同一作者可能多次浏览自己的文章

3. **排序**：
   - 按 id 升序排列

4. **列名**：
   - 输出列名为 id

## SQL 代码实现

### 方法一：WHERE + DISTINCT ⭐ 推荐

```sql
-- 最简洁的写法
SELECT DISTINCT author_id AS id
FROM Views
WHERE author_id = viewer_id
ORDER BY id;
```

### 方法二：使用 GROUP BY

```sql
-- 使用分组去重
SELECT author_id AS id
FROM Views
WHERE author_id = viewer_id
GROUP BY author_id
ORDER BY id;
```

### 方法三：使用子查询

```sql
-- 先筛选再去重
SELECT DISTINCT id
FROM (
    SELECT author_id AS id
    FROM Views
    WHERE author_id = viewer_id
) AS self_viewers
ORDER BY id;
```

### 方法四：使用 IN 子查询

```sql
-- 使用 IN 判断
SELECT DISTINCT author_id AS id
FROM Views v1
WHERE author_id IN (
    SELECT viewer_id
    FROM Views v2
    WHERE v1.author_id = v2.viewer_id
      AND v1.article_id = v2.article_id
      AND v2.author_id = v2.viewer_id
)
ORDER BY id;
```

### 方法五：使用 EXISTS

```sql
-- 使用 EXISTS
SELECT DISTINCT author_id AS id
FROM Views v1
WHERE EXISTS (
    SELECT 1
    FROM Views v2
    WHERE v1.author_id = v2.author_id
      AND v2.author_id = v2.viewer_id
)
ORDER BY id;
```

## 复杂度分析

**时间复杂度**：O(n log n)
- WHERE 筛选：O(n)
- DISTINCT 去重：O(n)
- ORDER BY 排序：O(n log n)

**空间复杂度**：O(n)
- 去重和排序需要额外空间

## 关键点总结

1. **自浏览条件**：`author_id = viewer_id`
2. **去重方法**：DISTINCT 或 GROUP BY
3. **列别名**：使用 AS id
4. **排序**：ORDER BY id
5. **性能优化**：WHERE 条件可以利用索引

## 易错点

1. **忘记去重**：
   - 错误：直接 SELECT author_id
   - 正确：SELECT DISTINCT author_id

2. **列名错误**：
   - 输出列名必须是 id，不是 author_id
   - 使用 AS id 重命名

3. **忘记排序**：
   - 题目要求按 id 升序
   - 必须添加 ORDER BY

4. **NULL 值处理**：
   - 虽然本题不涉及，但实际中要注意 NULL = NULL 是 FALSE

5. **重复行**：
   - 表中可能有重复行，必须去重

## 性能优化建议

```sql
-- 创建索引优化查询
CREATE INDEX idx_author_viewer ON Views(author_id, viewer_id);

-- 或者复合索引
CREATE INDEX idx_views ON Views(author_id, viewer_id, view_date);
```

## SQL 技巧对比

### 去重方法对比

| 方法 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| DISTINCT | 简洁直观 | 无法聚合 | 简单去重 |
| GROUP BY | 可以聚合 | 代码稍长 | 需要统计时 |

### 性能对比

```sql
-- 方法1：推荐（最快）
SELECT DISTINCT author_id AS id
FROM Views
WHERE author_id = viewer_id
ORDER BY id;

-- 方法2：稍慢（分组开销）
SELECT author_id AS id
FROM Views
WHERE author_id = viewer_id
GROUP BY author_id
ORDER BY id;

-- 方法3-5：不推荐（子查询开销大）
```

## 学习建议

1. **掌握去重**：
   - DISTINCT：去除完全重复的行
   - GROUP BY：分组去重，可配合聚合函数

2. **理解自连接**：
   - author_id = viewer_id 是特殊的"自连接"条件

3. **列别名使用**：
   - AS 关键字可选，但建议使用以提高可读性

4. **排序规则**：
   - ORDER BY 默认升序（ASC）
   - 降序需要显式指定 DESC

5. **性能意识**：
   - WHERE 条件先执行，应该尽早过滤
   - 索引可以显著提升查询速度

6. **代码简洁性**：
   - 优先选择最简洁的方法
   - 除非需要特殊功能（如聚合）才用复杂方法
