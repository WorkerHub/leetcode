## 题目描述

**Product** 表：

| 列名         | 类型    |
|--------------|---------|
| product_id   | int     |
| product_name | varchar |

`product_id` 是该表的主键。

**Sales** 表：

| 列名                | 类型 |
|---------------------|------|
| product_id          | int  |
| period_start        | date |
| period_end          | date |
| average_daily_sales | int  |

`product_id` 是该表的主键，`period_start` 和 `period_end` 是每种产品的销售区间，`average_daily_sales` 是每日平均销售额。

**要求：** 对每个产品，计算每年的总销售额。

- 如果某产品的销售期跨越了多个日历年，则分别计算每年的销售额。
- 每年的销售额 = 该产品在当年的销售天数 × 每日平均销售额。
- 结果按 `product_id` 和 `report_year` 升序排列。

**示例：**

输入 Sales：

| product_id | period_start | period_end  | average_daily_sales |
|------------|--------------|-------------|---------------------|
| 1          | 2019-01-25   | 2019-02-28  | 100                 |
| 2          | 2018-12-01   | 2020-01-01  | 10                  |
| 3          | 2019-12-01   | 2020-01-31  | 1                   |

输出：

| product_id | product_name | report_year | total_amount |
|------------|--------------|-------------|--------------|
| 1          | LC            | 2019        | 3500         |
| 2          | LC 2          | 2018        | 310          |
| 2          | LC 2          | 2019        | 3650         |
| 2          | LC 2          | 2020        | 10           |
| 3          | LC3           | 2019        | 31           |
| 3          | LC3           | 2020        | 31           |

## 解题思路

### 核心思想：生成日历年 + 计算每年实际销售天数

**难点：** 销售期可能跨越多个日历年，需要将一条记录拆分为多行（每年一行）。

**算法流程：**
1. **生成所有涉及的日历年**：找出所有销售记录涉及的年份范围。
2. **对每条销售记录，枚举其覆盖的每一年**：
   - 该年的销售开始日 = `MAX(period_start, 该年1月1日)`
   - 该年的销售结束日 = `MIN(period_end, 该年12月31日)`
   - 该年销售天数 = `(销售结束日 - 销售开始日).days + 1`
3. **计算总销售额**：销售天数 × `average_daily_sales`

## 代码实现

### 方法一：MySQL 8.0 递归 CTE

```sql
-- 步骤1：用递归 CTE 生成 2000-2024 年的年份列表（覆盖数据范围）
WITH RECURSIVE years AS (
    SELECT 2000 AS yr
    UNION ALL
    SELECT yr + 1
    FROM years
    WHERE yr < 2024
),
-- 步骤2：将每条销售记录与年份做交叉，筛选出有交集的年份
sales_by_year AS (
    SELECT
        s.product_id,
        y.yr AS report_year,
        -- 该年销售开始日：取 period_start 和该年1月1日的最大值
        GREATEST(s.period_start, CONCAT(y.yr, '-01-01')) AS start_date,
        -- 该年销售结束日：取 period_end 和该年12月31日的最小值
        LEAST(s.period_end,     CONCAT(y.yr, '-12-31')) AS end_date,
        s.average_daily_sales
    FROM Sales s
    JOIN years y
    -- 筛选：该年与销售期有交集
    ON YEAR(s.period_start) <= y.yr
    AND YEAR(s.period_end)  >= y.yr
)
SELECT
    p.product_id,
    p.product_name,
    CAST(s.report_year AS CHAR) AS report_year,
    -- 总销售额 = 天数 × 日均销售额（+1 因为两端日期都包含）
    (DATEDIFF(s.end_date, s.start_date) + 1) * s.average_daily_sales AS total_amount
FROM sales_by_year s
JOIN Product p ON p.product_id = s.product_id
ORDER BY p.product_id, s.report_year;
```

### 方法二：MySQL（不使用 CTE，使用 UNION 生成年份）

```sql
-- 先创建年份表（使用 UNION，适用于 MySQL 5.7）
SELECT
    p.product_id,
    p.product_name,
    CAST(y.yr AS CHAR) AS report_year,
    (DATEDIFF(
        LEAST(s.period_end, CONCAT(y.yr, '-12-31')),
        GREATEST(s.period_start, CONCAT(y.yr, '-01-01'))
    ) + 1) * s.average_daily_sales AS total_amount
FROM Sales s
JOIN Product p ON p.product_id = s.product_id
JOIN (
    SELECT 2018 AS yr UNION ALL
    SELECT 2019 UNION ALL
    SELECT 2020 UNION ALL
    SELECT 2021
) y
ON YEAR(s.period_start) <= y.yr
AND YEAR(s.period_end) >= y.yr
ORDER BY p.product_id, y.yr;
```

## 关键点总结

1. **跨年拆分**：核心操作是对每条记录按日历年拆分，每年单独计算。
2. **GREATEST/LEAST 求交集**：`GREATEST(period_start, 年份起始)` 和 `LEAST(period_end, 年份末尾)` 求两个区间的交集端点。
3. **DATEDIFF + 1**：两端日期都包含在销售期内，天数 = `DATEDIFF(end, start) + 1`。
4. **递归 CTE 生成年份**：MySQL 8.0 支持递归 CTE，可以动态生成年份序列，不需要硬编码。
5. **年份范围需覆盖数据**：生成的年份范围要足够大，覆盖所有销售记录的年份。

## 易错点

1. **忘记 +1**：`DATEDIFF` 返回的是两个日期相差的天数（不含起始），本题两端都包含，需要 +1。
2. **年份范围不够**：若硬编码年份（如 2018-2020），遇到超出范围的数据会漏算，应动态生成或足够宽泛。
3. **GREATEST/LEAST 与 MAX/MIN 的区别**：`GREATEST`/`LEAST` 是行级比较函数（比较多个值），`MAX`/`MIN` 是聚合函数（对一列多行汇总），此处应用 GREATEST/LEAST。
4. **report_year 的数据类型**：题目要求 report_year 为字符串，需用 `CAST(yr AS CHAR)` 或 `CAST(yr AS VARCHAR)`。

1. **GREATEST/LEAST 函数**：这两个函数专门用于行内多值比较，是处理"区间交集"的利器。
2. **递归 CTE**：MySQL 8.0+ 支持 `WITH RECURSIVE`，可以生成序列（数字、日期等），是处理"展开行"的强大工具。
