## 题目描述

表：`Traffic`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| user_id       | int     |
| activity      | enum    |
| activity_date | date    |
+---------------+---------+
该表没有主键，可能包含重复的行。
activity 列是一个枚举类型，包含：('login', 'logout', 'jobs', 'groups', 'homepage')。
```

编写一个 SQL 查询，报告在 90 天内（包括今天在内）首次登录的新用户的每日数量。假设今天是 `2019-06-30`。

查询结果格式如下所示。

**示例：**

输入：
```
Traffic 表：
+---------+----------+---------------+
| user_id | activity | activity_date |
+---------+----------+---------------+
| 1       | login    | 2019-05-01    |
| 1       | homepage | 2019-05-01    |
| 1       | logout   | 2019-05-01    |
| 2       | login    | 2019-06-21    |
| 2       | logout   | 2019-06-21    |
| 3       | login    | 2019-01-01    |
| 3       | jobs     | 2019-01-01    |
| 3       | logout   | 2019-01-01    |
| 4       | login    | 2019-06-21    |
| 4       | groups   | 2019-06-21    |
| 4       | logout   | 2019-06-21    |
| 5       | login    | 2019-03-01    |
| 5       | logout   | 2019-03-01    |
| 5       | login    | 2019-06-21    |
| 5       | logout   | 2019-06-21    |
+---------+----------+---------------+
```

输出：
```
+------------+-------------+
| login_date | user_count  |
+------------+-------------+
| 2019-06-21 | 2           |
| 2019-05-01 | 1           |
+------------+-------------+
```

解释：
- 用户 1 首次登录日期是 2019-05-01，在 90 天范围内
- 用户 2 首次登录日期是 2019-06-21，在 90 天范围内
- 用户 3 首次登录日期是 2019-01-01，不在 90 天范围内
- 用户 4 首次登录日期是 2019-06-21，在 90 天范围内
- 用户 5 首次登录日期是 2019-03-01，不在 90 天范围内

## 解题思路

这道题的核心是找到每个用户的**首次登录日期**，然后筛选出在 90 天范围内的日期，并统计每天的新用户数量。

**解题步骤：**

1. **筛选登录记录**：只关注 activity = 'login' 的记录
2. **找到每个用户的首次登录日期**：使用 `MIN()` 聚合函数按用户分组
3. **时间范围过滤**：筛选出距离今天（2019-06-30）90 天内的记录
4. **统计每天的新用户数**：按首次登录日期分组，统计用户数量
5. **排序输出**：按日期排序（通常按升序或降序）

**关键点：**
- 首次登录：一个用户可能有多次登录记录，需要找最早的那次
- 时间范围：使用 `DATEDIFF` 函数计算日期差
- 去重：确保每个用户只被计数一次

## SQL 代码实现

### 方法一：子查询（标准解法）

```sql
SELECT 
    login_date,
    COUNT(*) AS user_count
FROM (
    -- 子查询：找出每个用户的首次登录日期
    SELECT 
        user_id,
        MIN(activity_date) AS login_date
    FROM 
        Traffic
    WHERE 
        activity = 'login'
    GROUP BY 
        user_id
) AS first_login
WHERE 
    -- 筛选 90 天内的首次登录
    DATEDIFF('2019-06-30', login_date) <= 90
GROUP BY 
    login_date
ORDER BY 
    login_date;
```

### 方法二：窗口函数（推荐）

```sql
SELECT 
    login_date,
    COUNT(*) AS user_count
FROM (
    -- 使用窗口函数标记每个用户的首次登录
    SELECT 
        user_id,
        activity_date AS login_date,
        ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY activity_date) AS rn
    FROM 
        Traffic
    WHERE 
        activity = 'login'
) AS ranked
WHERE 
    -- 只保留首次登录记录（rn = 1）
    rn = 1
    -- 筛选 90 天内的记录
    AND DATEDIFF('2019-06-30', login_date) <= 90
GROUP BY 
    login_date
ORDER BY 
    login_date;
```

### 方法三：CTE（公共表表达式）

```sql
-- 使用 CTE 提高可读性
WITH first_logins AS (
    -- 第一步：找出每个用户的首次登录日期
    SELECT 
        user_id,
        MIN(activity_date) AS login_date
    FROM 
        Traffic
    WHERE 
        activity = 'login'
    GROUP BY 
        user_id
),
filtered_logins AS (
    -- 第二步：筛选 90 天内的首次登录
    SELECT 
        login_date
    FROM 
        first_logins
    WHERE 
        DATEDIFF('2019-06-30', login_date) <= 90
)
-- 第三步：统计每天的新用户数
SELECT 
    login_date,
    COUNT(*) AS user_count
FROM 
    filtered_logins
GROUP BY 
    login_date
ORDER BY 
    login_date;
```

### 方法四：简化版（单次查询）

```sql
SELECT 
    MIN(activity_date) AS login_date,
    COUNT(DISTINCT user_id) AS user_count
FROM 
    Traffic
WHERE 
    activity = 'login'
    AND DATEDIFF('2019-06-30', activity_date) <= 90
GROUP BY 
    user_id
HAVING 
    MIN(activity_date) = MIN(activity_date)
-- 注意：需要再次分组
SELECT 
    login_date,
    COUNT(*) AS user_count
FROM (
    SELECT 
        user_id,
        MIN(activity_date) AS login_date
    FROM 
        Traffic
    WHERE 
        activity = 'login'
        AND DATEDIFF('2019-06-30', activity_date) <= 90
    GROUP BY 
        user_id
) AS temp
GROUP BY 
    login_date;
```

## 复杂度分析

- **时间复杂度**：O(n log n)，其中 n 是 Traffic 表中登录记录的数量。主要开销在于分组和排序操作。
- **空间复杂度**：O(m)，其中 m 是不同用户的数量，需要存储中间结果。

## 关键点总结

1. **首次登录的识别**：使用 `MIN(activity_date)` 配合 `GROUP BY user_id` 来找到每个用户最早的登录日期
2. **活动类型筛选**：必须先过滤 `activity = 'login'` 的记录，因为表中包含多种活动类型
3. **时间范围计算**：`DATEDIFF('2019-06-30', activity_date) <= 90` 表示从今天往前推 90 天
4. **两次分组**：
   - 第一次按 user_id 分组，找首次登录日期
   - 第二次按 login_date 分组，统计每天的新用户数
5. **去重的重要性**：即使用户在同一天有多次登录，也只计数一次

## 易错点

1. **忘记过滤活动类型**：题目要求统计"登录"，必须添加 `WHERE activity = 'login'`
2. **时间范围计算错误**：
   - 错误：`activity_date >= '2019-04-01'`（硬编码日期）
   - 正确：`DATEDIFF('2019-06-30', activity_date) <= 90`（动态计算）
3. **重复计数**：如果用户在首次登录日期有多次登录，需要确保只计数一次
4. **时间边界问题**：注意是"90 天内（包括今天）"，所以应该是 `<= 90` 而不是 `< 90`
5. **NULL 值处理**：虽然题目没有说明，但实际中应考虑日期可能为 NULL 的情况
6. **子查询嵌套顺序**：必须先找到首次登录日期，再进行时间过滤，顺序不能颠倒

## 学习建议

1. **理解日期函数**：
   - `DATEDIFF(date1, date2)`：计算两个日期之间的天数差
   - `DATE_SUB(date, INTERVAL n DAY)`：日期减去指定天数
   - `DATE_ADD(date, INTERVAL n DAY)`：日期加上指定天数

2. **掌握分组聚合**：
   - `MIN()`、`MAX()` 找极值
   - `COUNT(DISTINCT col)` 去重计数
   - `GROUP BY` 配合 `HAVING` 过滤分组结果

3. **窗口函数的应用**：
   - `ROW_NUMBER()` 为每组记录编号
   - `RANK()` 和 `DENSE_RANK()` 排名
   - `PARTITION BY` 分组，`ORDER BY` 排序

4. **优化查询性能**：
   - 在 WHERE 子句中尽早过滤数据
   - 为常用查询字段（如 activity_date）建立索引
   - 使用 EXPLAIN 分析查询执行计划

5. **SQL 风格选择**：
   - 子查询：传统方法，兼容性好
   - CTE：可读性强，适合复杂逻辑
   - 窗口函数：简洁高效，但需要数据库支持

6. **实践建议**：
   - 先在纸上画出数据处理流程
   - 分步骤编写 SQL，逐步测试
   - 对比不同方法的执行效率
