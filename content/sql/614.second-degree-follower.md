## 题目描述

Table: Follow

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| followee    | varchar |
| follower    | varchar |
+-------------+---------+
(followee, follower) 是此表的主键
此表的每一行表示 follower 关注了 followee
```

写一个 SQL 查询，对于每一个用户，返回他的关注者数量。

需要满足以下条件：
- 该用户至少有一个关注者
- 该用户也关注了至少一个人

返回结果按 follower 字母顺序排序。

查询结果格式如下所示：

**示例：**
```
Follow table:
+----------+----------+
| followee | follower |
+----------+----------+
| A        | B        |
| B        | C        |
| B        | D        |
| D        | E        |
+----------+----------+

Result table:
+----------+-----+
| follower | num |
+----------+-----+
| B        | 2   |
| D        | 1   |
+----------+-----+

解释：
B 关注了 A，同时被 C 和 D 关注，所以 B 是二度关注者，有 2 个关注者
D 关注了 B，同时被 E 关注，所以 D 是二度关注者，有 1 个关注者
A 被 B 关注，但 A 没有关注任何人，所以 A 不是二度关注者
C 关注了 B，但没有人关注 C，所以 C 不是二度关注者
E 关注了 D，但没有人关注 E，所以 E 不是二度关注者
```

## 解题思路

二度关注者的定义：既是别人的关注者（follower），也是别人的被关注者（followee）。

**核心步骤：**
1. 找出所有作为 follower 出现的用户（说明他们关注了别人）
2. 找出所有作为 followee 出现的用户（说明有人关注他们）
3. 取交集，统计作为 followee 时的关注者数量

**SQL技巧：**
- 使用 GROUP BY 和 COUNT 统计关注者数量
- 使用 WHERE IN 或 INNER JOIN 筛选同时满足两个条件的用户
- 使用 ORDER BY 排序结果

## SQL 代码实现

### 方法一：子查询（推荐）

```sql
SELECT followee AS follower, COUNT(DISTINCT follower) AS num
FROM Follow
WHERE followee IN (
    -- 找出所有关注了别人的用户
    SELECT DISTINCT follower
    FROM Follow
)
GROUP BY followee
ORDER BY follower;
```

### 方法二：INNER JOIN

```sql
SELECT f1.followee AS follower, COUNT(DISTINCT f1.follower) AS num
FROM Follow f1
INNER JOIN Follow f2
ON f1.followee = f2.follower
GROUP BY f1.followee
ORDER BY follower;
```

### 方法三：使用 HAVING

```sql
SELECT followee AS follower, COUNT(DISTINCT follower) AS num
FROM Follow
GROUP BY followee
HAVING followee IN (
    SELECT DISTINCT follower
    FROM Follow
)
ORDER BY follower;
```

### 方法四：CTE 方式

```sql
WITH Followers AS (
    SELECT DISTINCT follower
    FROM Follow
),
Followees AS (
    SELECT followee, COUNT(DISTINCT follower) AS num
    FROM Follow
    GROUP BY followee
)
SELECT f.followee AS follower, f.num
FROM Followees f
INNER JOIN Followers fl
ON f.followee = fl.follower
ORDER BY follower;
```

## 复杂度分析

- 时间复杂度：O(n log n)，需要分组、计数和排序
- 空间复杂度：O(n)，存储中间结果

## 关键点总结

1. 理解二度关注者的定义：既关注别人，也被别人关注
2. 需要同时出现在 follower 和 followee 列中
3. 统计的是作为 followee 时的关注者数量
4. 使用 DISTINCT 避免重复计数
5. 记得按字母顺序排序

## 易错点

1. 只统计了被关注数，忘记检查是否关注了别人
2. 没有使用 DISTINCT 导致重复计数
3. 混淆了 follower 和 followee 的角色
4. 忘记排序结果
