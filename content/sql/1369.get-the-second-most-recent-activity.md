## 题目描述

**UserActivity** 表记录了用户的活动信息：

| 列名       | 类型    |
|------------|---------|
| username   | varchar |
| userEvent  | varchar |
| startDate  | Date    |
| endDate    | Date    |

该表没有主键，同一用户可能有多条记录。

**要求：** 对每位用户，找出他们**倒数第二近**的活动记录。如果某用户只有一条活动记录，则返回那一条。

**结果按任意顺序返回。**

**示例：**

输入：

| username | userEvent | startDate  | endDate    |
|----------|-----------|------------|------------|
| Alice    | Travel    | 2020-02-12 | 2020-02-20 |
| Alice    | Dancing   | 2020-02-21 | 2020-02-23 |
| Alice    | Travel    | 2020-02-24 | 2020-02-28 |
| Bob      | Travel    | 2020-02-11 | 2020-02-18 |

输出：

| username | userEvent | startDate  | endDate    |
|----------|-----------|------------|------------|
| Alice    | Dancing   | 2020-02-21 | 2020-02-23 |
| Bob      | Travel    | 2020-02-11 | 2020-02-18 |

解释：
- Alice 有3条活动，按 startDate 排序后，倒数第二是 Dancing（2020-02-21）。
- Bob 只有1条活动，直接返回该条。

## 解题思路

### 核心思想

本题需要取每位用户**最近活动的倒数第二条**，若只有一条则取唯一那条。

**关键点：**
1. 使用窗口函数 `ROW_NUMBER()` 按用户分组、按 `startDate` 降序排名（最近活动排名第1）。
2. 同时用 `COUNT()` 窗口函数统计每位用户的活动总数。
3. 筛选条件：排名为2，**或者** 用户只有1条活动（总数=1）。

### 方法一：ROW_NUMBER() + COUNT() 窗口函数（推荐）

**算法流程：**
1. 子查询中对每条记录计算：
   - `rk`：按用户分组、按 startDate 降序的行号
   - `cnt`：该用户总活动数
2. 外层筛选 `rk = 2 OR cnt = 1`

## 代码实现

### 方法一：SQL 窗口函数（推荐）

```sql
-- 使用 ROW_NUMBER() 和 COUNT() 窗口函数
SELECT username, userEvent, startDate, endDate
FROM (
    SELECT
        username,
        userEvent,
        startDate,
        endDate,
        ROW_NUMBER() OVER (
            PARTITION BY username
            ORDER BY startDate DESC
        ) AS rk,
        COUNT(*) OVER (
            PARTITION BY username
        ) AS cnt
    FROM UserActivity
) t
WHERE rk = 2 OR cnt = 1;
```

### 方法二：自连接（不使用窗口函数）

```sql
-- 思路：找到每位用户最近活动日期，再找倒数第二近
-- 先找出每位用户的最大 startDate（即最近活动）
-- 再找除最近活动外的最大 startDate

SELECT a.username, a.userEvent, a.startDate, a.endDate
FROM UserActivity a
WHERE a.startDate = (
    -- 找该用户除最近活动外的最近 startDate
    SELECT MAX(b.startDate)
    FROM UserActivity b
    WHERE b.username = a.username
      AND b.startDate < (
          SELECT MAX(c.startDate)
          FROM UserActivity c
          WHERE c.username = a.username
      )
)

UNION ALL

-- 用户只有一条活动的情况
SELECT a.username, a.userEvent, a.startDate, a.endDate
FROM UserActivity a
WHERE a.username NOT IN (
    SELECT DISTINCT b.username
    FROM UserActivity b
    WHERE b.startDate < (
        SELECT MAX(c.startDate)
        FROM UserActivity c
        WHERE c.username = b.username
    )
);
```

## 复杂度分析

### SQL 方法一（窗口函数）
- **时间复杂度**：O(n log n)，对每个分区内部排序
- **空间复杂度**：O(n)，存储中间结果

### SQL 方法二（自连接）
- **时间复杂度**：O(n²)，多次子查询扫描
- **空间复杂度**：O(n)

### Python 模拟
- **时间复杂度**：O(n log n)
- **空间复杂度**：O(n)

## 关键点总结

1. `ROW_NUMBER()` 窗口函数可以为每个分区内的行编排唯一序号，即使有相同值也不会并列。
2. `PARTITION BY username ORDER BY startDate DESC` 确保按用户分组、按时间从新到旧排序。
3. `COUNT(*) OVER (PARTITION BY username)` 可以在不 GROUP BY 的情况下获得组内总数。
4. 特殊情况：只有1条记录的用户，需单独处理（`cnt = 1`）。
5. 方法一（窗口函数）比方法二（自连接）更简洁高效，是现代 SQL 的最佳实践。

## 易错点

1. **忘记处理只有1条记录的用户**：题目明确要求只有一条时返回那唯一一条，需额外加 `OR cnt = 1` 条件。
2. **排序方向搞反**：要取"倒数第二近"，需按 `startDate DESC` 排序，第2行才是倒数第二近。
3. **使用 RANK() 而非 ROW_NUMBER()**：若两条记录 startDate 相同，`RANK()` 会出现并列，导致结果错误。`ROW_NUMBER()` 保证每行唯一序号。
4. **自连接写法容易超时**：对大数据集，避免嵌套三层子查询，优先使用窗口函数。

## 学习建议

1. **先掌握基础窗口函数**：`ROW_NUMBER()`、`RANK()`、`DENSE_RANK()` 是解决排名类 SQL 题的核心工具。
2. **理解 PARTITION BY 和 ORDER BY 的组合**：PARTITION BY 相当于分组，ORDER BY 决定组内排序。
3. **对比 ROW_NUMBER vs RANK vs DENSE_RANK**：
   - `ROW_NUMBER`：严格唯一序号，相同值也会分配不同序号
   - `RANK`：相同值并列，下一个序号跳跃（1,1,3）
   - `DENSE_RANK`：相同值并列，下一个序号连续（1,1,2）
4. 本题是典型的"取第N条"问题，掌握后可快速解决同类题目。
