## 题目描述

**Friends 表：**

| 列名     | 类型    |
|----------|---------|
| id       | int     |
| name     | varchar |
| activity | varchar |

`id` 是该表的主键。`name` 是朋友的名字，`activity` 是朋友参加的活动名称。

**Activities 表：**

| 列名 | 类型    |
|------|---------|
| id   | int     |
| name | varchar |

`id` 是该表的主键。`name` 是活动名称。

找出那些**既不是参与人数最多**，**也不是参与人数最少**的活动的名字。

每个活动在 `Activities` 表中都有记录（保证活动有效），返回结果顺序不限。

**示例：**

Friends 表：
```
+------+---------+---------------+
| id   | name    | activity      |
+------+---------+---------------+
| 1    | Jonathan| Reading       |
| 2    | Elvis   | Television    |
| 3    | Daniel  | Reading       |
| 4    | Eric    | Dead Pebblins |
| 5    | Daphne  | Television    |
| 6    | Adam    | Television    |
| 7    | Grace   | Dead Pebblins |
| 8    | Debbie  | Shopping      |
| 9    | Kevin   | Reading       |
| 10   | Avery   | Television    |
| 11   | Raven   | Dead Pebblins |
| 12   | Elaine  | Dead Pebblins |
+------+---------+---------------+
```

Activities 表：
```
+------+---------------+
| id   | name          |
+------+---------------+
| 1    | Reading       |
| 2    | Television    |
| 3    | Dead Pebblins |
| 4    | Shopping      |
+------+---------------+
```

结果表：
```
+---------------+
| activity      |
+---------------+
| Reading       |
| Dead Pebblins |
+---------------+
```

- Shopping：1人（最少），排除
- Television：4人（最多），排除
- Reading：3人
- Dead Pebblins：4人... 等

实际上 Television=4, Dead Pebblins=4（并列最多），Shopping=1（最少），Reading=3（居中）。

**注意：** 结果不应包含只有 0 个参与者的活动（Activities 表中有但 Friends 没有参加的）？本题保证每个活动至少有一个参与者。

## 解题思路

1. 先对 Friends 表按 activity 分组，统计每个活动的参与人数。
2. 找出参与人数的最大值和最小值。
3. 筛选出参与人数既不是最大也不是最小的活动。

**注意：** 如果所有活动的参与人数都相同（只有一个不同的参与人数），则所有活动都要排除，结果为空。

## SQL 解法

### 方法一：子查询 + HAVING（推荐）

```sql
SELECT activity
FROM Friends
GROUP BY activity
HAVING COUNT(*) > (
    SELECT MIN(cnt)
    FROM (
        SELECT COUNT(*) AS cnt
        FROM Friends
        GROUP BY activity
    ) AS sub
)
AND COUNT(*) < (
    SELECT MAX(cnt)
    FROM (
        SELECT COUNT(*) AS cnt
        FROM Friends
        GROUP BY activity
    ) AS sub
);
```

### 方法二：CTE（公用表表达式，更清晰）

```sql
WITH activity_count AS (
    SELECT activity, COUNT(*) AS cnt
    FROM Friends
    GROUP BY activity
)
SELECT activity
FROM activity_count
WHERE cnt > (SELECT MIN(cnt) FROM activity_count)
  AND cnt < (SELECT MAX(cnt) FROM activity_count);
```

**解释：**
1. `activity_count` CTE 统计每个活动的参与人数。
2. 外层查询筛选 cnt 既大于最小值又小于最大值的活动。
3. 使用 CTE 避免重复子查询，代码更清晰。

### 方法三：RANK 窗口函数

```sql
WITH activity_count AS (
    SELECT activity, COUNT(*) AS cnt
    FROM Friends
    GROUP BY activity
),
ranked AS (
    SELECT activity, cnt,
           RANK() OVER (ORDER BY cnt ASC)  AS rank_asc,
           RANK() OVER (ORDER BY cnt DESC) AS rank_desc
    FROM activity_count
)
SELECT activity
FROM ranked
WHERE rank_asc > 1 AND rank_desc > 1;
```

**解释：**
- `rank_asc` 是按参与人数升序的排名，排名为 1 的是最少的。
- `rank_desc` 是按参与人数降序的排名，排名为 1 的是最多的。
- 过滤两个排名都大于 1 的活动，即既不是最少也不是最多。
- 使用 `RANK()` 而非 `ROW_NUMBER()` 是因为可能有并列情况（如两个活动都是参与人数最多）。

### 方法四：NOT IN + 子查询

```sql
WITH activity_count AS (
    SELECT activity, COUNT(*) AS cnt
    FROM Friends
    GROUP BY activity
)
SELECT activity
FROM activity_count
WHERE cnt NOT IN (
    SELECT MAX(cnt) FROM activity_count
    UNION
    SELECT MIN(cnt) FROM activity_count
);
```

## 复杂度分析

- 时间复杂度：O(N)，其中 N 是 Friends 表的行数。统计参与人数需扫描一次，查找最大最小值需一次，过滤需一次。
- 空间复杂度：O(M)，其中 M 是不同活动的数量。

## 关键点总结

1. 分两步：先统计各活动参与人数，再找最大最小并过滤。
2. CTE 让 SQL 逻辑更清晰，避免重复子查询。
3. 使用 `RANK()` 而非 `ROW_NUMBER()` 处理并列情况（多个活动并列最多或最少时都要排除）。
4. 特殊情况：如果所有活动参与人数相同，结果为空集。
5. 本题只需要从 Friends 表中分组查询，不必 JOIN Activities 表（题目保证所有活动都有参与者）。

## 易错点

- 忘记处理并列情况：如果两个活动并列参与人数最多，两者都应被排除，`RANK()` 能正确处理，`ROW_NUMBER()` 不行。
- 使用 `NOT IN (MAX, MIN)` 时注意子查询需要分开写（MAX 和 MIN 是两个值，用 UNION 合并）。
- 如果题目不保证每个活动都有参与者，需要 LEFT JOIN Activities 表，并将 NULL 计数视为 0。
