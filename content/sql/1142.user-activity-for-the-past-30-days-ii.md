## 题目描述

表：`Activity`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| user_id       | int     |
| session_id    | int     |
| activity_date | date    |
| activity_type | enum    |
+---------------+---------+
该表没有主键，可能包含重复的行。
activity_type 列是 ENUM 类型，可能的值为 ('open_session', 'end_session', 'scroll_down', 'send_message')。
该表显示了社交媒体网站的用户活动。
请注意，每个会话只属于一个用户。
```

编写一个 SQL 查询，查找截至 2019-07-27（包括此日期）的 30 天内每个用户的平均会话数，结果保留 2 位小数。

我们只想统计那些在此时间范围内有会话的用户。

查询结果格式如下例所示。

**示例 1：**

输入：
```
Activity 表：
+---------+------------+---------------+---------------+
| user_id | session_id | activity_date | activity_type |
+---------+------------+---------------+---------------+
| 1       | 1          | 2019-07-20    | open_session  |
| 1       | 1          | 2019-07-20    | scroll_down   |
| 1       | 1          | 2019-07-20    | end_session   |
| 2       | 4          | 2019-07-20    | open_session  |
| 2       | 4          | 2019-07-21    | send_message  |
| 2       | 4          | 2019-07-21    | end_session   |
| 3       | 2          | 2019-07-21    | open_session  |
| 3       | 2          | 2019-07-21    | send_message  |
| 3       | 2          | 2019-07-21    | end_session   |
| 3       | 5          | 2019-07-21    | open_session  |
| 3       | 5          | 2019-07-21    | scroll_down   |
| 3       | 5          | 2019-07-21    | end_session   |
| 4       | 3          | 2019-06-25    | open_session  |
| 4       | 3          | 2019-06-25    | end_session   |
+---------+------------+---------------+---------------+
```

输出：
```
+---------------------------+ 
| average_sessions_per_user |
+---------------------------+ 
| 1.33                      |
+---------------------------+
```

解释：
用户 1 和 2 在过去 30 天内各有 1 个会话，而用户 3 有 2 个会话，所以平均值是 (1 + 1 + 2) / 3 = 1.33。

## 解题思路

这道题是 1141 题的进阶版，要求计算每个用户的平均会话数。

**解题步骤：**

1. **筛选日期范围**：
   - 截至 2019-07-27 的 30 天内
   - 即 2019-06-28 到 2019-07-27

2. **统计每个用户的会话数**：
   - 需要对 session_id 去重（因为同一会话有多条记录）
   - 按 user_id 分组，统计不同的 session_id 数量

3. **计算平均值**：
   - 总会话数 / 用户数
   - 使用 `ROUND` 或 `IFNULL` 处理结果

4. **边界情况**：
   - 如果没有用户，平均值为 0（需要用 IFNULL 处理）
   - 保留两位小数

## SQL 代码实现

### 方法一：子查询 + 聚合 ⭐

```sql
-- 先统计每个用户的会话数，再计算平均
SELECT 
    IFNULL(ROUND(AVG(session_count), 2), 0.00) AS average_sessions_per_user
FROM (
    SELECT 
        user_id,
        COUNT(DISTINCT session_id) AS session_count
    FROM 
        Activity
    WHERE 
        activity_date BETWEEN '2019-06-28' AND '2019-07-27'
    GROUP BY 
        user_id
) AS user_sessions;
```

### 方法二：直接计算 ⭐ 推荐

```sql
-- 直接计算总会话数 / 用户数
SELECT 
    IFNULL(
        ROUND(
            COUNT(DISTINCT session_id) / COUNT(DISTINCT user_id), 
            2
        ), 
        0.00
    ) AS average_sessions_per_user
FROM 
    Activity
WHERE 
    activity_date BETWEEN '2019-06-28' AND '2019-07-27';
```

### 方法三：使用 DATEDIFF

```sql
-- 使用 DATEDIFF 进行日期筛选
SELECT 
    ROUND(
        COUNT(DISTINCT session_id) / COUNT(DISTINCT user_id), 
        2
    ) AS average_sessions_per_user
FROM 
    Activity
WHERE 
    DATEDIFF('2019-07-27', activity_date) < 30
    AND DATEDIFF('2019-07-27', activity_date) >= 0;
```

### 方法四：CTE 写法（更清晰）

```sql
-- 使用 CTE 使逻辑更清晰
WITH UserSessions AS (
    SELECT 
        user_id,
        COUNT(DISTINCT session_id) AS sessions
    FROM 
        Activity
    WHERE 
        activity_date BETWEEN DATE_SUB('2019-07-27', INTERVAL 29 DAY) 
                          AND '2019-07-27'
    GROUP BY 
        user_id
)
SELECT 
    ROUND(AVG(sessions), 2) AS average_sessions_per_user
FROM 
    UserSessions;
```

### 方法五：处理空结果

```sql
-- 显式处理没有数据的情况
SELECT 
    COALESCE(
        ROUND(
            SUM(session_count) / COUNT(*), 
            2
        ), 
        0.00
    ) AS average_sessions_per_user
FROM (
    SELECT 
        user_id,
        COUNT(DISTINCT session_id) AS session_count
    FROM 
        Activity
    WHERE 
        activity_date BETWEEN '2019-06-28' AND '2019-07-27'
    GROUP BY 
        user_id
) AS t;
```

## 复杂度分析

**时间复杂度**：O(n)
- 需要扫描符合日期条件的所有记录
- 如果有索引可以优化

**空间复杂度**：O(m)
- m 为用户数，需要存储每个用户的会话统计

## 关键点总结

1. **去重两次**：
   - 统计会话数时要去重 session_id
   - 统计用户数时要去重 user_id

2. **除法精度**：
   - 使用 `COUNT / COUNT` 可能得到整数结果
   - 需要使用 `ROUND(..., 2)` 保留两位小数

3. **NULL 值处理**：
   - 使用 `IFNULL` 或 `COALESCE` 处理空结果
   - 避免除以 0

4. **日期范围**：
   - 过去 30 天：从第 29 天前到今天，共 30 天
   - BETWEEN 包含两端

5. **子查询 vs 直接计算**：
   - 子查询更清晰，符合思维逻辑
   - 直接计算更简洁高效

## 易错点

1. **忘记去重 session_id**：
   - 错误：`COUNT(session_id)` 会重复计数
   - 正确：`COUNT(DISTINCT session_id)`

2. **整数除法问题**：
   ```sql
   -- 错误：可能得到整数
   COUNT(DISTINCT session_id) / COUNT(DISTINCT user_id)
   
   -- 正确：确保浮点除法
   CAST(COUNT(DISTINCT session_id) AS DECIMAL) / COUNT(DISTINCT user_id)
   -- 或使用 ROUND 自动转换
   ROUND(COUNT(DISTINCT session_id) / COUNT(DISTINCT user_id), 2)
   ```

3. **日期范围错误**：
   - 过去 30 天不是从 30 天前开始
   - 应该是从 29 天前到今天

4. **未处理空结果**：
   - 如果没有数据，AVG 返回 NULL
   - 需要用 IFNULL 转换为 0.00

5. **小数位数不对**：
   - 必须保留 2 位小数
   - 使用 `ROUND(..., 2)`

## SQL 技巧对比

### 方法对比

| 方法 | 优点 | 缺点 |
|------|------|------|
| 子查询 | 逻辑清晰，易理解 | 需要两次扫描 |
| 直接计算 | 简洁高效，一次扫描 | 逻辑不够直观 |
| CTE | 可读性最好 | MySQL 5.7 不支持 |

### NULL 处理对比

```sql
-- IFNULL：只能处理 NULL
IFNULL(value, 0.00)

-- COALESCE：可以处理多个值
COALESCE(value1, value2, 0.00)

-- CASE WHEN：最灵活
CASE WHEN value IS NULL THEN 0.00 ELSE value END
```
