## 题目描述

表：`Accounts`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| id            | int     |
| name          | varchar |
+---------------+---------+
id 是该表的主键。
```

表：`Logins`

```
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| id            | int     |
| login_date    | date    |
+---------------+---------+
该表没有主键，可能包含重复项。
id 是 Accounts 表中 id 的外键。
```

编写 SQL 查询，找出**活跃用户**的 id 和 name。

活跃用户是指那些**至少连续 5 天登录账号**的用户。

返回的结果表按 id 排序，且不包含重复数据。

**示例：**

`Accounts` 表：
```
+----+----------+
| id | name     |
+----+----------+
| 1  | Winston  |
| 7  | Jonathan |
+----+----------+
```

`Logins` 表：
```
+----+------------+
| id | login_date |
+----+------------+
| 7  | 2020-05-30 |
| 1  | 2020-05-30 |
| 7  | 2020-05-31 |
| 7  | 2020-06-01 |
| 7  | 2020-06-02 |
| 7  | 2020-06-02 |
| 7  | 2020-06-03 |
| 1  | 2020-06-07 |
| 7  | 2020-06-10 |
+----+------------+
```

结果表：
```
+----+----------+
| id | name     |
+----+----------+
| 7  | Jonathan |
+----+----------+
```
解释：Jonathan 从 2020-05-30 到 2020-06-03 共 5 天连续登录（有重复日期也只算一天）。

## 解题思路

**方法：ROW_NUMBER 减 DENSE_RANK 差值分组法**

这是检测连续日期的经典 SQL 技巧：

1. 先对每个用户去重（同一天多次登录只算一次）
2. 为每个用户的登录日期分配行号 `rn`（按日期排序）
3. 用 `DATE_SUB(login_date, INTERVAL rn DAY)` 计算"基准日期"：如果日期是连续的，减去行号后得到同一个基准日期
4. 按 `(id, 基准日期)` 分组，统计每组天数，若 `COUNT >= 5` 则为活跃用户

**直觉理解：**
- 连续日期：2020-06-01, 06-02, 06-03，行号为 1, 2, 3
- 减去行号：06-01-1天=05-31, 06-02-2天=05-31, 06-03-3天=05-31 → 相同！
- 不连续时，基准日期不同，会分成不同组

## SQL 解法

### 方法一：ROW_NUMBER 差值分组（推荐）

```sql
SELECT DISTINCT a.id, a.name
FROM Accounts a
JOIN (
    -- 第三步：找出连续登录 >= 5 天的用户
    SELECT id
    FROM (
        -- 第二步：计算差值基准日期
        SELECT
            id,
            DATE_SUB(login_date, INTERVAL ROW_NUMBER() OVER (
                PARTITION BY id ORDER BY login_date
            ) DAY) AS base_date
        FROM (
            -- 第一步：去重，同一用户同一天只保留一条记录
            SELECT DISTINCT id, login_date
            FROM Logins
        ) dedup
    ) grouped
    GROUP BY id, base_date
    HAVING COUNT(*) >= 5
) active ON a.id = active.id
ORDER BY a.id;
```

### 方法二：自连接法（暴力，较慢）

```sql
SELECT DISTINCT a.id, a.name
FROM Accounts a
WHERE a.id IN (
    SELECT l1.id
    FROM Logins l1
    WHERE EXISTS (
        -- 检查从 l1.login_date 开始连续 5 天都有登录
        SELECT 1 FROM Logins l2 WHERE l2.id = l1.id AND l2.login_date = DATE_ADD(l1.login_date, INTERVAL 1 DAY)
    ) AND EXISTS (
        SELECT 1 FROM Logins l2 WHERE l2.id = l1.id AND l2.login_date = DATE_ADD(l1.login_date, INTERVAL 2 DAY)
    ) AND EXISTS (
        SELECT 1 FROM Logins l2 WHERE l2.id = l1.id AND l2.login_date = DATE_ADD(l1.login_date, INTERVAL 3 DAY)
    ) AND EXISTS (
        SELECT 1 FROM Logins l2 WHERE l2.id = l1.id AND l2.login_date = DATE_ADD(l1.login_date, INTERVAL 4 DAY)
    )
)
ORDER BY a.id;
```

### 方法三：分步 CTE 写法（更清晰）

```sql
WITH dedup AS (
    -- 步骤1：每个用户每天只保留一次登录记录
    SELECT DISTINCT id, login_date
    FROM Logins
),
numbered AS (
    -- 步骤2：为每个用户的登录日期编号
    SELECT
        id,
        login_date,
        ROW_NUMBER() OVER (PARTITION BY id ORDER BY login_date) AS rn
    FROM dedup
),
grouped AS (
    -- 步骤3：计算差值基准日期（连续日期基准相同）
    SELECT
        id,
        DATE_SUB(login_date, INTERVAL rn DAY) AS base_date,
        COUNT(*) AS consecutive_days
    FROM numbered
    GROUP BY id, base_date
)
-- 步骤4：找出连续登录 >= 5 天的用户并关联姓名
SELECT DISTINCT a.id, a.name
FROM Accounts a
INNER JOIN grouped g ON a.id = g.id
WHERE g.consecutive_days >= 5
ORDER BY a.id;
```

## 复杂度分析

- 时间复杂度：O(n log n)，主要由排序（窗口函数）决定，n 为登录记录数
- 空间复杂度：O(n)，中间结果集

## 关键点总结

1. 连续日期检测的经典方法：`日期 - ROW_NUMBER() = 常数`
2. 必须先对 `(id, login_date)` 去重，避免同一天多次登录影响行号
3. `HAVING COUNT(*) >= 5` 筛选连续登录 5 天及以上的分组
4. 最终结果需要 `DISTINCT` 去重（一个用户可能有多个满足条件的连续段）

## 易错点

- **忘记去重**：同一天多次登录会导致行号偏移，基准日期不准确
- **连续 5 天的含义**：是日历上连续 5 天，不是任意 5 次登录
- `DATE_SUB` 和 `DATE_ADD` 在不同数据库中语法不同：MySQL 用 `DATE_SUB(date, INTERVAL n DAY)`，PostgreSQL 用 `date - n`
