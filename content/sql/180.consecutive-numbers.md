## 题目描述

表：`Logs`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| num         | varchar |
+-------------+---------+
```

id 是这个表的主键。
id 是一个自增列。

编写一个 SQL 查询，查找所有至少连续出现三次的数字。

返回的结果表中的数据可以按任意顺序排列。

查询结果格式如下例所示。

**示例 1：**

```
输入：
Logs 表：
+----+-----+
| id | num |
+----+-----+
| 1  | 1   |
| 2  | 1   |
| 3  | 1   |
| 4  | 2   |
| 5  | 1   |
| 6  | 2   |
| 7  | 2   |
+----+-----+

输出：
+-----------------+
| ConsecutiveNums |
+-----------------+
| 1               |
+-----------------+

解释：1 是唯一连续出现至少三次的数字。
```

## 解题思路

这道题的关键是理解 **连续** 的含义：
- 连续是指 `id` 连续（1, 2, 3）
- 不是指 `num` 相同就算连续

### 核心思路

有多种方法判断连续：

1. **自连接法**：连接三次表，判断三个连续 id 的 num 是否相同
2. **窗口函数 LAG/LEAD**：查看前后行的值是否相同
3. **窗口函数 ROW_NUMBER**：利用 `id - row_number` 的差值分组

## SQL 代码实现

### 方法一：自连接（推荐，无窗口函数）

```sql
SELECT DISTINCT l1.num AS ConsecutiveNums
FROM 
    Logs l1,
    Logs l2,
    Logs l3
WHERE 
    l1.id = l2.id - 1
    AND l2.id = l3.id - 1
    AND l1.num = l2.num
    AND l2.num = l3.num;
```

**代码解释：**
1. `l1.id = l2.id - 1`：确保 l1 和 l2 的 id 连续
2. `l2.id = l3.id - 1`：确保 l2 和 l3 的 id 连续
3. `l1.num = l2.num AND l2.num = l3.num`：确保三个 num 值相同
4. `DISTINCT`：去重（因为可能有多组连续的相同数字）

### 方法二：LAG/LEAD 窗口函数

```sql
SELECT DISTINCT num AS ConsecutiveNums
FROM (
    SELECT 
        num,
        LAG(num, 1) OVER (ORDER BY id) AS prev_num,
        LEAD(num, 1) OVER (ORDER BY id) AS next_num
    FROM Logs
) AS temp
WHERE num = prev_num AND num = next_num;
```

**代码解释：**
1. `LAG(num, 1)`：获取前一行的 num 值
2. `LEAD(num, 1)`：获取后一行的 num 值
3. `WHERE num = prev_num AND num = next_num`：当前行、前一行、后一行的 num 都相同

### 方法三：ROW_NUMBER 分组法

```sql
SELECT DISTINCT num AS ConsecutiveNums
FROM (
    SELECT 
        num,
        id - ROW_NUMBER() OVER (PARTITION BY num ORDER BY id) AS grp
    FROM Logs
) AS temp
GROUP BY num, grp
HAVING COUNT(*) >= 3;
```

**代码解释：**
1. `id - ROW_NUMBER()`：对于连续相同的 num，这个差值是相同的
   - 例如：id=[1,2,3], row_number=[1,2,3], 差值=[0,0,0]
   - 如果不连续：id=[1,2,5], row_number=[1,2,3], 差值=[0,0,2]
2. `PARTITION BY num`：对每个 num 分别计算 ROW_NUMBER
3. `GROUP BY num, grp`：按 num 和分组标识分组
4. `HAVING COUNT(*) >= 3`：筛选出现至少 3 次的分组

### 方法四：变量法（MySQL 特有）

```sql
SELECT DISTINCT num AS ConsecutiveNums
FROM (
    SELECT 
        num,
        CASE 
            WHEN @prev_num = num THEN @count := @count + 1
            WHEN @prev_num := num THEN @count := 1
        END AS count
    FROM 
        Logs,
        (SELECT @prev_num := NULL, @count := 0) AS init
    ORDER BY id
) AS temp
WHERE count >= 3;
```

**代码解释：**
1. `@prev_num` 存储前一个 num，`@count` 存储连续次数
2. 如果当前 num 等于前一个，计数加 1
3. 如果不等，重置计数为 1
4. 筛选计数 >= 3 的记录

### 方法五：多层 LAG（适用于固定次数）

```sql
SELECT DISTINCT num AS ConsecutiveNums
FROM (
    SELECT 
        num,
        LAG(num, 1) OVER (ORDER BY id) AS num1,
        LAG(num, 2) OVER (ORDER BY id) AS num2
    FROM Logs
) AS temp
WHERE num = num1 AND num = num2;
```

**代码解释：**
1. `LAG(num, 1)`：前 1 行的 num
2. `LAG(num, 2)`：前 2 行的 num
3. 当前行与前两行都相同，说明至少连续 3 次

## 复杂度分析

**方法一（自连接）：**
- 时间复杂度：O(n³)，三表连接
- 空间复杂度：O(n³)，中间结果集
- 优点：不依赖窗口函数，兼容性好

**方法二（LAG/LEAD）：**
- 时间复杂度：O(n)，单次扫描
- 空间复杂度：O(n)
- 优点：逻辑清晰，易于理解

**方法三（ROW_NUMBER）：**
- 时间复杂度：O(n log n)，排序和分组
- 空间复杂度：O(n)
- 优点：可扩展到任意连续次数

**方法四（变量）：**
- 时间复杂度：O(n)
- 空间复杂度：O(1)
- 缺点：在新版 MySQL 中可能有兼容性问题

**方法五（多层 LAG）：**
- 时间复杂度：O(n)
- 空间复杂度：O(n)
- 缺点：只适用于固定次数（如 3 次）

## 关键点总结

1. **连续的定义**：基于 id 连续，而不只是 num 相同
2. **去重必须**：使用 `DISTINCT` 避免重复结果
3. **方法选择**：
   - 不支持窗口函数：方法一（自连接）
   - 支持窗口函数：方法二（LAG/LEAD）最直观
   - 需要扩展到 N 次连续：方法三（ROW_NUMBER）
4. **窗口函数优势**：代码简洁，性能更好
5. **ROW_NUMBER 技巧**：`id - row_number` 可以识别连续分组

## 易错点

1. **忘记 DISTINCT**
   ```sql
   -- 错误：可能返回重复的数字
   SELECT l1.num AS ConsecutiveNums ...
   
   -- 正确：去重
   SELECT DISTINCT l1.num AS ConsecutiveNums ...
   ```

2. **连接条件错误**
   ```sql
   -- 错误：这只保证 num 相同，不保证 id 连续
   WHERE l1.num = l2.num AND l2.num = l3.num
   
   -- 正确：必须同时检查 id 连续和 num 相同
   WHERE l1.id = l2.id - 1 AND l2.id = l3.id - 1 
         AND l1.num = l2.num AND l2.num = l3.num
   ```

3. **窗口函数缺少 ORDER BY**
   ```sql
   -- 错误：没有 ORDER BY，LAG/LEAD 结果不确定
   LAG(num, 1) OVER ()
   
   -- 正确：必须按 id 排序
   LAG(num, 1) OVER (ORDER BY id)
   ```

4. **HAVING 与 WHERE 混淆**
   ```sql
   -- 错误：WHERE 不能用于聚合结果
   WHERE COUNT(*) >= 3
   
   -- 正确：使用 HAVING
   HAVING COUNT(*) >= 3
   ```

5. **列名错误**
   ```sql
   -- 错误：列名必须是 ConsecutiveNums
   SELECT DISTINCT num
   
   -- 正确：
   SELECT DISTINCT num AS ConsecutiveNums
   ```

## 学习建议

1. **从简单到复杂**：
   - 先理解方法一（自连接），这是最直观的思路
   - 再学习方法二（LAG/LEAD），这是窗口函数的常见用法
   - 最后掌握方法三（ROW_NUMBER），这是高级技巧

2. **理解连续的本质**：
   - 连续 = id 连续 + 值相同
   - 手动模拟几组数据，理解什么是连续

3. **窗口函数必学**：
   - `LAG(col, n)`：向前看 n 行
   - `LEAD(col, n)`：向后看 n 行
   - `ROW_NUMBER()`：行号
   - 这些函数在很多题目中都会用到

4. **实践练习**：
   - 测试边界情况：空表、单条记录、所有数字都相同
   - 修改题目：改为至少连续 4 次、5 次
   - 扩展：找出所有连续出现的数字及其连续次数

5. **性能优化**：
   - 对比不同方法的执行计划（EXPLAIN）
   - 在大数据集上测试性能差异
   - 理解为什么窗口函数比自连接更高效

6. **面试技巧**：
   - 优先写方法一（自连接），适用范围最广
   - 如果允许窗口函数，展示方法二（更简洁）
   - 能够解释方法三的技巧（展示深度）
   - 记得加 DISTINCT 去重
