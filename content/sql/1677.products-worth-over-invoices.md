## 题目描述

表：`Product`
```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| product_id  | int     |
| name        | varchar |
+-------------+---------+
product_id 是主键
```

表：`Invoice`
```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| invoice_id  | int     |
| product_id  | int     |
| rest        | int     |
| paid        | int     |
| canceled    | int     |
| refunded    | int     |
+-------------+---------+
invoice_id 是主键
```

对每个产品，计算所有发票中 `rest`、`paid`、`canceled`、`refunded` 列的总和，返回 `rest > 0` 的产品名称和各列总和。

结果按产品名称升序排列。

## 解题思路

1. 按 `product_id` 分组，对各列求 SUM
2. JOIN `Product` 获取产品名称
3. 过滤 `rest > 0`
4. 按名称排序

## 代码实现

### 方法一：GROUP BY + HAVING（推荐）

```sql
SELECT
    p.name,
    SUM(i.rest) AS rest,
    SUM(i.paid) AS paid,
    SUM(i.canceled) AS canceled,
    SUM(i.refunded) AS refunded
FROM Product p
JOIN Invoice i ON p.product_id = i.product_id
GROUP BY p.product_id, p.name
HAVING SUM(i.rest) > 0
ORDER BY p.name;
```

### 方法二：先聚合再 JOIN

```sql
SELECT
    p.name,
    agg.rest,
    agg.paid,
    agg.canceled,
    agg.refunded
FROM (
    SELECT
        product_id,
        SUM(rest) AS rest,
        SUM(paid) AS paid,
        SUM(canceled) AS canceled,
        SUM(refunded) AS refunded
    FROM Invoice
    GROUP BY product_id
    HAVING SUM(rest) > 0
) agg
JOIN Product p ON p.product_id = agg.product_id
ORDER BY p.name;
```

## 复杂度分析

| 方法 | 说明 |
|------|------|
| GROUP BY + HAVING | 直接过滤，效率高 |
| 先聚合再 JOIN | 先过滤再关联，适合大数据量 |

## 关键点总结

1. `HAVING SUM(rest) > 0` 过滤非零 rest 的产品
2. `GROUP BY product_id, name`（同一产品有唯一名称，可以只 GROUP BY product_id）
3. 结果按产品名称升序排列

## 易错点

- 过滤条件在 `HAVING` 中（聚合后），不是 `WHERE`
- 结果需按名称排序，不是 ID
