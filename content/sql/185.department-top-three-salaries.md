## 题目描述

表：`Employee`

```
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| id           | int     |
| name         | varchar |
| salary       | int     |
| departmentId | int     |
+--------------+---------+
```

id 是这个表的主键。
departmentId 是 Department 表中 ID 的外键。
该表的每一行都表示员工的 ID、姓名、工资和所属部门的 ID。

表：`Department`

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| name        | varchar |
+-------------+---------+
```

id 是这个表的主键。
该表的每一行都表示一个部门的 ID 及其名称。

公司的主管们感兴趣的是公司每个部门中谁赚的钱最多。一个部门的 **高收入者** 是指一个员工的工资在该部门的 **不同** 工资中排名前三。

编写一个 SQL 查询，找出每个部门中 **收入高的员工**。

以任意顺序返回结果表。

查询结果格式如下所示。

**示例 1：**

```
输入：
Employee 表：
+----+-------+--------+--------------+
| id | name  | salary | departmentId |
+----+-------+--------+--------------+
| 1  | Joe   | 85000  | 1            |
| 2  | Henry | 80000  | 2            |
| 3  | Sam   | 60000  | 2            |
| 4  | Max   | 90000  | 1            |
| 5  | Janet | 69000  | 1            |
| 6  | Randy | 85000  | 1            |
| 7  | Will  | 70000  | 1            |
+----+-------+--------+--------------+

Department 表：
+----+-------+
| id | name  |
+----+-------+
| 1  | IT    |
| 2  | Sales |
+----+-------+

输出：
+------------+----------+--------+
| Department | Employee | Salary |
+------------+----------+--------+
| IT         | Max      | 90000  |
| IT         | Joe      | 85000  |
| IT         | Randy    | 85000  |
| IT         | Will     | 70000  |
| Sales      | Henry    | 80000  |
| Sales      | Sam      | 60000  |
+------------+----------+--------+

解释：
在 IT 部门：
- Max 的工资最高，为 90000
- Joe 和 Randy 都是 85000（第二高）
- Will 是 70000（第三高）
- Janet 是 69000（第四高），不在前三，不包含

在 Sales 部门：
- Henry 工资 80000（第一高）
- Sam 工资 60000（第二高）
- 只有 2 个不同的工资，所以都包含
```

## 解题思路

这道题的关键点：

1. **前三名不是前三个人**：是前三种不同的工资
2. **工资相同的员工都算**：85000 有两个人，都包含
3. **不足三种工资也返回**：Sales 部门只有 2 种工资，全部返回

### 核心思路

**最佳方法：** 使用 `DENSE_RANK()` 窗口函数
- 按部门分组排名
- 相同工资排名相同
- 排名连续无间隙（1, 1, 2, 3，而不是 1, 1, 3, 4）

**其他方法：**
- 自连接统计比当前工资高的不同工资数量
- 子查询筛选

## SQL 代码实现

### 方法一：DENSE_RANK 窗口函数（推荐）

```sql
SELECT 
    Department,
    Employee,
    Salary
FROM (
    SELECT 
        d.name AS Department,
        e.name AS Employee,
        e.salary AS Salary,
        DENSE_RANK() OVER (PARTITION BY e.departmentId ORDER BY e.salary DESC) AS rk
    FROM 
        Employee e
    JOIN 
        Department d ON e.departmentId = d.id
) AS ranked
WHERE rk <= 3;
```

**代码解释：**
1. `DENSE_RANK() OVER (PARTITION BY departmentId ORDER BY salary DESC)`：
   - `PARTITION BY departmentId`：按部门分组
   - `ORDER BY salary DESC`：按工资降序
   - `DENSE_RANK()`：密集排名（无间隙）
2. `WHERE rk <= 3`：筛选排名前 3 的
3. `JOIN Department`：获取部门名称

**为什么用 DENSE_RANK 而不是 RANK？**
```
工资：90000, 85000, 85000, 70000, 69000
RANK:      1,      2,      2,     4,     5  (有间隙，会漏掉第 4 名)
DENSE_RANK: 1,     2,      2,     3,     4  (无间隙，正确)
```

### 方法二：自连接统计（无窗口函数）

```sql
SELECT 
    d.name AS Department,
    e1.name AS Employee,
    e1.salary AS Salary
FROM 
    Employee e1
JOIN 
    Department d ON e1.departmentId = d.id
WHERE 
    3 > (
        SELECT COUNT(DISTINCT e2.salary)
        FROM Employee e2
        WHERE e2.departmentId = e1.departmentId
          AND e2.salary > e1.salary
    );
```

**代码解释：**
1. 对于每个员工 `e1`，统计同部门比他工资高的不同工资数
2. 如果这个数 < 3，说明他在前 3 名
3. 例如：
   - 最高工资：比他高的有 0 种，0 < 3，包含 ✓
   - 第二高：比他高的有 1 种，1 < 3，包含 ✓
   - 第三高：比他高的有 2 种，2 < 3，包含 ✓
   - 第四高：比他高的有 3 种，3 < 3 为假，不包含 ✗

### 方法三：变量模拟排名（MySQL 特有）

```sql
SELECT 
    Department, 
    Employee, 
    Salary
FROM (
    SELECT 
        d.name AS Department,
        e.name AS Employee,
        e.salary AS Salary,
        @rk := IF(@dept = e.departmentId, 
                  IF(@prev_sal = e.salary, @rk, @rk + 1), 
                  1) AS rk,
        @prev_sal := e.salary,
        @dept := e.departmentId
    FROM 
        Employee e
    JOIN 
        Department d ON e.departmentId = d.id,
        (SELECT @rk := 0, @prev_sal := NULL, @dept := NULL) AS init
    ORDER BY 
        e.departmentId, e.salary DESC
) AS ranked
WHERE rk <= 3;
```

**代码解释：**
1. 使用变量模拟 DENSE_RANK 的逻辑
2. 如果部门变了，重置排名为 1
3. 如果工资相同，保持排名不变
4. 如果工资不同，排名加 1

**注意：** 在 MySQL 8.0+ 中，变量赋值顺序可能不确定，推荐使用窗口函数。

### 方法四：子查询（性能较差）

```sql
SELECT 
    d.name AS Department,
    e1.name AS Employee,
    e1.salary AS Salary
FROM 
    Employee e1
JOIN 
    Department d ON e1.departmentId = d.id
WHERE 
    (SELECT COUNT(DISTINCT e2.salary)
     FROM Employee e2
     WHERE e2.departmentId = e1.departmentId
       AND e2.salary >= e1.salary) <= 3;
```

**代码解释：**
- 统计大于等于当前工资的不同工资数
- 如果 <= 3，说明当前工资在前 3 名

## 复杂度分析

**方法一（DENSE_RANK）：**
- 时间复杂度：O(n log n)，分区排序
- 空间复杂度：O(n)，存储排名
- 优点：简洁高效，逻辑清晰

**方法二（自连接）：**
- 时间复杂度：O(n²)，每行都需要统计
- 空间复杂度：O(1)
- 缺点：性能差，但不依赖窗口函数

**方法三（变量）：**
- 时间复杂度：O(n log n)
- 空间复杂度：O(1)
- 缺点：新版 MySQL 可能不稳定

**方法四（子查询）：**
- 时间复杂度：O(n²)
- 空间复杂度：O(1)
- 缺点：性能较差

## 关键点总结

1. **DENSE_RANK 是关键**：专门处理无间隙排名问题
2. **理解题意**：前三种工资，不是前三个人
3. **处理并列**：相同工资的员工都包含
4. **不足三种也返回**：部门工资种类 < 3 时，全部返回
5. **窗口函数最优**：代码简洁，性能好

## 易错点

1. **使用 RANK 而不是 DENSE_RANK**
   ```sql
   -- 错误：RANK 会产生间隙
   -- 工资：90000, 85000, 85000, 70000
   -- RANK: 1,      2,      2,      4（第 3 名缺失）
   RANK() OVER (PARTITION BY departmentId ORDER BY salary DESC)
   
   -- 正确：DENSE_RANK 无间隙
   -- 工资：90000, 85000, 85000, 70000
   -- RANK: 1,      2,      2,      3
   DENSE_RANK() OVER (PARTITION BY departmentId ORDER BY salary DESC)
   ```

2. **使用 ROW_NUMBER**
   ```sql
   -- 错误：ROW_NUMBER 给每行唯一编号，会把并列的分开
   -- 工资：90000, 85000, 85000, 70000
   -- ROW_NUMBER: 1,  2,      3,      4（两个 85000 排名不同）
   ROW_NUMBER() OVER (...)
   
   -- 这会导致其中一个 85000 被排除
   ```

3. **自连接条件错误**
   ```sql
   -- 错误：使用 >=，会把自己也算进去
   WHERE 3 >= (SELECT COUNT(DISTINCT e2.salary) ...)
   
   -- 正确：使用 >
   WHERE 3 > (SELECT COUNT(DISTINCT e2.salary) 
              WHERE e2.salary > e1.salary)
   
   -- 或者用 >= 但条件改为 <= 3
   WHERE (SELECT COUNT(DISTINCT e2.salary) 
          WHERE e2.salary >= e1.salary) <= 3
   ```

4. **忘记 DISTINCT**
   ```sql
   -- 错误：没有 DISTINCT，相同工资会被重复统计
   SELECT COUNT(e2.salary) ...
   
   -- 正确：必须去重
   SELECT COUNT(DISTINCT e2.salary) ...
   ```

5. **列名或顺序错误**
   ```sql
   -- 错误：列名或顺序不对
   SELECT name, salary, department ...
   
   -- 正确：
   SELECT Department, Employee, Salary
   ```

## 图解示例

以 IT 部门为例：

```
IT 部门员工：
id  name   salary
4   Max    90000   -> 不同工资排名 1
1   Joe    85000   -> 不同工资排名 2
6   Randy  85000   -> 不同工资排名 2（并列）
7   Will   70000   -> 不同工资排名 3
5   Janet  69000   -> 不同工资排名 4（超过前 3，不包含）

DENSE_RANK 结果：
name   salary  rk
Max    90000   1   ✓
Joe    85000   2   ✓
Randy  85000   2   ✓
Will   70000   3   ✓
Janet  69000   4   ✗ (rk > 3)

方法二统计逻辑：
Max (90000):   比他高的工资有 0 种，0 < 3  ✓
Joe (85000):   比他高的工资有 1 种 (90000)，1 < 3  ✓
Randy (85000): 比他高的工资有 1 种 (90000)，1 < 3  ✓
Will (70000):  比他高的工资有 2 种 (90000, 85000)，2 < 3  ✓
Janet (69000): 比他高的工资有 3 种 (90000, 85000, 70000)，3 < 3 为假  ✗
```

## 学习建议

1. **深入理解排名函数**：
   - `ROW_NUMBER()`：1, 2, 3, 4, 5（每行唯一）
   - `RANK()`：1, 2, 2, 4, 5（有间隙）
   - `DENSE_RANK()`：1, 2, 2, 3, 4（无间隙）
   - 画图对比三种函数的区别

2. **窗口函数必学**：
   - `PARTITION BY`：分组
   - `ORDER BY`：排序
   - 理解窗口函数不会聚合数据，保留原始行

3. **实践练习**：
   - 修改题目：找出每个部门工资前 5 的员工
   - 扩展：找出每个部门工资中位数以上的员工
   - 思考：如何找出每个部门工资最低的 3 个员工？

4. **理解题意细节**：
   - "前三" 指的是前三种不同的工资
   - 相同工资的员工都算
   - 不足三种也要返回

5. **性能对比**：
   - 使用 EXPLAIN 分析执行计划
   - 在大数据集上测试性能
   - 理解窗口函数的优势

6. **面试技巧**：
   - 优先写方法一（DENSE_RANK）
   - 能够解释为什么用 DENSE_RANK 而不是 RANK 或 ROW_NUMBER
   - 如果不允许用窗口函数，能写出方法二
   - 能够用例子说明三种排名函数的区别
   - 记得列名顺序

7. **扩展思考**：
   - 如何找出工资在部门内排名前 10% 的员工？
   - 如何找出工资高于部门平均工资的前 3 名员工？
   - 如何处理多个部门的综合排名？

8. **常见变体**：
   - Top K 问题（本题是 K=3）
   - 分组 Top K
   - 滑动窗口 Top K
   - 这些都可以用 DENSE_RANK 解决
